# Phase 23.6 — UI Design Contract

> Visual and interaction contract for the superadmin Rerun button, the research-run history on the
> intake page, and the internal "chosen run" label. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **No new visual language.** Every class below already exists on `admin.pulse.intakes.$id.tsx`,
> `NextStepBanner.tsx`, `ResearchRunProgress.tsx` or `styles.css`. `frontend/src/components/ui/` is not modified.
> DEV ONLY. The user could not be reached; every open choice is a recorded Claude's-discretion decision (section "Decisions").
>
> **Chosen run = internal only (D-23.6-02 revised).** Marking a run "chosen" records which finished run the final
> report is based on. Nothing client-facing changes: no client route, no mail, no PDF swap.

## Spacing Scale

Declared values (multiples of 4 only; Tailwind classes in brackets):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `py-1`) | Icon-to-label gap in badges; gap between the badge and its sub-line |
| sm | 8px (`gap-2`) | Gap between action buttons in a row; gap between row cells on mobile |
| md | 16px (`px-4`, `py-4`, `gap-4`) | Row padding (desktop `py-3` = 12px is the one row exception, see below); button horizontal padding |
| lg | 24px (`px-6`) | Block horizontal padding — matches the workflow card's `px-6` |
| xl | 32px (`mb-8`) | Unchanged gap below the workflow card |
| 2xl | 48px | not used in this phase |
| 3xl | 64px | not used in this phase |

Exceptions:
- Run rows use `py-3` (12px) on desktop — the same vertical rhythm as the existing skill-run history list, so a 5-run history stays scannable without scrolling the card off-screen.
- The history block uses `py-5` (20px) top/bottom — identical to `NextStepBanner`'s `px-6 py-5`, so the two blocks read as siblings.
- Buttons stay at the house size `px-4 py-2` (about 32px tall). On mobile (<768px) every row action button gets `min-h-[44px]` as the touch-target exception.

## Layout and placement

### Where it lives
The history REPLACES the single `IntakeOpenRunLink` row at the bottom of the workflow card
(`admin.pulse.intakes.$id.tsx`, the `RESEARCH_SURFACE_STATUSES` block after the stepper). Same
condition: rendered only when `intake.status` is `in_research`, `delivered` or `archived`, AND
`isSuperadmin` is true (`useAuth().isSuperadmin`). Non-superadmins see exactly what they see today.

Block shell: `border-t border-ink/10 bg-paperLight px-6 py-5`.


### Header row
- Left: title `font-mono text-[11px] uppercase tracking-wider text-ink/60` — `runs.title` with the count in `tabular-nums text-ink/40`.
- Right: the Rerun button (primary). `flex flex-wrap items-center justify-between gap-2`; on mobile the button drops below the title and goes full width (`w-full justify-center` below `sm`).

### Run list (desktop, `md` and up)
- A `<table>` with `w-full`; column heads in a `bg-paper2` strip, `font-mono text-[11px] uppercase tracking-wider text-ink/60`, `text-left`, `px-4 py-2`.
- Rows `border-t border-ink/10`, cells `px-4 py-3 align-top`, numbers `font-mono text-xs tabular-nums`.
- Columns, in order:
  1. **Attempt** — `research.runPage.trace.attempt` ("Poging {{number}}"), from the run's `attempt` value (not the list index).
  2. **Status** — status badge per the mapping above.
  3. **Started** — `fmtDate(started_at, "—")` from `lib/research/runClock.ts` ("d MMM yyyy HH:mm", locale-aware). Queued run with no `started_at` shows "—".
  4. **Duration** — `fmtDuration(started_at, completed_at)` for a terminal run; for an in-flight run the live `useElapsed(started_at, true)` clock. ONE clock definition — do not add another.
  5. **Cost** — `fmtCost(cost_usd_total, "—")`. Unknown cost is "—", never "$0.00".
  6. **Actions** — right-aligned `flex flex-wrap justify-end gap-2`, see "Row actions".
- Order: newest first by `attempt` descending (ties by `created_at` descending).
- The chosen run's row gets no background tint; the yellow badge is the only marker.

### Run list (mobile, below `md`)
- The table is not rendered; the same data renders as a stacked `<ol className="divide-y divide-ink/10">`, each `<li className="py-4 space-y-2">`:
  - line 1: attempt label (11px mono) left, status badge right (`flex justify-between items-center gap-2`);
  - line 2: `Gestart {date} · {duration} · {cost}` in 12px mono `text-ink/60 tabular-nums`, wrapping allowed;
  - line 3: the chosen-run badge (if any) with its sub-line;
  - line 4: actions, `flex flex-wrap gap-2`, each button `min-h-[44px]`.
- Nothing is hidden on mobile; it only reflows. The block keeps its `px-6` — at 320px the buttons wrap to one per line.

### Row actions (per row, left to right)
| Action | Shown when | Style | Behaviour |
|--------|-----------|-------|-----------|
| Chosen-run badge "Gekozen run" | this run is the chosen run (explicitly marked, or — display default only — the newest finished run when none is marked) | `badge-highlight` + `Check` 12px | Not clickable. Sub-line under it (14px sans `text-ink/60`): `runs.chosenBadgeMarked` or `runs.chosenBadgeDefault`. |
| "Kies als basis voor rapport" | run status is `completed` or `completed_degraded` AND it is not the explicitly marked run AND intake is not `archived` | secondary: `border border-ink bg-paper px-4 py-2 font-mono text-xs uppercase tracking-wider text-ink hover:border-2 disabled:opacity-50` | Opens the choose confirm. Also shown on the row that carries the badge only by the display default (so the operator can make the default explicit). |
| "Run openen" | always | existing `OpenRunLink` look: `inline-flex items-center gap-2 border border-ink/30 px-4 py-2 font-mono text-xs uppercase tracking-wider text-ink hover:bg-ink/5` + `ExternalLink` | `<Link to="/admin/pulse/runs/$runId">` (a real link: middle-click works). Drop the `mt-4` from the existing component in a row context. |

Button hierarchy per row: at most ONE secondary (ink-bordered) button ("Kies als basis voor rapport"); the three navigation links are the lighter `border-ink/30` style. The block's only primary (filled ink) button is Rerun.

## Interaction contract

### Rerun button
- Label `runs.rerun`, icon `RotateCw` 14px, primary style from NextStepBanner:
  `inline-flex items-center gap-2 bg-ink px-4 py-2 font-mono text-xs uppercase tracking-wider text-paper hover:bg-ink/85 disabled:opacity-50`.
- Visible when: superadmin AND intake status is `in_research` or `delivered` AND at least one run exists.
  Hidden on `archived` (the status override is the way back first) and on `decomposed` (the existing
  "Start deep research" button in NextStepBanner covers that path; D-23.6-03 says it keeps working).
- Disabled when:
  1. any run of this intake is in flight (`queued`, `running`, `needs_report_spec` — mirrors backend
     `RESEARCH_IN_FLIGHT`) → reason line `runs.rerunBlockedInFlight` under the header row (14px sans `text-ink/60`), also set as `title`;
  2. the run list is still loading or failed to load → no reason line (the loading/error state explains itself);
  3. the trigger request is in flight → `Loader2` spin + label `runs.rerunStarting`.
  `parked` is NOT in flight — Rerun is enabled and the dialog adds a note (below).
- Live status: the in-flight check reads the page's EXISTING single research stream (`researchRun`
  from `useActiveResearchRun`) for the newest run, plus the list for older rows. Do NOT open a second
  SSE connection. When `researchRun.status` changes, refetch the list once.
- Click opens the rerun confirm. Nothing is triggered by the click itself.

### Rerun confirm (shadcn `AlertDialog`, same as the existing research-start confirm)
- Title `runs.rerunConfirmTitle`; description `runs.rerunConfirmBody` (states ~$40, same questions and
  context pack, no run limit, and that the currently chosen run stays chosen until another is chosen —
  with the newest finished run counting as chosen only when none was marked).
- If the newest run is `parked`, append a second paragraph `runs.rerunConfirmParkedNote`.
- Footer: `AlertDialogCancel` = `runs.rerunConfirmCancel`; `AlertDialogAction` = `runs.rerunConfirmConfirm`.
  The trigger fires ONLY from `AlertDialogAction` (Phase 16 D-03 rule).
- Outcomes (reuse `classifyTriggerOutcome` + `resolveErrorKey`):
  - started → `toast.success(runs.toast.rerunStarted)`, `load()` + list refetch; the new row appears on top as `queued`.
  - error with an in-flight code (409 `RESEARCH_IN_FLIGHT`) → `toast.error(runs.toast.rerunInFlight)`, list refetch.
  - any other error → `toast.error(codeKey ? t(codeKey) : runs.toast.rerunFailed)`.
  - `needs_investigation` cannot happen for a superadmin (no cap, D-23.6-01); if it does, reuse
    `intakeDetail.toast.researchNeedsInvestigation` unchanged.

### Choose run (internal "chosen run" label)
- Click "Kies als basis voor rapport" opens an `AlertDialog`: title `runs.chooseConfirmTitle` (interpolates the
  attempt number), body `runs.chooseConfirmBody`, cancel `runs.chooseConfirmCancel`, action `runs.chooseConfirmConfirm`.
- On confirm: the button shows `Loader2`; success → `toast.success(runs.toast.chooseDone)` and the badge
  moves to that row (sub-line `runs.chosenBadgeMarked`) with no page reload; failure →
  `toast.error(runs.toast.chooseFailed)`, nothing moves.
- It is an internal label only (D-23.6-02 revised): no client route, no mail, no PDF swap. The planner must
  not wire any client-facing effect or mail to this action.

### Display default vs stored choice (behaviour the copy depends on)
- The badge row = the explicitly marked run. When NO run is explicitly marked, the badge shows on the newest
  `completed`/`completed_degraded` run with sub-line `runs.chosenBadgeDefault`. This is a DISPLAY DEFAULT
  computed at render time, NOT a stored pick: nothing is written until the operator confirms a choice, and a
  later finished run takes over the default badge while nothing is marked.
- Once a run is explicitly marked, a finished rerun does NOT take the badge; the marked run stays chosen
  until the operator chooses another (matches the rerun confirm copy).
- A rerun on a `delivered` intake must leave the intake `delivered` (CONTEXT D-23.6-03 — GET /report 404s on
  any other status, so the client would lose their report). The history block and Rerun button must still
  render on `delivered`.
- If no finished run exists, no row carries the badge and the list shows `runs.noChosenRun` under the header.

### States
| State | Render |
|-------|--------|
| Loading | Header row with the Rerun button disabled; two `<Skeleton className="h-10 w-full" />` rows with `gap-2`. No spinner text. |
| Empty (surface status but zero runs — e.g. a legacy `in_research` intake) | Header without Rerun; `runs.empty` in 14px sans `text-ink/60`. |
| Error | `runs.loadFailed` in `text-sm text-red-600` (house inline error), a secondary "Opnieuw proberen" button (`runs.retry`) that refetches, AND the existing `IntakeOpenRunLink` for the live run below it — so a failed list never removes the way into the run page. |
| One run | Same table with one row; count shows "(1)". |
| Archived intake | List renders read-only: no Rerun, no "Kies als basis voor rapport"; links and download stay. |

### Accessibility
- Table has a visually hidden `<caption>` = `runs.title`; column heads are `<th scope="col">`.
- The action column head is empty visually but has an sr-only label `runs.col.actions`.
- The chosen-run badge has `aria-label` = `runs.chosenBadge` + sub-line text.
- The reason line for a disabled Rerun is linked with `aria-describedby`.
- The history block is NOT a live region (the run page owns announcements); toasts announce outcomes.
