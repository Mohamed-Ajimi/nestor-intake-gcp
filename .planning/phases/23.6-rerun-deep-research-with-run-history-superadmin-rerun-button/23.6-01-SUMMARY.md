# Phase 23.6 Plan 01: Superadmin rerun rules + chosen-run storage Summary

A superadmin can now start any number of research runs on one intake. From `in_research` or `delivered`, a new run starts with no status change whenever no run of that intake is queued, running or in `needs_report_spec`. Migration 0018 adds a DB-enforced "one chosen run per intake" flag (`research_runs.chosen_at`), and `ResearchRunRepository.set_chosen` moves that flag in one transaction.

## What was built

**Task 1 — chosen-run storage (D-23.6-02 revised)**
- `0018_research_runs_chosen_at.py`: adds a nullable `chosen_at timestamptz` column with no default, plus a partial unique index `uq_research_runs_one_chosen_per_intake ON (intake_id) WHERE chosen_at IS NOT NULL`. The downgrade drops the index, then the column. No policy or grant changes. 0019 is still reserved.
- The ORM model mirrors the column (the comment text is byte-identical to the migration's) and the index.
- `set_chosen(intake_id, run_id)` locks every run of the intake with `SELECT ... FOR UPDATE` through `_scope`. It returns early if the target is already chosen. Otherwise it clears the current mark, sets `now()` on the target (matched on `id` AND `intake_id`), flushes, and returns the previously chosen id. It never commits and does not check run status; plan 02's route owns that rule.
- The head pin test is now `test_the_intake_alembic_head_is_0018`. The 0017 reverse test now steps down to 0017 first, reads its baseline there, and re-upgrades only to 0017 inside the `try`. The `finally` still returns the schema to head.

**Task 2 — trigger_research (D-23.6-01, D-23.6-03)**
- `_attempt_cap_reached(identity, prior) -> (capped, counted)`: a pure function. It returns not-capped for a superadmin; any other identity keeps the old 3-attempt rule, with cancelled runs not counted.
- `_RERUN_STATUSES = frozenset({"in_research", "delivered"})`. A trigger from either status returns 409 "No earlier research run to rerun for this intake" if the intake has no runs, and 409 "Research is already running for this intake" if ANY run is in `RESEARCH_IN_FLIGHT`. Otherwise `new_status = old_status`.
- Unchanged: the write transaction, the `patch_if` compare-and-swap, the attempt count inside the transaction, the audit row (a rerun writes `from == to`), the IntegrityError-to-409 translation and the driver scheduling.
- `_RETRYABLE_RUN_STATUSES`, `_MAX_ATTEMPTS` and `_CAP_EXEMPT_RUN_STATUSES` are kept. The comment on `_RETRYABLE_RUN_STATUSES` now says it no longer gates the trigger.
- New tests: superadmin has no cap (replaces `test_attempt_cap_3`), a pure non-superadmin cap test, rerun after completed/completed_degraded, rerun after parked (the parked row stays parked), refusal when an older run is still in flight, delivered stays delivered (with the audit row read back), delivered refused while queued/running/needs_report_spec, archived gets 409, and no prior runs gets 409 for both in_research and delivered.
