# Phase 23.6 Plan 04: Run history, Rerun button and chosen-run label on the intake page Summary

On `in_research`, `delivered` and `archived` intakes, superadmins now see "Research-runs (n)". It lists every run, newest first, with a status badge, start time, duration (a live clock for runs in flight) and cost. Each row has Open run, Verification report and raw-zip actions. Exactly one row carries the yellow chosen-run badge (marked, or the default). There is a ~$40 confirmed Rerun and an internal "Use for report" confirm. The component opens no stream of its own. The page's single `useActiveResearchRun` call now takes a reopen key, which is bumped after a rerun.

## What was built

- `frontend/src/components/intake/ResearchRunHistory.tsx` (560 lines). All decisions come from plan 03's pure rules: `rerunState`, `resolveChosenRun`, `canChooseRun`, `canDownloadRunZip`, `runStatusBadge`, `mergeLiveRun`, `sortRunsNewestFirst` and `classifyRerunFailure`. Layout by screen size:
  - desktop (`md+`): a `<table>` with an sr-only caption and `th scope="col"` headers;
  - mobile: an `<ol>` with four lines per run and `min-h-[44px]` action buttons.

  States follow the spec:
  - **Loading:** skeletons, and a disabled Rerun.
  - **Empty:** the `runs.empty` text, no Rerun.
  - **Error:** `loadFailed`, a Retry button, and `IntakeOpenRunLink`.
  - **Archived:** read-only; no Rerun and no choose button.
- `frontend/src/routes/admin.pulse.intakes.$id.tsx`:
  - `isSuperadmin` is now taken from `useAuth()`.
  - Added `researchReopenKey` as the second argument of the one existing `useActiveResearchRun` call, with a comment paragraph explaining it.
  - Added `onRerunStarted`, which calls `load()` and then bumps the reopen key.
  - The D-22-5 row is now `isSuperadmin ? <ResearchRunHistory …/> : <IntakeOpenRunLink …/>`.
  - `onStartAutoResearch` and NextStepBanner were not touched.

## Deviations from Plan

**1. [Rule 3 - Blocking] The i18n audit flagged a type annotation as JSX text.** The audit flagged `onRerunStarted: () => Promise<void> | void` as the JSX text "Promise" (it read `=> Promise<` as markup). I split the type into two aliases, `MaybePromise` and `RerunStartedHandler`, and the audit is back to 106 advisories. This does not change behaviour.

**2. [Note] `load()` swaps the whole page to its skeleton.** After a rerun, `onRerunStarted` calls `load()`. That sets `loading = true`, and the page renders its full-page skeleton, so `ResearchRunHistory` unmounts and remounts. On remount it fetches the list again, and it shows the new run as `queued`. The existing Start path (`onStartAutoResearch` → `load()`) behaves the same way. The browser walkthrough in plan 05 should confirm this looks acceptable.

**3. [Note] ESLint on the route file.** Running `eslint` on `admin.pulse.intakes.$id.tsx` reports many prettier errors. Most of that file uses 1-space indentation, which prettier rejects. I did not reformat it (out of scope). The plan's gates for this file were tsc, vitest, the i18n audit and the build, and all four pass.

Otherwise the plan was executed as written.
