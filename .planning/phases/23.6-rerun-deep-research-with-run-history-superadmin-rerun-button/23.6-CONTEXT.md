# Phase 23.6 — Rerun deep research with run history — Context

**Gathered:** 2026-09-25 (operator, in session)
**Status:** Ready for planning
**Scope:** DEV ONLY (`project-cb01b861-cb4a-438d-b9a`). No prod promotion in this phase.

<domain>
## Task boundary
A superadmin can start another deep-research run on an intake that already has one, see every run the intake has
had (each with its own report and raw-output zip), and choose which finished run the client sees.
</domain>

<decisions>
## Locked decisions (operator, 2026-09-25)

- **D-23.6-01 — No attempt cap for superadmin.** Today `trigger_research` counts prior runs against a cap of 3
  (D-23.4-07, `_CAP_EXEMPT_RUN_STATUSES`). For a superadmin the cap does not apply. Every run still costs ~$40;
  the confirm dialog must say so. Non-superadmins cannot start research at all today (D-23.1-16) — unchanged.
- **D-23.6-02 — The client sees the run the superadmin PICKS; newest finished run by default.** Closes
  DEF-23.5-07-04. Everything client-facing that shows a research result (results link, report/PDF, zip download,
  "research complete" mail links) must resolve through the ONE delivered-run choice, never "latest row".
  Changing the pick must not re-send mail on its own.
- **D-23.6-03 — Rerun button, same questions.** One click on the intake page starts a new run from the CURRENT
  approved questions and context pack. No status step-back to `decomposed` is required (today the trigger 409s
  unless status is `decomposed`). The existing path (status override back to `decomposed`, edit, start) keeps
  working. A rerun is refused while another run on the same intake is in flight (`RESEARCH_IN_FLIGHT`).
- **D-23.6-04 — History on the intake page.** A list of every run (newest first): started/finished time, status,
  cost if known, links to its run page, report and zip, and which one is delivered to the client.

## Already true (do not rebuild)
- Every run is kept as its own `research_runs` row (attempt = n) with its own `bundle_key` zip and per-run page
  (`admin.pulse.runs.$runId.*`). Deleting an intake keeps tribunal rows (D-23.5-06).
- Research-call concurrency on dev is already `NESTOR_TRIBUNAL_ANGLE_CONCURRENCY=15` (env only,
  `tribunal-worker-00016-cvq`); nothing to build for it.

## Constraints carried
- Legacy Supabase `run-research` never invoked; `research_router` stays mounted (D-23.1-10).
- `frontend/src/components/ui/` untouched; nl/fr/en keys for every new string (i18n-audit gate).
- Tribunal worker idle gate before any worker deploy; dev is NOT Terraform-managed (update by
  `gcloud run services update`, never `terraform apply` on dev).
- A schema change, if needed for the delivered-run pick, is an alembic migration in `backend/` (next free head);
  migrations run on dev via the migrate job.
