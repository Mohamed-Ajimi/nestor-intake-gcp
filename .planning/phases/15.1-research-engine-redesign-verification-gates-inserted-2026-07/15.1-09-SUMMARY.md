# Phase 15.1 Plan 09: Gate Replay + Calibration Summary

The recorded 1,162-claim fixture now replays through the **real** gate machinery and reproduces
the blind experiment's funnel exactly — `distilled 1162 → kept 456 → dropped 706 →
selected_verify 424 → skipped_stable 32`, with `gate_errors 0` and every drop attributed
(358/320/28) — at zero cost and zero flakiness. That is Success Criterion 1, and it is green.

## What was built

### Task 1 — `test_gate_replay.py`, the phase gate (commit `f751c67`)

`_AnswerKeyGateAudited` is a hand-written duck-typed fake that stands in for **the model only**.
On each call it splits the gate's own prompt into header + claims block, works out which of the
two gates is asking (the `STABLE NOTORIOUS FACTS` marker, read from the HEADER so no claim's own
wording can misroute an answer), parses the `INDEX | CLAIM_TEXT` lines back out, maps each text
to its 1-based fixture id, and renders the recorded decision in the gate's own plain-text line
format.

Everything between `apply_gates(...)` and that fake is production code doing its real job: the
real 40-claim batching, the real `asyncio.Semaphore` fan-out, the real `_parse_gate_lines`
bounds-checking, the real inverted KEEP-for-checking default, the real funnel arithmetic and its
three internal invariants. **No injectable classifier seam was added to `gates.py`**
(`grep -c "classifier=" → 0`): that would have been a second, untested production path bypassing
exactly the machinery this test exists to prove.

The text→id map is built once at module scope, keyed on the gate's own 240-character truncation
and trimmed on both sides. Collisions are collected rather than tolerated — `_KEY_COLLISIONS` is
asserted empty, with a message explaining that a collision makes one claim answer with another's
recorded decision. **There are none: all 1,162 truncated texts are distinct.**

Ten tests:

| # | Test | Proves |
|---|------|--------|
| 1 | `test_fixture_loads_the_recorded_population` | 1,162 claims, contiguous 1-based ids, both answer keys, the strict key covering exactly the KEEP ids, all tallies vs `RECORDED_FUNNEL_COUNTS`, zero prompt-key collisions |
| 2 | `test_replay_reproduces_the_recorded_funnel` | **THE PHASE GATE** — the five gate-computed numbers + three drop reasons + `gate_errors 0`, all computed by `apply_gates` |
| 3 | `test_every_claim_carries_a_gate_decision` | all 1,162 carry decision/reason/strict; `strict is None` exactly on DROP |
| 4 | `test_cluster_survives_if_any_member_survives` | G-04 step 3, driven by REAL replayed claims (not synthetic ones) |
| 5 | `test_funnel_reaches_verification_summary` | the carrier key exists in `pipeline.py`; the report re-publishes the funnel key-for-key; the fixture path matches the constant |
| 6 | `test_report_accounting_matches_the_replayed_funnel` | G-08 — bucket 2 == dropped + skipped_stable; the three buckets sum to 1,162 |
| 7 | `test_healthy_replay_reports_zero_bucket_three` | bucket 3 == 0, `verification_degraded is False`, no text |
| 8 | `test_injected_failure_replay_reports_a_non_zero_bucket_three` | **the operator's headline** — an injected usage-cap outage books every failed claim as a gate error, drops NOTHING, moves claims INTO the queue, and the report says `VERIFICATION DEGRADED` in words with the count |
| 9 | `test_replay_makes_no_live_llm_calls` | exact batch counts (`ceil(1162/40)=30` + `ceil(456/40)=12` = 42), only the gate's own model, and no provider-client attribute anywhere on the fake |
| 10 | `test_worker_persists_the_replayed_funnel_onto_the_run_row` | the funnel reaches the `run.verification_summary` **column**, in the same statement as `status='completed'`, cancel guard intact |

**G-13 boundary held.** The five gate-computed numbers are asserted; the sixth recorded constant
— which counts group-skeptic passes that returned during the 2026-07-22 cap incident — is not
named, not asserted, and not referenced anywhere in the file. Every recorded number is asserted
against `RECORDED_FUNNEL_COUNTS`, never a literal, so the constant stays the single source of
truth and a fixture edit cannot quietly re-baseline the phase.

### Task 2 — `test_gate_calibration.py`, the August measurement (commit `3a5f921`)

Opens with a header block stating, before the docstring, that the file contains no pass/fail
threshold, reports numbers, and is never a CI gate — with the reason: a green phase must not
depend on a coin the model flips, because the honest response to that kind of red build is to
weaken the check.

Two report-only tests, both `@pytest.mark.live`, both opening with an inline env-gated
`pytest.skip` naming G-01 and the 2026-08-01 cap reset:

1. `test_gate_agreement_against_the_blind_answer_key` — real `apply_gates` over an evenly-strided
   sample (default 300; the distilled TSV is ordered by facet, so the first N would be a biased
   slice of one topic). Prints overall agreement, the KEEP/DROP confusion matrix, agreement per
   DROP reason, VERIFY/SKIP_STABLE agreement among the recorded KEEPs, the gate's own funnel, and
   both disagreement lists — the costly direction first (recorded KEEP, gate DROP: a material
   claim that would ship unexamined), then the cheap one.
2. `test_known_contradiction_pairs_cluster_together` — real `group_claims` over the full
   population, reporting cluster count, singleton share (against the 92% baseline) and, per pair,
   whether the two variants collided. A probe that matches nothing prints
   `NOT FOUND IN FIXTURE` with the probe and its match counts, so fixture drift can never
   masquerade as a clustering failure.

Both close with a grep-able `[15.1-CALIBRATION]` one-liner, and each prints its own **measured**
cost: the audit writer and blob sink are local in-memory stand-ins, but the gemini client, the
cost table and the hash-chain module are the production ones. The factory is handed an Anthropic
placeholder, so this file cannot touch the capped account even by accident.

## Deviations from Plan

### 1. [Rule 3 - Blocking] Worktree was 105 commits stale — fast-forwarded to master

**Found during:** setup, before Task 1.
**Issue:** the branch sat at `a3a0c96`, 105 commits behind `master` (`db78b31`), with zero unique
commits. All four waves this plan depends on were absent: `load_selection_experiment`, `gates.py`,
the report `accounting` block, the pipeline gate stage and the worker's funnel write. A replay
test written on that base would have exercised machinery that does not exist.
**Fix:** `git merge --ff-only master` — lossless (`git rev-list --count master..HEAD` = 0). All
six dependency checks then passed. **This is now 7 of 9 agents cut stale in this phase.**

### 2. [Rule 2 - Missing critical coverage] Closed 15.1-08's carried-forward column-write gap

**Found during:** Task 1.
**Issue:** plan 15.1-08 added the single-statement `verification_summary` write to `worker.py`
but could not add a test for it without breaching its two-file boundary, and said so. Nothing in
the tree asserted that the funnel actually lands in the **column**. The plan's own test 5 proves
propagation only as far as the report shaper.
**Fix:** `test_worker_persists_the_replayed_funnel_onto_the_run_row` drives the real
`worker.execute_run` with a runner returning the **replayed** funnel and a fake session that
captures every statement and its bound parameters (the harness convention from
`test_async_worker.py`). It decodes `params["vsummary"]` and compares it to the funnel the gates
computed, and checks the write is the same statement that sets `status='completed'` with the
`WHERE ... status='running'` cancel guard intact. No database, no LLM, no marker, no new build
config — it runs inside the existing Postgres-free gates gate.
**Files modified:** `test_gate_replay.py` · **Commit:** `f751c67`

### 3. [Rule 3 - Blocking] `_build_funnel` is not called from the replay test

**Found during:** Task 1.
**Issue:** the plan's tests 5-8 want the pipeline-owned accounting keys on the funnel, and
`pipeline._build_funnel` is the production builder. But its signature has a keyword-only
parameter named after the incident-derived session constant, and Task 1's acceptance criterion
requires `grep -c "verify_sessions"` to return **0** for the file. Calling it — even passing 0 —
would have written that name into the phase gate, which is precisely what G-13 forbids.
Spelling the key indirectly to dodge the grep would have been worse: obfuscation that hides the
intent the criterion exists to make visible.
**Fix:** a local `_pipeline_funnel()` helper composes the three keys the **report shaper actually
reads** (`checked`, `should_have_been_checked`, `verification_degraded`) with the same clamping
rule, and its docstring says why the fourth key is absent and where the builder's full shape is
proven instead (`test_gate_selector.py::test_empty_claims_path_reports_the_gate_funnel_shape`,
already green). No coverage is lost; the naming boundary is kept literally.
**Files modified:** `test_gate_replay.py` · **Commit:** `f751c67`

### 4. [Test ergonomics] The opt-in skip guard is inlined in both calibration bodies

**Found during:** Task 2.
**Issue:** a shared `_require_opt_in()` helper is DRY-er, but Task 2's acceptance criterion
requires `grep -c "pytest.skip"` >= 2, and — more to the point — "the first statement of this
test refuses to run it" should be readable without following a call, because that statement is
the only thing between a full-suite run and a real provider bill.
**Fix:** the guard is inline in both bodies; the message is a single module-level constant, so
the wording is still written once.
**Files modified:** `test_gate_calibration.py` · **Commit:** `3a5f921`
