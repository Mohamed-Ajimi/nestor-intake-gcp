# Phase 15.1 Plan 03: Superseded Verdict (Producer Side) Summary

The skeptic can now return a fourth verdict — `superseded` — carrying a `superseded_note`
that states what changed and from when, and no verdict string outside the four-word
vocabulary can leave the parser.

## What Was Built

**Task 1 — tool schema + prompt** (`bbc4891`)

`EMIT_GROUP_VERDICT_TOOL`'s per-verdict `verdict` enum went from
`["support", "refute", "insufficient"]` to `["support", "refute", "insufficient", "superseded"]`.
The tool `description` gained the superseded rule, explicitly warning against using `refute`
for an overtaken-but-once-true fact and requiring the note to be quoted from the fetched source.
A new optional `superseded_note` string property was added to the per-verdict object schema —
deliberately NOT added to `required`.

`_GROUP_SYSTEM` in `group_skeptic.py` now reads
`support / refute / insufficient / superseded` and defines the fourth word beneath the existing
three, demanding the date / what-changed in `superseded_note`. The reconciliation block and the
closing "Finish by calling emit_group_verdict exactly once." are byte-identical.

`EMIT_VERDICT_TOOL` (the per-claim sibling) is unchanged, with a source comment recording that
the asymmetry is intentional and that plan 15.1-07 owns the per-claim path.

**Task 2 — parse-boundary normalisation** (`7e9525d`)

Added `_VERDICT_VOCAB: frozenset[str]` and a pure `_normalise_verdict(raw: object) -> str` that
lowercases/strips, returns the value if it is in the vocabulary, and otherwise logs a
`log.warning` naming the rejected value and returns `"insufficient"`. Non-strings return
`"insufficient"`.

Inside `_parse_group_verdict`, `v.get("verdict", "insufficient")` — the unvalidated passthrough —
was replaced with `_normalise_verdict(v.get("verdict"))`. `superseded_note` was added to the
per-index dict (trimmed string, empty unless the verdict is actually `superseded`), to the
fill-missing `setdefault` block, and to `_insufficient_group`'s fallback dicts, so every consumer
can read the key unconditionally.

The `_coerce_json` F-01 guards, the `0 <= idx < n_claims` bounds check, the
fill-missing-with-insufficient behaviour, the `reconciliation` sub-dict shape and the function
signature are all untouched. No `json.loads` on raw model text (`grep -c json.loads` = 0).

**Task 3 — producer-side proof** (`03ad24a`)

`tests/test_superseded_verdict.py` — 8 pure tests (no DB, no network, no mocking library),
using the duck-typed `_FakeBlock` convention from `test_tribunal_grouping.py`:

1. `test_tool_enum_offers_four_verdicts` — enum order + `superseded_note` present + not required,
   and the per-claim enum still has exactly three values.
2. `test_parser_preserves_superseded` — verdict and note survive verbatim.
3. `test_unknown_verdict_string_normalises_to_insufficient` — the `"supersede"` typo, a dict, and
   `None` all normalise; casing/whitespace is tolerated rather than rejected.
4. `test_superseded_survives_and_carries_caveat` — the G-07 proof (the name 15.1-VALIDATION.md
   binds), in two halves: adjudication returns `True` for a superseded verdict, and the caveat
   text is reachable from the parsed verdict.
5. `test_majority_refute_still_drops` — control; a superseded verdict cannot tip the majority.
6. `test_all_failed_group_fallback_carries_note_key` — `_insufficient_group` carries the key.
7. `test_filled_missing_claim_carries_note_key` — the fill-missing path carries it too.
8. `test_note_ignored_when_verdict_is_not_superseded` — a stray note on a `support` verdict is
   dropped.
