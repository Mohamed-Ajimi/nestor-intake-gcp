<objective>
`run.verification_summary` has NO production writer. Migration 0011 created the column, the ORM
declares it, `verification/report.py:234` reads it, and only the test fixture loader writes it.
The live pipeline builds a funnel-shaped dict and buries it in an `Output('synthesis_cache')`
row where it dies.

Purpose: SC1 requires the funnel to "propagate to `run.verification_summary`". That is net-new
work, not an extension. This plan builds the write path — in the worker's existing completion
transaction, so a run can never be marked `completed` without its honesty marker landing in the
same commit (G-10: "a run must never again report completed — green while its fact-checking
stage was gutted").

Output: the funnel on the pipeline result contract, the single-transaction completion write, and
the D15 feed's closing summary stating degradation in words.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker process → `run` table (tenant-scoped, RLS FORCE) | A write without the tenant GUC either fails or, worse, writes across tenants |
| pipeline result dict → JSONB column | Untrusted-shaped dict is serialised into a persisted column read by an operator API |
| run status → four API reads | `RunStatus` is a Literal validated FROM the DB row; an unknown value turns reads into HTTP 500 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.1-35 | Elevation of Privilege / Information Disclosure | the `UPDATE run` write path | mitigate | `await set_tenant_context(session, claimed["tenant_id"])` stays the first statement inside `session.begin()` (ASVS V4, T-06-02); the write reuses the existing tenant-scoped transaction rather than opening a new session |
| T-15.1-36 | Repudiation | a run marked `completed` without its degradation marker | mitigate | Status and funnel are set in ONE statement in ONE transaction, behind `WHERE id=:id AND status='running'` |
| T-15.1-37 | Tampering | a cancelled run being flipped to completed | mitigate | The `AND status='running'` guard and the `completed.rowcount` gate are preserved unchanged |
| T-15.1-38 | Denial of Service | a falsely-zeroed funnel on a non-Tribunal or funnel-less run | mitigate | The column is left NULL when no funnel is present; `report.py` emits `accounting: None` for a NULL funnel rather than a clean-looking zero |
| T-15.1-39 | Tampering | new run status breaking `ck_run_status` / CR-03 500s | mitigate | No status added; `grep` for `completed_degraded` returns 0 (G-10; 15.2's R6 owns the promotion) |

| T-15.1-SC | Tampering | npm/pip/cargo installs | accept | Zero packages installed this phase; `tribunal/requirements.txt` unmodified |
