# Phase 15.1 Plan 02: Claim Provenance and Merging Dedupe Summary

**Every distilled claim now names the researcher that produced it via `found_by`, and `_dedupe_claims` merges duplicate facts into that list instead of deleting them — with a property test proving the surviving claim list is byte-identical in length, order and text to the pre-15.1 behaviour.**

## Accomplishments

- **G-12 bug 1 closed.** `claim_distiller` built `units: list[(provider_name, chunk)]`, used the name only for the `### Provider: {name}` prompt header, and then threw it away. `_parse_distiller_response` now takes a keyword-only `provider` and every claim carries `found_by: [provider]`.
- **G-12 bug 2 closed.** `_dedupe_claims` collapsed the same fact from three different researchers and discarded the duplicates (2,976 raw → 1,162). It now unions the duplicate's `found_by` into the first occurrence. Three researchers independently confirming a fact is finally distinguishable from one asserting it alone.
- **Count preservation proven, not assumed** (RESEARCH Pitfall 5). A property test compares the new implementation against an inlined verbatim copy of the old discard implementation and asserts both equal length and equal surviving order/text.
- **Pre-existing cosmetic log bug fixed.** The summary line passed `len(claims)` twice, so the "atomic claims" and "after dedupe" slots always rendered the same number and the raw→deduped ratio was invisible in run logs. Now logs `raw -> after dedupe`, plus a distinct-provider count so corroboration coverage is observable.
- **31/31 tests green in Cloud Build**, including the pre-existing `test_distiller_coverage.py` regression file on the same functions.

## Decisions Made

- **`found_by` is a plain list, not a set.** The claim dict is serialised into `synthesis_cache` JSON after a pause; a bare `set` is not JSON-serialisable. The union preserves first-seen provider order and rejects duplicates by membership test.
- **The merge only touches `found_by` when the duplicate actually has provenance.** If neither the kept nor the incoming claim carries `found_by`, the kept dict is left exactly as the old implementation left it — so no call path that builds claims by hand sees a new key appear.
- **`provider` defaults to `""`** and yields `found_by: []` rather than raising, so the parse function stays usable from any future call site without a provider in scope.
- **Provenance is supplied by the pipeline, never parsed from model output** (threat T-15.1-05). A model cannot set its own attribution.
