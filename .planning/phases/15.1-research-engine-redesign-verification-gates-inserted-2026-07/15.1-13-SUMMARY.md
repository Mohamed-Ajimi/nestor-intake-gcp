# Phase 15.1 Plan 13: Superseded Caveat, Stage Schema, Appendix Honesty Summary

The superseded caveat now travels to the writing model as data, the `gate` stage the
pipeline has been reporting is finally declared (plus a source-driven test so no future
stage can go undeclared), and the client-facing appendix no longer describes unverified
claims by a stakes rule G-02 abolished.

## What Was Built

### Task 1 — CR-01 leg a: the caveat reaches synthesis (commit `cc6e0df`)

`group_skeptic._parse_group_verdict` produced `superseded_note` and nothing consumed it:
the note landed in `verdicts_by_claim` and died there, while `contested_notes` — the only
note list `synthesize_report` receives — was built solely from `group_reconciliations` and
`conflict_detector` output. A claim the skeptic marked "true until 1 April 2026" therefore
shipped in the report body with no caveat on any surface (the KPAnG failure, run 4cbb5311).

Added to `pipeline.py`:

- `_one_line(text)` — collapses all whitespace (newlines included) to single spaces.
- `_collect_superseded_notes(claims, verdicts_by_index) -> list[str]` — a **pure** module-level
  helper emitting `[SUPERSEDED] {claim[:120]}: {note}` for each index whose verdict is
  `superseded` with a non-empty note. Reads claim text via `c.get("text") or c.get("claim_text")`
  (both shapes exist in this codebase). Emits nothing for any other verdict value, a missing
  index, an empty/whitespace note, or a malformed dict — and never raises, because it runs
  inside the verify stage's `asyncio.gather` loop where one bad dict would cost a whole batch.
- `_SUPERSEDED_NOTE_CAP = 40` and `_SUPERSEDED_CLAIM_CHARS = 120` as module constants.

Wiring (three touch points, deliberately surgical because plan 15.1-14 edits `_flush_groups`
in the next wave):

1. `superseded_notes: list[str] = []` declared beside `group_reconciliations`, so the nested
   `_flush_groups` closes over it.
2. Inside `_flush_groups`, immediately after the `verdicts_by_index` unpacking loop:
   `superseded_notes.extend(_collect_superseded_notes(grp["claims"], vbi))`.
3. At the `contested_notes` construction site, right after the existing
   `for r in group_reconciliations:` loop: de-duplicate (`dict.fromkeys`), `log.warning` with
   the exact number dropped if the cap truncates, then `contested_notes.extend(...)`.

`synthesize_report`'s call signature is unchanged — `contested_notes` was already its third
input, which is precisely why that is the wiring point. The per-claim (non-group) verify branch
is untouched, with an inline comment recording that `superseded_note` is produced *only* by
`group_skeptic._parse_group_verdict`, so the omission reads as deliberate.

Six tests added to `test_superseded_verdict.py` (pre-edit test count **8**, post-edit **14**):
the happy path, stray notes on support/refute/insufficient producing nothing, empty and
whitespace-only notes producing nothing (plus malformed-input robustness), the newline
injection guard, both claim-text shapes plus truncation, and a source-inspection wiring gate
asserting `TribunalPipeline.run`'s source contains `_collect_superseded_notes(`,
`contested_notes.extend(`, `superseded_notes` and `_SUPERSEDED_NOTE_CAP`.

### Task 2 — WR-03: the gate stage is declared (commit `277f69c`)

`ENGINE_STAGES["tribunal"]` gained `{"key": "gate", "label": "Verification gates"}` between
`distill` and `verify`, with a comment naming WR-03 and stating the pipeline has been writing
this key since Phase 15.1 (`pipeline.py:536-562`). Line numbers in the edited file:
`distill` **43**, `gate` **49**, `verify` **50**. Nothing else in `stages.py` changed — the
`sdk` alias is the same list object and `stages_for` is already generic; the `adk` schema did
not gain the entry.

New `tests/test_stage_schema.py` (143 lines, 5 tests, pure — no DB, no network, no `live`
marker), filename exactly as pre-registered by sibling plan 15.1-11:

1. `gate` appears exactly once, at `distill`'s index + 1 and `verify`'s index − 1, with the
   right label, and is absent from the `adk` schema.
2. Every entry across every engine is a dict with non-empty `key` and `label`; keys unique.
3. `stages_for("sdk") == stages_for("tribunal")` and the alias inherits `gate`.
4. **The generalised gate**: reads `pipeline.py` as text (path resolved through
   `nestor_pulse_sdk.pipeline.tribunal.pipeline.__file__`, never a repo-root relative path,
   because the build context ships only the `tribunal/` subtree), extracts every stage key with
   a DOTALL `set_stage\([^)]*?"([a-z_]+)"` regex, asserts at least 8 distinct keys as a vacuity
   guard, and requires every key to be declared. The failure message names the offending key and
   points at `runs/stages.py`. A positive control asserts `{gate, verify, synthesize}` are in the
   extracted set.
5. `stages_for("nope") == []`.

Review IN-08 (jsonb key ordering putting the short key `gate` first in `stage_detail`) was left
alone as instructed — a pre-existing flaw in a different mechanism.

### Task 3 — WR-11: the false appendix line (commit `c6cb003`)

In `_verification_appendix`, the stakes-based bullet became
`f"*   **Not independently fact-checked:** {n_unverified}",` — same bullet prefix, same position
in `lines`, same value, neighbours untouched. A comment above it records that under G-02 stakes
no longer selects what gets checked (the gates do), that `n_unverified` is now "claims with no

reopened and resolved this in the 2026-07-25 gap-closure scope without introducing any 15.1 gate

`test_client_appendix_unchanged` keeps its entire forbidden-vocabulary loop and all three
positive controls, and gained `assert "low-stakes" not in text`, `assert "Waved through" not in
text` (both messaged with WR-11 and the stakes reasoning) and the exact-string positive control
`assert "**Not independently fact-checked:** 20" in text`. Its docstring gained a paragraph so
the next reader does not mistake this for G-14 being abandoned.

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 3 - Blocking] `report_spec` is a SECOND undeclared `set_stage` key**

- **Found during:** Task 2, writing the generalised schema gate.
- **Issue:** The plan specifies the gate as "every extracted key is either declared in
  `ENGINE_STAGES["tribunal"]` or is the literal `"done"`". Extracting the keys shows **12**
  distinct values, and one of them —
  `set_stage(run_id, tenant_id, "report_spec", ...)` at `pipeline.py:1172` — is **not** declared
  and is **not** `"done"`. Written literally, the new test would have shipped RED into the Cloud
  Build gate that plan 15.1-15 runs.
- **Fix:** The test declares `_NON_SCHEMA_MARKERS = {"done", "report_spec"}` with a comment
  explaining each: `done` is the documented implicit terminal position, and `report_spec` is an
  interactive **pause** (the run parks as `needs_report_spec` awaiting a user-supplied report
  shape), not an ordered pipeline stage. Declaring it in `ENGINE_STAGES` was rejected because it
  would put a phantom row in the ordered checklist the UI renders for **every non-interactive
  run** — a product-visible change the plan explicitly forbids ("nothing else in the file
  changes"). The exception is therefore visible and reviewable in source rather than silently
  absorbed. **This is a genuine pre-existing finding of the same class as WR-03 and is flagged
  below for the phase verifier.**
- **Files modified:** `tribunal/nestor_pulse_sdk/tests/test_stage_schema.py`
- **Commit:** `277f69c`

**2. [Rule 3 - Blocking] Comment wording vs. the `Waved through` acceptance grep**

- **Found during:** Task 3.
- **Issue:** The plan asks the new comment to record the old sentence, but the acceptance
  criterion `grep -c "Waved through" pipeline.py` returns 0 **without** excluding comment lines.
  Quoting the old bullet verbatim in the comment would have failed the criterion.
- **Fix:** The comment says the line "used to describe these claims as 'low-stakes supporting
  detail'" and never contains the literal `Waved through`. (The `low-stakes supporting detail`
  criterion does exclude comment lines, so quoting that half is safe.)
- **Files modified:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/pipeline.py`
- **Commit:** `c6cb003`

**3. [Documentation] The i18n verification path in the plan does not exist**

- **Found during:** Task 3 acceptance check.
- **Issue:** The criterion greps `frontend/src/i18n/`, which is not a directory in this repo.
- **Fix:** Ran the equivalent check against the real paths — `frontend/src/lib/i18n/` and
  `frontend/src/locales/` (en/fr/nl × admin, auth, common, intake). **Zero hits** for
  `low-stakes supporting detail`, confirming the plan's premise: this text is emitted as literal
  English markdown by server-side Python and is not routed through the frontend i18n layer, so
  no locale keys and no `i18n-audit.mjs` involvement. No code change.

**4. [Implementation detail] Two additions the plan did not name**

- `_one_line()` helper and the `_SUPERSEDED_CLAIM_CHARS = 120` constant. Both are the mechanism
  of the newline-stripping and truncation rules the plan *does* specify; extracting them keeps
  `_collect_superseded_notes` readable and makes the 120 bound a named, greppable value.
- Six tests were added to `test_superseded_verdict.py` rather than exactly five — the claim-shape
  (`text` vs `claim_text`) and truncation checks were split out of the happy-path test.
