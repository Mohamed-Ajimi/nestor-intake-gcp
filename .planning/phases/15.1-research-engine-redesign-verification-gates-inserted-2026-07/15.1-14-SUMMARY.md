# Phase 15.1 Plan 14: The First Production Writer for verification_verdict Summary

`persist_tribunal_claims` now writes one `verification_verdict` row per verdict —
survivors carrying the `claim_id` of the row inserted for them moments earlier in the
same transaction, refuted claims carrying `claim_id` NULL — so the operator report's
verdict lists and `counts.verdicts_total` finally read production data instead of
returning zero rows on every real run.

## What Was Built

### Task 1 — `_insert_verdict` + verdict persistence (commit `4bc0176`)

`citations/extractor.py` gained a module-private `_insert_verdict(session, *, tenant_id,
run_id, claim_id, verdict)` placed immediately after `_insert_claim`, following that
helper's raw-SQL idiom exactly: one `session.execute(text("INSERT INTO
verification_verdict ..."))` with every value a bound parameter, and the two JSONB
columns bound through `json.dumps(...)` + `CAST(:evidence AS JSONB)` /
`CAST(:recon AS JSONB)`. `import json` was added; the module stays ORM-free
(`session.add` count remains 0).

Field handling:

| Column | Source | Empty / missing |
|--------|--------|-----------------|
| `verdict` | `verdict.get("verdict")` stripped | `"insufficient"` (never NULL into a NOT NULL column) |
| `confidence` | `str(...)` — parser emits float, column is TEXT | `None` |
| `evidence_refs` | `json.dumps` of a non-empty list | `None` (not `"null"`) |
| `reconciliation` | `json.dumps` of a non-empty dict | `None` (not `"{}"`) |
| `superseded_note` | stripped string | `None` (never `""`) |
| `claim_id` | stringified, or `None` for dropped claims | `None` |

`persist_tribunal_claims` was widened with a keyword-only `dropped_claims:
Optional[list[dict]] = None` (documented in the Args block), the dict-or-list
verdict normalisation was hoisted into a module-private `_verdicts_for(claim,
verdicts_by_claim)` so the source-gathering block and the verdict writes share ONE
normalisation, and the return dict gained `verdict_ids` + `verdict_count`, both also
logged next to `claim_count` / `source_count` so a zero-verdict run is visible.

### Task 2 — feeding the writer (commit `57e1fe0`)

Three edits, no others:

1. `_flush_groups` now harvests `recon = res.get("reconciliation") or {}` ABOVE the
   member loop (it used to be read after it) and attaches `v["reconciliation"] =
   dict(recon)` — a copy, not an alias — to each member verdict, but only when the
   recon is meaningful. The existing `group_reconciliations.append(...)` block and its
   narrower condition were left exactly as they were; it feeds `contested_notes` and is
   a different consumer.
2. The single Stage-7 call site passes `dropped_claims=dropped`, with a comment
   recording why: `dropped` holds both adjudication losers and conflict losers (the same
   list the `rejected_claims` ledger above it is built from), and without it a refuted
   claim's verdict is never persisted at all.
3. Both monkeypatched `fake_persist` doubles in `tests/test_tribunal_pipeline.py` were
   widened with an explicit `dropped_claims=None` parameter. The first (which records
   `persist_calls`) now also records what it received, and the module docstring's guard
   `(f)` PERSISTENCE-SHAPE GUARD was extended to describe the widened call shape.

### Task 3 — no-DB write-path tests (commit `c4b3479`)

`tests/test_verdict_write_path.py` (310 lines, 11 tests, pre-registered in
`cloudbuild.test-gates.yaml`). A hand-written `_FakeSession` records `(str(stmt),
params)` per `execute` and returns a `_FakeResult` whose `.first()` satisfies
`_upsert_source`'s RETURNING path; no `begin` / `commit`, because the caller owns the
transaction. Tests are plain `async def` (pyproject sets `asyncio_mode = "auto"`), and
the deprecated loop-fetch idiom review IN-04 warns about appears nowhere.

The eleven: one row per verdict; survivors linked to the claim row just inserted (and
the two survivors get different ids); dropped-claim verdicts written with a NULL
`claim_id` and `verdict == "refute"`; tenant context set before every verdict insert
with a matching bound `tenant_id`; JSONB encoded and NULL-when-empty; `superseded_note`
verbatim and `""` → NULL; confidence stringified; a claim with no verdicts writes none;
a malformed verdict defaults to `insufficient` without raising; the return value reports
the verdict count; and the writer is callable without the `dropped_claims` keyword.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Worktree cut from a stale base**

- **Found during:** startup, before Task 1
- **Issue:** `git merge-base HEAD 6ef6a2e` returned `a3a0c96` — the worktree was cut from
  a ref predating both wave-7 dependencies. Editing there would have produced a
  `pipeline.py` without plan 15.1-13's `_flush_groups` wiring and a merge that silently
  reverted it.
- **Fix:** `git reset --hard 6ef6a2e` per the `<worktree_branch_check>` protocol, then
  re-ran all three dependency assertions (all passed).
- **Files modified:** none (worktree state only)
- **Commit:** n/a (pre-edit)

**2. [Rule 2 - Robustness] `str(...)` guard on the recon meaningfulness test**

- **Found during:** Task 2 edit (1)
- **Issue:** the plan specified `(recon.get("note") or "").strip()`. `recon` is built by
  `group_skeptic._parse_group_verdict` from raw model JSON via `recon.get("note", "")` —
  a model emitting a number there would make `.strip()` raise a `TypeError` inside
  `_flush_groups`, which is NOT inside the `_one_group_pass` try/except and would abort
  a paid run at the verification stage.
- **Fix:** `str(recon.get("note") or "").strip()` (and the same for `canonical`).
  Semantics are unchanged for `str` and `None`; a numeric note now counts as meaningful
  rather than crashing.
- **Files modified:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/pipeline.py`
- **Commit:** `57e1fe0`

**3. [Rule 3 - Blocking] `get_event_loop` named in prose failed its own criterion**

- **Found during:** Task 3 verification
- **Issue:** the module docstring cited the deprecated idiom by name to explain why it is
  avoided, which tripped the `grep -c "get_event_loop" == 0` criterion (a whole-file
  substring check that does not distinguish prose from code).
- **Fix:** reworded to "loop-fetch-then-run_until_complete idiom"; the explanation and
  the IN-04 reference are preserved. Count is now 0.
- **Files modified:** `tribunal/nestor_pulse_sdk/tests/test_verdict_write_path.py`
- **Commit:** `c4b3479` (fixed before the commit)
