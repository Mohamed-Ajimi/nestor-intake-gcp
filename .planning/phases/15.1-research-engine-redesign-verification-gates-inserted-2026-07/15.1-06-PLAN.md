<objective>
Make the verification report tell the truth. Today it computes
`unverified = total_claims - claims_with_verdict`, which lumps "was never checkable" together
with "should have been checked but the fact-checker crashed" — the exact P1 defect. And a
`superseded` verdict currently falls into `insufficient` silently.

Purpose: G-08's three buckets, G-10's loud degradation marker, and G-06's consumer side. Bucket
3 — SHOULD HAVE BEEN CHECKED BUT WASN'T — is this phase's most important number: it counts
passages that shipped unexamined, because an unchecked claim leaves its passage standing
untouched (only refutation triggers scrubbing).

Output: an `accounting` sibling key, a `verification_degraded` marker stated in words, a
`verdicts.superseded` class, the pydantic fields that let them cross the API boundary, and the
negative test proving the client-facing appendix is untouched (G-09/G-14).

**Deliberate non-changes:** the top-level `report["superseded"]` list keeps its existing
reconciliation-derived meaning (name collision — see `<interfaces>`); `report["unverified"]`
keeps its exact shape so the frontend does not break; `_verification_appendix` in `pipeline.py`
is NOT modified — operator ruling G-14, question closed.
</objective>
