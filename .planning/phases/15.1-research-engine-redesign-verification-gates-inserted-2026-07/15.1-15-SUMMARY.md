## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Worktree cut from the stale base `a3a0c96`**

- **Found during:** startup, before any read
- **Issue:** `git rev-parse HEAD` returned `a3a0c96` — the sixth consecutive agent in this phase to
  hit the stale-base trap. As the deploy plan, building from it would have shipped images **not
  containing the fix**, while every downstream record claimed otherwise.
- **Fix:** `git reset --hard 43c009d` per `<worktree_branch_check>` (tree was clean, HEAD was a
  strict ancestor, so nothing was lost). All five dependency assertions then re-run and passed.
- **Commit:** n/a (pre-edit)

**2. [Rule 1 - Bug] A supplied gate build had silently dropped an entire test file**

- **Found during:** Task 1
- **Issue:** The orchestrator supplied build `ab71170c` as proof of the fast gate. Its `collecting:`
  echo listed only **12** files — `test_verdict_write_path.py` was **absent** — yet it reported
  SUCCESS with `143 passed`. It had been submitted from a tree predating plan 15.1-14, and
  `cloudbuild.test-gates.yaml`'s `ls … || true` guard drops missing files silently. **That green
  build ran none of plan 15.1-14's 11 write-path assertions** — the writer that this entire phase
  exists to add.
- **Fix:** re-ran all three gates from the verified `43c009d` worktree. The re-run echoed **13**
  files and all 11 write-path tests passed. Recorded the incident in the UAT gate section so the
  `collecting:` echo is treated as the real evidence, not the build status.
- **Commit:** `e6d2040`

**3. [Rule 3 - Blocking] Read-only schema probe: wrong alembic version-table name**

- **Found during:** Task 2
- **Issue:** The probe queried `tribunal.alembic_version` and failed with
  `UndefinedTableError`. The tribunal line sets `version_table="tribunal_alembic_version"` in
  `alembic/env.py:95-96` precisely so it never collides with the intake `nestor` line.
- **Fix:** queried `tribunal.tribunal_alembic_version` → `0012`. Recorded the gotcha in both the
  runbook and the deploy record, since a future reader hitting that error would reasonably but
  wrongly conclude the migration had failed.
- **Commit:** `d7bd00b`
