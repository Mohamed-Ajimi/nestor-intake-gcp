The verification report now publishes the `superseded_note` caveat it always claimed to carry, and
can no longer emit an `unverified` block that contradicts the `accounting` block sitting next to it.

### Task 1 — the shaper and the wire contract (`127a8b8`)

Three edits to `verification/report.py`:

1. **`_verdict_dto` gained a sixth key** — `"superseded_note": getattr(row, "superseded_note", None)`.
   `runs/schemas.py:237` had declared the field since 15.1-03 with a comment claiming it "survives
   the round trip", but the DTO never emitted it, so `extra="ignore"` had nothing to carry and the
   wire value was unconditionally `None` regardless of what was stored (CR-01 leg b). The `getattr`
   default is load-bearing: rows arrive in three shapes and only ORM rows post-0012 carry the
   column — a bare attribute access would `AttributeError` the `SimpleNamespace` fakes in
   `test_verification_buckets.py` and the fixture loader's rows.

2. **The `verdicts_total == 0` accounting fallback.** When a run has zero verdict rows AND real gate
   data (`accounting is not None`), `claims_with_verdict` is re-derived as
   `min(int(claim_count), int(accounting["checked"]))` and `unverified_count` recomputed from it, so
   the unverified figure comes from the *same funnel* the accounting block reads and the two agree
   by construction. Both guards are ANDed: a run **with** verdict rows keeps the row-derived
   arithmetic untouched (`test_unverified_is_honest_count` depends on it), and a pre-15.1 run with
   no gate data keeps its legacy figure rather than having one invented. The fallback is **visible**,
   not silent — `unverified_note` states in a full sentence that no `verification_verdict` row was
   persisted, that the figure is therefore funnel-derived, and that the per-claim verdict lists are
   empty because nothing wrote them, not because nothing was checked.

3. **WR-02** — the gate-error sentence now reads
   `"{n} claim(s) were sent for checking on a defaulted gate answer."` instead of
   `"{n} gate batch(es) also errored."`. `gates.py:557-558` increments the counter once per **claim**,
   so at the default `_GATE_BATCH = 40` one failed batch previously rendered as forty of them — a
   40x overstatement. The phrase is gone from every non-comment line of the module.

`runs/schemas.py` declares `unverified_from_accounting: bool = False` and
`unverified_note: str | None = None` on `VerificationReport`, immediately after `unverified` — declared
rather than left riding on `extra="allow"`, per the file's own "Declare, don't assume" rule.
`VerificationUnverified` is untouched: its three fields stay.

## Cross-Plan Notes

- **Plan 15.1-11** adds the `superseded_note` **column**; that migration was not visible in this
  worktree, which is expected. The DTO uses `getattr(..., None)`, so this plan's code is correct both
  before and after that column lands.
- **Plan 15.1-14** lands the production verdict **writer**. That is the primary CR-02 fix; the
  fallback here is the regression guard that holds if the writer breaks or a run predates it. Once
  the writer ships, `verdicts_total > 0` on healthy runs and the fallback stays dormant — which is
  the intended steady state, pinned by `test_fallback_does_not_engage_when_verdict_rows_exist`.
- **Plan 15.1-16** owns the rendering half: `report.verdicts.superseded` and the `superseded_note`
  this plan now emits reach the browser with no display site today. The two new top-level keys
  (`unverified_from_accounting`, `unverified_note`) are likewise unrendered — the existing unverified
  block renders a coherent payload without edit because the fallback changed values, not keys.
