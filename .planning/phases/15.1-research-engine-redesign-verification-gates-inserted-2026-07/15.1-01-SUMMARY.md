# Phase 15.1 Plan 01: Fixture Foundation & Verification Gates Summary

Built the shared foundation for phase 15.1: one CRLF/LF/embedded-tab-safe parser for the
selection-experiment TSVs, the 13-key recorded funnel constant encoding the G-08 accounting
numbers, and a no-Postgres Cloud Build gate the rest of the phase verifies against.

## What Was Built

### Task 1 — `load_selection_experiment()` (commit `d771582`)

A single public reader in `loader.py`, placed directly after `build_verification_summary()`,
returning `(claims, classified, strict)`:

- `claims` — 1,162 dicts shaped exactly like `claim_distiller` output
  (`{"id", "text", "facet", "evidence"}`), where `id` is the **1-based line number** of
  `claims-distilled-full.tsv` (that file has no id column; the other two TSVs join on it).
- `classified` — `{id -> reason}` over all 1,162 rows, from the `reason` column (literally
  `KEEP` on KEEP rows), one of `KEEP` / `NOT_FALSIFIABLE` / `NOT_LOAD_BEARING` / `BOTH`.
- `strict` — `{id -> decision}` over exactly the 456 KEEP ids, `VERIFY` / `SKIP_STABLE`.

The three parsing traps from RESEARCH § The Fixture Contract are handled here and only here:

1. **Embedded tabs** — `line.split("\t", 2)` (maxsplit 2), matching the production parser
   `_parse_distiller_response` (`synthesis/steps.py:690`). 74 of the 1,162 rows carry literal
   tabs inside `evidence`; a bare `split("\t")` or `csv.reader` mis-shapes them.
2. **Mixed line endings** — per-line `rstrip("\r")` after splitting on `"\n"`, rather than
   trusting one file-level convention (the two big TSVs are CRLF, `keep-strict.tsv` is
   LF-only, and a Windows checkout may renormalise either way — confirmed locally: this
   checkout shows CR on all three).
3. **No header on the distilled file** — line 1 is data; the two answer keys drop line 1 via
   the `_read_headed_tsv()` helper.

Ids are assigned by `enumerate(..., start=1)` **before** blank-line skipping, so a stray blank
line could never renumber claims. Path resolution goes through `_report_dir()`; no repo-root
`docs/` path was introduced (verified: that string appears only at the pre-existing module
docstring line 7 and inside `_report_dir()`'s fallback at 73/78). Re-exported from the fixture
barrel in both the import block and `__all__`.

## Deviations from Plan

### 1. [Rule 3 - Blocking] Worktree was 62 commits stale — fast-forwarded to master

**Found during:** setup, before Task 1.

**Issue:** The worktree branch `worktree-agent-ad459a916d62cfeae` was checked out at `a3a0c96`
(2026-07-24), 62 commits behind `master` (`a76956f`). Two of the plan's four target files did
not exist in the worktree at all — `tests/fixtures/run_4cbb5311/loader.py` and its
`__init__.py` were introduced by commit `c9f192a`, which was among the missing 62. The entire
`.planning/phases/15.1-.../` directory was also absent, as were `verification/report.py` and
`test_verification_report_endpoint.py`. The plan was unexecutable against that base.

**Fix:** `git merge --ff-only master`. The branch had **zero** unique commits
(`git rev-list --count master..HEAD` = 0), so the fast-forward was strictly lossless — no
rebase, no reset, no `git clean`, nothing discarded. Branch namespace and worktree isolation
were re-verified afterwards.

**Note for the orchestrator:** if the sibling wave-1 worktrees were created from the same stale
ref, they hit the same wall. Worth checking before the merge-back.

### 2. [Rule 3 - Blocking] `ls` file-list guard added to the gates config

**Found during:** Task 3.

**Issue:** The plan's snippet is `FILES=$(ls fileA fileB ... 2>/dev/null)` under `set -e`. With
7 of the 10 files not yet created, `ls` exits 2 (verified locally). Under `set -e` a variable
assignment takes the exit status of its command substitution, so the build would abort before
running a single test — the config could never go green in wave 1.

**Fix:** added `|| true` to the substitution plus an explicit empty-list early exit, and
documented why in the file header. Also moved the file-listing inside the python container so
the literal string `-m "not live"` survives verbatim (needed for the acceptance grep) instead
of being mangled by nested quoting.

### 3. [Minor] Critical-config header wording

The plan asked to "update the file's header comment to name the addition" while also requiring
`grep -c "test_verification_report_endpoint.py"` to return **1**. Naming the file literally in
the header makes that count 2. Resolved by naming it descriptively
("the verification-report-endpoint test") in the header, keeping the literal filename to the
single pytest-invocation occurrence. Both the instruction's intent and the grep hold.

### 4. [Minor] `build_verification_summary()` return annotation widened

The plan said to change only the docstring. The return annotation was also widened from
`dict[str, int]` to `dict[str, int | bool]` to stay consistent with the constant it copies.
The **body is untouched** (`return dict(RECORDED_FUNNEL_COUNTS)`), which is what the acceptance
criterion and the lockstep guarantee actually depend on. Note `bool` is a subclass of `int` in
Python, so this is a documentation improvement rather than a behavioural change.

### 5. [Minor] `_read_headed_tsv` docstring made raw

The helper's docstring contains `split("\t")`; as a normal string that renders as an actual tab
character. Changed to a raw docstring so the parsing contract reads correctly.

  in the build log.
