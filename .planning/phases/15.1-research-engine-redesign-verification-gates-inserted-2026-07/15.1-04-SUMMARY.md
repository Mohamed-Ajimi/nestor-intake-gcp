# Phase 15.1 Plan 04: LLM Clustering in grouping.py Summary

Replaced exact-string `entity│attribute` bucketing with a block-then-cluster LLM pass, so
claims stating the same fact in different words or languages land in ONE skeptic session —
with `group_claims`'s signature and five-key return shape frozen, and a claim that fails to
cluster still verified as its own singleton.

## What Was Built

**Task 1 — cross-batch identity strategy, documented in source** (commit `4893cc2`)

The module docstring gained a `Cross-batch cluster identity` section. It states why the
problem exists (the `ENTITY|ATTRIBUTE` key space is global, so tagging is embarrassingly
parallel; model-invented cluster ids are not, and 1,162 claims do not fit one 4096-token
call), the three-stage strategy, why the entity tag is the blocking key (it already exists,
is already tested, and `_norm` already merges case/space/punctuation variants), the
`{block}#{chunk}#{cluster_id}` namespacing rule, and — explicitly — the ONE accepted
limitation with its measurement route:

> two claims that state the same fact will NOT merge if their entity tags normalise
> differently, or if they land in different chunks of an oversized block … How often it bites
> is MEASURED by the hand-run August calibration (G-05), never asserted by a CI gate.

Four tunables landed on the existing `NESTOR_TRIBUNAL_*` + `os.environ.get(..., default)`
idiom (`CLUSTER_BATCH=40`, `CLUSTER_MAX_BLOCK=60`, `CLUSTER_CONCURRENCY=4`, `CLUSTER=true`),
so tuning needs no Cloud Run env change. The exact-key bucketing was extracted into
`_exact_keys` + `_assemble_groups` and put behind the `_CLUSTER_ENABLED` switch. Behaviour
was byte-identical in this commit — verified green on Cloud Build `87ec1331` before the
clustering pass landed.

**Task 2 — the clustering pass** (commit `c1dbc65`)

- `_CLUSTER_PROMPT` — plain text, one `INDEX | CLUSTER_ID` line per claim in input order.
  Its instruction makes the load-bearing point explicit: claims stating the same fact with
  CONFLICTING values *must* share a group. Both security properties of `_TAG_PROMPT` survive:
  claim text truncated to 240 chars and output addressed by index only.
- `_parse_cluster_lines(text, n) -> list[int]` — structure copied from `_parse_tag_lines`:
  pre-filled list, regex-extracted index, `0 <= idx < n`, out-of-range and garbled lines
  ignored, never raises, model text never parsed as JSON. Sentinel `-1` = unclustered.
- `_cluster_block` — `_tag_batch`'s shape verbatim (`_make_config()`, conditional `config`
  kwarg, `resp.text` → `resp.candidates[0].content.parts[0].text` fallback, all egress through
  `audited.gemini_generate`). Its `except Exception` returns `[-1] * n`, i.e. every claim
  becomes its own singleton.
- `_cluster_keys` — blocks by `_norm(entity)` alone; empty entity goes straight to
  `__singleton__:{i}`; blocks over `_CLUSTER_MAX_BLOCK` are chunked into `_CLUSTER_BATCH`
  pieces; one call per chunk of 2+ under `asyncio.Semaphore(_CLUSTER_CONCURRENCY)`; chunks of
  1 make no call at all.
- The closing INFO log now reports claims in, groups out, multi-claim, singletons, blocks
  formed and cluster calls made.

**Task 3 — nine tests** (commit `ed8ecd6`)

`_PromptAwareGrouperAudited` answers tag calls and cluster calls separately (the clusterer
makes two different kinds of call), records both, and can compute a cluster answer from the
block actually sent — so a test never has to know how production chunked it. The existing
`_FakeGrouperAudited` is untouched. Tests: same-fact merge across languages, conflicting
values co-located, claim conservation by object identity, unclustered→singleton, cluster-call
failure loses nothing, oversized-block chunking with no key collision, MAX stakes, the
disabled A/B path, and the parser bounds check.

## Key Implementation Notes

- **Never-drop is a chain, not a check.** Four independent paths all end in "own singleton and
  still verified": empty entity tag, failed cluster call, unparseable cluster id, and an index
  the model simply omitted. Three tests pin them.
- **Group construction is single-sourced.** `_assemble_groups` builds the frozen dict for both
  paths, so the cluster path and the A/B fallback cannot drift. It also implements the
  "first NON-EMPTY entity/attribute seen" rule properly (the old inline loop took whatever the
  group's first member had, and only fell back at creation time).
- **The key string changed; the contract did not.** `pipeline.py` and `group_skeptic.py` read
  the five dict keys and treat the key string as opaque — confirmed by direct read before
  changing it. The docstring now says so explicitly.

## Notes for the Next Plan

- **G-04 ordering is now possible** (plan 15.1-07 implements it): cluster FIRST via the
  unchanged `group_claims` call, then gate per claim, then let a cluster survive if ANY member
  survives. Nothing in this plan presumes gate ordering.
- **Cost shape changed.** Clustering adds one call per multi-claim entity block on top of the
  30 tagging calls. Blocks of one — which the recorded run was full of — cost nothing.
- **The A/B switch is real.** `NESTOR_TRIBUNAL_CLUSTER=false` restores pre-15.1 grouping
  exactly, with zero cluster calls, and is pinned by a test. Useful if the August calibration
  finds over-merging.
