<objective>
Give the `superseded` verdict class a place to appear on the operator's screen, and let its caveat
render when there is no reconciliation note to carry it.

Purpose: closing the backend gaps alone would activate a silent drop. Traced in source:

  * `report.py`'s classing branch is `if/elif` — a `superseded` verdict goes EXCLUSIVELY into
    `verdicts.superseded` and never into `support` / `refute` / `insufficient`.
  * `VerificationReport.tsx` renders `verdicts.refute` (282), `verdicts.support` (289),
    `verdicts.insufficient` (295), the TOP-LEVEL `report.superseded` (303) and `report.reconciled`
    (311). It never renders `report.verdicts.superseded`.
  * The top-level `superseded` list requires a canonical value —
    `report.py:302-305` pushes only when `(relation == "scoped" or note) and canonical`.
  * `VerdictItemRow` builds its amber caveat from `reconciliation.note` only
    (`VerificationReport.tsx:87`), never from `item.superseded_note`.
  * The frontend types do not even know the class exists: `VerificationReport["verdicts"]`
    (`research.ts:97-101`) declares only support/refute/insufficient, and
    `VerificationVerdictItem` (`research.ts:80-93`) has no `superseded_note` field.

Net effect on a real run once plan 15.1-14's writer lands: a claim the skeptic marked `superseded`
with a real caveat, whose group reconciliation carries no `canonical` — the ordinary shape for a
single-member group, where `relation` defaults to `"single"` and `canonical` to `""` — is rendered
NOWHERE on the operator's verification report. Not the row, not the caveat. Before Phase 15.1 that
same claim came back as `support` and at least appeared. The phase's own new verdict class turned a
visible row into an invisible one, latent only because no verdict rows existed yet.

That is the exact failure this phase is named for, and it contradicts G-06 in its own words:
making `superseded` a verdict "makes it visible to every count, screen and bucket."

**Wave numbering:** the gap-closure set CONTINUES phase numbering — plans 01-10 hold waves 1-6,
closure plans hold waves 7-9. This plan is wave 7, depends on nothing, and shares no file with any
other plan. Its data sources (plan 15.1-12's DTO key, plan 15.1-14's writer) land in the same phase
before plan 15.1-15 deploys; the component compiles and renders correctly regardless of their order.

**This plan makes a frontend rebuild + deploy REQUIRED for Phase 15.1**, which the original pass
did not need. Plan 15.1-15 owns that step.

Output: a verification report where no verdict class can be silently dropped.
</objective>
