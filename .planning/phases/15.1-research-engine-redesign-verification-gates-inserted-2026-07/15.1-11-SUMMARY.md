# Phase 15.1 Plan 11: `superseded_note` Storage + Gate Pre-registration Summary

Gave the G-07 `superseded_note` caveat a real home — an additive nullable `TEXT` column on
`verification_verdict` at tribunal alembic `0012`, mirrored on the ORM model — and pre-registered
the three gap-closure test files in the fast no-Postgres Cloud Build gate.

## What Was Built

### Task 1 — migration `0012` + ORM mirror (commit `3d18c31`)

`tribunal/nestor_pulse_sdk/alembic/versions/0012_verdict_superseded_note.py`:

- `revision = "0012"`, `down_revision = "0011"` — pinned to the TRIBUNAL line head
  (`0011_cost_verification.py`), which `ls versions/ | tail -1` confirmed before writing. The intake
  `nestor` line's own 0011/0012 (Phases 16/17) are a different alembic line and are untouched; the
  header docstring says so explicitly.
- `upgrade()` runs **exactly one** DDL statement:
  `op.add_column("verification_verdict", sa.Column("superseded_note", sa.Text(), nullable=True))`.
  No `schema=` kwarg — the migration runs with `search_path` already on the tribunal schema, matching
  every additive column in 0011.
- `downgrade()` runs exactly one: `op.drop_column(...)`.
- **No** `CREATE POLICY` / `DROP POLICY` / `ENABLE|FORCE ROW LEVEL SECURITY` / `CREATE INDEX` /
  `GRANT`. The rationale is recorded as a `#` comment block in `upgrade()`: the table already carries
  FORCE RLS and `verification_verdict_tenant_isolation` from 0011, and a PostgreSQL row-level policy
  is a table-level object evaluated against row values, so a new column is covered by construction.
  Re-issuing any of it would be regression risk with zero security benefit (T-15.1-52).
- The header docstring records what the column carries (the caveat a `superseded` verdict supplies —
  what changed and from when), why it is nullable, which alembic line it belongs to, and that it
  closes the storage leg of review finding CR-01.

`tribunal/nestor_pulse_sdk/db/models/verification_verdict.py`:

- `superseded_note: Mapped[str | None] = mapped_column(Text, nullable=True)` added immediately after
  `reconciliation`, so ORM field order mirrors physical column order.
- Docstring `Columns:` list gained the matching entry in the neighbouring alignment style.
- The mirror contract line now reads "Mirrors migrations 0011 + 0012's `verification_verdict` table
  EXACTLY", so it stays literally true, and notes that 0012 re-issues no RLS DDL.
- Stale vocabulary corrected: the `verdict` line now reads
  `(support | refute | insufficient | superseded)`. The column has no CHECK constraint, so this
  docstring is the only place the verdict vocabulary is documented — leaving it three-valued while
  15.1-14 persists a fourth value would have made the file's own documentation false.
