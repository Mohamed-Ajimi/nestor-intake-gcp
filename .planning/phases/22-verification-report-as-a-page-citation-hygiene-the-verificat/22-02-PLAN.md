<objective>
Give the report a pure, testable answer to "which `[n]` markers belong to this verdict row", and
teach the frontend type system about the two fields the deduped payload adds.

Purpose: 22-01/22-05's read-time dedupe DROPS citation entries. `VerificationReport.tsx:210-220`
builds `citationsByClaim` keyed strictly on `first_claim_id`, so a claim whose only source was
absorbed would render **no marker at all** — a silent regression on a verdict row that carries one
today. The fix is an additive `also_claim_ids` alias, indexed on both sides. Extracting the builder
into its own module (the `verificationGate.ts` precedent, verbatim) is what makes that assertable
without a React harness, which this repo does not have.

Output: two frontend type fields, one pure module, one test file.
</objective>

  <action>
Create `frontend/src/lib/research/citationIndex.ts` exporting one function matching the
`<interfaces>` signature:

`buildCitationIndex(citations: Citation[] | undefined): Map<string, Citation[]>`

It walks the list once and, for each citation, collects the candidate claim ids as
`[c.first_claim_id, ...(c.also_claim_ids ?? [])]`. For each candidate it skips anything that is not
a non-empty string, skips an id already recorded for THIS citation (so a duplicate id inside one
entry cannot push the same object twice), and otherwise appends the citation to that key's array.

The module docstring must state WHY the alias half exists, in these terms: the engine's read-time
dedupe (D-22-4) emits ONE entry per normalized source URL and drops the rest. A dropped entry took
its `first_claim_id` with it, so a verdict row whose claim introduced only that source would render
no `[n]` at all — a silent regression on a row that has a marker today. `also_claim_ids` carries
those claim ids onto the survivor and this index is where they are honoured.

It must ALSO state what this module is not: **it does no dedupe and no URL handling.** The list
arriving here is already deduped by the engine (D-22-4 requires ONE shared normalization, and a
TypeScript function cannot be shared with the Python `INSERT`). A `normalizeUrl` appearing in this
file would be the defect, not the fix.

Pure: no React, no fetch, no side effects, never throws on malformed input.

Then create `frontend/src/lib/research/citationIndex.test.ts` with one NAMED test per property in
