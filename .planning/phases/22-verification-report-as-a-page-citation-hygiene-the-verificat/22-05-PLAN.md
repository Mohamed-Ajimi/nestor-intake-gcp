<objective>
Wire the shared identity function into the ONE read path the operator's verification page reads
from, at the one seam where it cannot break anything upstream.

Purpose: D-22-4, read-time layer. `_assign_numbers` already reuses a number when it sees a source
again — that half is correct. What creates duplicates is that two `source` rows exist for one page,
because the INSERT key is the RAW url. Until the write-side fix lands (its own phase), collapsing on
the way out is what makes one URL render as one number.

Output: a deduped `citations` list on `GET /api/runs/{id}/verification`, with every number exactly as
`number_citations` assigned it.
</objective>
