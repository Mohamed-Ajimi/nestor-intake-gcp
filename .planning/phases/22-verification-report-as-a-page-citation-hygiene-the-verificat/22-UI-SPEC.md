# Phase 22 — UI Design Contract

> Visual and interaction contract for the verification report page, the citation hover card, and
> the collapsed citation list. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**The problem this contract solves, in one line:** the report is *long*, not *bad*. Every fix here
is navigation, hierarchy and progressive disclosure — **nothing is dropped, summarised or reordered**
(D-22-2).

## Typography

Four sizes, two weights. Values are the existing house scale, not a new one.

| Role | Size | Weight | Line Height | Family | Notes |
|------|------|--------|-------------|--------|-------|
| Meta / label | 11px | 400 | 1.4 | mono | `uppercase tracking-wider`, `text-ink/50`–`/70` |
| Body | 13px | 400 | 1.6 (`leading-relaxed`) | sans | verdict prose, evidence, list rows |
| Section heading | 13px | 600 | 1.4 | mono | `uppercase tracking-[0.1em]`, `text-ink` |
| Stat figure | 24px | 400 | 1.2 | mono | `tabular-nums` — the dashboard numbers |
| Page title (h1) | 20px | 600 | 1.2 (`leading-tight`) | serif | matches `admin.pulse.runs.$runId.tsx:238` |

Two weights only: **400 regular** and **600 semibold**. No 500, no 700.

**Exception:** the breadcrumb row reuses the run page's `text-[10.5px] uppercase tracking-[0.1em]`
verbatim. This is deliberate — the two pages must have an identical breadcrumb, and matching it is
worth one off-scale value.

**Section headings are an upgrade, not an invention.** Today's sections are `11px/400` mono, which
is the same weight as the metadata inside them — one reason the report reads as an undifferentiated
wall. Raising headings to `13px/600` is the single typographic change that makes the document
scannable, and it costs no new token.

### Quality tier is NOT colour-coded

Tier is a **data-quality signal**, so it is encoded as **text + shape**, never colour:

| Tier | Glyph (using the existing `.mark` marks) | Text label |
|------|------------------------------------------|------------|
| 1 | ■ ■ ■ (three `mark-ink`) | Official source |
| 2 | ■ ■ □ (two `mark-ink`, one `mark-outline`) | Serious press |
| 3 | ■ □ □ (one `mark-ink`, two `mark-outline`) | Blog / other |

All three squares are `#000000` ink or an ink outline. The glyph group carries
`aria-label={t("verification.hoverTierLabel", { tier })}` and the text label is **always rendered**
beside it — the glyph is redundant reinforcement, never the sole carrier.

## Contract 1 — The dashboard layout

### 1.1 Route

**Primary: `/admin/pulse/runs/$runId/verification`**

- New file: `frontend/src/routes/admin.pulse.runs.$runId.verification.tsx`
- **Required companion change:** rename `admin.pulse.runs.$runId.tsx` →
  `admin.pulse.runs.$runId.index.tsx`.

⚠ **Why the rename is mandatory, and the trap it avoids.** If `admin.pulse.runs.$runId.tsx` stays
as-is while a `$runId.verification.tsx` sibling appears, TanStack promotes the run page from a leaf
to a **layout route**, and it will render nothing but its own component unless it grows an
`<Outlet/>`. This repo already carries a live scar from exactly that: `routes/intake.$id.tsx:42-48`
has a `useMatches` + conditional-`Outlet` workaround with a comment explaining that child pages
"could never render". Do not reproduce that workaround. With both siblings named `.index.tsx` and
`.verification.tsx` and **no** `$runId.tsx` present, TanStack builds a pathless parent and both are
leaves — no Outlet, no conditional, no scar.

⚠ **Verification step the planner must schedule:** after the rename, the two existing call sites
(`components/intake/ResearchRunProgress.tsx:218` and `components/research/RunActions.tsx:192`, both
`to: "/admin/pulse/runs/$runId"`) must still typecheck against the regenerated `routeTree.gen.ts`.
Index routes are sometimes registered with a trailing slash. `npx tsc --noEmit` in `frontend/` is
the gate; if it goes red, fix the `to` values, do not fall back silently.

**Fallback (only if the rename causes route-type churn the planner judges unbounded):**
`admin.pulse.verification.$runId.tsx` → `/admin/pulse/verification/:runId`. Zero changes to existing
files, less pretty URL. Record which option was taken in the plan.

**Route contract, either way:**
- Superadmin-only **by placement** under `admin.pulse` (inherits the admin guard) — the identical
  posture documented in `admin.pulse.runs.$runId.tsx:32-38`. The page adds no verb, no parameter,
  no new caller.
- The page learns its intake **only** from `locateResearchRun(runId)`. It accepts **no** intake id
  from a query parameter (T-15.3-71 / TENANT-02). Reuse the run page's exact cold-open block.
- Availability is gated by `canHaveVerificationReport(status)` from
  `@/lib/research/verificationGate` — **imported, never reimplemented** (D-22-1). Exactly one call
  site per page.

### 1.2 Page shell — and why it is NOT the run page

The run page is a **fixed-height column with one internal scroll region** and a live footer ticker
(`h-[calc(100vh-7.75rem)]`). The report page must **not** copy that.

> **The report page scrolls naturally in the document flow, like every other admin page.**

This is the structural expression of "the report page must not become a second run page": no
internal scroll container, no live region, no footer ticker, no SSE connection, no feed. A document
that scrolls with the page is also what makes browser find-in-page, deep anchors and print work — all
three of which a nested scroll region breaks, and all three of which matter for a document the
operator called "very good information".

### 1.4 Ordering justification — and why nothing moved

**E1–E9 are in the EXACT order `VerificationReport.tsx` renders them today.** D-22-2 forbids
reordering sections on the assumption they are noise, and this contract takes that literally: not one
section changes position, and not one is dropped, truncated, collapsed-by-default (except the
citation list, which the operator explicitly ruled) or summarised.

That is not a cop-out, because the existing order is *already* decision-ordered — funnel first, then
refuted, i.e. "how much was checked" then "what failed" — and because **the length complaint is
solved by navigation and by lifting the answer above the fold, not by resequencing.** Concretely:

- **What an operator needs first when judging whether a run's findings can be trusted** is a single
  number pair: *how many claims were checked, and how many of them broke.* Today that answer is
  scattered across a raw funnel line and a sentence 400 lines down. The **stat strip (B)** puts it in
  the first viewport. That is the whole trust question, answered before any scrolling.
- **Second** is proportion — the funnel as *shape*, not as a comma-separated list of numbers. Bars
  (C) make "3,000 in, 40 out" legible in one glance where `stage: count` text does not.
- **Third** is reachability. The **nav rail (D)** carries each section's label and row count, so the
  operator jumps to "Refuted (7)" in one click. Once every section is one click away, its ordinal
  position stops being an information-architecture decision at all — which is precisely why
  reordering was unnecessary.

### 1.5 A. Header

Reuse the run page header's structure verbatim so the two pages read as one product:

- Breadcrumb (`10.5px` mono, `tracking-[0.1em]`, `text-ink/50`):
  `Pulse · Intakes · {clientName} · Run · Verification`
  — `Run` links to the run page; `Verification` is the current (unlinked) crumb.
- `h1`: `t("verification.title")` — serif 20px/600. **Existing key, no new locale entry.**
- Meta row (`11px` mono, `text-ink/50`): `t("research.runPage.metaRun", { id: runId.slice(0,8) })`
  and the client name. **Existing key.**
- A `Back to run` link with lucide `ArrowLeft` — new key `verification.backToRun`.
- The block carries `border-l-4` in `#FF2D87` — the report's inherited identity mark, moved from the
  old inline container to the page header. This is the accent's one large-surface use.

### 1.6 B. Stat strip

Six tiles, `grid grid-cols-2 md:grid-cols-3 lg:grid-cols-6 gap-4`, each
`bg-paperLight px-6 py-5` (no border between tiles — the paper/paperLight contrast is the division).

| # | Label (11px mono uppercase, `text-ink/50`) | Figure (24px mono tabular-nums) | Source | Zero/absent |
|---|---|---|---|---|
| 1 | Claims | `unverified.total_claims` | report | `—` in `#6B7280` |
| 2 | With verdict | `unverified.claims_with_verdict` | report | `—` |
| 3 | Refuted | `verdicts.refute?.length ?? 0` | report | `0` in `#6B7280`, **not** red |
| 4 | Unverified | `unverified.count` | report | `0` in `#6B7280` |
| 5 | Sources cited | deduped citation count | D-22-4 read-time dedupe | `0` |
| 6 | Cost | `true_cost.cost_usd_total` | report | `—` |

**Tile 3 is the only tile that ever takes a colour**: `#DC2626` when `> 0`, `#6B7280` when `0`.
Colour is not the sole carrier — the label says "Refuted".

**Tile 6 is C1 facts-only, unchanged.** When `true_cost.cost_pending` is true, the figure shows
`cost_usd_total` and an amber `bg-amber-50` chip reading `t("verification.costPending")` beneath it.
**Never a numeric placeholder for the pending class.** Reuse `verification.costTotalWithPending` /
`verification.costPending` — existing keys.

**⚠ Facts-only bar — three things the strip must NOT do:**
1. No percentages, no ratios, no "N% verified". `total_claims` can be `0`; a derived rate would be a
   division-by-zero away from rendering `NaN%` as if it were a fact.
2. No trend, no comparison to a previous run. There is no such data.
3. **No "N duplicates removed" figure and no corroboration claim anywhere on this page.**
   Read-time dedupe changes **display only** — cost and corroboration still count the duplicate rows
   until the write-side fix lands (D-22-4). Tile 5 is labelled `Sources cited`, deliberately not
   `Sources fetched`, because the deduped number is the count of distinct sources *shown*.

### 1.7 C. Gate funnel

`report.funnel` is `Record<string, number>` with **engine-authored keys**. Render each stage as a row:

```
STAGE_KEY   ████████████████████████████████████   3,412
STAGE_KEY   ██████████                              1,162
STAGE_KEY   ██                                         40
```

- Bar: a `div` with `width: (count / max) * 100%`, `bg-ink`, `h-2`, on a `bg-paper2` track. No chart
  library — recharts is installed but a proportional div matches the house language and costs
  nothing.
- Stage key rendered raw (as today). It is an engine identifier and is deliberately not translated —
  inventing labels for keys this build has never seen is exactly the fabrication the project bars.
- Count: `11px` mono `tabular-nums`, right-aligned.
- The whole row carries `aria-label={t("verification.funnelStage", { stage, count })}` — **existing
  key**, and the bar itself is `aria-hidden`.
- `max` is `Math.max(...counts, 1)` — a funnel of all zeros must not divide by zero.
- Section heading: `t("verification.funnelTitle")` — existing key.

### 1.8 D. Section nav rail

- `lg:` and up: a left column, `sticky top-4`, `w-56`, sitting beside the document.
- Below `lg`: a horizontally scrollable chip row directly under the funnel.
- Contents: one entry per section E1–E9 that **has rows**, each `11px` mono uppercase:
  `{section label}` + a right-aligned count in `text-ink/50`.
- Labels reuse the **existing** section-title keys (`refutedTitle`, `supportTitle`,
  `insufficientTitle`, `supersededVerdictsTitle`, `supersededTitle`, `reconciledTitle`,

- Rail heading: new key `verification.navLabel` → "On this page".
- Anchors: `href="#refuted"` etc. Each section gets `id` + `scroll-mt-6` so the sticky header does

- **Active state:** an `IntersectionObserver` marks the section currently in view; the active entry

- **Empty sections are omitted from the rail and still omitted from the document** — that is today's

## Contract 2 — The citation hover card

### 2.1 Implementation

`renderCitationMarker` in `frontend/src/components/intake/CitationPanel.tsx` becomes a real component
(`CitationMarker`) so it can own state. The exported `renderCitationMarker(citation, onOpen)`
signature is **kept** as a thin wrapper returning `<CitationMarker …/>`, so no call site changes.

```
<HoverCard open={open} onOpenChange={setOpen} openDelay={120} closeDelay={80}>
  <HoverCardTrigger asChild>
    <button … the existing [n] button, unchanged classes … />
  </HoverCardTrigger>
  <HoverCardContent side="top" align="start" className="…">
    … four lines, below …
  </HoverCardContent>
</HoverCard>
```

- Primitive: `@/components/ui/hover-card` — **already installed** (`@radix-ui/react-hover-card@1.1.17`).
  Do not add a tooltip library. Do not use `@/components/ui/tooltip`: a tooltip is for a short label
  on a control; this is a rich preview of a record, which is what HoverCard exists for.
- **No network call.** Every field comes off the in-memory `Citation`. `getSource` is called by the
  panel only.

### 2.2 Exact content — a closed list

| Line | Content | Type | Fallback |
|------|---------|------|----------|
| 1 | `[{n}]` + `citation.title` | mono 11px + sans 13px/600 ink | `t("citation.untitled")` |
| 2 | `t("citation.retrieved", { date })` | mono 11px `text-ink/60` | `t("citation.dateUnknown")` |
| 3 | tier glyph (■■■/■■□/■□□) + tier text label | mono 11px, `bg-paper2 px-2 py-0.5` | tier is non-null by type |
| 4 | `t("verification.hoverClickHint")` | mono 10px `text-ink/45`, `border-t border-ink/10 pt-2 mt-2` | — |

**Lines 1–3 are the operator's ruling, verbatim: title + date + quality tier, and nothing else.**
Explicitly **excluded** from the hover: `single_source`, `temporal_note`, `snapshot_text`, the URL,
the provider. Those live in the panel and belong to the click.

⚠ **Line 4 is the one addition beyond the ruled three fields, and it is flagged for the operator to
strike.** It is an *affordance hint*, not source metadata: with a preview now appearing on hover, an
operator has no way to learn that clicking does something different unless told. If the operator
reads the ruling strictly, delete line 4 — it is one JSX element and one locale key, and nothing else
in this contract depends on it.

### 2.3 The label copy is a correctness requirement, not a style choice

> **Line 2 reads `Retrieved: {{date}}`. It must never read "Published".**

`citations/numbering.py:29-32` states it outright: `publication_date` carries `source.fetched_at` —
when the crawler pulled the page, not when the page was published. Presenting a proxy as a fact is
exactly what the operator's "NO ESTIMATES — facts and correct calculations only" bar forbids.

⚠ **This also fixes a live factual misstatement.** `frontend/src/locales/*/intake.json` currently
defines `citation.published` = `"Published: {{date}}"`, and `CitationPanel.tsx:123` renders it today.
That string is wrong about the same field, on screen, right now.

**Required (in scope as "citation hygiene"):** rename the key to `citation.retrieved` in all three
locales, update `CitationPanel.tsx:123` to `t("citation.retrieved", …)`, and have the hover card use
the **same** key. One key, one wording, two surfaces — so the two can never drift into disagreeing
about what the date means. Removing `citation.published` from all three locales keeps i18n CHECK A
(3-way parity) green; leaving it in one locale only would break it.

### 2.4 Visual treatment

`HoverCardContent` className override (the ui/ file itself is untouched):

```
w-72 border border-ink/30 border-l-4 bg-paperLight p-4 shadow-none
```
plus `style={{ borderLeftColor: "#FF2D87" }}` — the same identity mark the panel and the page header
carry. `shadow-none` overrides the primitive's default `shadow-md`: this design system has 0px radii
and hard borders; a drop shadow is the wrong dialect. Radius is already `0px` globally
(`--radius-*: 0px`), so nothing to override there.

Placement: `side="top"`, `align="start"`, `sideOffset={6}`, `collisionPadding={16}`. Top-aligned
keeps the card off the line of text being read; Radix flips it on collision automatically.

### 2.5 Trigger, dismiss, keyboard and focus

| Interaction | Behaviour |
|-------------|-----------|
| Pointer enters marker | card opens after `openDelay` 120ms |
| Pointer leaves marker and card | card closes after `closeDelay` 80ms |
| Pointer moves marker → card | card **stays open** (Radix handles the safe area); the card is not interactive, but a user reading a long title must be able to travel to it |
| `Tab` to marker | card opens on focus (Radix `HoverCard` opens on trigger focus) |
| `Esc` while open | card closes; focus stays on the marker |
| `Enter` / `Space` / click | **card closes, then `onOpen(citation)` fires** — see below |
| Screen reader | the marker keeps its existing `aria-label={"citation " + n}`; card content is exposed via Radix's `aria-describedby` wiring on the trigger |

**How hover and click stop fighting.** They fight in exactly one place: click while the card is open
leaves a floating preview on top of the panel that just opened. The fix is that `open` is
**controlled** — the marker owns `const [open, setOpen] = useState(false)` — and the click handler is:

```
onClick={() => { setOpen(false); onOpen(citation); }}
```

Deterministic, one line, no reliance on Radix's pointer-down heuristics. Uncontrolled `HoverCard`
must not be used here.

**Touch.** HoverCard has no touch trigger by design — on a touch device the marker is a plain button
and a tap opens the panel. That is the correct degradation: touch users get the full record instead
of a preview, and this is a superadmin desktop surface.

### 2.6 Where the click-through panel opens

⚠ **A defect this phase would otherwise ship.** Today `CitationPanel` renders **inside** the citation
list block (`VerificationReport.tsx:380-386`). Once that list is collapsed by default (D-22-3),
clicking a `[n]` inside a verdict row would set `openCitation` and render the panel **inside a
collapsed container** — invisible, hundreds of pixels down the page. The click would appear to do
nothing.

**Required fix: hoist `CitationPanel` out of the citation list into a page-level `Sheet`.**

- `@/components/ui/sheet`, `side="right"`, `className="w-full sm:max-w-lg overflow-y-auto bg-paper"`.
- Rendered once at page level, `open={openCitation !== null}`, driven by the same `openCitation`
  state that exists today.
- `<CitationPanel intakeId runId citation onClose={() => setOpenCitation(null)} />` goes inside
  **unchanged** — it keeps its own header, its own `[n]` title and its own close button. Do not add a
  second visible header.
- ⚠ Radix Dialog requires an accessible title. Add `<SheetHeader><SheetTitle className="sr-only">`
  with `t("citation.regionLabel")` (**existing key**). Without it the console warns and the sheet is
  unlabelled for screen readers.
- Behaviour that comes free and is required: Esc closes, focus is trapped then restored to the
  marker, and **the report does not scroll** — the operator returns to exactly the sentence they were
  reading.
- The panel's security posture is untouched: stored `snapshot_text` only, never a live-URL re-fetch
  (T-15-14/15/16b), superadmin-only by placement.

**Fallback** if the planner rejects a modal on this page: render the panel in a fixed
bottom-right docked block. The non-negotiable part is only this — *the panel must not render inside
the collapsible.*

## Contract 3 — The collapsed citation list

### 3.1 Default state and affordance

Section E8, using `@/components/ui/collapsible` with `defaultOpen={false}`.

The trigger row is **always visible** and is the section's heading:

```
┌────────────────────────────────────────────────────────────┐
│ ▸  NUMBERED CITATIONS            17 sources                │   ← collapsed (default)
└────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────┐
│ ▾  NUMBERED CITATIONS            17 sources                │   ← expanded
│                                                            │
│  [1]  ■■■  Retrieved 2026-08-05   Belgian Official Journal │
│  [2]  ■■□  Retrieved 2026-08-05   De Tijd — Q2 results     │
│  …                                                         │
└────────────────────────────────────────────────────────────┘
```

- Chevron: lucide `ChevronRight` → `ChevronDown` on open, `h-3.5 w-3.5`, `text-ink/50`.
  Rotation only, no colour change (the chevron is **not** accent).
- Heading text: `t("verification.citationsTitle")` — **existing key**.
- The whole row is the `CollapsibleTrigger` (`w-full`, `flex items-center justify-between`,
  `hover:bg-paper2`, `py-3`). A whole-row target beats a chevron-sized one.
- `aria-expanded` is supplied by the primitive. The trigger's accessible name is the heading text
  plus the count, so a screen-reader user hears the count without expanding — the same guarantee
  sighted users get.

### 3.2 The count is mandatory while collapsed

> **The operator must be able to tell how many citations exist without expanding.**

Right-aligned in the trigger row: `t("verification.citationsCount", { count })` → EN
`"{{count}} sources"`, `11px` mono `tabular-nums` `text-ink/60`.

**`count` is the DEDUPED count** (D-22-4: one number per normalized URL), and it is the same number
as stat tile 5. Two places showing the same figure must read from one computed value — not two
independent `.length` calls that can drift.

The word is **"sources"**, not "citations", and that is deliberate: after dedupe each `[n]` maps
1:1 to a distinct source, so "sources" is the accurate noun. It also avoids implying anything about
cost or corroboration, which still count the duplicate rows (D-22-4's warning).

### 3.3 Expanded list rows

One row per deduped source, `13px` sans, `space-y-2`:

`[n] marker` · `tier glyph + label` · `retrieved date` · `title`

- The `[n]` marker in the list is the **same `CitationMarker` component** as in the verdict rows: it
  hovers and it clicks, identically.
- Title falls back to `t("citation.untitled")` — existing key.
- **No internal scroll container and no max-height.** A list capped at 320px inside a section the
  operator has just chosen to expand would re-create the exact "hidden behind a small window"
  complaint that started this phase.
- Collapse is reachable from the trigger row, which stays in place at the top of the section.

### 3.4 What happens to a `[n]` hover when its list entry is collapsed

**Nothing changes. The hover works identically.**

This is a design guarantee, not an accident, and it rests on three properties:

1. The hover card is fed from the in-memory `Citation` object, **not** from the DOM of the list
   entry. Collapsing the list removes no data.
2. The click opens the **page-level Sheet** (§2.6), which is outside the collapsible. Collapse state
   cannot swallow it.
3. Therefore a `[n]` click **never auto-expands the list**, and must not be made to. Auto-expanding
   would scroll the operator away from the verdict they were reading in order to show them a one-line
   list entry that carries strictly less than the panel they just opened.

The collapsed list is a *directory* of sources. The markers are the *live* interface to them. The
directory being closed says nothing about the markers.

## Accessibility Requirements

- **No `aria-live` region on this page.** The run page owns the product's one live region
  (`RunStatusCard`, T-15.3-82). This page is a static document; a second live region would
  double-announce.
- Tier: text + shape, never colour alone (§Color).
- Refuted count: colour + the word "Refuted", never colour alone.
- Focus rings: the global `button:focus-visible` (2px `rgb(20 20 20 / 0.3)`, 2px offset) applies
  everywhere. Do not remove it on the `[n]` marker, the collapsible trigger or the nav anchors.
- The `[n]` marker keeps `aria-label={"citation " + n}` (existing).
- Sheet: labelled via `sr-only` `SheetTitle`; focus trapped and restored by Radix.
- Nav rail: `<nav aria-label>` + `aria-current` on the active anchor.
- Every section heading is a real `<h2>` with a matching `id`, so heading navigation works — this is
  a large part of what makes a long document usable for a screen-reader user, and it is free.

## Visual Direction — RESOLVED

**✅ CLOSED by operator ruling, 2026-08-11. This is NOT an open decision — do not re-open it.**

stat strip + proportional funnel above the fold, then the full report as a structured, navigable
document with a sticky section rail, borrowing the run page's big-mono-figure header language. Zero
content changes, zero reordering. **§1.3–1.9 above already specify exactly this** — the spec was

The reason it lost is the reason it must not be reintroduced later as an "improvement": it fragments
a document whose value the operator explicitly endorsed as *reading material* ("very good
information"), and multi-column cards are hostile to the long markdown evidence blocks `MdText`
renders. **"Dashboard" in this phase means an instrumented document.** A future agent proposing a
card grid here is reversing a ruling, not polishing a spec.
