## ⚠ THE FILTER IS UNCONDITIONAL — NOT ROLE-CONDITIONAL

This is the point most likely to be got wrong, because plan 23.2-06 next door IS role-conditional.

`run_context_pack` runs on the `ai_router`, which carries a router-level
`Depends(superadmin_gate)` (23.1 D-23.1-02), so **the generator is ALWAYS a superadmin**. A
role-conditional filter here would therefore never fire and the fix would be inert — green
tests, unchanged behaviour.

The relevant role is not the generator's. It is the **artifact reader's**, and that is the
client. Filter unconditionally, and put that sentence in the code comment so the next reader
does not "harmonise" this with plan 23.2-06's `identity.role` check.

## WHERE, EXACTLY

In `read_fn`, between `answer_rows = IntakeAnswerRepository(...).list_for_intake(intake_id)` and
the `answers = [...]` comprehension. Drop rows whose `field_key` is in `admin_only_field_keys()`.

`dto["answers"]` is not read anywhere else — measured at `922fd91`:
`grep -n 'dto\["answers"\]\|dto.get("answers")' backend/app/ai/skills/context_pack.py` returns
**0 lines**; `call_fn` uses `dto["user_message"]` and `write_fn` uses `dto["space_id"]`. So
filtering at the source is complete, and there is no second consumer to keep in sync. Confirm
that grep yourself before relying on it.

Do NOT filter inside `_format_intake_markdown`. That function is a pure renderer with a single
caller today; putting policy in a formatter hides it from anyone reading `read_fn`, which is
where the data-flow decision belongs.

## WHAT THIS PLAN MUST NOT DO

- **Do NOT add any output-side filtering** of `raw`, of `text_content`, or of the artifact. Not
  a regex, not a "redact" pass, not a prompt instruction telling the model to omit it. D-23.2-01
  rejects this by name. A prompt instruction is not a control: the content would still be in the
  prompt, and the model's compliance is not a boundary.
- **Do NOT touch `_CONTEXT_PACK_USER_PREFIX` or `CONTEXT_PACK_SKILL_PROMPT`.** Changing the
  system prompt changes the output shape of a paid skill and is not what this decision asks for.
- **Do NOT touch `get_context_pack`** (`intake_routes.py:629`). Filtering the generated markdown
  there is the output-side scrubbing this decision forbids, and the route stays as-is.
- **Do NOT touch the embeddings path** (`ai/skills/embeddings.py:89-100`, hop 4). It indexes the
  pack, and `/search` is gated (23.1), so it is not a client-reachable leak. Once the pack input
  is clean, the index is clean as a consequence.
- **Do NOT touch `read_brief_inputs` or `assemble_brief`** (hop 5). Research reads are gated.
- **Do NOT change the missing-intake sentinel, the CAS transition, the artifact insert, or the
  run finalize.** Only the answer list changes.
- **Do NOT hand-write a field key.**

```python
def _format_intake_markdown(client_name, answers) -> str:        # :105
    lines = [f"# Intake — {client_name or ''}", "", f"**Klantnaam**: {client_name or ''}",
             "", "---", ""]
    for answer in answers:
        value = answer.get("value")
        if (value is None or value == "") and answer.get("value_json") is not None:
            value = json.dumps(answer["value_json"], ensure_ascii=False)
        if value in (None, ""):
            continue
        lines.append(f"**{answer['field_key']}**: {value}")
    return "\n".join(lines)

def read_fn(session):                                            # :143
    intake = IntakeRepository(session, identity).get(intake_id)
    if intake is None:
        return {"missing": True}
    answer_rows = IntakeAnswerRepository(session, identity).list_for_intake(intake_id)
    answers = [{"field_key": r.field_key, "value": r.value, "value_json": r.value_json}
               for r in answer_rows]
    client_name = intake.client_name
    space_id = str(intake.space_id)
    user_message = _CONTEXT_PACK_USER_PREFIX + _format_intake_markdown(client_name, answers)
    return {"client_name": ..., "space_id": ..., "answers": answers, "user_message": ...}
```
