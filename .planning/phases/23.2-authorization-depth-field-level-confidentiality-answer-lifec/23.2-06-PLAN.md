* `blind_spots` — a nested object `{upstream, downstream, perspectief}` whose three members map
  onto the admin-only keys `blind_spots_upstream` / `blind_spots_downstream` /
  `blind_spots_perspectief` (`AIReviewPanel.tsx:127-129` does exactly that mapping).

Derive the drop rule; do not hand-write `{"bias_radar", "blind_spots"}`:

> drop top-level key `K` if `K in admin_only_field_keys()` **or** any admin key `A` satisfies
> `A.startswith(K + "_")`.

verify that claim in the test by asserting the surviving key set. It auto-closes for a fifth
admin-only field, and it errs toward over-dropping for a `role=user`, which is the safe
direction. Put the rule in ONE private helper in `intake_routes.py` with a docstring naming the
`blind_spots` case as its reason for existing.

`output_parsed` is `dict | None`; `None` stays `None`. A non-dict value (legacy row) is returned
unchanged rather than raising — a projection must never 500 on odd data.
