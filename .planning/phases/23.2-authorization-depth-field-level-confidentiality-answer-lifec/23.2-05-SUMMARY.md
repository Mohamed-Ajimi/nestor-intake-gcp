# Phase 23.2 Plan 05: Compare-and-Swap the Tribunal Status Flips Summary

Both Tribunal re-queue verbs now let the **database** arbitrate the flip — measured before the
change, two concurrent callers both re-queued the same parked run.

## What changed

`tribunal/nestor_pulse_sdk/runs/api.py` (+78 / -13)

- **`resume_run`** — the read and both guards are KEPT (they classify the refusal, and the
  existing source gate at `test_checkpoint_resume.py:429` depends on them). The three attribute
  assignments are replaced by one conditional UPDATE:
  `WHERE Run.id == run_id AND Run.status == "parked"`, setting `status="queued"`,
  `worker_id=None`, `error_message=None`, with `.execution_options(synchronize_session="fetch")`.
  `rowcount == 0` raises `HTTPException(409, "run is not parked")` — the read-check's message,
  byte for byte.
- **`submit_report_spec`** — same shape with `needs_report_spec`, and the **order is inverted**:
  the CAS runs FIRST, the `Output(format="report_spec")` insert second. The loser therefore
  writes nothing at all, rather than depending on `get_db_session`'s transaction unwinding.
- **Freshness** — I chose BOTH belt and braces, and state that explicitly because the plan asked
  which: `synchronize_session="fetch"` **and** an explicit
  `select(Run).where(...).execution_options(populate_existing=True)` re-select whose result is
  what gets `model_validate`d. Reason: `"fetch"` may *expire* rather than *set* attributes, and
  an expired attribute accessed later in an async context is implicit IO. The re-select refreshes
  the instance from a real row with no lazy load.
- **The docstring** — the false sentence is gone. The replacement says the allow-list is enforced
  twice (read for a readable 404/409, UPDATE `WHERE` for the concurrent case), and says plainly
  that the previous wording claimed this of a plain read-then-write and was wrong. An equivalent
  paragraph was added to `submit_report_spec`, which made no false claim but now has the same
  mechanism.

`tribunal/nestor_pulse_sdk/tests/test_run_state_cas.py` (new, 677 lines, 12 tests)
`tribunal/cloudbuild.test-cas.yaml` (new, expected count **12**)

   literal: a reader grepping for the phrase would still find it, and verification criterion 4
   requires zero lines. Rewritten to *name* the claim without reproducing the string. Recording
   this because "correct a false comment" and "delete the false string" are not the same
   instruction, and only the second is testable.

3. **`REAP_SQL` untouched, and no existing cloudbuild config edited** — confirmed by
   `git show --stat`: three files, all in scope, zero deletions.

Nothing else in the plan was false. The pre-fix numbers, the 31/0 checkpoint baseline, the

## Findings recorded, not fixed

is not a polluter.** `test_run_state_cas.py` + `test_checkpoint_resume.py` = 43 passed, 0 failed

tribunal CI gap.

four test files and none of the 37 ownership/idempotency tests. This plan added a standing gate

like `cloudbuild.test-rls.yaml`. Its expected count of 12 is keyed to this file's test count and
must be updated in both the grep and the success echo if a test is added.
