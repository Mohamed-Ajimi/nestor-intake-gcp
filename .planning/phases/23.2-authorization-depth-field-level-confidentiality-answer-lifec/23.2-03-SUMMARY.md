## Deviations from Plan

### [Rule 1 — Bug] A SECOND pre-existing test pinned the F-04 defect, and the plan said it must stay green

The plan's `<read_first>` states that
`test_re_issuing_deactivate_retries_the_member_whose_idp_call_failed` "must stay green", and
`<done>` requires "Exactly ONE pre-existing test was edited". **Both are false.** Measured after
the handler inversion:

```
FAILED tests/test_space_deactivation_cascade.py::test_re_issuing_deactivate_retries_the_member_whose_idp_call_failed
E  AssertionError: assert 'active' == 'space_deactivated'
```

The cause is a bare, message-less assertion in the middle of that test:

```python
assert _status_of(engine, mid_flaky) == SPACE_DEACTIVATED
```

`mid_flaky` is precisely the member whose IdP disable was rejected. That line encodes the *same*
F-04 over-claim the plan set out to remove — a second instance of CONTEXT § 11 trap 5 that the
plan's own analysis missed. I inverted it deliberately and **strengthened** rather than weakened
it (old: one bare assertion; new: two assertions with reasons, covering both members). The
test's actual purpose — that the second press re-attempts both members — is untouched and its
closing `retried == ["uid-flaky", "uid-ok"]` assertion is unchanged and still green.

So: **two** pre-existing tests were edited, both for the same reason, both enumerated below.

### [Rule 3 — Blocking] Two small test helpers added despite "add no new harness"

The plan says "Reuse them; add no new harness", but its own `<behavior>` spec requires asserting
`members_cascaded == 2` and `idp_failed_uids == ["uid-two"]` from the audit row, and neither test
file had any way to read audit **metadata** (only `_count_audit`, which counts rows). Likewise
`test_admin_routes.py`'s `_create_space` takes no `status` argument, so a deactivated space could
not be seeded at all. Added, minimally and in the house style:

* `tests/test_space_deactivation_cascade.py::_audit_metadata` — the sibling of `_count_audit`,
  reads `AuditLog.event_metadata` for an actor/event_type.
* `tests/test_admin_routes.py::_deactivate_space_row` — a direct `UPDATE ... SET status =
  'deactivated'`, so a guard test seeds its one precondition without dragging the whole cascade
  and its Admin-SDK doubles into a test about a later call.

No parallel harness, no new fixtures, no changes to any existing helper.

## Ruling 1 applied — PER-CALL count semantics

`members_cascaded` / `members_restored` now count the rows **this call** flipped. A code comment
in both handlers states the semantics explicitly so an operator reading `1` does not misread it
as a partial failure:

> PER-CALL, never a running total: an audit row records what ITS OWN event did, and a reader
> reconstructs total state by summing the sequence. A clean retry after a partial failure
> therefore reports 1 while three members are down — that is CORRECT, not a second partial
> failure.

Pinned in tests on both verbs: deactivate audits `2` then `1` across the two presses (test 3
above), reactivate audits `2` then `1` (tests 1 and 2 above).
