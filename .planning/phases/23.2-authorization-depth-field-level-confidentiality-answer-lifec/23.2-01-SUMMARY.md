# Phase 23.2 Plan 01: Canonical Admin-Only Derivation Summary

Four derived views of the canonical intake schema on `app/intake_canonical.py` — the
confidentiality set, the membership set, per-field lookup, and a client-visible schema copy —
all computed once at import from the section-level `admin_only` flag the backend had never
read, with a test that re-derives every expectation independently from the raw JSON.

## What was built

**`backend/app/intake_canonical.py`** (+131 lines, nothing removed). A private `_derive()`
walks `CANONICAL_TEMPLATE_SCHEMA` exactly once at import and returns four module constants;
the four public functions are thin accessors over them.

```python
def admin_only_field_keys() -> frozenset[str]: ...   # 4 keys today
def canonical_field_keys()  -> frozenset[str]: ...   # 29 keys
def canonical_field(field_key: str) -> dict | None: ...
def client_visible_schema() -> dict: ...             # 13 of 14 sections
```

The walk mirrors the defensive register of `structure_answers._flatten_template_keys`
(`isinstance` guard on section and field, skip a field with no `key`). It reads
`section.get("admin_only")` for **truthiness**, not `is True` — a hand edit could land `1` or
`"true"` in the JSON and the safe reading of any truthy value is "hide it". It reads the flag
off sections identified by `id`; **sections carry no `key`** (`section["key"]` is `None` for
all 14), which is the failure shape T-23.2-01-01 names.

`_CLIENT_VISIBLE_SCHEMA` is `copy.deepcopy(CANONICAL_TEMPLATE_SCHEMA)` **then** filtered, so
the surviving sections in the client copy are copies too.

The module docstring gained an `Admin-only confidentiality (D-23.2-02)` section explaining why
the set is derived rather than listed. Both key-set docstrings state what the function is NOT:
membership is not a confidentiality filter, the client-visible set is the difference of the
two. `CANONICAL_TEMPLATE_ID`, `CANONICAL_TEMPLATE_NAME` and `CANONICAL_TEMPLATE_SCHEMA` are
untouched. No consumer changed; no route, no skill, no other test.

**`backend/tests/test_intake_canonical_derivation.py`** (245 lines, 10 tests). Every
expectation is re-derived inside the test by reading `app/data/pulse_intake_v1.json` off disk
via `Path(__file__).parents[1]` — the module under test is never used to compute its own
expectation. Pure schema logic: no marker, no engine patch, no seeded space, no fixture.

## Residual risk for the consumer plans

`client_visible_schema()` hands back **one shared import-time constant**, exactly as the plan
mandates (deep copy once, never per request). The deep copy protects
`CANONICAL_TEMPLATE_SCHEMA`; it does **not** protect the client-visible object itself. A
consumer that mutates the returned dict corrupts it for every later request in that process.
The docstring says "serialise it, do not mutate it", and the isolation test restores its own
mutation in a `finally:` for the same reason. Plans 06/07 should serialise, not edit.
