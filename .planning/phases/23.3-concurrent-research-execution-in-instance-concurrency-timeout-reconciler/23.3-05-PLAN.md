<objective>
Build the stateless orphaned-run reconciler: a sweep that finalizes any non-terminal
`nestor.research_runs` row whose poll driver died, serialised so nestor-api's four
instances cannot fight over it. This plan builds the callable unit only; plan 06 triggers it.

Purpose (23.3-CONTEXT.md § 8, the scoping that keeps this a small phase rather than a
rewrite): **the worker is already durable** — SKIP LOCKED claim, 30 s heartbeat, stale
reclaim, `MAX_RECLAIMS=2`, worded reap. That is a real at-least-once guarantee and it is not
touched here. What is fragile is `run_poll_driver`: a `while True` inside a FastAPI
`BackgroundTask` with no wall-clock cap. If the instance recycles, the engine keeps
executing and spending, `research_runs` is never mirrored or finalized, and nothing sweeps
it. So the fix is a stateless RECONCILER, not a dispatch rewrite — a sweep that mirrors each
non-terminal row's current engine state makes the per-run driver an OPTIMISATION (fast
updates) rather than the only path to a terminal state.

Two constraints on the design, both measured:
* **Cloud Scheduler API is NOT ENABLED** on this project (verified 2026-09-07:
  `gcloud scheduler jobs list --location=europe-west1` -> `PERMISSION_DENIED: Cloud
  Scheduler API has not been used in project ... before or it is disabled`). Enabling it is
  an operator/IAM action. So the sweep is written as a plain callable unit that either an
  in-process timer (plan 06) or a future Scheduler HTTP trigger can drive.
* **nestor-api runs `maxScale=4`** (confirmed live 2026-09-07, `nestor-api-00049-wgk`).
  Concurrent sweeps must be serialised.

Output: one module, one test file. No route, no timer, no deploy.
</objective>

  <action>
Create `backend/app/research/reconcile.py` with a module docstring that states what this is
and, just as importantly, what it is NOT: it is a DIFFERENT DRIVER over `run_task.py`'s
existing machinery, not a second implementation of it, and it does not touch the Tribunal
worker, which is already durable.

Constants, each with its derivation written down:

* `ORPHAN_CUTOFF_MINUTES = 15`. **This number is not taste.** A live poll driver is silent
  — it `continue`s without calling `mirror_tick` — for up to
  `_MAX_METRICS_AUTH_OUTAGE_SECONDS = 600` (10 minutes) while it tolerates a 401/403 from a
  Cloud Run revision rollout. That budget was itself sized from the live 2026-07-28 incident.
  A cutoff at or below 10 minutes would sweep a driver that is healthy and deliberately
  waiting. 15 minutes clears it by 50%. Say in the comment that anyone raising
  `_MAX_METRICS_AUTH_RETRIES` must raise this with it, and vice versa.
* `LEASE_MINUTES = 5`. Long enough for one `get_metrics` (`_TIMEOUT_S = 30.0`) plus a
  completion build, short enough that a sweep killed mid-flight frees the row within one
  sweep interval. A LEASE, not a lock: it expires by itself, so a dead sweeper cannot
  strand a run — the exact property that makes the reconciler self-healing.
* `SWEEP_BATCH = 10`. Bounded on purpose: an unbounded sweep on a bad day is a thundering
  herd of seam calls from an instance that is also serving requests.

`def claim_orphans(limit: int = SWEEP_BATCH) -> list[dict]`

ONE short transaction on `get_superadmin_engine()` — cross-space reach, no GUC, exactly the
shape `sweep_orphaned_skill_runs` already uses and for the same reason: the sweep does not
know which space a lost run belongs to until it reads the row. Statement shape:

```
UPDATE nestor.research_runs
   SET reconcile_lease_until = NOW() + make_interval(mins => :lease)
 WHERE id IN (
   SELECT id FROM nestor.research_runs
    WHERE status IN ('queued', 'running', 'needs_report_spec')
      AND (reconcile_lease_until IS NULL OR reconcile_lease_until < NOW())
      AND COALESCE(driver_heartbeat_at, created_at) < NOW() - make_interval(mins => :cutoff)
    ORDER BY created_at
    FOR UPDATE SKIP LOCKED
    LIMIT :limit
 )
RETURNING id, space_id, intake_id, status, tribunal_run_id,
          acting_user_id, acting_email, bundle_key
```

Four details are load-bearing and each needs a comment:

1. **`FOR UPDATE SKIP LOCKED`** is what makes two concurrent sweeps disjoint at the instant
   of claiming; the LEASE is what keeps them disjoint afterwards, once the transaction has
   committed and the connection has gone back to the pool. Both are needed — neither alone
   is enough. This is the same pattern the Tribunal worker already uses; do not invent a
   third.
2. **`make_interval(mins => :x)`**, never `INTERVAL ':x minutes'`. The literal-bind form
   fails at runtime with bound parameters — the B2 fix already recorded in
   `tribunal/nestor_pulse_sdk/runs/worker.py`'s module docstring. Do not rediscover it.
3. **`COALESCE(driver_heartbeat_at, created_at)`** so rows written before migration 0017
   behave exactly as they would have: they fall back to age, which for a row already older
   than the cutoff is the right answer.
4. **A POSITIVE `status IN (...)`, never `NOT IN (terminal)`.** An unknown future engine
   status must fail OPEN — simply not a candidate — rather than be swept as an orphan. Same
   reasoning, same three literals, as `uq_research_runs_one_inflight_per_intake`.

Return PLAIN dicts, never live ORM rows: the connection is released the moment this function
returns and a detached row would explode later (the release contract).

`def reconcile_one(row: dict) -> str` — returns a short outcome word for logging
(`"mirrored"`, `"finalized"`, `"skipped_no_actor"`, `"skipped_no_engine_run"`,
`"skipped_lost_cas"`, `"error"`). It NEVER raises: this runs on a timer inside the API
process and an escaping exception would kill the sweep for every other row.

**Identity.** Build
`Identity(uid=row["acting_user_id"], email=row["acting_email"], role="superadmin", space_id=None)`.
That is a REPLAY of the identity this run's own driver already ran under — `_patch_run`'s
docstring records that the write path runs under a superadmin identity because the trigger
actor has no own space — not a widening of anyone's authority, and not an actor taken from
request input: both values were written server-side from a verified token at trigger time
(plan 04). Say exactly that in a comment, because "constructs a superadmin Identity from a
database row" is a line that should stop a reviewer, and the answer needs to be there when
it does.

If `acting_user_id` or `acting_email` is falsy — a pre-0017 row, or a superadmin token that
carried no email — return `"skipped_no_actor"` after ONE `log.warning` naming the run id.
⛔ Do NOT substitute a placeholder address or a system actor id. The seam's 400 on empty
acting headers exists because D-05 attribution is a hard legal constraint on a frozen audit
chain; a fabricated actor is worse than an unswept row, and the warning is what gets a human
to look.

If `tribunal_run_id` is NULL the run never reached the engine — return
`"skipped_no_engine_run"` with a warning. Finalizing it is a judgement about a run that may
never have started, and this plan does not make it. (Recorded as **DEF-23.3-03**.)

**The seam call holds NO database connection** (T-16-06). Order, exactly:
1. build `ctx` — `space_id`, `acting_user_id`, `acting_email` from the row, `service_url`
   and `app_base_url` from `get_settings()`, `project_title` and `intake_id` as
   `load_trigger_context` builds them (read the intake in its own short session first, or
   carry the fields the mail templates need; do not hold that session open);
2. `tribunal_client.get_metrics(run_id=row["tribunal_run_id"], **seam_kwargs)` —
   NO connection held. Wrap it: a `httpx.HTTPStatusError` or any transport error is logged
   and returns `"error"`. **Do NOT retry here.** The driver's 5xx and 401/403 budgets exist
   because a driver has one chance; the sweep runs again in minutes, which is a better
   retry than a loop that pins an API instance;
3. `mirror_tick(identity, row["id"], row["tribunal_run_id"], metrics)` — always, terminal or
   not. This alone is most of the value: an orphaned run stops being frozen at whatever the
   UI last saw;
4. if `metrics["status"]` is NOT in `RESEARCH_TERMINAL`: clear the lease
   (`reconcile_lease_until = NULL`) and return `"mirrored"`. The sweep does NOT schedule a
   replacement driver — a `BackgroundTask` needs a request and there is none. The run simply
   gets swept again next tick, which is the whole point of § 8's framing: the per-run driver
   becomes an optimisation, not the only path to a terminal state;
5. if it IS terminal, finalize.

**The finalize, and the two things that must not happen twice.**
* Build the completion ONLY when `is_research_success(status)` AND `row["bundle_key"]` is
  NULL. A non-NULL `bundle_key` means the live driver already built and uploaded the bundle;
  rebuilding it would re-run `verify_chain`, re-fetch the report and re-upload to GCS for
  nothing. This cheap read-time guard is what keeps the narrow claim-to-write window from
  costing anything.
* Do the terminal write through `ResearchRunRepository.patch_if` with
  `expected={"status": row["status"]}` — the status observed at claim time. If the live
  driver (or another sweep whose lease had expired) finalized in between, the precondition
  fails, `rowcount == 0`, and this function returns `"skipped_lost_cas"` having sent NO
  mail. A read-then-write here would produce two completion mails and two terminal writes on
  a ~$45 run; `patch_if` puts the precondition in the same UPDATE, which is the D-23.1-05
  guarantee. Route the actual field values through the existing
  `finalize_completed` / `finalize_failed` / `finalize_parked` bodies rather than
  re-deriving them — the reconciler must not grow a second opinion about what a terminal
  row looks like.
* **Mail after the commit, never inside the write.** Build the html with the existing
  `render_research_complete` / `render_research_failed` / `render_research_parked`, then
  send AFTER the write transaction has committed, in its own `try`, logging and swallowing
  transport failures. This is F-06 / D-23.2-14 stated in `run_poll_driver`'s own docstring:
  a Resend error inside the write rolled back a completion and rewrote a paid, completed run
  as `failed`. Send only if the CAS was WON.

`def sweep_once(limit: int = SWEEP_BATCH) -> dict` — `claim_orphans(limit)` then
`reconcile_one` per row, tallying outcomes; returns
`{"claimed": n, "mirrored": n, "finalized": n, "skipped": n, "errors": n}` and logs one
WARNING line naming the counts when anything was claimed (WARNING, not INFO: uvicorn's
default logging config drops INFO from app loggers — the note already at the top of
`run_task.py`, learned at the cost of a full UAT day). It takes no FastAPI object and no
request: it is a plain callable so an in-process timer (plan 06) or a future Cloud Scheduler
HTTP trigger can both drive it.
