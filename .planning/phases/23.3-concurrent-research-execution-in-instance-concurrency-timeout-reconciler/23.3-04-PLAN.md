<objective>
Give `nestor.research_runs` the four facts a stateless reconciler needs, and start writing
them. This plan ships NO reconciler — it only makes one possible, and it is a strict no-op
for every existing code path.

Purpose: `run_poll_driver` (`backend/app/research/run_task.py:643`) is a `while True`
(`:725`) inside a FastAPI `BackgroundTask` with no wall-clock cap. If that nestor-api
instance recycles — a deploy, a scale event, Cloud Run's own lifecycle — the driver dies
silently: the engine keeps executing and spending, `research_runs` is never mirrored or
finalized, and nothing sweeps it. That is DEF-23.2-03 (23.3-CONTEXT.md § 8). The fix is a
stateless reconciler (plans 05 and 06), and a stateless reconciler needs four things this
table does not have:

1. **WHO.** The Tribunal seam REQUIRES non-empty `X-Acting-User-Id` and
   `X-Acting-User-Email` and answers 400 without them, because the D-05 acting-user
   attribution is a hard legal constraint on a frozen audit chain
   (`tribunal/nestor_pulse_sdk/auth/internal_caller.py:184-223`). A reconciler that invents
   a system actor would corrupt exactly that attribution. It must replay the original
   human's, so the row must carry it. The completion mail (D-10) needs the same address.
2. **LIVENESS.** There is no `updated_at` on this table, and this project has already paid
   for the lesson that a creation timestamp is not a liveness signal (the D-E defect: a
   live 35-minute long-poll was indistinguishable from a process that died 35 minutes ago,
   and the designed response to a dead process is to re-run at full cost). A driver
   heartbeat is the honest signal, and `mirror_tick` already runs every ~3 s.
3. **A LEASE.** nestor-api runs `maxScale=4`. Two instances mirroring the same run
   concurrently is the defect this phase must not introduce (§ 8).

Output: migration 0017, four mapped columns, two write sites, one test file.
</objective>
