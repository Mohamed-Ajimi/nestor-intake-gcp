async def lifespan(app: FastAPI):
    init_firebase()
    try:
        swept = sweep_orphaned_skill_runs()

  <action>
Add two module constants near the logger:

* `RECONCILE_INTERVAL_SECONDS = float(os.environ.get("NESTOR_RECONCILE_INTERVAL_S", "300"))`
  — 5 minutes. Derived, not chosen: the sweep's whole job is to recover runs whose driver
  died, and the loss window a human notices is minutes, not seconds; a shorter interval
  spends seam calls to shave a delay nobody is waiting on. **`0` (or negative) DISABLES the
  timer entirely** and logs one WARNING saying so at startup. That kill switch is not
  decoration: it is the only way an operator can stop the sweep without a code deploy, and
  this phase adds a background loop to a service that previously had none.

Add `async def _reconcile_loop() -> None` next to `lifespan`:

```
while True:
    await asyncio.sleep(RECONCILE_INTERVAL_SECONDS)
    try:
        counts = await asyncio.to_thread(sweep_once)
    except Exception:
        logger.warning("research reconcile sweep failed", exc_info=True)
        continue
    if counts.get("claimed"):
        logger.warning("research reconcile sweep: %s", counts)
```

Four things need comments, because each is a way this quietly stops working:

1. **`asyncio.to_thread` is mandatory, not stylistic.** `sweep_once` is blocking pg8000 +
   blocking httpx. Awaiting it directly on the loop would stall every request on this
   instance for the duration of a 30-second seam call. This is the same rule
   `app/db/ai_session.py`'s docstring already states for the AI path.
2. **Sleep FIRST, then sweep.** A sweep on the very first tick would run before the instance
   is serving and would delay readiness behind a seam call, for a run that has by
   definition already been orphaned for more than 15 minutes and can wait 5 more.
3. **`except Exception ... continue`.** A single bad sweep must never end the loop. A dead
   timer is invisible — nothing polls it, nothing alerts on it — which makes it worse than a
   noisy failure. WARNING level on purpose: uvicorn's default logging config drops INFO from
   app loggers, the note already at the top of `run_task.py`.
4. **`counts.get("claimed")` gates the log line**, so an idle service does not print a line
   every 5 minutes forever.

In `lifespan`, after the existing `sweep_orphaned_skill_runs` block and before `yield`:
create the task when `RECONCILE_INTERVAL_SECONDS > 0`, hold it in a local variable (a
strong reference — a bare `create_task` result can be garbage-collected), and after `yield`
cancel it and await it under `contextlib.suppress(asyncio.CancelledError)` BEFORE the
existing engine dispose. Order matters: disposing the pool while the sweep is mid-write
would surface as a confusing shutdown error.

Wrap the task creation in the same `try/except Exception` posture as the existing sweep:
**startup must never fail because the reconciler could not start.** Liveness does not depend
on it (T-02-04).

Do NOT add a route. A Cloud Scheduler HTTP trigger stays available as belt-and-braces once
an operator enables the API — `sweep_once` is already a plain callable, which is the whole
point — but adding an endpoint now would create request surface for an API that is not
enabled and a trigger nobody can call. Recorded as DEF-23.3-04.
