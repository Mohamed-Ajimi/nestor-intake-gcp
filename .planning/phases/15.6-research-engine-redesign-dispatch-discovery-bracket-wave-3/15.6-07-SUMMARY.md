## Issues Encountered

**The per-file log-attribution regex undercounted before it was fixed — worth carrying.** A first pass
that matched `^path::name OUTCOME` on a single line found 1212 results against a summary of 1296.
The cause is that Cloud Build's log transport **wraps long pytest `-v` lines**, so a long node id puts
the outcome token on a continuation line. Counting `PASSED` occurrences alone gave exactly 1283,
matching the summary, which confirmed the wrap hypothesis; re-attributing each outcome token to the
most recently seen file path then reconciled to 1296 exactly across 35 files. **A per-file count read
off a wrapped CI log will silently under-report** — reconcile it against the summary line before
believing it.

**`ls || true` has no counterpart in the gates config.** `cloudbuild.test-engine.yaml` has the
`EXPECTED_FILES` assertion; `cloudbuild.test-gates.yaml` has only `if [ -z "$FILES" ]`, so a single
mistyped path there would be a silent skip of one file with no red build. It was reconciled **by hand**
here (13 named, 13 collected). Not fixed — that file is out of this plan's ownership — but flagged: it
is the same defect class the engine config was hardened against, still live one file over.
