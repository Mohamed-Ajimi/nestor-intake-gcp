## Decisions Made

1. **The clause fires only for a genuine `str`.** The plan said `researched = _sanitize(item.get(...))`.
   That is one guard short. `_sanitize` calls `str(value or "")` **outside** its own `try` block, so a
   value with a hostile `__str__` or `__bool__` raises out of `_sanitize`, is caught by the outer
   handler, and **collapses the entire section to the empty placeholder** — the precise failure the
   function's contract forbids ("a hostile item costs that one item, never the section"). Gating on
   `isinstance(raw_researched, str)` means `str()` is never called on the value at all. It also makes
   the acceptance criterion true rather than approximately true: `""`, `None`, `0`, `False`, `[]`,
   `["x"]`, `{"a": 1}`, `7`, `1.5`, `b"x"` and a hostile object **all** render exactly as the
   no-clause case. Note `["x"]` would otherwise have rendered the literal text `['x']` after the
   sentence *"the research answered it:"* — asserting that a question was answered which was never
   even framed. Mutation **M6** removes this guard and turns
   `test_a_non_string_annotation_renders_exactly_as_the_no_clause_case` red.

2. **The clause also requires a renderable conflict (`if researched and raw_flag`).** Half a conflict
   — an `assumption` with nothing to contrast it against — is dropped today by the `if text_value`
   guard. Without the `raw_flag` half, an annotated half-conflict would render as
   `"*    <clause> <question>"`: a bullet naming a question and no disagreement. Requiring both keeps
   that case **byte-identical to the base**, which is what the driver measured. Mutation **M7**.

3. **`_flatten(raw_flag)` in an f-string, not `raw_flag += ...`.** `raw_flag` is typed `Any` and the
   three legacy-key branches accept any truthy value, so `{"note": 17, "researched_as": "..."}` would
   make `+=` raise `TypeError` — again costing the whole section rather than the item.

4. **The item cap wins over the clause, deliberately.** `_sanitize` truncates the composed bullet to
   `_SECTION_ITEM_CHARS` (400) after the clause is appended, so an oversized conflict loses the clause
   to truncation rather than escaping the bound. `_truncated_items` still bounds the list.
   T-15.6-21 is satisfied by the same two controls that bound the other three fields, with no new
   sanitiser and no new regex. Pinned by `test_the_item_cap_still_bounds_the_annotated_bullet`. See
   **Observations** — this bites on realistic input and the operator should know it.

5. **Tests DISCOVER the key; exactly one test pins its name.** `_annotation_key` returns the single
   key `annotate_conflicts` added (set difference) and asserts on the way through that no original
   field changed. Twelve of the thirteen tests never type `researched_as`; one,
   `test_the_report_reads_the_key_the_producer_writes`, owns the literal. So a rename on either side
   fails loudly in one obvious place instead of quietly turning every rendering assertion into a test
   of nothing. Mutation **M9** (the read side reads a different key) turns six tests red.

6. **"Renders once, not twice" is counted on `"The research found:"`, not on the conflict's own
   words.** The producer's frame legitimately quotes `assumption` and `world_says` back, so those
   strings appear twice on ONE correct row — my first version of that assertion was wrong and failed
   against correct code. `"The research found:"` belongs only to the consumer's composed sentence (the
   frame says *"A source read during orientation says instead:"*), so counting it counts how many
   times the conflict was composed into a bullet. Bullet count `"*   " == 1` is the primary detector;
   mutations **M1** and **M10** both bite.

### The harness, and the two traps it was built to avoid

`steps.py` cannot be imported here — it reaches `citations/numbering.py` → sqlalchemy. So the module is
**exec'd from source text** with faithful `sys.modules` parents, and the two symbols `_sanitize`
actually calls are **lifted from the real files**, not faked: `ANCHOR_RE` from `citations/anchors.py`
and `strip_unresolved_cite_markers` (with its `_CITE_MARKER_RE`) from `audit/audited_llm_client.py`,
each verified to be the real implementation before use. Both traps named in the plan were live:

- **`subprocess.run(text=True)` decodes git output as cp1252 on Windows.** The base source is read as
  **bytes and decoded UTF-8 explicitly**. This file now carries four languages of accented text and a
  French clause ending in a narrow-space colon; cp1252 would have made unchanged strings compare
  unequal.
- **`importlib.reload` re-finds the spec via the parent package `__path__`**, silently swapping a
  mutant for the clean file. No `reload` anywhere: every load is a fresh `types.ModuleType` + `exec`,
  and the module is registered in `sys.modules` **before** the exec because `@dataclass` resolves
  `sys.modules[cls.__module__].__dict__` while processing a class body (this failed loudly first,
  which is how it was found rather than assumed).
- A third, unlisted trap bit: **the working tree is CRLF while `git show` returns LF.** The mutation
  anchors are matched against LF-normalised text, and the control run uses the same normalisation, so
  no mutation result is an artefact of it. Every anchor asserts it matched **exactly once** — a silent
  `str.replace` no-op would have reported a BLIND mutation that never happened, which is the
  `ls || true` trap wearing a different hat.
