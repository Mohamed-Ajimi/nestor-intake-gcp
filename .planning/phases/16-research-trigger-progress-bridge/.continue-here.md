## Root causes found tonight (three, stacked — this is why it looked haunted)

1. **Commit-ordering (THE core bug, fixed `11e3043`):** the BackgroundTask poll driver
   runs BEFORE the trigger request's dependency transaction commits (sync-generator
   `maker.begin()` dependency + FastAPI ordering). Consequences, each observed live:
   driver's mirror/finalize patches matched 0 rows (row uncommitted → panel frozen at
   "wordt gestart"); the intake row lock stayed held for the driver's lifetime (the 900s
   hang + 504 on a concurrent trigger); instance death rolled back entire triggers (the
   18:08 "vanished rows"). FIX: flip+audit+run-row-insert now run in an explicitly
   COMMITTED `tenant_session` BEFORE `add_task` (the `create_running_skill_run` pattern —
   which is why AI-skill routes never had this). The earlier scale-to-zero theory was a
   real risk but NOT the cause; `min-instances=1` stays anyway.
2. **Idempotency key burned by attempt numbers (fixed `721086d`):** the create_run key was
   `uuid5(intake_id, "attempt-N")`. Every pre-fix cycle burned attempt numbers on dead
   engine runs; row cleanup replays attempt numbers → idempotent return of a corpse →
   insta-fail. FIX: key = `uuid5(intake_id, research_run_id)` — unique per trigger, still
   stable across HTTP retries within one driver.
3. **Zero observability (fixed `615b6bc`):** the driver had no logging; uvicorn drops app
   INFO (no root handler). Added WARNING/ERROR diagnostics: `research driver scheduled` →
   `run_poll_driver START` → `create_run` (+engine_status; a non-queued value = idempotent
   corpse return) → `terminal` → `DONE`, plus ERROR on any 0-row patch, plus a crash
   catch-all. These lines are load-bearing — do not remove.

## The superadmin-DB-access pattern (rediscovered tonight — classifier rules)

Ad-hoc prod SQL runs through the **nestor-migrate job with arg overrides** (backend image,
`get_superadmin_engine()` = RLS bypass). The auto-mode classifier BLOCKS the agent from
executing the job (env-override + destructive SQL) — **the USER must run it via `!`**.
Recipe (scripts live in the session scratchpad, may be gone — recreate):

```bash
SCRIPT='from app.db.base import get_superadmin_engine
from sqlalchemy import text
e = get_superadmin_engine()
with e.begin() as c:
    ...  # SQL here
'
gcloud run jobs execute nestor-migrate \
  --region=europe-west1 --project=project-cb01b861-cb4a-438d-b9a \
  --args="^@@^python@@-c@@${SCRIPT}" \
  --update-env-vars="SUPERADMIN_DB_PASSWORD_SECRET=projects/1055853212188/secrets/nestor-app-superadmin-pw/versions/latest" \
  --wait
# output lands in Cloud Logging: resource.type="cloud_run_job" + execution_name label
```

then `gcloud run services update nestor-api --image=<tag> --region=europe-west1`.
