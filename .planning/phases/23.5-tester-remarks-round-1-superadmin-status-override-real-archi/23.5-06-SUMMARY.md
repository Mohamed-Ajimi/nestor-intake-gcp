# Phase 23.5 Plan 06: Sources Renderer + Truncation Continuation Summary

The publisher URL that was already resolved and stored is finally printed
instead of the opaque provider redirect, and a chapter that hits the output cap
gets exactly ONE continuation call — or, failing that, an honest one-line notice
in the run's own language — with both changes behind switches that default OFF
and a golden proving the off path is byte-identical to unmodified code.

## What was built

### Mechanism 4 — the Sources list stops printing redirects

`build_graded_sources_section` now computes, per entry:

```python
url_out = url
if show_resolved and url:
    url_out = str((entry or {}).get("resolved_url") or "").strip() or url
label = title or _domain(url_out) or url_out or "source"
```

`url_out` is the markdown link target and the fallback for the display-domain
label. BOTH `url` and `url_out` go into `numbered_urls`, so the append-only
prose rescue recognises the document under either spelling.

Four deliberate details:

- **`.get`, never `[...]`.** Plan 05 adds the key only on the flags-on path; on
  the flags-off path and on every stale row it is ABSENT, not `None`. A
  subscript here would be a `KeyError` the first time an operator flipped the
  master against existing rows.
- **`or url` covers `None` and `""` alike.** A failed resolution falls back to
  the redirect, never to a blank link.
- **`show_resolved` is read ONCE per call**, not per entry: a switch must not be
  able to change halfway down a single Sources list.
- **`if show_resolved and url`** — the `url_out` computation is skipped entirely
  when there is no url, so the no-url plain-text branch is reached by exactly
  the same condition as today.

Untouched, as the plan required and as the diff proves: `_TIER_LABELS`, the tier
words, the `retrieved` date word and the C1 reasoning behind it, the
`single-source` segment, the anchor-cleaned scan copy, and the whole
`if not numbered` fallback to `_extract_sources_section`. **The entire renderer
change removes exactly two lines.**

### Remark 2b — one continuation, then an honest notice

Added to `steps.py`:

| Symbol | What it is |
|---|---|
| `_TRUNCATION_NOTICE` | one italic line per language, on the SAME four `_norm_lang` keys as `_SECTION_STRINGS` |
| `_CONTINUATION_MARKER` | the named prompt delimiter — the tests classify a recorded call by the constant actually sent, not by a literal that could drift |
| `_splice_continuation` | joins at the last paragraph break |
| `_continue_truncated` | EXACTLY ONE extra call; NEVER raises |

`_continue_truncated` returns `(text, still_truncated)`. `still_truncated` is
True in three states, not one: the continuation also hit the cap, the
continuation was REFUSED, or the call raised. All three are states in which the
reader must be told the chapter is short rather than handed something that
looks whole. A refusal specifically returns `("", True)` — T-dn8-05 again: a
refusal can arrive WITH partial content, and that content is exactly what must
not be pasted.

`_splice_continuation` drops the half-paragraph the cap produced **only when
there is a paragraph break to drop it at**. With no break — a single-paragraph
section, or a cap that bit in the opening lines — there is no "last complete
paragraph" to restart from, so the partial is kept whole; dropping it would
throw away the only content the section has. An empty continuation returns the
partial untouched, so a failure costs the improvement and never content the
client paid for.

Wired into BOTH `max_tokens` branches. At the wrap call the splice runs
**before** the exec/tail `re.finditer(r"^##\s+", ...)` split, so the split still
sees a complete document — a wrap cut mid-heading would otherwise misplace the
boundary for the whole report, not just for the sentence that was cut.

The existing `log.warning` is untouched at both sites. It is the live counter
that found this defect in the first place, and all three `it is TRUNCATED`
warnings survive.

## WORST-CASE EXTRA PROVIDER CALLS PER RUN — for plan 07's cost read

The plan asks for this number explicitly.

```
worst case extra calls = (number of body sections) + 1
```

One continuation per TRUNCATED section, plus one for the wrap. There is no loop
and no retry: a continuation that itself truncates gets the notice, not a third
call, and this is asserted as a call-count EQUALITY on three separate paths.

Reading it against a real run:

- the extra calls happen ONLY for sections whose `stop_reason` was
  `max_tokens`. On run 7784e71c that was **2 of the chapters**, not all of them,
  so the realistic figure is far below the ceiling.
- each extra call is bounded by the same `_SECTION_MAX_TOKENS = 20_000` (or
  `_WRAP_MAX_TOKENS` for the wrap) as the call it continues, and re-sends that
  section's own prompt plus its partial output — so its INPUT is roughly one
  section prompt plus the partial, not the whole run.
- with `NESTOR_SYNTHESIS_CONTINUE_TRUNCATED` unset — the shipped default — the
  extra-call count is **0** and the run costs exactly what it costs today.

**Plan 07 should read the dev run's section-level call count against
`sections_truncated + (1 if wrap_truncated else 0)`, not against the section
count.** If it exceeds that, the bound has been broken and the switch should go
back off.

## Deviations from Plan

**1. [Rule 1 — Bug in my own test fixture] The RED fixture's continuation opened
with the same words as the fragment it replaced.**

- **Found during:** Task 2, the first GREEN run.
- **Issue:** `SECTION_CONTINUATION` started `"And then the sentence stops at
  Twente…"` while `HALF_PARAGRAPH` was `"And then the sentence stops at Tw"`.
  The continuation is SUPPOSED to restate the cut paragraph, so it naturally
  opens with the same words — which means `HALF_PARAGRAPH not in report`
  matched a PREFIX of the CORRECT continuation and went red on working code.
  This is the substring trap the phase memory warns about, met head-on: the
  assertion could not tell "the fragment survived" from "the paragraph was
  rewritten".
- **Fix:** `ZZFRAGMENT` appears only in the cut text, `ZZWHOLE` only in the
  rewrite. Both facts are now separately assertable, and the raising-path test
  (which needs the fragment KEPT) still asserts the same constant meaningfully.
- **Files modified:** `tests/test_synthesis_continuation.py`
- **Commit:** `628927d` (called out in the commit body — the flaw is in the RED
  commit `0bfcc55` and the record should show it)
- **No bound assertion was weakened.**

### Two acceptance criteria that are FALSE AT HEAD — recorded, not worked around

Both are gate-integrity issues in the plan's own criteria, not in the code.

**(a) `grep -c 'it is TRUNCATED' steps.py == 2`.** The count at the base commit
is already **3**, not 2: `final_synthesis_audited` (line 419) has one too,
alongside `_one_section` and the wrap. The criterion's INTENT — "both existing
warnings survive" — is satisfied and then some: the count is still **3** and no
warning was edited. Taken literally the criterion could only be met by DELETING
a warning, which is the opposite of what it asks for. Recorded rather than
satisfied.

**(b) The `timeout=` and streaming-entry-point criteria are substring greps
over docstrings, not just code.** `_continue_truncated`'s docstring has to tell
the next reader that the two escape hatches stay unbuilt — but writing either
token in prose would have tripped the grep, since the existing occurrences live
on `#:` comment lines that `grep -v '^ *#'` excludes. The docstring therefore
names them by description ("no per-call deadline kwarg", "the streaming entry
point") rather than by literal. The warning is still there for the next reader
and both counts are 0.
