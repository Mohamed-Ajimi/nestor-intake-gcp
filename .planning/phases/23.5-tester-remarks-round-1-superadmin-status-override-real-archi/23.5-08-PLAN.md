<retention_boundary>
**What a delete destroys, and what it deliberately does not.**

DESTROYED (app side, by the DB's `ON DELETE CASCADE` edges on `nestor.intakes.id` —
verify each before relying on it): `intake_answers`, `skill_runs`, `research_artifacts`,
`decompositions`, `research_questions`, **`research_runs`** (`models/research_runs.py:77`,
`ForeignKey("nestor.intakes.id", ondelete="CASCADE")`), `intake_sources`, `transcripts`,
`extracted_insights`, `artifact_embeddings`, `findings`. Plus the intake's own GCS objects,
prefix-asserted and enumerated from the DB, exactly as plan 02 built it.

RETAINED, on purpose: everything on the TRIBUNAL side. `tribunal.run` and its cascaded
claims / sources / verdicts / outputs live in the **`tribunal` schema** with their own
alembic line and NO foreign key into `nestor` (`tribunal/nestor_pulse_sdk/db/models/run.py`
declares FKs to `org.id` and `project.id` only). The hash-chained audit blobs in the audit
bucket are likewise untouched — the GCS cleanup only ever sees keys read off
`intake_sources` / `research_artifacts` rows and prefix-asserted to
`{space_id}/{intake_id}/`, which the audit bucket's keys are not. That is the cost and
audit record and it stays.

The one real consequence of retention: `research_runs.tribunal_run_id` is a plain `String`
with no FK, so once the nestor row is gone **nothing points at the retained tribunal run
any more**. Task 1 closes that by writing those ids into the `intake.deleted` audit row
before the cascade takes them. Retaining a record nobody can find is not retention.

**NO tribunal endpoint is called. NO file under `tribunal/` is edited. `git diff --stat
tribunal/` must be EMPTY at the end of this plan.**
