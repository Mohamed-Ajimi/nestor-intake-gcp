## Remark 2 — "the link between the claims and the mentioned sources is not correct"

**Fully diagnosed 2026-09-19** on the prod DB (read-only Cloud Build psql as `tribunal-run@`; outputs in `gs://nestor-pulse-prod-nestor-audit/diagnostics/7784e71c/{diag.txt,outputs.txt,report.md}`; memory `citation-source-list-defect-run-7784e71c`). Every client figure reproduced exactly (2,681 sources, 1,824 mislabelled, 66 opaque redirects, Wikipedia 125 / ebay.de 44 / ah.nl 29, `[1]`×45, 16 unnumbered extras). Numbers: 586 claims, 4,999 claim_source rows, **159 claims with zero sources**, sources/claim median 1 · avg 8.5 · max 58; 232 of 427 sourced claims anchor to a host that is not their own domain.

**Five mechanisms, file-anchored:**
1. **Skeptic fan-out** — `pipeline/tribunal/group_skeptic.py::_parse_group_verdict` copies `citations` (= EVERY `web_search` RESULT url + every `web_fetch` of the whole group session, `skeptic.py::_collect_citation_urls`) onto every claim's verdict; `citations/extractor.py::_gather_source_urls` upserts them all as `claim_source` rows of every claim in the group.
2. **One title per claim** — `extractor.py` ~1063 `source_title = claim["source_domain"]` applied to ALL urls of the claim; `_upsert_source` dedupes by url hash, first writer wins → 1,824 wrong labels. Same shape for the grade: `quality_by_url.get(url) or claim_quality` stamps the provider's self-grade on skeptic urls ("established press" on an ebay listing).
3. **Anchor picks a random source** — `citations/numbering.py::_CLAIM_SOURCE_SQL` orders `c.position, c.id, s.id`; `_assign_numbers` maps a claim to its FIRST source in that order = lowest UUID.
4. **`resolved_url` never rendered** — `synthesis/steps.py::build_graded_sources_section` prints `url` only; 21 of 27 redirects were resolved and stored.
5. **Unnumberable anchors** — `anchors.build_ledger` shows the writer anchors for ALL claims; `number_citations_with_claims` only maps claims with a `claim_source` row → the 159 sourceless claims (mostly `distiller_fallback`, which zeroes `source_domain` and carries no usable url) produce the 108 stripped anchors. New in this run (0 in the 3 prior runs).
Minor: some skeptic `evidence_refs` are "URL (quote)" free text stored verbatim as `source.url` (visible as garbage tier labels in the rendered list).

**Fix (behind `NESTOR_CITATIONS_V2`-style switches, one per mechanism or one master + fine-grained, planner decides):**
(a) skeptic urls become VERDICT evidence (or only the fetched/cited pages, tagged `skeptic`), never `claim_source` rows of every group member; (b) title + grade per URL from the provider that supplied it; (c) anchor a claim to its PRIMARY provider url (`source_urls[0]`) — deterministic, never lowest uuid; (d) render `resolved_url` when present, redirect as fallback; (e) ledger offers the writer only claims that can be numbered; distiller-fallback claims carry a source url through or get no anchor. Keep `_CLAIM_SOURCE_SQL`'s determinism contract (pinned test) — add a new ordering rather than mutating the old under the flag OFF.

**⚠ Collisions to respect:** Phase 24 (unplanned) owns UAT-22-F2/F3 and DEF-22-06's alembic **0019** (`normalized_url` + drop `idx_source_tenant_content_hash`). This phase must need **no migration**; if one proves unavoidable it takes a number that cannot collide and says so in the SUMMARY. Do not touch `run`/`worker` code, CLAIM_SQL, heartbeat, or anything under `runs/` (D-23.1-06 fence).

**Acceptance numbers (offline replay over the recorded rows, then the dev run):** labels ≠ host = **0** (excluding redirects, where label = provider label); anchors resolving to a url not among the claim's own provider urls = **0**; stripped anchors = **0**; numbered redirect urls rendered opaque while `resolved_url` exists = **0**; total numbered sources on the recorded run collapses from 2,681 to the count of distinct provider urls (~300–500, record the exact figure).
