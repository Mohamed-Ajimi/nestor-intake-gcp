<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `DELETE /intakes/{id}` | an authenticated caller asks for irreversible destruction |
| `delete_intake` -> `app.storage.gcs` | object keys read out of DB rows cross into a destructive seam call |
| `delete_intake` -> `nestor.intakes` | one DELETE fans out through ten `ON DELETE CASCADE` foreign keys |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-delete-cascade | Tampering | `delete_intake` GCS cleanup | mitigate | every candidate key must `startswith(f"{intake.space_id}/{intake.id}/")` before it reaches `gcs.delete_object`; keys are enumerated from DB rows only, never from a bucket listing; proven by a set-equality test with a deliberately out-of-prefix seeded row |
| T-delete-paid | Tampering | deleting an intake with paid research | mitigate | 409 `_DELETE_BLOCKED_DETAIL` when any `research_runs` row exists (D-23.5-02), checked BEFORE any key collection or audit write so a refused delete has zero side effects |
| T-23.5-02-E | Elevation of privilege | both new routes | mitigate | `Depends(superadmin_gate)` before `Depends(get_tenant_repo)`; both routes added to `_GATED_VERBS` |
| T-23.5-02-I | Information disclosure | `GET /deletable` on a foreign intake | mitigate | 404 `"Intake not found"` — the eligibility read must not become an existence oracle for other tenants' intakes |
| T-23.5-02-R | Repudiation | destruction with no trace | mitigate | `intake.deleted` audit row written on the same session BEFORE the delete; `audit_log` has no FK to `nestor.intakes` so the row outlives the intake — asserted by a test, not assumed |
| T-23.5-02-D | Denial of service | mass deletion | accept | superadmin-only, one intake per call, typed confirmation in the UI; the operator is the trust boundary here |
| T-23.5-02-SC | Tampering | npm/pip/cargo installs | mitigate | this plan installs NO package — `git diff frontend/package.json backend/pyproject.toml` must be empty |
</threat_model>
