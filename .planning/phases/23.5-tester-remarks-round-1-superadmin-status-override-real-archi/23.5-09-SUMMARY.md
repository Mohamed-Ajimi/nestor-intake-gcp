# Phase 23.5 Plan 09: Client Name in Research Mails + Active-Client Sync Summary

The research notification mails now name the **client** and the **project** — in body and
subject, from both the driver and the reconciler sweep — and opening an intake in the admin
switches the top-bar client dropdown to that intake's client.

## What was built

Two gap-closure items from the client's test of the 2026-09-24 prod release.

**D-23.5-08 — the mails name whose research finished.** `load_trigger_context` now reads
`organizations.name` for the intake's own space and returns it as `ctx["client_name"]`. A
single helper `_research_subject(base, ctx)` composes the subject qualifier, and all seven
render call sites — four in `run_task.py` (success, parked, failed, `on_error`) and three in
`reconcile.py` — pass `client_name=`. The nine templates each carry one byte-identical
expression.

**D-23.5-09 — the dropdown follows the intake.** One pure predicate,
`shouldSyncActiveSpace`, shared by the intake detail page and the two run pages.

`<base> — Rocketship BV`; neither → the base sentence unchanged.

**The two separators differ on purpose** (D-23.5-08): the em dash attaches the qualifier to
the base sentence, the slash separates client from project inside it. The body uses an em
dash between the two names because there it is the only separator in the sentence.

## The naming trap, and what was done about it

`client_name` means two different things in this codebase and plan 23.5-03 exists because
that confusion shipped false copy once.

| name | what it actually is |
|---|---|
| `intakes.client_name` (DB column) | the operator's free-text label for ONE intake — the **PROJECT** name since 23.5-03; column deliberately not renamed |
| `ctx["project_title"]` | `intake.client_name or "dit intake"` → the **project** |
| `ctx["client_name"]` (new) | `organizations.name` for the intake's space → the real **client / tenant** |

That table is written in prose at both definition sites — `load_trigger_context`'s docstring
and each of the three `render_research_*` docstrings — so a later reader cannot assume the
key is the column and put the project in the client slot.
