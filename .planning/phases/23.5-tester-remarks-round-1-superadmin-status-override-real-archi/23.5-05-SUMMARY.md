# Phase 23.5 Plan 05: Citation Anchors — Mechanisms 3 and 5 Summary

A claim's `[n]` now comes from a url its own provider supplied instead of from
whichever linked source held the lowest UUID, the numbered entries carry
`resolved_url` for plan 06, and the fact ledger stops offering the writer claims
that can never be numbered — all behind `NESTOR_CITATIONS_V2`, with the pinned
determinism contract untouched.

## What was built

### `citations/numbering.py` — a second ordering, beside the first

`_CLAIM_SOURCE_SQL` was not edited. Not one character. It carries its own "do
not change one character" comment, it is pinned by
`test_citation_numbering.py::test_numbering_is_deterministic_and_all_resolve`,
and that test file is byte-unchanged (`git diff --stat` on it is empty).

Added beside it:

- **`_CLAIM_SOURCE_SQL_V2_HEAD`** — the same SELECT plus `s.resolved_url`, the
  same two joins, the same `WHERE c.run_id = :rid`, and the shared head of the
  ORDER BY.
- **`_claim_source_sql(primary_first)`** — appends one of two FIXED tails:
  `s.id ASC`, or `(s.title IS NULL) ASC, s.id ASC`. A bool chooses between two
  literals; no caller value is ever interpolated (T-23.5-05-T2). Both outputs
  are asserted against string literals in the new test.
- **`_select_claim_sources()`** — returns `(sql, include_resolved)`, read from
  `runtime_flags` at CALL time. `number_citations` and
  `number_citations_with_claims` both go through it, so they cannot be built
  from different reads — the invariant `number_citations_with_claims` exists to
  protect.
- **`_assign_numbers(..., include_resolved=False)`** — adds exactly one key,
  `resolved_url`, read via `_row_get` so a hand-built row without the column
  yields `None` rather than raising. Default `False`, because 15.2-05's Layer-1
  tests compare WHOLE entry lists and an extra key on the flags-off path would
  mean the shipped default was not in fact today's behaviour.

### `citations/anchors.py` — an opt-in ledger filter

`build_ledger(claim_rows, *, numberable_claim_ids=None)`. `None` is no filter
(today). A set filters. **The empty set means nothing is numberable and the
ledger comes back empty** — it is emphatically not "no filter". Writing
`if not numberable_claim_ids` would have collapsed those two cases at exactly
the moment a run has no citations at all, which is when offering the writer an
anchor for every claim does the most damage. The branch is `is None` and it has
its own test. Ids compare as strings, so a caller holding `uuid.UUID` keys
filters correctly instead of silently withholding everything.

### `pipeline/tribunal/pipeline.py` — four lines of wiring

Only `_load_citation_context` changed: one local import and the return, 8
changed lines, no signature anywhere in the file. The `try/except`, the
`set_tenant_context` call, both queries and the return tuple are exactly as they
were, so the best-effort `([], [], {})` degradation is intact.

## An interaction the numbers exposed, now pinned

`c04c` has no `source_urls` of its own — every url it carried arrived through
the shared group verdict. Plan 04's mechanism 1 stops emitting those as its
`claim_source` rows, so with the master on the claim becomes **unnumberable**,
and this plan's mechanism 5 then withholds it from the writer.

That is the right direction: a claim with no evidence of its own is no longer
offered as citable, rather than being offered, anchored and stripped. But it
means the flags-on ledger shrinks for a reason BEYOND the 159 sourceless claims.
**Plan 07 should expect that on the dev run and not read it as over-filtering.**
`test_a_claim_whose_only_urls_came_from_the_group_is_also_withheld` pins it so
it is a known property rather than a later surprise.

## Deferred Issues

### DEF-23.5-05-01 — "primary" means *a* provider url, not `source_urls[0]`

`(s.title IS NULL) ASC` selects a url the claim's own provider supplied and
labelled. It does **not** pin the provider's FIRST url. A claim with two titled
provider urls is anchored to whichever has the lower source UUID among them —
deterministic and always the claim's own, but not order-faithful to what the
provider said first.

Closing it needs a stored rank on `claim_source`, which has
`(claim_id, source_id, tenant_id, snippet, confidence, provider_quality)` and no
rank, sequence or timestamp column. That is a migration, and this phase adds
none. **Candidate rider for Phase 24's alembic `0019`** (DEF-22-06,
`normalized_url` + dropping `idx_source_tenant_content_hash`). `snippet` is
Phase 24's own UAT-22-F2 excerpt slot and `confidence` is PHASE2-05's — neither
may be hijacked as a rank. The limit is written into `numbering.py` at the point
of the decision, not only here.

### Pre-existing, NOT caused by this plan

`test_scrub_research.py` fails (5 of 8) whenever another async module runs
first — DEF-23.5-04-01, recorded by plan 04 and reproduced byte-for-byte at the
base commit. Confirmed again here against a module this plan does not touch:
8 passed alone; `test_citation_anchors.py` + `test_scrub_research.py` together
gives **5 failed, 55 passed**. The cause is
`asyncio.get_event_loop().run_until_complete` at `test_scrub_research.py:41` on
Python 3.12. Not fixed: the file sits over `pipeline/`, and this phase's guard
requires that surface to stay untouched. DEF-23.5-04-02 (cross-module isolation,
including `test_citation_roundtrip`'s `org_slug_key` collision) likewise stands.
