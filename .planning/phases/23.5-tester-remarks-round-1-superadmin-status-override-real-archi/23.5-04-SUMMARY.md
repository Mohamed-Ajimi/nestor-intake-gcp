# Phase 23.5 Plan 04: Citation Sources — Mechanisms 1 and 2 Summary

Run 7784e71c's skeptic fan-out and cross-host labelling are both fixed behind
`NESTOR_CITATIONS_V2`, with the persist loop's decisions lifted into a pure
function and pinned by a golden generated from code nobody had edited.

## What was built

**`nestor_pulse_sdk/runtime_flags.py`** — seven switches, every one read from
`os.environ` at CALL time:

| Env var | Default | Gated by the master |
|---|---|---|
| `NESTOR_CITATIONS_V2` | false | — (it IS the master) |
| `NESTOR_CITATIONS_SKEPTIC_AS_EVIDENCE` | true | yes |
| `NESTOR_CITATIONS_PER_URL_META` | true | yes |
| `NESTOR_CITATIONS_PRIMARY_ANCHOR` | true | yes |
| `NESTOR_CITATIONS_LEDGER_NUMBERABLE_ONLY` | true | yes |
| `NESTOR_CITATIONS_RENDER_RESOLVED` | true | yes |
| `NESTOR_SYNTHESIS_CONTINUE_TRUNCATED` | false | no (separate master) |

The import-time idiom (`anchors.py:87 _ANCHORS_ENABLED`) is deliberately not
reused: it is the reason `test_citation_anchors.py` has to `skipif` rather than
assert both states, and the flags-off golden test would be worthless if it could
not turn the master off in-process. An unparseable value (including the empty
string Cloud Run gives a declared-but-blank variable) falls back to the
documented default, so a typo cannot silently disable a fix.

**`tests/fixtures/citations_replay/`** — a synthetic, pure-python fixture: 12
claims covering all nine measured shapes (sourceless claims, the median
single-url claim, the max-58 tail, the three-claim group sharing ONE verdict
object, the wikipedia/ebay/ah foreign-host shape, a resolved and an unresolved
grounding redirect, a `distiller_fallback` claim, a free-text `evidence_refs`
entry, and a partial `provider_quality_by_url`), plus a 13th exercising the
200-char title truncation. No database, no network, no prod rows.

**`extractor._plan_claim_sources(claim, verdicts_by_claim, resolved_map)`** —
returns one dict per url that would be upserted and linked, in write order,
carrying `url`, `title`, `provider_quality`, `resolved_url`,
`resolution_status` and the new `origin` (`"provider"` | `"skeptic"`).
`_gather_source_urls` is now its url projection, so the Stage-7 resolution
pre-pass and the persist loop share the DECISION rather than merely a helper.
The persist loop iterates the plan and decides nothing.

**The two mechanisms**, both ANDed with the master:

- *Mechanism 1* (`skeptic_as_evidence`) — verdict-derived urls are still walked
  (one ordering code path, not two) but are not emitted as `claim_source`
  entries. The evidence stays on the verdict row; `_insert_verdict` and
  `group_skeptic.py` are untouched.
- *Mechanism 2* (`per_url_meta`) — the claim's `source_domain` is applied only
  to a grounding redirect or to a url actually on that host; its scalar
  `provider_quality` may speak only for urls it DECLARED in `source_urls`.
  Everything else gets `None` and falls back to the renderer's own display
  domain and `derive_quality_tier`'s heuristic.

## Deviations from Plan

None. The plan executed as written, in the order written.

Two judgement calls worth naming, both inside the plan's letter:

1. **`is_redirect_url`'s function-local import moved** out of
   `persist_tribunal_claims` and into `_plan_claim_sources` — it moved with the
   code that uses it, and leaving it behind would have left a genuinely unused
   import. `test_the_persistence_function_cannot_reach_the_resolver_at_all`
   still passes: the resolver's request entry point remains absent from the
   file.
2. **`_domain` is imported from `citations/numbering`**, not re-derived. The
   plan's `<interfaces>` names it as the contract, and a second copy would let
   "the title matches the host" be true in this function and false in the code
   that prints the label.

## A rule the fixture made visible

With `per_url_meta` on, `c05`'s own wikipedia url loses its title: the claim's
`source_domain` is `wikipedia.org` while `_domain(url)` is `en.wikipedia.org`,
so the plan's literal rule drops it to `None` and the renderer falls back to
`en.wikipedia.org`. That is honest and satisfies the acceptance criterion
("labels ≠ host = 0"), but it does mean a provider label is discarded whenever
it is a registrable domain and the url is on a subdomain. If the dev run in
plan 07 shows a lot of bare `en.wikipedia.org`-style labels where a nicer
publisher name was available, the rule to revisit is the equality in
`_plan_claim_sources`, not the fixture. Flagging rather than changing it: the
plan said what the rule is, and this is the sensitive plan.
