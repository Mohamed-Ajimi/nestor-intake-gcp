# Phase 23.1 Plan 10: Gate the Eight Intake Operator Verbs — Summary

Closed the SEC-01 hole: the eight intake operator verbs in `23.1-CONTEXT.md` § 1 now resolve
the shared `superadmin_gate` before anything else, denying a role=`user` caller with an
existence-hidden 404 and no side effect, while the ten client routes and the superadmin's own
use of all eight are unchanged.

## Deviations from Plan

### 1. [Rule 2 — missing critical verification] A sixth fixture file the plan did not list

The plan's `files_modified` authorizes fixture-only edits in five test files. **Six files
actually drive a now-gated verb as a role=`user` identity.** The missing one is
`backend/tests/test_mail_locale.py`, whose six tests POST to `/intakes/{id}/mail/results`.
Discovered by the full-suite run (9 failed) after the five listed files were all green.
Treated identically — fixture only, every assertion untouched — because leaving it red would
have left the phase's own suite broken, and the licence's stated shape ("a pre-existing test
that drives one of the eight gated verbs as a role=user identity") describes it exactly.

### 2. [Rule 1 — bug in my own test helper] `_count_audit` was not scoped to the intake

First written filtering only on `event_type`. The conftest `engine` connects as the migration
owner, for which the audit read is not space-filtered, so the count saw every space's rows.
Measured symptom: `test_review_superadmin_still_works` passed alone and failed in-file, having
counted `test_review_user_role_404`'s row. Fixed by filtering on the intake id.

### 3. [Rule 1 — pollution my suite introduced] audit rows outliving `_cleanup_spaces`

`audit_log.space_id` is a plain nullable column with **no ForeignKey**, deliberately, so the
trail outlives its space (`models/audit.py`) — dropping the organization does not cascade the
rows. My superadmin arms legitimately write `mail.sent` rows, and
`test_mail_endpoints._count_mail_sent_audit` counts `mail.sent` GLOBALLY, so
`test_timestamp_on_success_only` went red on collection order alone (**saw 6 where it asserts
1**). Fixed inside MY file: `_cleanup_spaces` now sweeps `audit_log` for the seeded space.
`test_mail_endpoints.py`'s assertion was NOT touched.

### 4. [Rule 1 — false criterion in my own structural test] "mounted exactly once"

`app.main.app` includes the module-global `protected_router` LAZILY (D-23.1-14), so the router
object it holds is live: every other suite's `_build_app()` calling
`protected_router.include_router(intake_router)` adds another mount. **Measured: 11 mounts of
`GET /members`** under a multi-file run. Relaxed to "mounted at least once, and the gate
present on EVERY mount" — strictly stronger for the security property. Mount-count hygiene is
already owned by `test_client_surface_open.test_client_route_inventory_is_pinned`.
