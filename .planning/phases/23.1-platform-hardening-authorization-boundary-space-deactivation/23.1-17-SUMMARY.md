# Phase 23.1 Plan 17: Gate the Paid Research Trigger — Summary

Closed D-23.1-16: `POST /intakes/{intake_id}/research` — the one verb on `research_router`
that spends (~$45/call, `NESTOR_TRIBUNAL_UNCAPPED=1`) — was its last ungated write, and is
now superadmin-gated with the gate resolving BEFORE `get_tenant_repo`, proved by an observed
RED, two existence-hidden 404s, a no-side-effect assertion on the spend seam, and a live
mutation proof that the ordering is load-bearing.

**Commit:** `5d65f98`

---

## The observed RED (before the gate)

Measured with a throwaway probe against live Postgres, with `run_poll_driver` stubbed so
nothing could actually spend. A `role=user` **in the intake's own space**, on a `decomposed`
intake with validated questions:

```
RED status                = 202
RED body                  = {"research_run_id":"943c0a0f-9ac3-465d-90f4-3e2c86ffd7a8","status":"queued"}
RED intake status         = in_research
RED research_runs rows    = 1
RED run_poll_driver calls = 1
```

A non-operator authorized the ~$45 run, flipped the intake, queued the row, and dispatched
the driver. A **null-space** caller got:

```
403 {"detail":"No space — not authorized"}
```

— `get_tenant_repo`'s D-04 default-deny, i.e. an existence oracle for the most valuable
endpoint on the router.

## The fix

`backend/app/api/research_routes.py:250-260` — the signature, with the ordering comment:

```python
def trigger_research(
    intake_id: str,
    background: BackgroundTasks,
    # ORDER IS LOAD-BEARING AND THIS IS THE ROUTER'S HARDEST SIGNATURE. `repo` used to
    # be declared first; the gate MUST stay above it. ...
    identity: Identity = Depends(_superadmin_gate),
    repo: IntakeRepository = Depends(get_tenant_repo),
) -> dict:
```

`repo` was declared FIRST in source order — this is the case where getting the order wrong
does not merely feel untidy, it converts a silent denial into the 403 above.

## Post-fix behaviour (all observed)

| Caller | Status | Body |
|---|---|---|
| `role=user`, intake's own space | **404** | `{"detail":"Intake not found"}` |
| `role=user`, `space_id=None` | **404** | `{"detail":"Intake not found"}` |
| `superadmin` | **202** | `{"research_run_id": ..., "status":"queued"}` — flip, run row, driver scheduled once |

## No side effect on denial (the expensive half)

Both denial arms assert, beyond the status code:

* `research_runs` holds **zero** rows for the intake — nothing was queued for the worker;
* intake status is still **`decomposed`** — no half-transition an operator must undo;
* the `run_poll_driver` recorder is **empty** — the denied caller never reached the driver.

## Zero provider spend, by construction

`research_routes.run_poll_driver` is monkeypatched to a recorder in **every** test in the new
file, including the superadmin 202 arm. The 202 arm asserts the driver was **scheduled**
(recorder length 1, carrying the run id from the response body) and never that Tribunal ran.
`fake_tribunal_client` / `fake_resend` are additionally taken by that arm as belt-and-braces,
and it asserts `fake_tribunal_client["create_run"]` stayed **empty**. No test in this work
can start a run even if a future edit let the route succeed where it should deny.

## The ordering test's count guard

`tests/test_superadmin_gate.py::test_every_gated_research_route_resolves_the_gate_before_the_repo`
introspects the live router and asserts `gate_pos < repo_pos` for every gated route, behind
an anti-vacuity guard. The guard was **raised 9 → 10**, not weakened:

```python
assert checked == 10, f"expected 10 gated research routes, found {checked}"
```

with a comment recording that it was raised by this plan, that it must never become `>= 9`,
and that 10 of 11 is the ceiling because `stream_research_run` is the excluded eleventh.

## The mutation proof (ordering is load-bearing, not asserted)

`test_ordering_mutation_produces_the_403_existence_oracle` re-registers the **real**
`trigger_research` function under a `__signature__` whose gate/repo parameters are swapped,
mounts it, and drives a null-space caller at it. Observed live:

```
403 {"detail":"No space — not authorized"}
```

The same function body, the same dependencies, only the parameter order changed — so the
index assertion in `test_superadmin_gate` is now backed by a demonstrated consequence rather
than by a comment. The test also asserts its own precondition (the shipped signature is
correctly ordered) so it cannot pass vacuously.

## Collateral: the eight pre-existing trigger cases

`tests/test_research_routes.py` drove the trigger as `role=user` in eight cases. Gating made
all eight red (measured: `8 failed, 595 passed`). They were converted to act as

## Findings — the scrutiny pass

### 1. There is no tenth ungated verb. The router is 10/11 gated.

Audited by walking the live router's resolved dependency tree (not by grep — the
`_superadmin_gate` alias and `include_router` both defeat substring approaches):

```
GATED    GET   /intakes/research/runs/{run_id}/locate                 locate_research_run
GATED    POST  /intakes/{intake_id}/research                          trigger_research      <- this plan
GATED    POST  /intakes/{intake_id}/research/resume                   resume_research
GATED    POST  /intakes/{intake_id}/research/cancel                   cancel_research
GATED    GET   /intakes/{intake_id}/research/{run_id}/bundle-url      get_bundle_url
GATED    POST  /intakes/{intake_id}/research/{run_id}/verify-chain    reverify_chain
GATED    GET   /intakes/{intake_id}/research/{run_id}/verification    get_research_verification
GATED    GET   /intakes/{intake_id}/research/sources/{source_id}      get_research_source
GATED    GET   /intakes/{intake_id}/research/{run_id}/audit/{audit_id} get_research_audit_body
GATED    GET   /intakes/{intake_id}/research/{run_id}/events          get_research_events
UNGATED  GET   /intakes/{intake_id}/research/stream                   stream_research_run
```

### 2. ⚠ D-23.1-16's rationale for excluding `stream_research_run` is FALSE for this codebase.

**Not acted on** — the instruction to leave the stream alone was explicit, and it is the
right call for this plan. But the reason recorded in CONTEXT is wrong and should not be
carried forward as settled:

> "It is SSE and `EventSource` cannot set an Authorization header, so it may authenticate
> differently — gating it blind could break the live run feed."

The frontend does **not** use `EventSource`. `frontend/src/lib/api/research.ts:572`
(`openResearchStream`) opens the stream with `fetch(...)` carrying
`Authorization: Bearer ${token}` from the same `currentIdToken()` source `apiFetch` uses,
and reads `resp.body` as a stream. The header constraint that justified the exclusion does
not exist here. The route already runs a scope pre-flight (403 null-space / 404 out-of-scope)
before opening the stream, and its only two mount points — `admin.pulse.intakes.$id.tsx` and
`admin.pulse.runs.$runId.index.tsx`, via `ResearchRunProgress` — are admin routes.

So the stream is very likely gateable without breaking the feed. It is a **read** of run
status, not a spend, so the exposure is materially smaller than the trigger's — but the
decision to leave it should be re-taken on the real facts, not on the `EventSource` premise.
Recommend a follow-up that gates it with the same ordering contract and pins the admin feed
with a superadmin-still-streams arm.

### 3. The `tx_runs.create()` arm is now unreachable — kept deliberately.

`trigger_research` branches on `identity.role == "superadmin"` to choose `create_in_space`
vs `create`. With the gate admitting only superadmins the `create()` arm is dead. It is
**kept**, matching this module's existing "Open Q2 defense-in-depth" convention (the other
nine verbs keep their in-body role re-checks), with a comment explaining that deleting it
would make any future relaxation of the gate silently write the run row into the *caller's*
space instead of the intake's. Flagged rather than silently removed.
