## FALSE / UNSOUND CRITERION FOUND — one, and it is in a test the plan told me to trust

The plan's own criteria held up: the probe criterion was the right shape and was honoured as an
observed probe; the task-2 verify grep is honest; `<done>`'s "read each hit; do not count them"
is exactly right. **But the plan instructs the executor to name
`backend/tests/test_no_run_research_route.py` in `CLAUDE.md` as proof the prohibition is
enforced — and half of that file is vacuously green.**

`test_no_run_research_route.py:44` forbids the bare token `research` in any live route path.
The app mounts **seven** `/research` paths (`research_routes.py:191, 249, 384, 528, 733, 793,
877`). The assertion should be RED. It is not, because **D-23.1-14** (CONTEXT § 11) measured that
under fastapi 0.141.1 `app.routes` holds 8 entries including lazy `_IncludedRouter` placeholders,
so a naive flat loop sees ZERO of the 65 real routes. Measured here:
`grep -c "_flatten_routes" backend/tests/test_no_run_research_route.py` → **0** — it uses exactly
the naive loop D-23.1-14 proved returns nothing.

Consequences, recorded as DEF-23.1-05:

- That test is not evidence of anything today. The prohibition is really carried by
  `ci_no_run_research.sh` (measured green), by `test_scope_guard_run_research.py` which exercises
  it in both directions, and by the source-scan test in the same file (which does bite).
- **When a future plan fixes route flattening — as D-23.1-14 requires of plans 10 and 11 — this
  test flips RED against the live, intended research router.** The correct fix is to drop the
  bare `research` token, NOT to unmount the router. That is precisely the failure mode
  D-23.1-10 exists to prevent, so it is written down now.

`CLAUDE.md` still names both tests, as instructed — the sentence claims the prohibition is
enforced by them, which is true of the guard script test and of the source scan. The vacuity is
recorded rather than silently repaired, because this plan changes no code.
