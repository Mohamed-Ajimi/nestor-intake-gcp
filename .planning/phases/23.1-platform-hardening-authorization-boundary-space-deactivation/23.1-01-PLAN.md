intake operator verbs (plan 23.1-10) and `ai_router` (plan 23.1-11) can depend on the SAME

`Depends(get_current_identity)` and no role gate. The fix must be ONE gate with ONE
convention and ONE test surface — per-route role comparisons are how the next audit finds
verb number ten.

Output: `backend/app/auth/gates.py` exporting `superadmin_gate`; `research_routes.py`
importing it instead of defining it; a unit test file proving the three outcomes and proving
that the research routes use the shared object rather than a copy of it.

## WHAT THIS PLAN MUST NOT DO

- **Do NOT change the gate's behaviour in any way.** 404 stays 404. The message string
  `"Intake not found"` stays byte-identical: `test_research_cross_tenant.py` asserts
  `str(intake_a) not in resp.text`, and other suites may assert the phrase. Behaviour-identical
  is the whole reason the existing denial suite can stay untouched (D-23.1-01).
- **Do NOT edit `backend/tests/test_research_cross_tenant.py`.** It is the regression proof.
  If it needs an edit, the promotion was not behaviour-identical and you have a defect, not a
  test problem.
- **Do NOT add a `require_role(...)` factory, a 403 variant, or a second gate.** D-23.1-01 is
  explicit: one gate, one convention, one test surface. `db/session.py:357`'s
  `get_admin_session` 403 is a DIFFERENT, pre-existing convention for the admin router where
  existence is not secret — leave it alone and do not unify the two.
- **Do NOT gate any route in this plan.** Applying the gate is 23.1-10 and 23.1-11.
</objective>
