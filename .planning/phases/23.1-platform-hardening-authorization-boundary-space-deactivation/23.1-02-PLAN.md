<objective>
Build the safety net BEFORE the gating lands. `23.1-CONTEXT.md` § 1 names this as "the single
most likely way this phase does damage": `IntakeForm.tsx:16` — the CLIENT form — reads
`GET /intakes/{id}/skill-runs` and `GET /intakes/{id}/skill-runs/{run_id}`, which render the

every type, lint, locale and i18n-audit gate still green.

Purpose: a denial suite proves what is CLOSED. Nothing in this repo proves what must stay
OPEN, and that asymmetry is exactly how an authorization phase breaks a product. This plan
writes the positive half, and proves the positive half actually bites.

Output: `backend/tests/test_client_surface_open.py` — one named test per client route
asserting a role=`user` caller gets a real 2xx, plus a route-inventory guard that fails when
a new route is added to `intake_router` without a decision about which side of the boundary
it belongs on.

## THE VACUITY PROBLEM, AND HOW THIS PLAN SOLVES IT

Every assertion in this file is GREEN AT HEAD. That is the point of a regression pin, but it
also means the file proves nothing on its own — a test that was always green cannot tell you
it would have caught anything. Task 2 closes that hole by MUTATION: apply
`Depends(superadmin_gate)` to one stay-open route, observe the suite go red, revert. Without
Task 2 this plan is decoration.

## WHAT THIS PLAN MUST NOT DO

- **Do NOT modify any application file.** `files_modified` is one test file. If a route needs
  changing to make a test pass, you have found a live defect — record it and stop, do not fix
  it here.
- **Do NOT gate anything.** That is 23.1-10 and 23.1-11.
- **Do NOT assert "not 404"** anywhere. `assert resp.status_code != 404` is green for a 500,
  a 403 and a 422 alike. Assert the EXACT expected status.
- **Do NOT leave the mutation from Task 2 committed.** Task 2's `<done>` requires a clean
  `git diff` over `backend/app/`.
