<objective>
Close the second half of D-23.1-04's cost/correctness pair: `ai/skills/context_pack.py:171`
calls `patch(intake_id, status="decomposed", ...)` UNCONDITIONALLY, so an intake in ANY status
becomes `decomposed`. `23.1-CONTEXT.md` § 3 names the pattern to copy — `/review` already has
an allow-list (`_next_review_status`, 409 otherwise) and it lives one directory away.

Purpose: `decomposed` is the scope ceiling and the gate the research trigger reads. A skill
run that can drag `delivered` or `in_research` backwards to `decomposed` can re-open a closed
intake and re-arm a paid research trigger. That is a lifecycle-corruption bug wearing a
cost-control hat.

Output: a `patch_if` conditional-update primitive on the tenant repository; a
`_CONTEXT_PACK_TRANSITIONS` allow-list in the skill; a refusal path that finalizes the run
`failed` with a readable sentence; and a test suite that proves each.

## PLANNING FINDING — THE ALLOW-LIST HAS EXACTLY ONE ENTRY, AND HERE IS THE DERIVATION

Do not guess this set and do not widen it "just in case". Traced through the UI at `047dcfe`:

- `frontend/src/components/intake/NextStepBanner.tsx:270-289` — the Generate-context-pack
  button renders in EXACTLY ONE phase, `awaiting_context_pack`.
- `frontend/src/lib/intake-phase.ts:55-58` — `awaiting_context_pack` is derived from
  `status === "validated_by_client" && !intake.context_pack_artifact_id`.

So the only status from which a human can legitimately launch this skill is
`validated_by_client`. **The allow-list is `{"validated_by_client": "decomposed"}` and nothing
else.** If you find a second caller during execution, add its status AND record the evidence
in the SUMMARY — do not add a status without a caller.

## PLANNING RULING — A REFUSED TRANSITION KEEPS THE ARTIFACT

D-23.1-05 pins the run outcome (`failed`, readable message, no orphan `running` row) but is
silent on the artifact. By the time `write_fn` runs, the Claude call has already been made and
paid for. Ruling: **still INSERT the `research_artifacts` row, do NOT link it onto the intake,
and name its id in the failed run's `output`.** Rationale: `GET /intakes/{id}/context-pack`
already returns `{latest, history}`, so this table is append-only history by design and an
unlinked row is a shape it already handles; discarding a paid generation to punish a status
mismatch costs money and teaches nobody anything. Record this ruling in the code comment so
the next reader does not "clean it up".

## WHAT THIS PLAN MUST NOT DO

- **Do NOT change `_REVIEW_TRANSITIONS`, `_SUBMIT_TRANSITIONS` or `_DELIVER_TRANSITIONS`** in

  the comparison.
- **Do NOT change the AI dedup path.** The `skill_runs` partial unique index is plan 23.1-12.
