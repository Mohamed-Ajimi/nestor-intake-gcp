## WHY THE GUARD FIX IS A MOVE, NOT AN EXCLUSION

`scripts/ci_no_raw_db_access.sh` excludes `app/db/` (the seam) plus `main.py` and
`session.py` by name, on the stated principle that "calling the seam's interface is the
allowed path, not a bypass". `get_engine_for_pool_check` (`run_task.py:240`) is exactly such a
call — a thin indirection so the pool-safety test can assert `engine.pool.checkedout() == 0`
against the SAME pool the real writes use. It is a db-seam concern that happens to live in a
research module.

**Fix: move it to `app/db/session.py` and import it back.** Do NOT add `run_task.py` to the
guard's exclusion list — that weakens a guard whose entire job is to stop a feature module
opening its own session, which is the inherited Supabase isolation hole this project exists to
make unrepeatable.

`backend/tests/test_research_run_task.py:303` and `:520` monkeypatch
`run_task.get_engine_for_pool_check`. That keeps working after the move, because
`monkeypatch.setattr(run_task, ...)` patches the name in `run_task`'s namespace and a
`from ... import` binds exactly that name. Verify it rather than assume it.
