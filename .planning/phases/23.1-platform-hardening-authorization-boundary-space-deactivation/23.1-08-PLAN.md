## ⚠ PLANNING FINDING — DROPPING rehype-raw HAS A VISIBLE CONSEQUENCE. DO NOT PRETEND OTHERWISE.

`BattlecardMarkdown.tsx:71-84` passes `rehypePlugins={[rehypeRaw]}` AND registers two custom
element handlers, `marker` and `conf`. Those handlers only ever fire because `rehype-raw`
turns the raw `<marker data-type="…">` / `<conf data-level="…">` tags in battlecard markdown
into real nodes. **Removing the plugin means the two badges stop rendering** — they will be
dropped or shown as text.

This is acceptable ONLY because the sole reachable caller is
`admin.sales.projects.$id.tsx:1081`, on the legacy Supabase path that CLAUDE.md records as
being retired and that is inert without `VITE_SUPABASE_*` (CONTEXT § 5 verified this).

**You must record this consequence in the SUMMARY and in `deferred-items.md`** as
DEF-23.1-01: "the sales battlecard's MarkerBadge / ConfidenceBadge no longer render; the
component is on the inert legacy Supabase path; if that path is ever revived, the badges need
a sanitiser-based reinstatement (`rehype-sanitize` with a schema allowing `marker`/`conf`),
not a plain `rehype-raw` restore." Do NOT silently drop the badges and call it hygiene, and do
NOT add a new sanitiser dependency in this phase — CONTEXT § 9 defers dependency work to its
own phase.

- **Do NOT remove `@react-pdf/renderer`.** `ContextPackPDF.tsx` still uses it.
- **Do NOT run `npm install`.** Memory of this repo: the lockfile IS committed; use `npm ci`
  to install and `npm uninstall` only for the one deliberate removal below.
