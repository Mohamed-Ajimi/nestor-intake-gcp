# Phase 23.1 Plan 01: Shared Superadmin Gate Summary

Promoted `_superadmin_gate` from a private function inside `research_routes.py` into
`app/auth/gates.py` as the backend's single superadmin gate object, behaviour-identical
(existence-hidden 404, byte-exact `"Intake not found"`), with all nine `Depends` sites
re-pointed via an alias so the pre-existing denial suite passed unedited at 35.

## What was built

**`backend/app/auth/gates.py`** — one public callable, `superadmin_gate`, moved verbatim:
same condition, same `status.HTTP_404_NOT_FOUND`, same detail string, same `-> Identity`
return. No DB symbol, no settings lookup, no logging, no audit write. Its docstring carries
the original two rationale paragraphs across and adds the three required by the plan: why it
lives here (D-23.1-01), the ordering contract restated as a rule for future callers, and why
it is 404 while `db/session.py`'s `get_admin_session` is deliberately still 403.

**`backend/app/api/research_routes.py`** — the local `def` is gone; a module-top
`from app.auth.gates import superadmin_gate as _superadmin_gate` replaces it, above every
`Depends` default. A pointer comment at the former def site names D-23.1-01 and keeps the
ordering rule visible to anyone grepping this file for the 404.

**`backend/tests/test_superadmin_gate.py`** — 10 named tests, non-integration, no
TestClient, no container; runs in ~1.1s standalone.

## Deviations from Plan

### 1. [Rule 4, resolved by CONTEXT] The plan's grep-based criterion is false and was not pursued

**Found during:** Task 2, before making any edit.

**Issue:** The plan asserts as a success criterion that
`grep -rn 'role != "superadmin"' backend/app/ --include='*.py'` returns **exactly one** line
in `gates.py`, and Task 2 instructs a test asserting that substring appears **nowhere** in
`research_routes.py`. Measured at the base commit, that string occurs **14 times across 3
files**: 13 in `research_routes.py` (the gate itself, **nine in-body defense-in-depth
re-checks**, and three docstring mentions) and one in `db/session.py:357`.

The planner appears to have believed the gate's own comparison was the only occurrence. It
is not. The nine in-body re-checks are a documented second wall behind the gate — the
module's own docstrings label them "Open Q2 defense-in-depth" — and `db/session.py:357` is
the `get_admin_session` 403 the plan **explicitly orders left alone**.

**Resolution:** Satisfying the criterion literally would mean deleting nine security
re-checks inside a plan whose stated premise is *"Do NOT change the gate's behaviour in any
way"* and *"Do NOT gate any route in this plan"*, and whose own `<done>` predicts a two-line
diff. `23.1-CONTEXT.md` is the authority and D-23.1-01's operative sentence is *"Behaviour
identical (existence-hidden 404) so its existing denial suite stays green untouched"*; its
"NO per-route role-comparison copies" clause targets a second gate **definition**, not
defense-in-depth assertions behind the gate.

**What was done instead:** `test_research_routes_defines_no_gate_of_its_own` asserts
`"def _superadmin_gate"` is absent from that one file — non-vacuous (it was present at the
base commit), scoped to the single file, and testing what D-23.1-01 actually forbids. The
test's docstring records the substitution and why, so no future reader re-derives it.

**Not fixed, deliberately:** the nine in-body re-checks and `get_admin_session`'s 403 are
untouched. **Downstream plans 23.1-10 and 23.1-11 must not inherit the grep criterion.**

### 2. [Rule 1 - Stale comment] The route-ordering comment's rationale moved out of the file

**Found during:** Task 2. **Files:** `backend/app/api/research_routes.py`. **Commit:** `ef1d541`.

The comment above `locate_research_run` justified that route's position with *"It sits
directly beneath `_superadmin_gate` because a `Depends` default is evaluated at def time."*
Once the `def` left the module that sentence asserts a constraint that no longer exists.
Rewritten to say the module-top import satisfies it now and only the ROUTE order still
binds. No code change.

### 3. [Rule 2 - Missing critical coverage] The ordering contract had no test

**Found during:** Task 2. **Commit:** `ef1d541`.

The plan's `must_haves` include *"The gate denies a null-space user with EXACTLY 404 — it
must win over `get_tenant_repo`'s null-space 403"*, and the **mechanism** for that is purely
declaration order in each handler signature. Nothing pinned it — it lived only in prose, and
moving a function is precisely when such a property is lost.

Added `test_every_gated_research_route_resolves_the_gate_before_the_repo`, which introspects
the live `research_router` and asserts `gate_pos < repo_pos` for every route depending on the
gate, with a `checked == 9` guard so the test cannot go vacuous. All 9 pass.

### 4. [Cosmetic criterion missed, knowingly] `research_routes.py` diffstat is +20/-19, not a net deletion

Task 2's `<done>` predicts a net line **deletion**. Actual: **+20/-19, net +1**. Code lines
are a net deletion of four (17 lines of `def` + docstring removed, 1 import line added); the
remainder is the pointer comment preserving the ordering explanation at the former def site,
which was required over the plan's bare "two-line comment". The stronger constraint was
preferred; the criterion measured line count, not the property it stood for.
