3. `settledSeqs(events: ReadonlyArray<Pick<RunEvent, "seq" | "kind">>): Set<number>` — the
   POSITIONAL PAIRING RULE, and the only place it is written down. Walk the group's events in
   order holding a FIFO list of the `seq` values of `agent_run` rows seen and not yet paired.
   On each event whose `kind` is in `AGENT_TERMINAL_KINDS`, shift the OLDEST unpaired `seq` off
   that list and add it to the returned set. A terminal row arriving with nothing unpaired is
   ignored — never a thrown error and never a fabricated seq.
   The docstring must state the mechanism honestly: D-07 measured that there is NO correlation
   key, so this reproduces the CONVENTION the engine already follows (start rows and finish
   rows appear in matching order within a stage) rather than reading an identifier that does
   not exist. It must also state the two degradations: more terminals than starts settles
   nothing extra, and fewer terminals than starts leaves the NEWEST rows unsettled, which is
   the correct direction to fail.

4. `isRowLive(input: { kind: string; seq: number; settled: ReadonlySet<number>; isLastGroup: boolean; feedActive: boolean }): boolean` —
   returns true only when ALL FOUR of these hold: `kind === "agent_run"`, `feedActive` is true,
   `isLastGroup` is true, and `settled.has(seq)` is false. Written as a single conjunction so
   no branch can be added later that grants liveness on three of four.
   The docstring must state the three conditions in the operator's terms: a run that has ENDED
   has no live rows at all; a phase the engine has MOVED PAST has no live rows; and a row whose
   finish line has already arrived is not live.

5. `hasHiddenRows(bodyLength: number, previewRows: number = COLLAPSED_PREVIEW_ROWS): boolean` —
   returns `bodyLength > previewRows`. Docstring states D-09's mechanism: `body` excludes
   dividers and summaries, so a phase whose only events are its divider and its summary has an
   empty `body` and a toggle over it expands to reveal nothing.

No default export. Named exports only, per the repo convention in `frontend/CLAUDE.md`
conventions ("Named exports preferred").
