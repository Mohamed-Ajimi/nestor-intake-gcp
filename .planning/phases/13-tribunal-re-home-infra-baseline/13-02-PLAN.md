<interfaces>
The worker's existing SKIP-LOCKED claim (from tribunal/nestor_pulse_sdk/runs/worker.py — the advisory
lock WRAPS this claim, it does not replace it). CLAIM_SQL returns:
  RETURNING id, tenant_id, project_id, engine, brief

execute_run(claimed: dict) is the existing dispatch+execute function in worker.py. It:
  1. dispatch_runner(claimed["engine"]) -> runner
  2. runner.run(brief=, run_id=, tenant_id=)
  3. set_tenant_context(session, claimed["tenant_id"]) BEFORE any tenant-scoped write (T-06-02 ordering)
  4. UPDATE run SET status='completed'|'failed'|'needs_input'|'needs_report_spec'

The advisory-lock primitive (plan 01-19 KEYSTONE, verbatim SQL — RESEARCH §Pattern 2):
  SELECT pg_advisory_xact_lock(('x' || md5(:run_id))::bit(64)::bigint);
  -- 64-bit key: NOT hashtext (that's int4, ~50% birthday collision at ~65k runs)
  -- After acquiring: re-check the run is still claimable:
  --   claimable  = status='queued' OR (status='running' AND started_at stale)
  --   NOT claimable = needs_input, needs_report_spec, cancelled, completed, failed
  -- If not claimable after the lock, skip (another executor already finished it) — exactly-once.

set_tenant_context (tribunal/nestor_pulse_sdk/db/rls.py) sets the `app.tenant_id` GUC via SET LOCAL —
call it immediately after the claim, before the pipeline runs (never before the claim).
