## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| new frontend origin → backend/API + storage | a new public origin must be added to CORS allowlists (never `*`) |
| deploy operator → live GCP config | user-run gcloud/Console changes mutate live auth/CORS surfaces |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-10 | Tampering / Info Disclosure | CORS on the new origin | mitigate | Runbook adds EXACTLY the captured run.app origin to `CORS_ALLOWED_ORIGINS` + GET-only bucket CORS — never `*`, never a guessed URL (Task 2, Pitfall 4). |
| T-12-11 | Spoofing | Firebase authorized domains | mitigate | Runbook adds only the run.app host to Identity Platform authorized domains (Console manual step) so auth redirects are not rejected and no wildcard domain is trusted (Task 2). |
| T-12-12 | Elevation of Privilege | public frontend service | accept | The frontend gets an `allUsers` run.invoker (public web app); it is SSR-only and does NOT proxy the API — the browser calls nestor-api directly with its own verified token. Documented in the runbook + tf (Task 1, A6). |
| T-12-13 | Tampering | stale backend image at catch-up | mitigate | Runbook Step 12.1 mandates a Cloud Build image REBUILD (jinja2/httpx) before flipping env/secrets (Pitfall 3) — no config-only deploy (Task 2). |
| T-12-14 | Info Disclosure | legacy Supabase project | mitigate | Explicit D-08 note: NO Supabase-side actions in the runbook; independence proven code-side, not by teardown (Task 2). |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (IaC + doc only). Per 12-RESEARCH this phase installs nothing new; no slopcheck checkpoint required. |
