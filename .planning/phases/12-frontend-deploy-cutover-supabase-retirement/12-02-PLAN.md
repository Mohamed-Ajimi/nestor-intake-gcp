## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-args → bundle | `VITE_*` build-args are inlined into the public JS bundle at build time |
| container → Cloud Run | The runtime image serves untrusted browser traffic on $PORT |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-03 | Information Disclosure | Docker build-args | mitigate | Only PUBLIC config baked (Firebase web apiKey is a public identifier; API base URL is public). NO Supabase vars, NO Secret-Manager secrets in build-args (Task 2). |
| T-12-04 | Information Disclosure | `.output/` bundle | mitigate | The build stage runs the D-11 guard (`ci_no_supabase_in_bundle.sh .output`) — the image fails to build if a Supabase signature leaked (Task 2). |
| T-12-05 | Tampering | stale build context | mitigate | `.dockerignore` excludes the local `.output` (stale cloudflare preset) so the image always contains a fresh node-server build (Task 2). |
| T-12-06 | Info Disclosure | dead Supabase code path | mitigate | Sales code retained but inert: `VITE_SUPABASE_*` never set → `supabase.ts` client is null → sales routes render no data / make no calls (D-09, Task 3). |
| T-12-SC | Tampering | npm/pip/cargo installs | accept | No NEW package installed; `npm ci` restores the already-audited committed lockfile. Per 12-RESEARCH this phase installs nothing new; no slopcheck checkpoint required. |
</threat_model>
