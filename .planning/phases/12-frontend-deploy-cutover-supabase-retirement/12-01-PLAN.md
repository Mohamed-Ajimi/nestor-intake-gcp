    Create the D-11 bundle guard mirroring the two existing guard scripts. Requirements:
    - `#!/usr/bin/env bash` + `set -euo pipefail`.
    - `SCAN_DIR="${1:-.output}"` (default `.output`, overridable so the self-test can point at a temp dir).
    - Missing scan dir → print to stderr and `exit 2`.
    - PATTERN detecting Supabase signatures: `supabase\.co|VITE_SUPABASE|"role":"anon"|eyJhbGciOi`.
    - Scan with `grep -rEn "$PATTERN" "$SCAN_DIR"`; if grep matches (offender present) print an
      `ERROR: Supabase signature found ... INFRA-05/D-11 violation` to stderr and `exit 1`; else
      print `OK: no Supabase signature in $SCAN_DIR.` and `exit 0`. The exit code IS the gate — do
      NOT use `grep -c ... == 0`.
    - Add a `--self-test` branch (before the main scan) copying the ci_no_hardcoded_dutch.sh harness:
      `mktemp -d` with an EXIT trap `rm -rf`, plant `printf 'const x = "https://xyz.supabase.co";\n'`
      into a file under the temp dir, re-invoke `bash "${BASH_SOURCE[0]}" "$TMP_DIR"` capturing rc via
      `|| rc=$?`, and FAIL the self-test (exit 1) if rc == 0, else print `SELF-TEST OK ...` and exit 0.
    - Make the file executable (chmod +x, or note in the summary that the Dockerfile invokes it via `sh`).
  </action>
  <verify>
    <automated>cd frontend && bash scripts/ci_no_supabase_in_bundle.sh --self-test</automated>
  </verify>
  <acceptance_criteria>

    - Running the guard against a temp dir with only benign content exits 0 and prints `OK: no Supabase signature`.
    - Running the guard against a non-existent path exits 2.
    - The script contains the literal token `ci_no_supabase_in_bundle` (in comment/usage) and the PATTERN alternation `VITE_SUPABASE`.
    - Grep confirms the gate does NOT use `grep -c` on an unfiltered `== 0` comparison.
