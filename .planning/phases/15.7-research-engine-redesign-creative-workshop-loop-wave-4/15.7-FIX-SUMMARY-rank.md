## CR-02 — clustering ran before indices were stamped

**Files:** `workshop_rank.py` (the loop, step 5b/5c), `workshop.py` (`cluster_candidates` bucket key).

**What changed — both halves:**

1. `workshop_rank.py`: `_stamp_loop_candidates` moved **above** the `cluster_candidates` call. The
   clusterer is now handed `stamped` and returns into `stamped`; the old post-cluster stamp and the
   `new_candidates = mutations` hand-off are gone. `next_index` advances by the number **stamped**,
   before clustering, so an index consumed by a candidate the clusterer merged or the register
   dropped is *burned* and never reissued — `merged_from` records those indices.
2. `workshop.py:2387`: the bucket key no longer trusts `candidate.get("index", position)`. A missing,
   unparseable **or negative** index now falls back to `__unstamped__:{chunk_index}:{position}`.

**Deviation from the instruction, stated:** the review says "add a `position` fallback". A bare
`position` is not safe — it collides with a real positive `index` of the same number carried by
another candidate, and positions repeat across chunks, so it would trade one silent deletion for a
different one. The `__unstamped__` namespace cannot collide with `__singleton__` by construction, so
every unstamped candidate is guaranteed a bucket of its own. That is the intent of the instruction,
implemented so it actually holds.

**Bookkeeping checked, as instructed:** `next_index += len(stamped)` now counts pre-cluster stamps
(monotonic, strictly no reuse — strictly safer than before). `population = population + stamped` at
the end of the round is unchanged and still appends the post-cluster survivors.
`round_metrics(new_candidates=len(stamped))` still reports the post-cluster count, as it did before.

## CR-03 — an admitted invented angle was re-bought and duplicated every round

**File:** `workshop_rank.py` only.

**What changed — two guards, both structural:**

1. **A pre-lookup gate, ABOVE the spend** (loop step 5a). Before `admit_invented_angles` is called,
   `invented` is filtered against the texts of every angle already admitted this run **and** against
   every key already in `register["barred"]`. Identity is `workshop_register._key` — the run's one

   can never disagree. Suppression emits a NOTE (D-12), never a degradation.
2. **A Rule-5 text dedup in `_fill_remaining_discovery_slots`**, keyed on the composed question text
   (`discovery_bracket._norm(...).casefold()`), checked against `already` and against what this call
   has already taken. Keyed on text and not on Rule 5's `(parent, assumption, world_says)` because
   `_conflict_from_admitted` writes the INVENT move's own text instead of composing one through
   `discovery_question_text`'s frame — the triple is not this shape's identity. Case-folding is
   stricter than Rule 5 on purpose: a duplicate dropped costs one slot occupant, a duplicate that
   gets through costs a whole paid research question.

`discovery_bracket` was not modified.

### CONTRADICTION 2 — I did NOT record the admitted angle in the register, and I think that is right

The instruction says *"prefer recording it in the register (the mechanism `evolve_generative`
already reads via `barred_block`) so the prompt layer suppresses re-proposal."* I did not, for three
reasons, and I am flagging rather than silently choosing:

1. **`workshop_register.py` is outside my assigned files** (`workshop_rank.py` + one edit in
   `workshop.py`), and `bar()` accepts exactly three causes. None of them fits: `BAR_LOOKUP_FAILED`
   means *"the grounded lookup admitted nothing"*, which is the **opposite** of what happened, and
   it is the string that reaches the model as the entry's `flaw`. Using it would put a false
   diagnosis into a prompt on an EU-AI-Act-audited path.
2. **The module explicitly forbids a fourth cause**, at length: *"Do not 'complete' the set later: a
   fourth member would move the guarantee from impossible to nobody has done it yet."* Adding
   `BAR_ALREADY_ADMITTED` is an operator decision, not a fix.
3. **You cannot have the prompt layer alone.** `barred_block` and `_barred_shadows` read the *same*
   `register["barred"]` list, so anything put there to suppress a re-proposal in the prompt
   **automatically becomes a clustering shadow**. A later SPECIALISE of a live mandate candidate that
   clustered near the admitted discovery question would then be **dropped** — mandate work
   suppressed because a discovery question exists. That is the "over-eager dedup strangles
   discovery" failure the register's own docstring warns about, inverted. The instruction's premise
   that the register buys only the prompt layer does not hold in this code.

**What my gate buys instead, and it is strictly more:** it stops the spend *before* it happens
rather than asking a model nicely afterwards — which is exactly what `barred_block`'s own docstring
demands (*"THE PROMPT LAYER ALONE WILL NOT HOLD. A model asked nicely is not a control."*).

**A sixth defect found while doing this, and my gate closes it too:** the review says the register
is *"closed for the half that fails"* — i.e. `BAR_LOOKUP_FAILED` protects dropped inventions. It
does not, structurally. The bar's *enforcing* layer is the semantic drop inside
`cluster_candidates`, and **the INVENT path never goes through `cluster_candidates`** (invented
angles are split out at `:4082` before the cluster call). So a dropped-and-barred angle was also
protected by the prompt alone. My gate checks the barred keys as well, so both halves now have a
structural guard.

**What is NOT closed, stated plainly:** a **reworded** re-invention. String identity cannot catch
one and the semantic layer is not on this path. Closing it means routing INVENT through the
semantic drop — the standing warning at `workshop_rank.py:4159`, a separate change with its own
cost (one more clustering call per round). My gate is the exact-text floor beneath it.

## CR-05 — `BAR_WEAK_TWICE` barred a candidate that stayed live

**File:** `workshop_rank.py` only.

**What changed:** a new pure helper `_pool_after_bars(population, *, barred_keys, client_questions,
key_of)` plus one call site in the loop, placed **after** the exit check and **before**
`population = population + stamped`.

**Which list is filtered, which is not — stated in the helper's docstring and in the call site, as
instructed:**

| list | filtered? | why |
|---|---|---|
| `population` | **YES**, between rounds only | it is the pool the next round critiques, ranks and selects from — the only place where "removed" means what the bar says |
| `ranked` | **NO** | `enforce_scope_guard` runs after the loop over the **full** final ranked list; its repair ladder PROMOTES a below-the-cut candidate before injecting a client question verbatim. Filtering `ranked` would make a loser unpromotable and silently break coverage (T-15.7-09-02) |
| `selected` / winners | **NO** | same reason, one step later |

Placement is after the exit check so a round that has already ranked and selected is never rewritten
underneath itself; a barred candidate still in the pool for the final round therefore still appears
in `ranked` and stays promotable. **The bar shrinks the pool going forward; it never reaches back
into a ranking that already happened.**

**Coverage outranks the bar.** A barred candidate is KEPT when dropping it would leave a client
question with nothing in the pool. Same rule and same failure direction as `critique_candidates`'
Guard 1. The rescue pass runs in population order and updates its own coverage set, so exactly one
barred candidate is rescued per otherwise-uncovered question, never all of them. There is also a
Guard-2-shaped floor: if everything is barred and nothing is rescuable, the whole population is
kept — an empty pool is a bookkeeping failure, never a correct answer.

## Name resolution — the claim the lift cannot make

`nameresolve.py` walks the AST, collects every name **bound** anywhere in the file (imports, defs,
classes, assignments, `for`/`with`/`except` targets, parameters, comprehension targets, walrus,
`global`/`nonlocal`) plus builtins, and reports every `Name`-load bound nowhere. It executes nothing.

| file | result |
|---|---|
| `workshop_rank.py` | OK — every `Name`-load is bound somewhere |
| `workshop.py` | OK |
| `workshop_admission.py` (current) | OK |
| **`workshop_admission.py` at `151bb45` (pre-CR-01)** | **UNRESOLVED: `DISCOVERY_PARENT` lines `[792, 812, 888, 965]`** |

That last row is the instrument's non-vacuity proof: it reproduces CR-01 exactly, at the four line
numbers the review cites, on a file it was not written against.

**Its limit, stated:** it over-approximates — a name bound in one function and read in another is
accepted — so it cannot catch a *scope* error. It catches exactly the CR-01 shape: a name that
exists in no binding position at all.
