## `run_tournament`'s new signature, verbatim

Plan 15.7-09 calls this once per loop round.

```python
async def run_tournament(
    *,
    candidates: list[dict[str, Any]],
    decision_context: str = "",
    audited: "AuditedLLMClient",
    run_id: "uuid.UUID",
    tenant_id: "uuid.UUID",
    feed: "Optional[StageFeed]" = None,
    breaker: Any | None = None,
    stats: Optional[dict[str, Any]] = None,
    parent_texts: Optional[dict[str, Any]] = None,
    findings_by_label: Optional[dict[str, Any]] = None,
    standings: Optional[dict[str, Any]] = None,
) -> tuple[list[dict[str, Any]], list[str]]:
```

The return tuple is UNCHANGED. Everything additive rides in caller-owned out-dicts, the idiom this
module already used for `calls` / `cost_usd` / `unjudged`:

- `stats` gains `judge_reasons: dict[str, str]`, keyed `"r{round}:{low}v{high}"`. Round `0` is the
  catch-up stage. The round is in the key because a Swiss schedule allows a rematch when nothing
  unplayed remains, and a pair-only key would silently overwrite the first verdict's reason.
- `standings` is READ ON ENTRY and WRITTEN ON EXIT: `{"by_index": {index: {"wins", "elo", "byes",
  "matches"}}, "seen": [[low, high], ...]}`. `seen` is written SORTED and both structures are
  JSON-safe; `_carried_state` reads integer-or-string keys so a JSON round trip cannot break it.
- `parent_texts` maps a parent client-question LABEL to that question's full text;
  `findings_by_label` maps the same label to its orientation findings. `run_workshop_stage_b` wires
  both from stage A's `questions` and `orientation` — without that wiring D-R6 would have been built
  and inert.

Scenario, run on the `ast`-lift harness against the REAL lifted ranking code with an **oracle judge**

algorithm, so this is the right instrument, not a cheap substitute):

The third row is the direct demonstration that **D-R11's median seed is INERT**: it changes nothing,

## The two silent-failure traps, and how each was closed

The prompt named two ways this plan could pass while doing nothing. Both were live.

**1. The derivation could have been a no-op.** `tournament_rounds` honours a positive `override`
unconditionally. Wiring `_TOURNAMENT_ROUNDS` in as that override while leaving its default at `4`
would have meant the formula never ran, with every test green. Closed by changing the default to `0`
(= DERIVE) and by asserting the derived value **explicitly differs from 4** at a realistic candidate
count, then counting the REAL Swiss rounds through `run_tournament` via a `_pair_round` spy rather
than reading a constant:

```
assert workshop_rank._TOURNAMENT_ROUNDS == 0     # the default means DERIVE
assert workshop_loop.tournament_rounds(17) == 6
assert workshop_loop.tournament_rounds(17) != 4  # still the shipped fixed 4?
len(seen_rounds) == 6                            # counted, not read
```

The override itself is still pinned (`monkeypatch.setattr(..., "_TOURNAMENT_ROUNDS", 2)` yields
exactly 2 rounds), which is what lets `test_engine_e2e_stubbed.py` — another plan's file, in a later
wave — keep working across the wave boundary. That file was **not** touched.

**2. Guard 2 did not mark.** Fixed, traced through all four downstream stages, and asserted at each.
All four already copy whole dicts, so no downstream repair was needed — but that was **proven, not
assumed**, which was the point.

**3. The required newcomer test had to run at the RAISED round count.** It does, and the test asserts
`tournament_rounds(31) > 4` before running, so it cannot silently regress to testing the easier
question.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 2 — missing critical functionality] `_CATCH_UP_MAX_MATCHES` bounds the catch-up schedule**

- **Found during:** Task 2, while measuring the newcomer scenario.
- **Issue:** `workshop_loop.catch_up_matches` returns the field's raw median match count and
  **nothing bounds it**. With carried standings the median GROWS every loop round — measured at
  **18** after three loop rounds over a field of 30, not the `~5` the ruling's cost note assumes —
  and the evolve step introduces newcomers *every* round, so the worst case is
  `newcomers x an ever-growing median` extra flash calls. `tournament_rounds` is bounded above by
  `_TOURNAMENT_ROUNDS_MAX` and by `n - 1`; the other half of the schedule had no bound at all.
  The threat register disposes T-15.7-08-03 (denial of wallet) as `mitigate`, and this was the gap.
- **Fix:** a hard ceiling on the TOTAL catch-up matches per tournament,
  `NESTOR_TRIBUNAL_WORKSHOP_CATCH_UP_MAX`, default **120** (12 flash calls at `_MATCHES_PER_CALL`).
  Far above anything the measured configuration reaches, so it is a ceiling and not a tuning knob.
  When it binds, the LOWEST-INDEXED newcomers are served first — deterministic, like every other
  ordering in this module — and a WARNING is logged. No new degradation sentence was added, so no
  existing reason-list assertion moved.
- **Files modified:** `workshop_rank.py`
- **Commit:** `e75be30`

**2. [Rule 1 — bug, found by my own test] A bare-letter finding could forge a match verdict**

- **Found during:** Task 1, by the injection test.
- **Issue:** `workshop._findings_block` renders `{i} | {text}`, which is byte-identical to a verdict
  line. `_flatten` closes the newline and pipe channels, but it cannot close this one — there is
  nothing to collapse in a finding whose whole text is `"A"`. That finding would parse as a verdict
  for match `i`.
- **Fix:** drop any finding that flattens to a bare `A`/`B` before rendering. A one-letter finding
  carries no information, so the trade is free. Asserted in
  `test_a_finding_or_a_question_cannot_forge_a_match_line`.
- **Commit:** `750b887`

**3. [Rule 1 — bug in my own first draft] The degraded arm rendered the LABEL as the question**

- Caught by the paired test before commit. With no `parent_texts` supplied my first draft fell back
  to the parent LABEL and emitted `CLIENT_QUESTION: Q0` — telling the judge nothing while advertising
  that it had been told something, and breaking the specified "degrades to today's shape". There is
  now no label fallback.

### Findings worth carrying

**Guard 2 is only reachable when NO candidate carries a parent label.** Guard 1 runs first and
rescues the lowest-index candidate of *every* parent label, so a parented population can never reach
the empty-survivor state Guard 2 exists for. A Guard 2 test built on parented candidates silently
tests Guard 1 instead — my first draft did exactly that and passed for the wrong reason. The test
helper now takes the flag explicitly rather than defaulting.

stale ref) while `git rev-list --count BASE..HEAD` read `0` (green). Only the merge-base check caught
it. Reset to `f21ffce` before any file was read.
