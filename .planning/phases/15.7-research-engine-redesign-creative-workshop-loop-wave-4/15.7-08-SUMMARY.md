# Phase 15.7 Plan 08: Judges That Reason, Rounds That Follow The Field, And A Guard That Marks — Summary

Rebuilt `workshop_rank.py`'s tournament half against `workshop_loop.py`'s pure arithmetic: the judge
now states one clause of reasoning and can see the client question it is judging for, the Swiss round
count is derived from the candidate count instead of frozen at 4, a newcomer plays the matches it
missed rather than being seeded at a median Elo that is provably inert, and Guard 2 marks what it
rescues so a blanket critique rescue can no longer read as a perfect quality pass.

## `run_tournament`'s new signature, verbatim

Plan 15.7-09 calls this once per loop round.

```python
async def run_tournament(
    *,
    candidates: list[dict[str, Any]],
    decision_context: str = "",
    audited: "AuditedLLMClient",
    run_id: "uuid.UUID",
    tenant_id: "uuid.UUID",
    feed: "Optional[StageFeed]" = None,
    breaker: Any | None = None,
    stats: Optional[dict[str, Any]] = None,
    parent_texts: Optional[dict[str, Any]] = None,
    findings_by_label: Optional[dict[str, Any]] = None,
    standings: Optional[dict[str, Any]] = None,
) -> tuple[list[dict[str, Any]], list[str]]:
```

The return tuple is UNCHANGED. Everything additive rides in caller-owned out-dicts, the idiom this
module already used for `calls` / `cost_usd` / `unjudged`:

- `stats` gains `judge_reasons: dict[str, str]`, keyed `"r{round}:{low}v{high}"`. Round `0` is the
  catch-up stage. The round is in the key because a Swiss schedule allows a rematch when nothing
  unplayed remains, and a pair-only key would silently overwrite the first verdict's reason.
- `standings` is READ ON ENTRY and WRITTEN ON EXIT: `{"by_index": {index: {"wins", "elo", "byes",
  "matches"}}, "seen": [[low, high], ...]}`. `seen` is written SORTED and both structures are
  JSON-safe; `_carried_state` reads integer-or-string keys so a JSON round trip cannot break it.
- `parent_texts` maps a parent client-question LABEL to that question's full text;
  `findings_by_label` maps the same label to its orientation findings. `run_workshop_stage_b` wires
  both from stage A's `questions` and `orientation` — without that wiring D-R6 would have been built
  and inert.

## The measured newcomer rate, with its seed count

Scenario, run on the `ast`-lift harness against the REAL lifted ranking code with an **oracle judge**
(deterministic, zero LLM calls, zero spend — the newcomer property is a question about the ranking
algorithm, so this is the right instrument, not a cheap substitute):

- field of 30 incumbents with shuffled hidden strengths, **3 prior loop rounds** of carried standings
  (`run_tournament` is called once per loop round, so this *is* "introduced in a late round"),
- then one newcomer joins that is strictly the strongest question in the field,
- derived round count for the 31-candidate field: **6** (not 4 — asserted directly),
- top N = `winner_count(31)` = **11**.

| Configuration | Reaches top N | Seeds | Best/worst observed rank |
| ------------- | ------------- | ----- | ------------------------ |
| catch-up schedule, sort UNCHANGED | **200/200** | 200 | worst rank 1 |
| no catch-up (the falsifying column) | **0/200** | 200 | best rank 27 |
| median-Elo SEED instead, no catch-up (D-R11 exactly as ruled) | **0/200** | 200 | best rank 27 |

The third row is the direct demonstration that **D-R11's median seed is INERT**: it changes nothing,
because the standing sorts `(-wins, -elo, index)` with wins primary and Elo only the tie-break. The
fix is the SCHEDULE, not the sort, and `_pair_round` and `_apply_elo` are byte-identical to the phase
base (verified by AST unparse against `f21ffce`).

The committed pytest tests parametrise **8 seeds** of the same scenario for CI time, in both the
passing and the falsifying direction (`test_a_strong_late_newcomer_still_reaches_the_top_n` and
`test_the_same_newcomer_fails_without_the_catch_up`).
