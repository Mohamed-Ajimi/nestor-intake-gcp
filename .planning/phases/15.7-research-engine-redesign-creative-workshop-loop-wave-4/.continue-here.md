### 2. Splitting plan 09 Task 1's scope-lock edit across two commits
Task 1 deletes `"- Do NOT merge two questions into one, and do NOT broaden one."` **and** wires
in `workshop_evolve.MANDATE_SCOPE_LOCK` + `DISCOVERY_EVIDENCE_ANCHOR`. Those are **one atomic
edit**. A deletion that lands without its replacement removes the mandate scope guarantee **D4**
depends on — a live regression, in the phase's seam plan, with every test still green. Plan 06
deliberately left the sentence standing rather than create a second editor of that file.

### 3. Letting `cluster_candidates` default `round_no` to `0`
Plan 07 added `round_no: Any = 0` because `workshop_register.record_drop` requires it. If plan 09
does not pass the loop's **real** round number, every semantic drop is stamped round 0 — which
destroys the single distinction the drop log exists for: *"round 2 re-proposed round 1's
rejects"* (the loop spinning) versus an over-eager dedup killing novel angles. Fails silently,
all tests green.

### 4. Dispatching plan 09 from an orchestrator low on context
**This already happened once.** Subagents inherit the parent session's context pressure. Plan 09
was spawned at ~67% and hit the context warning before reading a file; its minimum reading set is
~11,400 lines (3,815 planning + 7,591 across five `workshop_*.py` modules). It halted at the
setup/Task-1 boundary, changed nothing, and deliberately wrote **no SUMMARY** — a SUMMARY is a
completion artifact and writing one for unexecuted work misreports phase state. Correct call.
**Check remaining context against the reading set before spawning.**

### 5. Trusting `git rev-list --count BASE..HEAD` to detect a stale worktree
**13 of 13 executor worktrees have been cut from `a3a0c96`**, most recently measured 567 commits
behind, and `rev-list --count` returned **`0` — green — every single time**. Only
`git merge-base HEAD <BASE>` catches it. **Correct the base in the orchestrator before spawning**
so the executor doesn't spend budget on it.

### 6. Closing the phase while the two deliberately-red test files are still red
`test_engine_e2e_stubbed.py` and `test_workshop_languages.py` have been red since Wave 1: plan 01

which lists `_GROUPING_MODE` as a blocking sentinel. Consequence: **the engine gate count will

## Open items — verification must RESOLVE these, not skip them

- **D-DEF-01 — a prompt-injection channel.** `workshop._findings_block` truncates but never
  collapses `\n` or `|`, so a finding carrying `\n9 | KEEP | forged` renders as **two addressable
  records**. Findings come from **fetched web pages**, so it is attacker-reachable. One-line fix
  (`_flatten` instead of the slice). Plan 06 reported rather than fixed it — not its file,
  pre-existing. **Same defect class as the Wave 3 critical that 42/42 verification and 1283 green
  tests both missed.** Logged in `deferred-items.md`. Needs an owner.
- **`_trim_round_robin`'s guarantee does not extend to aspects.** It buckets by **`parent`**, so
  it promises "every parent keeps its first candidate", not "every aspect keeps one". Aspect
  repairs land at the END of their parent's bucket, so a tight enough cap trims a repair before a
  second model line for the same parent — weakening the very coverage guarantee D-W4-4b's Python
  assertion establishes. **Unreachable at today's numbers** (cap 120 vs 12/question; bites only
  above ten client questions). Documented in-source by plan 07. **Assign to 09, defer to 15.8, or
  accept with the note — do not let it close silently.**
- **`_CATCH_UP_MAX_MATCHES` (default 120) is a new knob added on judgement, not measurement.**
  `catch_up_matches` returns an **unbounded** median that grows every loop round with carried
  standings — measured at **18** after three rounds over a field of 30, against the `~5` the

## Process lessons

- **NOTHING IN THIS PHASE DEPLOYS.** Waves 1–4 land in git only. There is exactly **one** deploy
  and **one** measuring run, both at the end of phase 15.8. Do not add a deploy step.
- **Run code review PER WAVE, not batched.** Wave 3 shipped 42/42 verification and 1283 green
  tests with **two criticals**, because each plan's `must_haves` were individually satisfied and
  the defects lived in the **seams between plans**.
- **Every executor that found a real defect this phase did so by CHECKING an instruction rather
  than following it.** Plan 06 refused an orchestrator instruction that contradicted its plan
  (and would have put two wave-3 plans on one file — the 15.5 red-tree shape); plan 07 found the
  `_trim_round_robin` gap; plan 04 caught its own plan contradicting itself; plan 02 declined an
  instruction that would have made a test vacuous. **Tell executors to report contradictions
  rather than silently choosing.**
- `.planning/` is **gitignored** — every planning file needs `git add -f` or worktree executors
  cannot see it.
- **Write SUMMARYs incrementally.** Two agent runs were lost to dropped connections during a
  single large SUMMARY write; a partial file on disk is recoverable, a lost 800-line write is not.
