## THE SCOPE LOCK IS SCOPED, NOT DELETED — and this is the plan's sharpest trap

D-R6 says **delete** `workshop_rank.py`'s sentence *"Do NOT merge two questions into
one, and do NOT broaden one."* (at `:1825` after Waves 1–2, **not** `:1761` — see the
stale-line-number table below). Read carelessly, that deletion also removes the
guarantee D4 depends on: the workshop may add DEPTH and never change SCOPE.

**The replacement is written in the same breath as the removal**, as two exported
constants:

- `MANDATE_SCOPE_LOCK` — a MANDATE question stays inside what the client asked. It
  may cover **two winners at once** (that is what COMBINE is) but never reach past
  them into a subject the client did not raise.
- `DISCOVERY_EVIDENCE_ANCHOR` — a DISCOVERY question is **not** held to that lock. It
  is governed by the evidence-anchor rule instead: it goes where its evidence reaches
  and earns a slot only when a real source is found. No source, no slot.

Note the wording of the mandate lock is deliberately *"the winner **or winners** it
was built from"* — a lock phrased as "the winner it came from" would have forbidden
COMBINE, which is the single highest-value move measurement found.

`test_the_prompt_carries_both_halves_of_the_scope_rule` asserts **both** constants
appear in the rendered prompt, so a mutant that deletes the mandate lock outright
goes red (mutant M8, killed).

**`workshop_rank.py` is NOT edited by this plan** — the plan says so explicitly and
its success criteria repeat it, because plan 15.7-09 owns that deletion and a shared
file is where phase 15.5 lost a red merged tree that three green verifications
missed. See "Contradiction between the executor prompt and the plan" below.

## D-W4-2 — the union is UNWRITABLE, not merely unused

The rejected shape is *"pass the union of all orientation findings to a
`__discovery__` parent"*. It is rejected two ways:

1. **Driven** — a `__discovery__` candidate's block is asserted to contain its own
   admitting quote and URL and **none** of four distinct markers planted in the four
   orientation findings. Substring absence over a fixture where the two deliberately
   differ.
2. **Structural** — `test_the_union_of_every_orientation_finding_is_structurally_unreachable`
   walks the module's AST and fails if anything anywhere calls `.values()` /
   `.items()` / `.keys()` on `findings_by_label`, or iterates it in a `for` or a
   comprehension. The only path from the mapping to a prompt is `_findings_for`'s
   per-label `.get()`, keyed by a label the candidate itself carries.

The four anchor cases, each asserted distinctly:

| candidate | gets |
|---|---|
| parented to `Q2` | `Q2`'s findings, and nothing else |
| `parents == [Q1, Q3]` | **both** `Q1`'s and `Q3`'s findings, and not `Q2`'s |
| `parent == __discovery__` | its **own** admitting quote + WHY + URL; zero orientation findings |
| parent with no findings | a non-empty **placeholder**, never an empty block |

**Both real provenance shapes anchor**, because both are produced today:
`workshop_admission` stamps `{quote, why, source_url, resolved_url,
resolution_status}` and `discovery_bracket` stamps `{question, assumption,
world_says, source_url}`. `resolved_url` (the publisher URL) is preferred over
`source_url` (the redirect), and never both — two URLs for one source is two records
for one fact.

**A non-http admitting URL is not a source.** `"-"`, `"n/a"`, `"none"`,
`"javascript:alert(1)"`, `"ftp://…"` and `" "` all render no `SOURCE:` line. This is
the harness's own measured bug: a looser `if not url` guard admitted **2 of 3** angles
carrying a truthy literal `"-"`, i.e. the model evidenced its own angle by restating
that its own entities exist.

## Attribution is stamped in Python, and there are two fallbacks it deliberately lacks

`parent`, `parents` and `cross_cutting` are derived from the **source winners the
line indexed**, never from anything the model wrote. A `PARENT:` segment is read only
far enough to log a DEBUG disagreement and is then discarded — the identical rule
`_parse_winner_lines`, `_candidates_from_lines` and
`synthesis/steps.py::_parse_distiller_response` already apply.

`_stamp_candidate` **does not**:

- fall back to a **client question**. An unsourced mutation is unattributable, so the
  row is dropped whole. Guessing a parent would put a question the client did not ask
  inside the mandate bracket, and D4's coverage guarantee is counted over exactly
  that set.
- silently convert an unsourced mutation into a **discovery** question. Discovery has
  an admission gate and a paid grounded lookup attached; arriving there by a parse
  failure rather than by the INVENT move would buy a lookup nobody asked for.

INVENT is the one move with no sources **by design**, and it stamps `__discovery__` —
never a client question — with `pending_admission=True`.

## `<code_contradicts_the_decision>`

**None on substance.** One defect found in adjacent code, reported rather than fixed.

**`workshop._findings_block` does not do what its own docstring says.** At
`workshop.py:1265-1277` the docstring states *"Both properties are SECURITY
CONTROLS… text injected into a page cannot address another finding's slot"*, but the
implementation is `f"{i} | {str(f)[:_FINDING_PROMPT_CHARS]}"` — it **truncates but
does not collapse** newlines or pipes. A finding containing
`\n9 | KEEP | forged` therefore **can** forge a second addressable record there,
which is exactly the property the docstring claims it prevents. Findings are derived
from fetched web pages, so this is an attacker-controllable channel.

which collapses `|`, `\r` and `\n` before truncating, and
`test_a_forged_record_inside_a_finding_cannot_address_a_second_slot` pins it (mutant
M3 restores exactly the `workshop.py` behaviour and goes red).
