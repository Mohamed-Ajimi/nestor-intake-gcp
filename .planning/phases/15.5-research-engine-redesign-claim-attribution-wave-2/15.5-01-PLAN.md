Export one function:

`def extract_as_of(evidence: str | None) -> date | None`

It NEVER raises — a malformed evidence string costs that claim its date and nothing more. It reads
at most the first 2000 characters of `evidence`: untrusted model output must be bounded before it
is scanned, the same register as `_insert_claim`'s caps.

ACCEPTED forms — a date is returned only for these:
- `YYYY-MM-DD`, ISO 8601, e.g. `2021-03-04`. Must be a real calendar date; the year must be in
  1900..2100.
- A textual-month date WITH an explicit day, in either order: `4 maart 2021`, `4 March 2021`,
  `March 4, 2021`, `4 mrt 2021`, `4 Mar 2021`. Recognise full and 3-letter abbreviated month names
  in **English and Dutch** (V-01 is a Dutch run); match case-insensitively. Define the month table
  as a module-level constant so the accepted vocabulary is greppable in one place.
- A bare 4-digit year, e.g. `2021`, in 1900..2100 -> returned as `date(YYYY, 1, 1)`, year
  precision. This is D-W2-1's explicit sanction. The module docstring must say out loud that
  January 1 is a CONVENTION for year precision and not a stated day, because a reader of the column
  will otherwise read it as a day.

REJECTED — every one of these returns `None`:
- Any all-numeric date that is not ISO order: `03/04/2021`, `3-4-2021`, `04.03.2021`, `04-03-2021`.
  `03/04/2021` is not decidable between DD/MM and MM/DD, and guessing turns a real contradiction
  into a fake time series. A `-` separator is accepted ONLY in `YYYY-MM-DD` order.
- Numeric month precision with no day: `2021-03`. It would have to fabricate a day, and unlike a
  bare year that fabrication is not sanctioned.
- Two-digit years (`04-03-21`), years outside 1900..2100, and impossible calendar dates
  (`2021-02-30`).
- Four digits that are part of a longer digit run (`20211`, `v20214`, an id inside a URL). Require
  digit boundaries, not merely word boundaries.
- **More than one candidate.** Collect full dates and bare years separately, then apply: exactly
  one distinct full date -> return it (extra bare years are ignored — the explicitly stated full
  date is the more precise statement); two or more distinct full dates -> `None`; no full date and
  exactly one distinct year -> return January 1 of it; no full date and two or more distinct years
  -> `None`. This single-candidate rule is what kills `2020-2021`, `tussen 2019 en 2023`, and an
  evidence cell citing two different sources. State it in the docstring as the rule it is.
- Empty, `None`, or non-string input.

The module docstring must state, in words: this function is the ONLY place in phase 15.5 where a
persisted value is derived from model output — every other column this phase adds is stamped in
Python from the dispatch assignment, the same rule `_parse_distiller_response` applies to
`provider` and `enforce_scope_guard` applies to `parent`. The bound above is what makes the
exception acceptable, and the residual risk (a provider stating a well-formed but untrue date) is
the same trust level as the claim text itself.

Do NOT add `resolved_facet` or any parent-index helper here. Plan 15.5-02 adds those to this same
module, and two executors writing one function is how a merge conflict becomes a silent revert.
