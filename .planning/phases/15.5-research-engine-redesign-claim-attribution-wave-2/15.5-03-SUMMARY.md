# Phase 15.5 Plan 03: The Claim Attribution Write Path Summary

`_insert_claim` now knows about three more columns and treats each one exactly the way it already
treats `found_by` and `certainty` — explicitly typed, clamped at the boundary, and absent-means-NULL —
with the values arriving off the claim dict the merge produced and nine fake-session tests proving it
without a database.

## What Was Built

**Task 1 — the boundary** (`6b4ff39`)

`_insert_claim` gains three keyword-only parameters after `found_by`: `sub_question`,
`corroboration_key`, `as_of`, all defaulting to `None`. Two module-level caps beside
`_MAX_FOUND_BY` / `_FOUND_BY_MAX_CHARS`: `_SUB_QUESTION_MAX_CHARS = 500` and
`_CORROBORATION_KEY_MAX_CHARS = 32`, commented as a **bug bound and not an injection control** —
these values are caller-supplied, stamped in Python from the dispatch assignment, never
model-supplied — together with the other half of that sentence: the column must not be a place a bug
can write unbounded data.

Two new helpers sit beside `_clamp_enum`, which is the file's own established shape for exactly this:

- `_clamp_attribution(value, max_chars, *, field)` — a non-string, an empty string or a
  whitespace-only string becomes `None`; an over-long string is truncated and the truncation is
  logged at WARNING **with the field name and both lengths**.
- `_coerce_as_of(value, *, field)` — a `datetime` is narrowed with `.date()`, a `date` passes, and
  anything else (including an ISO string) becomes `None` with a WARNING.

The INSERT names all three in both the column list and the VALUES list, and the **existing**
`.bindparams(...)` call — there is still exactly one — gained
`sqlalchemy.bindparam("as_of", type_=sqlalchemy.Date)`.

**Task 2 — the call site** (`bfa3aeb`)

The single `_insert_claim` call in `persist_tribunal_claims` passes
`sub_question=claim.get("sub_question")`, `corroboration_key=claim.get("corroboration_key")`,
`as_of=claim.get("as_of")`. No `or ""`, no re-derivation, no second parse. `persist_tribunal_claims`'
signature is unchanged — the values ride on the claim dicts it already receives, exactly as
`certainty` and `found_by` do.

**Task 3 — the proof** (`400d0fe`)

Section 5 of `test_claim_attribution.py`: 9 async tests over a hand-written `_FakeSession` that
records `(sql_text, params)` and opens no connection. The harness is **copied** from
`test_verdict_write_path.py`, not imported — those two files are collected by different Cloud Build
configs, and a fixture shared across a gate boundary is a coupling neither config expresses.

## Key Implementation Details

**Why `_coerce_as_of` checks `datetime` first.** `datetime.datetime` is a **subclass** of
`datetime.date`, so the obvious `isinstance(value, date)` guard alone would let a timestamp straight
into a `Date` column. The order of the two branches is the entire mechanism, and the mutation that
replaces `return value.date()` with `return value` is caught by
`test_a_datetime_as_of_binds_as_a_date_so_no_time_can_reach_the_column`.

**Why the INSERT test splits the statement in half.** This is the one place a mutation found a real
weakness rather than confirming one. The first version asserted `column in sql_text`. That passes on
a statement that has **lost `as_of` from its column list**, because the `:as_of` placeholder is still
sitting in the VALUES clause — precisely the shape that writes nothing while reading correctly. The
test now partitions on `VALUES`, requires the bare name in the head and the `:name` placeholder in
the tail, checks the two lists are the same length, and checks the three new columns sit at matching
indexes. The mutation that was green is now red.

**Why `is None` and never falsiness.** `research_division.py` deals the top-3 winners a real key and
deals the remainder round-robin with the **empty string**, so `""` arrives on roughly 12 of 15
winners. `assert not row["corroboration_key"]` would pass on both the correct NULL and the bug it is
meant to catch. Written `is None` throughout, and the docstring says why.

**No RLS test, stated in the source.** The section heading carries both reasons so nobody adds one
later thinking it was forgotten: a table-level `POLICY` covers a newly added column by construction
(migrations 0003/0008 give `claim` its `claim_tenant_isolation` / `claim_worker_all` policies), and
this gate provisions no database, so a role-less DB test would connect as superuser, RLS would not
apply, and every isolation assertion would pass vacuously. What is left is an **ordering** fact, and
that is asserted: `set_config` is recorded before the first `INSERT INTO claim (`.

## Deviations from Plan

**1. [Rule 1 - Bug] The INSERT-names-the-columns test passed on a statement missing a column**

- **Found during:** Task 3 non-vacuity run
- **Issue:** The test asserted `column in sql_text` over the whole statement. The `:as_of`
  placeholder in the VALUES clause satisfies that substring even when `as_of` has been dropped from
  the **column list** — the exact failure shape that writes NULL on every row forever while the
  statement still mentions the name. The mutation ran green.
- **Fix:** The statement is partitioned on `VALUES`; the bare name must appear in the column list and
  `:name` in the values list; the two lists must be the same length; the three new columns must sit
  at matching indexes. The docstring records why the split exists so it is not "simplified" back.
  Re-ran the mutation: now RED.
- **Files modified:** `tests/test_claim_attribution.py`
- **Commit:** `400d0fe`

**2. [Judgement call] The coercions are module-level helpers, not inline blocks**

The plan says "applied in the function body before the INSERT". Implemented as `_clamp_attribution`
and `_coerce_as_of` placed beside `_clamp_enum` and **called from** `_insert_claim`'s body. This is
the file's own precedent — `certainty`'s clamp is already a module-level helper called the same way —
and it avoids two near-identical inline blocks for the two text columns. Recorded because a reviewer
checking the acceptance criterion "verify in the function body, not the docstring" will find the rule
one call away rather than inline. Both helpers were driven directly as part of verification.

**3. [Judgement call] `.strip()` is applied to the two attribution strings**

`_clamp_attribution` strips before measuring and stores the stripped value. This follows the
`found_by` precedent in the same function (`str(p).strip()[:_FOUND_BY_MAX_CHARS]`) and is what makes
`"   "` collapse to `None` as D-W2-2 requires. It means a `sub_question` with incidental leading or
trailing whitespace is stored trimmed. Flagged rather than taken silently, since the plan says
"binds those three values through unchanged" for the happy path — which still holds for every value
that carries no surrounding whitespace.
