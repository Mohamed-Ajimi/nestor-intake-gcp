# Phase 15.4 Plan 10: D-R2's retry half — Summary

**One-liner:** a provider whose fact list could not be read now gets ONE corrective
re-ask of itself — same contract block verbatim, over its own report text, on
gemini-2.5-flash — before its report is downgraded to prose distillation; and when the
re-ask fails, every operator-facing string is equal to what a run with the retry
switched off produces.

## Scope — one of three deviations, and only one

ROADMAP criterion 4's three gemini fact-list deviations have split ownership. This plan
owns exactly one:

| V-01 idx | Deviation | Owner | State |
|---|---|---|---|
| 12, 16 | No `FACTS_START`/`FACTS_END` block at all | **this retry** | shipped here |
| 8 | Every line prefixed with a literal `STATEMENT` column | 15.4-04's `_strip_uniform_leading_column`, with this retry as the safety net | already green |
| 4 | `[cite: N]` in the `SOURCE_URL` column | 15.4-04's cite index — **not this retry** | already green |

idx 4 is the trap: those facts *survived* parsing, so that report never reaches
`needs_distiller_fallback` and a retry could never see it. **No retry path was added
for it.** The exclusion is stated in `build_fact_list_retry_prompt`'s docstring and in
the Group F header comment, so the next reader does not re-add one.

## What was built

### Task 1 — `build_fact_list_retry_prompt` (`facts.py`), commit `e511dd1`

Composes, in order: a corrective naming the deviation ACTUALLY observed →
`build_fact_list_prompt_block(language=…, provider=…)` **verbatim** → the provider's own
report fenced by the new `RETRY_REPORT_START` / `RETRY_REPORT_END` constants.

Three correctives, selected by `previous`'s discriminators in **the same order
`parse_fact_list` uses to compose `fallback_reason`** — so the sentence the operator
reads in the log and the sentence the provider reads in the re-ask name the same
deviation, and cannot drift apart:

1. `had_block` False → "no `FACTS_START`/`FACTS_END` block at all"
2. `parse_errors > 0` → "not one line parsed (N ignored)", naming the `STATEMENT`-column
   shift as the known cause
3. `placeholder_urls > 0` → "every fact named a placeholder instead of a source"
4. otherwise → a generic sentence

Built from **the provider name and integers only** (T-15.2-66 / T-15.4-27). The offending
line is deliberately *not* quoted back at the model: that is the obvious-looking way to
write a corrective, and it is exactly the move that lifts attacker-controlled text out of
the fenced region and into the instruction region.

The function is pure and cannot raise — for a `FactListResult`, for `None`, for an `int`,
or for an object whose every attribute access explodes. That matters because a raise here
would propagate to a path where the enclosing `except` does **not** append to
`fallback_units`.

### Task 2 — the retry (`steps.py`), commit `581400a`

`_retry_fact_list` on the `needs_distiller_fallback` branch, **before**
`fallback_units.append(...)`. Returns `None` (no call made / call failed) or a
`FactListResult`. On a usable result the caller takes the first-pass treatment exactly:
`reports_with_fact_list += 1`, `_normalise_fact_claim(..., fact_source="fact_list")`,
`facts_from_list += kept`, `not_found` harvested — and the report is **not** appended to
`fallback_units`.

Cost and safety bounds, each with a named test:

| Bound | Mechanism |
|---|---|
| one call per report | no loop, no chunking; asserted by counting calls on the fake client |
| cheap path only | `_DISTILLER_MODEL` (`gemini-2.5-flash`); `models` recorded and asserted |
| no re-research | `deep_research_raw` entry points raise on the fake **and** a source-level regex asserts none gained a caller |
| one provider, named | `_FACT_LIST_RETRY_PROVIDERS = ("gemini",)`, the `_LEAD_IN_PROVIDERS` idiom |
| kill switch | `NESTOR_TRIBUNAL_FACTLIST_RETRY=0`, resolved at import time |
| never truncate | over-ceiling reports are skipped (see Deviations) |

The **label and cite indexes are built from the ORIGINAL REPORT**, not from the re-ask
response. A retry answers with the fact list alone, so a `[cite: N]` marker in it has no
bibliography to resolve against unless the report's own one is handed in — without this,
the fix for idx 12 would have reintroduced idx 4's loss. `test_the_retry_reads_the_reports_own_bibliography`
pins it.

## The additive property, and how it is actually proven

The plan's acceptance criterion asks for string equality on `fallback_reason` against
"the expected sentence". `test_a_failing_retry_leaves_the_fallback_byte_identical` does
something stronger **as well**: it runs the same entries **twice** — once with
`_FACT_LIST_RETRY_ENABLED = False`, which *is* the pre-plan code path, and once with the
retry on and answering garbage — and asserts `fallback_notes`, every `reason`, every
`reports_fell_back` and every `reports_with_fact_list` are equal between them. A
hand-copied expected sentence only catches a change to one path; this catches a change to
both. The spelled-out sentence is asserted too, rebuilt from the `FACTS_START` /
`FACTS_END` constants rather than pasted.

Four named tests cover the ways a retry could become a new failure mode:

- `test_a_retry_that_raises_still_reaches_the_distiller` — the client raises; the helper
  catches it.
- `test_the_call_sites_own_guard_catches_a_raising_helper` — the helper itself is replaced
  by one that raises **before it can catch anything**, and the report still reaches the
  distiller. This is the belt-and-braces guard at the call site, proven independently of
  the helper's own discipline. Without it, an escape lands in
  `collect_provider_facts`'s per-report `except`, which passes the report through as prose
  and **never appends it to `fallback_units`** — a stream silently losing its distillation
  after its research was already paid for.
- `test_an_over_long_report_is_skipped_rather_than_truncated`
- `test_the_retry_kill_switch_restores_todays_behaviour_exactly`

## Deviations from Plan

### 1. [Rule 2 — missing critical functionality] The retry is gated on `_d8_prompted`

- **Found during:** Task 2, reading `_fallback_note`'s two wordings.
- **Issue:** the plan places the retry on the fallback branch unconditionally. But
  `_d8_prompted` is False when `NESTOR_TRIBUNAL_D8_FACT_LIST` is off, or when the provider
  is outside `_D8_PROMPT_PROVIDERS`. Re-asking such a stream would **issue the very
  request the D8 kill switch exists to suppress**, and would make `_fallback_note`'s
  "was not asked" sentence false in the same run that printed it. A stream that was never
  asked has not deviated from anything.
- **Fix:** the call site checks the per-report `result["_d8_prompted"]` (not the
  per-provider accumulator, so precision is per report).
- **Test:** `test_a_stream_that_was_never_asked_is_never_re_asked`.
- **Commit:** `581400a`

### 2. [Rule 2] An over-long report is SKIPPED, not truncated

- **Found during:** Task 2, deciding what "send the report in ONE call without chunking"
  means for a 3 MB report.
- **Issue:** the two obvious options both break the additive property. Chunking is several
  calls. Truncating is worse: a fact list parsed over the first N characters would take
  the **success** path and skip the distiller, so every fact in the tail would be lost —
  by an operation whose entire justification is that it cannot lose anything.
- **Fix:** `_FACT_LIST_RETRY_MAX_REPORT_CHARS` (default 400 000, env-overridable). Over
  the ceiling: no re-ask, a WARNING saying why, and the report falls through to the
  distiller, which chunks it properly.
- **Test:** `test_an_over_long_report_is_skipped_rather_than_truncated`.
- **Commit:** `581400a`

### 3. [Rule 1 — trail correctness] The recovery WARNING retracts a superseded line

- **Found during:** Task 2, capturing the real log records.
- **Issue:** `parse_fact_list` announces "its report will be run through the
  full-extraction distiller instead (D-14)" during the **first** pass — before any re-ask
  exists. On a successful retry that statement is left standing and is false. It cannot
  simply be reworded: it is 15.2-04's own sentence, is consumed verbatim as the record's
  `reason`, and `tests/test_fact_list_parser.py` holds byte-level assertions nearby.
- **Fix:** the recovery WARNING explicitly retracts it by name, in the line that overtook
  it. The original sentence is untouched.
- **Test:** `test_the_retry_says_out_loud_what_it_did` asserts the retraction.
- **Commit:** `581400a`

### 4. [Judgement call, no rule] `_response_text` is not shared with `_distill_unit`

`_distill_unit` carries the same seven lines of response-text extraction inline. Sharing
would be tidier, but it edits the **paid distiller path**, whose tests
(`test_claim_distiller.py`) live in `cloudbuild.test-gates.yaml` — a second build — inside
a plan whose whole property is that it changes nothing about the fallback. Left alone,
with the reason written into `_response_text`'s docstring. This is the same call 15.4-03
made about `line.strip()`.
