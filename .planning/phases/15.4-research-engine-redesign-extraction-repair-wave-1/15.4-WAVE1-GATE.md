## Three defects the gate caught that review had not

**1. The build config had become unsubmittable.** Registering the 32nd test file pushed the inline
script to 13,473 chars against Cloud Build's 10,000-char limit for one step arg, and
`gcloud builds submit` refused it outright — `build step 0 arg 1 too long`. The gate could not run
at all. 9,416 of those chars were commentary. Moved **verbatim** into YAML comments above `steps:`
(outside the arg, so free) rather than deleted — this file explicitly asks not to have its guards
tidied away. Executable script proven byte-identical: 75 lines before, 75 after.

**2. A disabled resolver was recording a measurement it never made.** `resolve_redirects`
pre-populated `resolved[url] = None` for every URL *before* the kill-switch check and returned that
map when disabled. But a URL present-with-None is precisely how the caller spells "attempted and
failed", so with `NESTOR_REDIRECT_RESOLVE_ENABLED=0` every citation was stamped `'unresolved'` on a
run that issued **zero requests**. The old log line said it aloud: *"stored unresolved, 0 requests
issued"*. This is the three-state collapse the two columns exist to prevent, and the same class of
defect as the `0 facts` removed by 15.4-05. Fixed: return `{}` when disabled.

**3. The plan contradicted itself, and the gate is what surfaced it.** Task 1 specified "with the
kill switch off the function returns an all-None map"; Task 2 specified NULL = never attempted /
`resolved` / `unresolved`. Both cannot hold — an all-None map *is* "attempted and failed". The status
rule wins. The kill-switch test's stated rationale was also factually wrong about the caller ("every
URL still comes back as a key, **so the caller still upserts every citation**"):
`persist_tribunal_claims` upserts by iterating the claims' own `deduped_urls` and calls
`_upsert_source` unconditionally — membership never governed whether a citation is written. Its real
assertions (`client.requests == []`, `client.entered == 0`) were kept untouched.
