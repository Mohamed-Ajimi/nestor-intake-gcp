Add a module-private pre-parse in `facts.py`, applied to the region returned by `_extract_region`
BEFORE the per-line loop:

  `_LEADING_COLUMN_TOKENS: frozenset[str] = frozenset({"STATEMENT", "FACT", "CLAIM"})`
  `def _strip_uniform_leading_column(region: list[str]) -> tuple[list[str], str | None]`

It returns the region unchanged and `None` unless ALL of these hold: there are at least two
non-empty lines; every non-empty line contains a tab; and the first tab-column of every non-empty
line, uppercased and stripped, is the SAME token and that token is in `_LEADING_COLUMN_TOKENS`. When
they hold, it returns each line with that first column and its separator removed, plus the token
that was stripped.

The uniformity requirement is the whole safety argument and must be stated in the docstring: a
single echoed header line is a header and stays a parse error; only a block where EVERY line carries
the prefix is a shifted block. Do not relax it to "most lines".

Wire it into `parse_fact_list` immediately after `_extract_region`. When a prefix was stripped, log
at WARNING naming the provider and the token — this is a provider format deviation that was
previously invisible and is exactly the class of silence this phase exists to end. Count nothing as
a parse error for the stripped lines: they parsed.
