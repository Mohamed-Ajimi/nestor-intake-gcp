<interfaces>
`persist_tribunal_claims` (citations/extractor.py) — the per-claim loop at ~715-792 already:
  - gathers `source_urls` from the claim dict and from each verdict's `evidence_refs` / `citations`;
  - dedupes them PER CLAIM into `deduped_urls` (`seen_urls` / `deduped_urls`, ~740-747);
  - calls `_upsert_source(session, tenant_id=…, url=url, provider="tribunal_skeptic",
    snapshot_text=url, title=source_title)` per URL (~776-784).

That per-claim dedupe is NOT the dedupe D-V01-11 asks for: V-01 saw 642 instances collapse to 225
UNIQUE urls across the run. The dedupe must therefore be a PRE-PASS over the whole call's URL set,
before the per-claim loop.

**WHERE THE PRE-PASS RUNS — REVISED 2026-07-29 BY OPERATOR DECISION. Read this before Task 2.**
The pre-pass does **not** run inside `persist_tribunal_claims`. That function's own docstring says
*"Caller (TribunalPipeline) opens the session + transaction"*, and the call site confirms it —
`pipeline.py` ~3074-3103, Stage 7:

```
    _sm = get_sessionmaker()
    async with _sm() as session:
        async with session.begin():
            await persist_tribunal_claims(...)
```

Resolving inside that block would put up to 30 s of network I/O inside the **final persistence
transaction of a ~$50 run**, holding a pooled connection with RLS tenant context set. A pool stall or
a hung socket there costs the run its claims — for an enrichment that is, by design, allowed to fail.
So resolution happens in `pipeline.py` **before `_sm()` is called**, and the resulting map is passed
into `persist_tribunal_claims` as a parameter.

The bounds (deadline, per-request timeout, concurrency cap, kill switch) are still required. They are
now defence in depth against stalling the run, **not** the thing that makes an unsafe placement safe —
do not weaken them on the grounds that the transaction is no longer open.

`_upsert_source` (extractor.py:135) computes `content_hash` from `snapshot_capped` ALONE and INSERTs
with `ON CONFLICT DO NOTHING`, returning the existing row's id on conflict. Its `title` docstring
states the rule the new columns inherit: a column that is not part of `content_hash` cannot change
source dedupe, and an existing row KEEPS what it already had — a later, better value never silently
rewrites history.

`VERTEX_REDIRECT_HOST = "vertexaisearch.cloud.google.com"` (pipeline/tribunal/facts.py:118) — the ONE
definition. Import it function-locally; do not fork a second copy.

`httpx==0.28.1` is already pinned in `tribunal/requirements.txt`. This plan adds NO dependency.

Schema (plan 15.4-02, alembic 0016): `source.resolved_url` TEXT NULL, `source.resolution_status`
TEXT NULL with three meanings — NULL = never attempted, `'resolved'`, `'unresolved'`.

Create `tribunal/nestor_pulse_sdk/citations/redirect_resolver.py` exporting:

    async def resolve_redirects(urls: Iterable[str]) -> dict[str, str | None]

Contract, stated in the module docstring and enforced in code:
  - DEDUPE FIRST. Build the unique set before issuing anything (V-01: 642 → 225).
  - Only URLs whose host equals `VERTEX_REDIRECT_HOST` are requested; everything else maps to None
    and is never touched. Import the constant function-locally from `pipeline.tribunal.facts`.
  - `httpx.AsyncClient(follow_redirects=False)`, `HEAD`, read the `Location` header, ONE hop.
  - THE LOCATION IS UNTRUSTED. Accept it only when it parses to an `http`/`https` scheme and is at
    most 2048 chars — the same control `_parse_url_cell` applies and for the same reason: this value
    is rendered as a clickable link in the superadmin citation panel, so a `javascript:` or `data:`
    target chosen by whoever controls the redirect is an elevation-of-privilege path into the
    operator's own tool. Anything else maps to None.
  - NEVER RAISES, for any input, including a hostile mapping or a malformed URL.
  - Bounded by four `NESTOR_*` env knobs with defaults, in the `grouping.py` idiom:
    `NESTOR_REDIRECT_RESOLVE_ENABLED` (default 1 — the kill switch),
    `NESTOR_REDIRECT_RESOLVE_CONCURRENCY` (default 8),
    `NESTOR_REDIRECT_RESOLVE_TIMEOUT_S` (per request, default 5.0),
    `NESTOR_REDIRECT_RESOLVE_DEADLINE_S` (overall, default 30.0).
    The overall deadline is the one that matters: this pre-pass sits between the end of adjudication
    and the persistence of a ~$50 run's claims, so an unbounded pre-pass is an unbounded stall on the
    run's critical path. State in the docstring that resolution is an ENRICHMENT which is allowed to
    fail and must never delay or endanger persistence — so nobody "improves" it by removing the
    deadline, and nobody relocates it into the transaction (see Task 2).
  - One summary log line at INFO with unique/resolved/unresolved counts, and one WARNING when the
    deadline was hit or when the unresolved fraction is non-zero — a citation that did not resolve is
    a named loss, not a silent one.

Add the behaviours above to `tests/test_source_resolution.py` (created by plan 15.4-02, already in

| Boundary | Description |
|----------|-------------|
| third-party redirect service → `source.resolved_url` | The 302 `Location` is chosen by a remote host, not by us |
| resolver network I/O → the run's critical path | The pre-pass sits between adjudication and persistence — outside the transaction, but still on the path of a ~$50 run |
| `resolved_url` → superadmin citation panel | The stored value is later rendered as a clickable link |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.4-21 | Elevation of privilege | `Location` header value | mitigate | Accepted only when it parses to `http`/`https` and is ≤2048 chars — the same control as `_parse_url_cell`; a `javascript:`/`data:` target maps to None and is asserted by a named test |
| T-15.4-22 | Denial of service | a stalled pre-pass delaying persistence of a paid run | mitigate | **Placement first:** resolution completes before the session opens, so a stall can never hold a pooled connection or an RLS-scoped transaction (asserted by the placement test). **Then bounds:** overall `NESTOR_REDIRECT_RESOLVE_DEADLINE_S` (30 s default), a per-request 5 s timeout, a concurrency cap, and a kill switch. Resolution failure degrades to an empty map and persistence proceeds — the enrichment is allowed to fail, the claims are not |
| T-15.4-23 | Denial of service | a hostile redirect chain | mitigate | `follow_redirects=False` and exactly ONE hop; a redirect loop costs one request |
| T-15.4-24 | Tampering | source dedupe / historic rows | mitigate | Neither new column enters `content_hash`; `ON CONFLICT DO NOTHING` means an existing row keeps its values, so a later resolution never rewrites history — asserted by the equal-upsert-count test |
