# Phase 15.4 Plan 09: Redirect Resolution at Ingest — Summary

Gemini grounding redirects are now resolved to their publisher URL once per unique URL and stored
beside the redirect, with resolution completing **before** the persistence transaction opens.

## What was built

**`citations/redirect_resolver.py` (new).** `resolve_redirects(urls) -> dict[str, str | None]`:
dedupes first (V-01's 642 instances → 225 unique), requests only URLs whose host equals
`VERTEX_REDIRECT_HOST` (imported function-locally — no fork of the constant), issues `HEAD` with
`follow_redirects=False`, reads exactly one `Location`, and never raises. The `Location` is treated
as untrusted: accepted only as `http`/`https` with a host and ≤2048 chars (T-15.4-21). Four
`NESTOR_REDIRECT_RESOLVE_*` knobs, read at call time. The module contains no database symbol at all.
It also exports `is_redirect_url`, the one host predicate.

**`citations/extractor.py`.** `_gather_source_urls(claims, verdicts_by_claim)` is the single URL
extraction, called by the pre-pass over the whole run and by the per-claim loop with a one-element
list — so the set resolved and the set upserted cannot drift. `persist_tribunal_claims` gained
`resolved_urls=None`; `_upsert_source` gained `resolved_url=None` / `resolution_status=None`, written
into **both** INSERT branches, neither part of `content_hash`. `resolve_redirects` is named nowhere
in this file.

**`pipeline/tribunal/pipeline.py`.** Stage 7's body moved to a module-level
`_resolve_then_persist_claims`, which resolves first and *then* calls `get_sessionmaker()`. The
`except Exception` that deliberately does not block synthesis on a persistence failure moved verbatim.

**Three states, never collapsed.** NULL = never attempted · `'resolved'` · `'unresolved'`. A redirect
that fails to resolve is still upserted, marked `'unresolved'`.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 — Blocking] `tests/conftest.py`: redirect resolution OFF for the whole suite**
- **Found during:** Task 2, checking which suite files reach Stage 7.
- **Issue:** Wiring `resolve_redirects` into Stage 7 means every test that drives the pipeline against
  a **recorded** gemini report would issue live `HEAD` requests to `vertexaisearch.cloud.google.com`
  from CI. `tests/fixtures/run_4cbb5311/…` and `tests/fixtures/run_7dcf51d5/…` contain real grounding
  redirects. The engine gate's own header states it makes no network calls.
- **Fix:** an autouse fixture setting `NESTOR_REDIRECT_RESOLVE_ENABLED=0`. The resolver's own tests
  clear it and inject a fake client, so they still exercise the enabled path. The **production**
  default is unchanged.
- **File:** `tribunal/nestor_pulse_sdk/tests/conftest.py` (not in `files_modified`).
- **Commit:** `314b21c`

**2. [Rule 3 — Blocking] `test_tribunal_pipeline.py`: three stand-ins widened**
- **Issue:** two `fake_persist` doubles and one `fake_upsert_source` double use explicit keyword-only
  signatures with **no** `**kwargs` — deliberately, per their own comments ("the next widening
  surfaces here instead of passing silently"). Passing `resolved_urls=` / `resolved_url=` would have
  raised `TypeError`; in the pipeline case Stage 7's `except Exception` would have swallowed it and
  the test would have failed on an empty `persist_calls` list rather than on the real cause.
- **Fix:** the new parameters named explicitly, in the same style, with the reason recorded. The
  pipeline double now also **captures** the map, so it pins that resolution reaches persistence.
- **Commit:** `314b21c`

**3. [Rule 2 — Missing critical functionality] `_as_list` guard in `_gather_source_urls`**
- **Issue:** the pre-existing extraction did `for url in (claim.get("evidence_refs") or [])`. A
  model-authored **string** there is iterated CHARACTER BY CHARACTER, and each character passes the
  `isinstance(url, str)` test — so `"unknown"` became seven one-character source rows. Likewise a
  citation dict whose `url` was not a string reached `.strip()` and raised inside the persistence
  step of a paid run.
- **Fix:** `_as_list()` (a string is deliberately not a sequence of items) plus an `isinstance` guard
  on the citation URL. Proved locally.
- **Commit:** `314b21c`

### Design choices worth flagging

**4. Stage 7 extracted to `_resolve_then_persist_claims`.** The plan asks the placement test to
"drive `pipeline.py` Stage 7 with a duck-typed sessionmaker". Doing that with Stage 7 inline means
running the whole engine through the stubbed e2e harness — heavy, fragile, and it would prove the
ordering only incidentally. A module-level coroutine is drivable directly. Behaviour is unchanged:
the same call, the same arguments, the same `except Exception`, the same log line.

**5. `is_redirect_url` lives in the resolver and is imported function-locally by the extractor.**
The plan's status rule needs the extractor to know whether a `None` in the map means "not a redirect
host" (NULL) or "attempted and failed" (`'unresolved'`). A second copy of the host predicate would
let those two meanings drift, which is the exact thing the two-column design exists to prevent. What
is imported is a pure string predicate with no client and no I/O; the acceptance criterion
(`grep -n "resolve_redirects" extractor.py` → nothing) holds literally, and a test asserts it.

**6. The extractor docstring deliberately does not spell the function name.** It says "the resolver
in `citations/redirect_resolver.py`" rather than naming `resolve_redirects`, so the literal grep
criterion is satisfied by the whole file rather than by an executable-code-only scan. (Plan 15.4-02
hit the same tension on the index name and resolved it the other way; here the prose loses nothing.)

**7. "ONE source row" for the shared-URL test is stated as "one unique URL upserted".** Two claims
citing one redirect produce two `_upsert_source` calls naming the same URL; collapsing them to one
row is `ON CONFLICT DO NOTHING`, which needs a real Postgres and is proved in
`test_citation_roundtrip.py`. The test asserts what a no-DB test honestly can: one resolver request,
one unique URL, two `claim_source` links.

**8. The pre-pass gathers `survivors` + `dropped`, as the plan instructs.** Dropped claims get no
`claim` row and therefore no source rows, so a redirect cited only by a dropped claim is resolved and
the result is never stored. The cost is bounded by the dedupe and by the deadline; flagging it rather
than narrowing the plan's instruction.

**9. A relative `Location` maps to `None`** — the plan allows either choice. Resolving it against the
request URL would produce another `vertexaisearch.cloud.google.com` URL, which is the very thing that
expires. All 225 observed Locations on V-01 were absolute.
