<domain>
## Phase Boundary

**What happened.** V-01 (run `7dcf51d5`, 2026-07-28) produced a client report whose coffee section said
the Benelux data *"geeft geen volledig beeld"*. That statement was **false**. The distiller had returned
**278 well-formed coffee claims** and `_parse_distiller_response` threw away every one of them on a
string comparison: the model wrote the literal five-character string `<TAB>` instead of U+0009, because
**the prompt itself uses `<TAB>` as a placeholder describing the separator**. The only trace was a
`log.debug`, which production does not serve.

**What this phase delivers.** The engine stops silently discarding claims it successfully extracted, and
says so loudly when it does. Four things:

1. A separator-tolerant distiller parser + a prompt contract that cannot be copied back as data.
2. "Returned lines, kept zero claims" is a **WARNING**, and the ZERO-claims warning stops crying wolf.
3. One additive retry when a gemini fact list is unusable — covering **all three** observed deviations.
4. Gemini grounding redirects resolved to publisher URLs at ingest, so citations cannot rot.

Plus two smalls: the missing `gpt-5.6-sol` cost row and the dropped `run_event` rows.

**Ships alone.** Wave 1 is deployed and measured by ONE live run before Wave 2 starts. Everything
downstream in the redesign is judged through the extraction funnel — shipping the redesign on top of a
broken meter would attribute the parser bug to the redesign.

**Out of scope — explicitly.** Waves 2–5 of the spec (claim attribution, dispatch redesign, the creative
workshop loop, yield instrumentation). Anything in spec § 7 "What we are deliberately NOT doing".

### D-R1 — The `<TAB>` fix (spec § 1.1)

**File:** `tribunal/nestor_pulse_sdk/pipeline/synthesis/steps.py`

- **(a) Parser** — `_parse_distiller_response` (def at line 1260) currently does `if "\t" not in line:
  continue` then `line.split("\t", 2)`. Replace with a separator-tolerant split accepting, **in this
  priority order**: a real tab, `<TAB>`, `|||`, `|`, and a run of 2+ spaces. Priority order is
  load-bearing: a line containing both a real tab and a literal `<TAB>` MUST split on the tab. `|||`
  MUST be tried ahead of `|`. Returns `None` when no separator is present at all.
- **(b) Prompt** — `_build_distiller_prompt` (def at line 1185). **Stop describing the separator with a
  token the model can copy.** Decision taken: switch the contract to `FACET ||| CLAIM_TEXT ||| EVIDENCE`
  and keep accepting a tab for back-compat. (The rejected alternative was writing a real tab into the
  example — invisible in source, fragile under reformatting.)
- **(c) Make the drop loud** — in `_distill_unit` (line 1537), after `_parse_distiller_response` (called
  at line 1568): if the model returned text but zero claims parsed, `log.warning` with the provider, the
  non-empty line count, and the first line truncated to 200 chars. **This one line is the whole lesson
  of V-01.** WARNING is the lowest level production actually serves (D-V01-6).
- **(d) Scope the ZERO-claims warning** — line 1580 iterates every focus area in the mission brief and
  reports zero for any label absent from *this call's* output, in scope or not. On V-01 it cried wolf
  about `convenience` (never in the call) next to a real coffee zero. Restrict it to facets present in
  the call's **inputs** (`_angle` on the provider reports).

### D-R2 — Retry on an unusable fact list (spec § 1.2)

**Files:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/facts.py` +
`synthesis/steps.py::collect_provider_facts` (line 1820; `needs_distiller_fallback` branch at line 2002).

Gemini's fact-list failures are **three distinct format deviations**, not one. A retry covering only
"block absent" fixes one of three:

| V-01 idx | Deviation | Symptom |
|---|---|---|
| 12, 16 | No `FACTS_START`/`FACTS_END` block at all | `gemini returned no FACTS_START/FACTS_END block` |
| 8 | Block present; every line prefixed with a literal `STATEMENT` column, shifting every field one place | `not one line in it parsed as a fact (4 line(s) ignored)` |
| 4 | Block well-formed; `SOURCE_URL` column holds the `[cite: N]` marker | ~20 × `rejecting non-http(s) SOURCE_URL '[cite: 25, 26]'` — facts survived, **sources did not** |

- **One** retry per report, at the `collect_provider_facts` level, on the `needs_distiller_fallback`
  branch, **before** falling through to `fallback_units`.
- Re-ask the **same provider** for **only the fact list**, over its own report text, using the same
  `build_fact_list_prompt_block` contract plus an explicit corrective naming the deviation observed.
- Parse the retry with the same `parse_fact_list`. On success, treat it exactly as a first-pass block.
- On failure, fall through to the distiller **exactly as today** — the retry is **additive, never a new
  failure mode**.
- Log the attempt and the outcome at **WARNING**.
- Add a **normalising pre-parse** in `parse_fact_list` for the idx-8 shape: when every non-empty line in
  the block starts with an identical leading column that is not a claim (`STATEMENT`, `FACT`, `CLAIM`),
  strip it before field assignment.
- For idx 4: do **not** reject the fact — reject only the URL (already the behaviour) — but **record the
  `[cite: N]` marker** so redirect resolution can use it.

### D-V01-11 — Resolve gemini redirects at ingest (spec § 1.3)

Every `vertexaisearch` grounding redirect resolves via a plain `302` to a publisher URL; **225/225
resolved** on V-01, and they **expire ~30 days after the run**.

- **Dedupe first** (V-01: 642 instances → 225 unique).
- `HEAD`, follow one hop, read `Location`. No API key; parallelises trivially.
- On failure **keep the redirect and mark it unresolved — never drop a citation**.
- Store the publisher URL **alongside** the redirect, not instead of it.
- This is the durable form of the one-off preservation already committed as
  `docs/tribunal-run-reports/run-20260728-7dcf51d5-CITATIONS.tsv`.

## Specific Ideas

### Located in code, 2026-07-29 — the three items the spec named but never placed

Verified by reading master. No research agent was run; these are the greps that would have justified one.

**1. The cost table is a hot-reloadable JSON file, not Python.**
`tribunal/nestor_pulse_sdk/audit/cost_prices.json`, loaded by `audit/cost_table.py` (`COST_PRICES_PATH`
env override, `_DEFAULT_PRICES_PATH` at line 58). Keys are `provider/model`; values are USD **per 1M
tokens** as `{prompt, completion, cache_read, cache_creation_5m}`. **Confirmed: there is no `gpt-5`
entry of any kind** — the openai block runs `gpt-4o`, `gpt-4o-mini`, `o4-mini`, `o4-mini-deep-research`,
`o3`, `gpt-4-turbo`. So the fix is one JSON object keyed `openai/gpt-5.6-sol` with **published** rates.
The file's own `_tool_fees_source` note sets the standard: a null means "no published rate exists", NOT
`$0.00`, and it yields `cost_usd` NULL + `cost_pending` rather than a fake zero. **Do not invent prices
to make `cost_pending` clear** — that would trade a known-unknown for a silent wrong number.

**2. The dropped `run_event` rows are NOT an `emit_safe` bug — `emit_safe` is working as designed.**
This corrects the spec's phrasing ("~20 `KeyError`/`TypeError` in `emit_safe`"). `runs/run_events.py:402`
`emit_safe` takes a **zero-argument build callable** precisely so a malformed provider dict raises
*inside* its `try` instead of at the call site in the paid dispatch loop — its docstring spells this out
as D-06, and warns not to hoist `build()` above the try. It caught these. The run was unaffected. **The
events were still lost**, because the build lambdas themselves are intolerant:

- `pipeline/tribunal/research_division.py` ~1188 — `f"{len(result['facts'])} facts"` is a **subscript**.
  A degrading provider returning a short dict raises `KeyError` and the `agent_done` line vanishes. The
  same file at ~1376 uses `.get` for `agent_run` and its comment explicitly names the asymmetry:
  *"`.get` here and NOT a subscript, unlike the `agent_done` line below"*.
- `pipeline/tribunal/own_researcher.py` ~776 — the `own_research` `agent_done` lambda calls
  `_raw_fact_count(fact_block)`, which **RAISES by design** rather than guess (its docstring says so).
  Every own-research `agent_done` line dies whenever that raise fires.

**So the fix is the build lambdas, not the emitter.** Make them tolerant (`.get` with a fallback, and a
guarded `_raw_fact_count`) while keeping the fact honest — a count that cannot be established should
render as unknown, not as `0`. **Do not "fix" this by loosening `emit_safe`** and do not hoist `build()`
out of the try; both undo D-06.

**3. Redirect resolution belongs at the source upsert in the citation extractor.**
`citations/extractor.py` ~735–790 already dedupes `source_urls` in order (`seen_urls` / `deduped_urls`)
and then calls `_upsert_source(session, tenant_id=..., url=url, provider=..., snapshot_text=url,
title=source_title)` per URL. That loop **is** the ingest point — the dedupe the spec asks for is
already there. Related existing machinery: `pipeline/tribunal/facts.py:118 VERTEX_REDIRECT_HOST` and the
markdown-link path at ~401–454, which already recovers the publisher's display domain from the
provider's own link label (that is where `source_domain` → `title` comes from, per the D-13 comment).

**This one needs a schema change.** `db/models/source.py:27` `Source` has `url`, `title`, `provider`,
`fetched_at`, `snapshot_text`, `snapshot_gcs_uri`, `content_hash` — **no column for a resolved URL**.
Storing the publisher URL *alongside* the redirect (the decision) therefore needs a new nullable column
and an alembic revision. **Current head is `0015_run_events` → this is `0016`.** Two invariants: the
column must be **nullable** so existing rows are untouched, and `content_hash`'s partial UNIQUE index
(`idx_source_tenant_content_hash`) must be unaffected — an additive nullable column cannot change source
dedupe, and it must stay that way.
