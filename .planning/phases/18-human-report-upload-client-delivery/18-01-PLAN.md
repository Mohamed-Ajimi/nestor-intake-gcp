<objective>
Add the backend surface that owns the human-report delivery lifecycle: a `POST /intakes/{id}/deliver`
verb (the sole `in_research → delivered` transition — run `completed` never auto-delivers), a
`POST /intakes/{id}/report/replace` verb (post-delivery correction, D-04/D-05), and a status-gated
`GET /intakes/{id}/report` client read (REPORT-02 invisibility). All three join the cross-tenant
denial suite from day one, and a dedicated `test_report_delivery.py` covers the happy paths,
status/PDF gates, mail-failure recoverability, and replace.

Purpose: This is the contract source of truth the frontend plans (18-02 admin block, 18-03 client
page) mirror. It composes existing, deployed seams (storage upload/signed-url, recipient/locale
resolution, results mail, transition-verb idiom) — no new table, no migration, no new secret.
Output: three new endpoints + two Pydantic models + one transition allow-list in
`intake_routes.py`, and two test files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client/user → API | Membership ids, storage_path, intake_id cross here — all untrusted |
| superadmin → API | Cross-tenant actor with a null-space repo; must target the intake's OWN space |
| API → GCS | Signed-URL minting; storage_path must be prefix-asserted before any sign/link |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-18-02 | Elevation / Info Disclosure | deliver/replace/report cross-tenant (BOLA) | mitigate | Scoped `repo.get` → existence-hidden 404; suite cases `deliver_cross_tenant` + `report_cross_tenant` from day one |
| T-18-03 | Tampering | Forged storage_path aimed at another tenant's tree | mitigate | `body.storage_path.startswith(f"{space_id}/{intake_id}/reports/")` prefix-assert → 404 before any link/sign (D-08) |
