## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin browser → AI skill trigger POSTs | fire live LLM/Whisper/embedding background runs on the intake (already tenant-scoped server-side) |
| admin browser → clipboard link | writes an authenticated /intake/{id} URL (no secret token) to the clipboard |
| browser → /templates/ static asset | shared, non-tenant template PDF served by vite (no tenant data) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-11-01 | Elevation of Privilege | AI skill triggers from the UI | mitigate | Triggers carry no tenant field — the backend derives scope from the verified Identity and existence-hides a cross-tenant intake as 404 (07 backend invariant). The UI only sends intakeId in the path; adding the CTA does not widen server authz. |
| T-7-11-02 | Information Disclosure | intake-link now uses intake.id (not a secret token) | accept | The authenticated /intake/{id} route requires an Identity Platform login (Phase 3 guard); intake.id is not a bearer secret. Copying it is safe — access is gated by auth, not by URL secrecy. This is the intended Phase-6 model that retired the token links. |
| T-7-11-03 | Information Disclosure | /templates/ static assets | accept | Template assets (NDA PDF, etc.) are SHARED, non-tenant documents by design (the legacy shared-path 404 was the bug). Serving them from the public static root exposes no client data — same trust level as the app logo. No signed URL needed. |
| T-7-11-04 | Denial of Service | repeated skill-trigger clicks | mitigate | Each CTA disables while its own busy state is set; the server creates one running run per dispatch. No new amplification beyond the existing apply/context-pack triggers. |
| T-7-11-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — uses existing lib/api/skills.ts + sonner + lucide already in the tree. No package-legitimacy checkpoint required. |
</threat_model>
