<objective>
Add the space-scoped READ surface the generated context pack has always lacked, and a
skill discriminator on the skill-run projection so the frontend can tell apply-intake-skill
runs apart from context-pack / structure / extract runs.

Two UAT gaps close here (both major):
1. "Artifacts-read endpoint + Context Pack display" — the generate-context-pack backend
   writes a `research_artifacts` row (`text_content` = briefing markdown, linked via
   `intakes.context_pack_artifact_id`) but NO GET surface projects it, so
   `ContextPackBlock.loadLatest`/`loadHistory` are stubbed and the pack never renders.
2. "Run-list skill discriminator" (minor) — `SkillRunView` omits the `skill` name, so
   `IntakeForm` (client validation proposals) and the admin review effect both assume the
   newest succeeded run is apply-intake-skill. With context-pack now producing succeeded
   runs too, that assumption is wrong. Surfacing `skill` lets the consumers filter (07-10).

Purpose: gives the frontend (07-10) a read endpoint to render the pack + a field to
disambiguate runs. Backend-only; no LLM call, no write path.
Output: `ContextPackView` + `GET /{intake_id}/context-pack` (latest + history query),
`skill` on `SkillRunView`, `ResearchArtifactRepository`, `get_research_artifact_repo`,
and tests asserting the projection shape, the BOLA 404, and the discriminator.

ENVIRONMENT: dev machine has NO Python/Docker (author-by-construction). Do NOT run pytest
or uvicorn locally. Acceptance criteria are source assertions; the suite runs in Cloud
Build and the change ships in the next image rebuild (note it in the summary, do not run).
</objective>
