## Decisions Made

- **The emits ride `_stage_log_transition`, not the `set_stage` shim.** The plan says to put them in the shim, beside the existing `_stage_log_transition` call. Doing so would have satisfied every listed acceptance criterion and still failed the plan's own must-have truth — *"the feed shows a `divider` at every stage boundary"* — because `_write_final_report` is a MODULE-LEVEL function that calls `_stage_log_transition` directly for `synthesize` and `done` (pipeline.py:3505 and :3704, each followed by its own real `set_stage`). The feed would have gone silent two stages before the end of every run. Emitting from the transition function covers all three call sites with one edit and reuses the existing transition detection exactly rather than duplicating it.
- **`result["facts"]` stays a subscript on the `agent_done` path.** A `.get("facts", [])` would emit `0 facts` for an angle whose fact count is merely unknown — a feed row asserting something the run never established, which is exactly T-15.3-23. Dropping the line is the honest degradation, and D-06's own contract says a run that loses events is DEGRADED while a run that dies is a REGRESSION.
- **The `agent_run` line uses `.get`, which is not an inconsistency.** The focus-area division path (`divide()` without winners) produces angles with no `sub_question` key at all, so a subscript there would drop the live line for every angle on a whole code path rather than for a degraded provider. The distinction is written into the code as a comment so a later reader does not "harmonise" the two.
- **The summary line's `text` is empty.** The design of record composes a summary row entirely from `worked / actions / items / cost` (every `kind:"summary"` entry in `ResearchRunImproved.tsx`). Adding a duplicate human sentence would be ignored by the renderer the next plan builds.
- **`wait_s: 0` is written rather than omitted on the coverage retry.** The coverage gate re-dispatches immediately on a different stream. An absent backoff is a fact about that retry, not missing data.

**3. [Rule 3 — Blocking/consistency] Two documentation comments tripped their own grep gates**
- **Found during:** Tasks 1 and 2

**4. [Rule 1 — Bug] Nested-brace f-string in the `plan` line**
- **Found during:** Task 2
- **Issue:** The stream count was first written as `f"{len({...set comprehension...})}"`. Legal in 3.11, but a set literal opening immediately inside an f-string replacement field is exactly the construct that breaks on a Python-version or formatter change, in a file with no local interpreter to catch it.
- **Fix:** `len(set(... generator ...))` — no braces inside the replacement field.
- **Files modified:** `research_division.py`
- **Verification:** `test_a_batch_of_three_angles_emits_one_dispatch_then_three_agent_runs` asserts `"3 angles"` in the emitted `plan` text.
- **Committed in:** `6050ccf`

**5. [Rule 2 — Missing critical functionality] Negative controls on both halves of test (i)**
- **Found during:** Task 3
- **Issue:** As specified, test (i) asserts that `run_angles` returns the same value for a degraded result. That would pass just as happily against an implementation whose thunk never touched `facts` at all — the input would simply have been harmless. This repository has a documented history of gates that were green because they proved nothing.
- **Fix:** Each half first asserts the construction genuinely raises when performed OUTSIDE the emitter (`KeyError` / `TypeError` on the dict shapes; `ValueError` from `_stage_event_summary_meta` on a corrupt `opened_at`), and the run_angles half additionally asserts the swallowed exception type appears in the emitter's WARNING log for the degraded shapes and does NOT for the well-formed one.
- **Files modified:** `tests/test_run_event_emit.py`
- **Verification:** both PASSED in build `c5771540`.
- **Committed in:** `b8cd633`
