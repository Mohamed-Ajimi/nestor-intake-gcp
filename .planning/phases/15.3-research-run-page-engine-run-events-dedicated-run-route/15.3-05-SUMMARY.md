## Accomplishments

- **The stage that decides what the whole run researches stopped being a silent gap.** Thirteen new lines: three for brief parsing (`intake`), six for orientation / candidate generation / clustering, four for the tournament (`workshop`). On run `d6bb3aae` the engine turned 11 client questions into 32 workshop parents and nobody could watch it happen; the counts that would have exposed that are now feed rows.

- **`brief_conflicts` will reach a human for the first time.** D4's "the brief assumes X, the world says Y" has been produced, parsed, de-duplicated and carried as pipeline data since 15.2-10, into a report section no completed run has ever rendered. The orientation `agent_done` line names the count and lists what conflicted. This is the engine's only channel for an angle the client did not think of.

- **`parse_brief`'s never-raises contract survives, and that is proven at the call site rather than asserted.** `pipeline.py` places this call OUTSIDE its checkpoint branch *in writing* because the parser is pure, free and safe. `test_a_parse_result_with_none_of_the_keys_the_lines_read_costs_only_the_lines` hands `_emit_parse_events` an object with **none** of the attributes the three lines read, with **nothing** on `run_events` monkeypatched, and asserts three swallowed `AttributeError`s in the emitter's log — so it cannot pass by never having reached the fragile construction. A `ParsedBrief` equality battery over eight degenerate briefs pins the return value itself.

- **The named no-behaviour-change proof is winner-list EQUALITY, and it holds twice.** Under a recorder that raises on every call, and again when `winner_count` itself cannot be computed, `run_tournament` returns the identical list — same indices, same ranks, same Elo. The engine's ranking decisions are under active design review (open questions Q1-Q4), and a phase that quietly altered which questions win would have corrupted the evidence the next clean run exists to provide.

- **The DoS bound is asserted as an EXACT count, not a ceiling.** 24 candidates over 4 rounds is 48 pairwise judgements; the tournament emits exactly one `dispatch`, exactly R `agent_run` rows, one `agent_done` and one `summary` — six rows. A second test flips `_TOURNAMENT_ROUNDS` to 2 and asserts exactly two round rows, so the count is provably R and not a hardcoded four.

- **D-G holds through a NEW egress.** A feed row is a fresh path out for client-authored text. `test_no_stakeholder_line_reaches_an_event` asserts that none of `mohamed.ajimi`, `@`, `MEEMZ`, `Primair contact`, `Decision-maker`, `NDA-status` or `Output-omvang` appears in any emitted text — and, so the test cannot pass against an implementation that emits nothing, that the client's decision **does**.

## Decisions Made

- **No context line reaches an event.** The design copy for the intake block is "Analyzing brief — {client}, {decision}", and the only client-ish label available inside this module is the brief's opening line. For the seam producer that is a project title; for any brief that leads with its context pack it is a `§9 Stakeholders` bullet — and `- **Primair contact klant:** MEEMZ (mohamed.ajimi@azentic.be)` is one of the four lines that bought paid third-party research on d6bb3aae. The line instead names the question count and the decision. `scrub_pii` at the emitter is the second layer, not the first (T-15.3-40).
- **The emit is outside `parse_brief`'s own `try`.** This is the difference between a missing feed line and a corrupted parse: inside the try, an event failure would be caught by the parser's `except` and returned as `source="error"`, sending the caller down its legacy whole-brief detector path — reintroducing D-G by way of a telemetry bug.
- **`conflict["assumption"]` is a subscript.** `_collect_conflicts` copies conflict entries verbatim out of whatever the orientation results carried, so a restored or degraded shape can lack the key. A placeholder would render a conflict the run never established (T-15.3-23); dropping the line is honest, and the count survives either way.
- **The tournament's closing line reports this stage's cut.** `winner_count(...)` is what reaches the evolve step; `enforce_scope_guard` can add more later for an uncovered client question. The code says so where the number is composed, so a later reader does not "fix" the line into claiming a final total.
- **The `summary` row's `text` is empty.** The design of record composes a summary entirely from `worked / actions / items / cost`; a duplicate human sentence would not be rendered. Same choice 15.3-03 made.

**2. [Rule 1 — Bug] Three event values were computed in the ARGUMENT LIST, outside their thunks**

- **Found during:** self-review after Task 2, before the tests were written
- **Issue:** This is the exact defect `emit_safe` exists to prevent, smuggled in as an argument and looking entirely correct:
  - `workshop.py`: `parents=len({c.get("parent") ... for c in candidates})` walked the whole candidate list **in the argument list**, so a malformed entry would have raised in the middle of the workshop;

  Arguments are evaluated before the callee is entered, so none of the three was protected by the emitter's `try` no matter how carefully the helper was written. Both grep gates were green throughout — this class of defect is invisible to them.
- **Fix:** two named compose functions (`_candidates_done_event`, `_tournament_done_event`), each documented as callable only from inside a thunk, plus `winner_count` moved inside the summary's lambda.
- **Verification:** `test_the_candidate_line_survives_a_malformed_population` and `test_a_tournament_whose_counts_cannot_be_built_selects_the_same_winners`, each with a negative control asserting the composition genuinely raises outside the emitter first. Both PASSED in build `bd2af7b3`.
