<objective>
Make the page honest about every state the run can actually be in, carry over the four
affordances the prototype drops, and fold the phase into the deploy it ships with.

Three purposes, kept distinct because each protects something different:

**The eight statuses.** The prototype models three (idle / running / done). Production has eight,
and two carry traps already learned the hard way and re-stated in D-11: `completed_degraded`
renders the SUCCESS card, because a degraded run still cost around forty-five dollars and keeps
its download, its verification report and its frozen feed; and `parked` renders its OWN card,
because routing it to the failure card offers a retry that discards every checkpoint the engine
already paid for.

**The four D-10 affordances.** The audit body drill-down is the EU AI Act Art. 12 record;
`chain_status` handling stops the page handing out raw output whose hash chain failed — the
prototype's "Download output" button is unconditional; resume on parked protects paid
checkpoints from a retry that discards them; and the Stop confirmation exists because the cost
incurred so far is not refunded and the run cannot be continued afterwards, while the prototype's
Stop fires immediately.

**The deploy record.** D-03 is an operator decision — 15.3 ships in the SAME deploy batch as the
15.2 gap fixes. The accepted risk was recorded because it will matter during V-01: the next live
run exercises a changed engine AND a changed frontend simultaneously, so an unexpected result is
harder to attribute. The mitigation D-03 requires of this phase is a deploy record stating
exactly what shipped together.
