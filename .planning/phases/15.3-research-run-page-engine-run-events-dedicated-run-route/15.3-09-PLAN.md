  <action>
    Create `frontend/src/components/research/RunFeed.tsx` implementing the `<interfaces>` signature.

    Grouping is DERIVED, never declared: fold the ordered `events` array into consecutive runs of
    the same `stage`. `stage` IS the group key — the engine already emits it and it already
    carries the stage vocabulary, so adding an engine stage costs this component nothing. Do not
    hardcode a stage list, a stage count or a stage order anywhere in this file; that data-driven
    property is the current component's best one and the reason Phase 15.2's added stages cost the
    UI nothing.

    Render by `kind`, using a lookup keyed on the string with a DEFAULT branch, not an exhaustive
    switch that can fall through to nothing. `RunEventKind` is available for the known set; an
    unknown kind from a newer engine build renders as a plain mono line rather than a blank row or
    a thrown error.

      * `divider` — the uppercase mono phase label with the hairline rule beside it. The text comes
        from the event, which now carries the human LABEL (plan 15.3-03), so this component does
        NOT look up `ENGINE_STAGES` and does not need to.
      * `summary` — the "Worked for X · N actions · N items · $Y" line, composed from
        `meta.worked` / `meta.actions` / `meta.items` / `meta.cost`, each part shown only when the
        event carries it. Reuse `research.feed.summaryCard` / `summaryItemsRead` where they fit.
      * `dispatch` — the bold header line with the zap glyph, at the group's base indent. This is
        the parent the agent rows hang under.
      * `agent_run` / `agent_done` / `agent_retry` / `agent_fail` — INDENTED one level, with the
        lucide icon the existing `StageIcon` already maps for each state (spinner / check / rotate
        / alert) and the existing colour vocabulary (done muted, retry amber, fail red).
      * `thinking` / `tool` / `search` / `plan` / `streams` — at base indent with their own lucide
        icons in the dim tone: a brain, a wrench, a magnifier, a branch, layers. Match the
        prototype's icon semantics; use lucide equivalents rather than inlining SVG paths.

    Affordances: `meta.is_live` on an `agent_run` renders the pink `live` badge. The LAST event in
    the array renders the blinking cursor — one interval owned by the feed, not one per row; the
    prototype's per-row `setInterval` is fine in a demo and is a thousand intervals here.

    Collapse: a group is COMPLETE when a later group exists after it. A complete group renders a
    "Show more / Show less" toggle and, when collapsed, its divider, the last two non-summary rows,
    and its summary. Default a completed group to collapsed and the current group to expanded,
    exactly as the design does.

    Performance (volume is a design input, not an afterthought): memoise the derived groups on the
    events array identity; memoise each row component with `React.memo` keyed on `seq` so a cursor
    advance re-renders the tail, not the history. A thousand-row feed must not re-render every row
    when one event arrives. Auto-scroll to the newest row ONLY while the run is active AND the user
    has not scrolled up — a feed that yanks the viewport away from something the operator is
    reading is worse than one that does not follow.

    Every user-facing string via `t()` in the `intake` namespace, new keys under
    `research.runPage.feed.*`, added to en, nl AND fr in this same edit, with real Dutch and French
    in the register the existing `research.*` keys use. No two-argument `t()` fallbacks.

    Tailwind utilities only. Do not modify `frontend/src/components/ui/`. No new npm dependency —
    lucide-react is already a dependency.
