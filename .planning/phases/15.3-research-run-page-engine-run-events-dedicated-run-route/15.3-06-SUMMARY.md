## The One Subtlety, Written Down Twice

**The cursor advances on `parked`; `completed_at` does not.** These pull in opposite directions and the difference is not cosmetic:

- `completed_at` answers *has this run ended*. A park is a pause awaiting one superadmin click, so stamping it would make the card render a duration for a run that is still waiting (15.2-19 / 15.2-24's rule, restated and left intact).
- `event_seq` answers *how far has its feed got*. A parked run's feed is **exactly** what the operator reads before deciding whether to resume. Freezing the cursor one tick early would hide the rows that explain the park, and a run that later resumes would keep emitting past a cursor that never moved — silently truncating the feed.

This is recorded in `finalize_parked`'s docstring (immediately below the paragraph that says D-L deliberately stops at that door, so the two rules are read together) and pinned by a **single test asserting both halves**. Splitting them into two tests would let someone "harmonise" the cursor with `completed_at` while the other test stayed green.

## The Constraint That Was Not Broken

The frame carries a **cursor, never a payload**. `test_the_frame_carries_no_event_payload` asserts no value in the returned dict is a list and that no `events` / `run_events` key exists. Two failures this prevents: the frame is re-sent **in full** on every change, so a thousand-row history would ride the wire per tick; and a second copy of the run's story on the authoritative connection is the first step toward two sources of truth for "is this run over". The SSE stream remains the sole terminal authority.

**3. [Rule 2 — Security/correctness] `_seam_event_seq` rejects more than the plan's literal `int()`-in-try/except**

- **Found during:** Task 2.
- **Issue:** The plan says "coerce with `int()` inside a try/except that skips the field on failure". A bare `int()` **accepts** `True` (→ `1`) and accepts negatives. Under T-15.3-50 (tampering with a seam-supplied cursor), a cursor that silently became `1` would rewind a live feed to its second row, and a negative cursor would make every tick re-fetch the whole run.
- **Fix:** Bools and negatives are rejected explicitly, each with a WARNING naming the field and leaving the column untouched. Floats still truncate toward zero — the safe direction, documented as such.
- **Verification:** `test_a_malformed_cursor_is_ignored_and_never_raises` parametrises `true` / `false` / `negative` alongside the string/dict/list/null cases; `test_a_float_cursor_truncates_toward_the_safe_direction` pins the accepted case.
- **Commit:** `cc568d7` (code), `8970c69` (proof).

## Notes for the Next Plan

- **15.3-08:** the key is `event_seq` on the research-run SSE frame; `null` means the run has produced no events (never `0`). Fetch the delta only when it **increases** — a frame arrives whenever anything else on the row changes too.
- **15.3-07:** the cursor is the `after_seq` the proxy's paged reader expects. 15.3-02's anti-rewind property matters here: an empty page returns the caller's own cursor, never 0.
- **A parked run keeps emitting.** Any consumer that stops polling the feed on `parked` will miss the rows a resumed run produces.
- **Nothing is deployed.** Migration 0013 is committed and gate-proven against a container Postgres; it has not run against live Cloud SQL. It rides the 15.2 deploy batch (D-03), where the proof is the literal `Running upgrade 0012 -> 0013` line.
