## Accomplishments

- **A long poll is distinguishable from a stall, in words, in the feed.** Every stride line reads, in full: *"Still waiting on Google {agent} — 5 min elapsed, poll 10 of 70, provider still reports running. The provider has not answered yet; a deep-research call routinely runs for tens of minutes. THIS IS A WAIT, NOT A STALL."* Elapsed minutes and attempt-of-max are what let an operator decide to wait rather than infer a hang from silence, and `test_a_long_poll_says_in_words_that_it_is_a_wait` asserts the arithmetic (`5 min elapsed`), the position (`poll 10 of 70`) and the sentence — at the production cadence of 30 s, with `asyncio.sleep` replaced so the test costs nothing.

- **The volume is bounded by a stride, not by hope.** 31 polls produced 4 `thinking` rows (one dispatch + three heartbeats). The test asserts an **upper bound** rather than an exact count, so retuning `NESTOR_RUN_EVENT_POLL_STRIDE` does not make it lie. At the default a 35-minute wait is seven lines, not seventy (T-15.3-33).

- **The fourth stream stopped degrading silently.** A missing `SERPAPI_API_KEY` or an open breaker previously produced a clean, wordless three-stream run — and to an operator, silence reads as absence, not as loss. There is now a named `agent_fail` on the pre-flight gate *and* on the provider being lost mid-session. Both name the reason (`serpapi_key_missing`, `serpapi_breaker_open`) and both say the run continues.

- **D-06 is true at the sites, and both halves of the gate hold on both files.** `run_events.emit(` is **0** and `from nestor_pulse_sdk.runs.run_events import` is **0** on `own_researcher.py` and on `audited_llm_client.py`. `emit_safe` sites: **7** in the own-researcher (floor 6) and **13** in the client (floor 5).

- **The named concrete raise is driven through the REAL call site.** `test_a_turn_whose_shape_makes_the_line_itself_raise_changes_nothing` hands `run_own_research` (a) an `emit_fact_list` input with no `facts` key, so the done line's skipped count raises, and (b) a `web_fetch` block whose content carries no URL, so the host construction raises. Nothing on `run_events` is monkeypatched — not `emit`, not `emit_safe`. Each half first asserts the construction genuinely raises **outside** the emitter (`_raw_fact_count`, `_host_of`), then asserts the swallowed exception type appears in the emitter's WARNING log for the degraded shape and is **absent** for the well-formed one, so the test cannot pass by never reaching the fragile code nor against a line broken for every run. ## Decisions Made

- **The poll loops learn their run from a ContextVar bound in `start_call`.** `gemini_deep_research_raw` and `openai_deep_research_raw` take no `run_id`, and their only production callers are `tools/gemini_adapter.py` and `tools/openai_adapter.py` — files that belong to no plan in this phase. Adding a parameter would have meant editing them, which the executor brief forbids; adding an unused optional parameter would have shipped a headline feature that emits nothing in production, which is a stub. What *is* available is that both adapters call `start_call` **immediately before** the raw method, in the same coroutine and therefore the same asyncio Task. A ContextVar set inside `start_call` is visible for the rest of that task, and `asyncio.gather` — which is how `research_division.run_angles` dispatches — gives each angle its own copied Context, so two concurrent angles cannot read each other's run. Instance state on `self` would have been shared by all twenty-four. `test_a_poll_with_no_run_context_emits_nothing` pins the other half: with no `start_call`, the client emits nothing rather than inventing a run.
- **The `search` line is emitted for a search that RAN.** The plan places it at the clamp. Doing that would have put `Searching — …` on the feed for a query refused by the budget or by an unavailable provider — a row asserting work the run did not do, which is T-15.3-23 and the same reasoning 15.3-03 used to keep `result["facts"]` a subscript. The line still carries the clamped, already-scrubbed value that was actually dispatched, read from the same `args` dict the provider received, so the feed row and the egress remain the same string. `test_a_refused_search_is_not_reported_as_a_search` pins it.
- **The heartbeat sits after the GET and after the terminal checks.** Emitted before the GET it could only say "we are in a loop". Emitted where it is, it says what the provider itself last reported — the "no state change" fact that, together with the fresh line arriving every five minutes, is what separates a wait from a hang.
- **The client's thunks were not made artificially fragile.** They contain arithmetic over local ints and `.get` chains, all inside `emit_safe`'s try. Manufacturing a raise in a paid poll loop to have something to test would be worse than the gap it closes; the plan's named concrete raise is proved where it genuinely exists, in the own-researcher's done and fetch lines, and the client's "calling is safe" half is covered by the raising-recorder test on the shared emitter.
- **The done line has no query number.** The design shows `Own query 01 done`. `run_own_research` handles one question and no per-run query index exists at that layer, so numbering one would be a fabricated ordinal. The line reads `Own query done — N facts from M pages · K skipped`.
