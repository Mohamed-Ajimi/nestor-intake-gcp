<objective>
Give the run its page: a flat route at `/admin/pulse/runs/:runId`, the transport that fills it,
and the entry point that leads to it.

Purpose: D-01 in the operator's own words — "running a deep research should open its own page …
users can close the page and reopen it to check advancement, timer shouldn't restart each time u
check on the page." Today the run is one card partway down an intake page, with no URL, and its
feed is a 28rem scroll area nested inside the page's own scroll.

This plan builds the SHELL and the DATA. The feed body is plan 15.3-09; the status cards are
15.3-10; the four carried-over affordances are 15.3-11.

Output: `research.ts` event verbs, the shared clock module, `useRunEvents`, the route, the
"Open run" link, and en/nl/fr keys.
</objective>

    and `fmtDate` into it VERBATIM — same bodies, now exported. Head the module with the reason it
    exists: the design prototype's timer counts from mount (`setSecs(s => s+1)` from
    `useState(0)`), which restarts at 00:00 on every visit and is the exact behaviour D-01 exists
    to eliminate; extracting the real one makes reusing it easier than rewriting it. Do not change
    any formatting or the `Date.now()` fallback.

    Create `frontend/src/lib/research/useRunEvents.ts`. Contract: given `intakeId`, `runId` and the
    SSE `cursor` (`run.event_seq`), it holds an append-only `events` array and a private
    `afterSeq` ref.
      * On mount (or when `runId` changes) it BACKFILLS: loop `getRunEvents(..., afterSeq, 500)`
        while `has_more` is true, appending each page and advancing `afterSeq` to
        `next_after_seq`. Cap the backfill at a bounded number of pages (10 pages / 5000 events)
        and stop with a flag the page can render as "history truncated" rather than looping
        forever on a pathological run.
      * Thereafter it fetches ONLY when `cursor > afterSeq`. A tick where the cursor has not moved
        performs NO request. This is the property that keeps a 3-second SSE cadence from becoming
        a 3-second request cadence.
      * It never removes or reorders events; it appends by ascending `seq` and de-duplicates on
        `seq` so a reconnect that replays a page cannot double a line.
      * Every failure path is silent-degrade: `apiFetch` returns `ApiResult`, so on `success:false`
        keep what is held, stop the in-flight loop, and let the next cursor advance retry. No
        throw, no toast — a transient events failure must not take the status card down with it.
      * An unmount cancels: guard every `setState` behind a `cancelled` flag exactly as
        `useActiveResearchRun` does.

    NO new npm dependency. `npm ci`, never `npm install`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL path to API | A user-supplied `runId` from a bookmarked URL drives every subsequent request |
| API JSON to DOM | Engine-authored event text is rendered into the operator's browser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.3-70 | Elevation of privilege | a client-role user opening `/admin/pulse/runs/{id}` | mitigate | every read is superadmin-gated server-side (15.3-07); the page shows the error card, and placement under `admin.pulse` inherits the existing admin guard |
| T-15.3-71 | Spoofing | an intake id supplied via query string | mitigate | the intake is resolved ONLY through `locateResearchRun`; the route accepts no intake parameter (TENANT-02) |
| T-15.3-72 | Information disclosure | event text rendered as markup | mitigate | React renders text children escaped; no `dangerouslySetInnerHTML` anywhere on this page |
| T-15.3-73 | Denial of service | unbounded backfill on a pathological run | mitigate | page cap (10 pages / 5000 events) with a visible truncation flag rather than an infinite loop |
| T-15.3-74 | Denial of service | a request per SSE tick | mitigate (INSPECTION-ONLY) | fetch only when `cursor > afterSeq`; a no-change tick issues no request. The guard is read, not exercised — no frontend test framework exists. Treat as designed-for, not proven |
| T-15.3-75 | Tampering | npm/pip/cargo installs | mitigate | this plan adds NO dependency; `npm ci` only, and `package-lock.json` unchanged is an acceptance criterion (the 2026-07-21 Radix/React #185 break came from `npm install`) |
</threat_model>
