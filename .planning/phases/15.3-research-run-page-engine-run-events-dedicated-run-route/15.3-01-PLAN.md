<objective>
Create the durable, ordered, append-only substrate the whole phase rests on: a `run_event`
table on the tribunal line, and a best-effort in-process emitter that any pipeline module can
call without threading a new argument through its signature.

Purpose: `stage_detail` is a MERGE keyed by stage (`stages.py::set_stage` writes
`stage_detail || :entry`), so a stage that reports twice overwrites itself and the
intermediate states a feed is made of are gone before anything reads them (D-04). An
append-only row with a monotonic `seq` is what makes "close the page and reopen it" show real
history instead of a snapshot.

Output: alembic `0015`, the `RunEvent` model, `runs/run_events.py`, its unit test, and the
engine gate updated to run that test.
</objective>

Vocabulary — the twelve line kinds of the design of record

Table `run_event` (tribunal schema):

    id          uuid PK
    tenant_id   uuid NOT NULL  FK org.id ON DELETE CASCADE
    run_id      uuid NOT NULL  FK run.id ON DELETE CASCADE
    seq         bigint NOT NULL          -- monotonic per run, assigned in-process
    ts          timestamptz NOT NULL DEFAULT now()
    stage       text NOT NULL            -- an ENGINE_STAGES key; ALSO the feed's group key
    kind        text NOT NULL            -- one of RUN_EVENT_KINDS
    text        text NOT NULL            -- scrubbed then clamped
    meta        jsonb NULL               -- whitelisted keys only

    index idx_run_event_tenant_run_seq on (tenant_id, run_id, seq)

Module `nestor_pulse_sdk/runs/run_events.py`:

    RUN_EVENT_KINDS: tuple[str, ...]
    MAX_TEXT_CHARS: int
    async def open_run(run_id: uuid.UUID, tenant_id: uuid.UUID) -> None
    def       emit(run_id, *, stage: str, kind: str, text: str, meta: dict | None = None) -> None
    def       emit_safe(run_id, *, stage: str, kind: str,
                        build: "Callable[[], tuple[str, dict | None]]") -> None
    async def close_run(run_id: uuid.UUID) -> None

`emit` is SYNCHRONOUS on purpose: an emit site inside a tight loop must not have to be
`await`ed, must not yield the event loop, and must not be able to raise into a paid angle.
`tenant_id` is bound once at `open_run` so the six emit-site modules never carry it.

`emit_safe` EXISTS BECAUSE `emit` IS NOT ENOUGH, and this is the crux of D-06.

Wrapping `emit`'s BODY protects nothing against the caller's ARGUMENTS, which are evaluated
BEFORE `emit` is entered. `f"... {result['cost']:.2f}"` raises `KeyError` — or `TypeError` on a
`None` cost — at the call site, inside the paid angle-dispatch loop, and no amount of defensive
code inside `emit` can catch it. An event write must never fail a run; today the text of an
event IS built from provider-shaped dicts that are exactly the thing most likely to arrive
malformed.

`emit_safe` takes a ZERO-ARGUMENT CALLABLE that returns `(text, meta)`, so the construction
happens INSIDE the try. Callers write:

    run_events.emit_safe(run_id, stage="deep_research", kind="agent_done",
                         build=lambda: (f"Angle {i+1} done — {result['facts']} facts",
                                        {"cost": result.get("cost_usd")}))

A raising `build` is logged at WARNING naming run / stage / kind and the row is dropped.

THIS IS THE ONLY EMIT ENTRY POINT ANY PIPELINE MODULE MAY USE. Plans 15.3-03/04/05 call
`emit_safe` and NEVER `emit`; `emit` stays public solely because `emit_safe` delegates to it and
the unit tests drive it directly. That rule is deliberately structural rather than a discipline:
about thirty emit sites land across five modules, and requiring thirty hand-written try/excepts
is the "thirty edits, each of which is a chance to miss one" anti-pattern this codebase already
names in `pipeline.py`'s `set_stage` shim. One helper is checkable with one grep; thirty
wrappers are checkable only by a reviewer who does not get tired.

    MAX-read failure specifically, seed from 0 and log that the run's event numbering may
    restart; degraded observability is acceptable, a dead run is not.

    `emit(run_id, *, stage, kind, text, meta=None)` — SYNCHRONOUS, no `await`, no DB touch,
    wrapped head-to-toe in `try/except Exception: log.warning(...)` and returning `None` on every
    path. In order: (1) look up the buffer; if the run was never opened, log ONCE per run at
    WARNING naming the run and drop — never open lazily, because a lazy open has no tenant_id
    and a tenant-less write is exactly the isolation bug this project forbids; (2) clamp `kind`
    to `RUN_EVENT_KINDS`, dropping the row with a WARNING when it is not a member (an
    out-of-vocabulary kind renders as a blank line in the feed, which is worse than an absent
    one); (3) coerce `stage` and `text` to `str`; (4) `scrub_pii(text)` FIRST and clamp to
    `MAX_TEXT_CHARS` (default 400) SECOND — that order is load-bearing: clamping first can cut
    an email in half and leave a recognisable fragment the scrubber no longer matches
    (D-07); (5) whitelist `meta` keys to `sub, is_live, worked, actions, items, cost, audit_id,
    provider, model, angle, attempt, max, wait_s`, dropping unknown keys with a WARNING exactly
    as `StageFeed._normalise_row` does, and running `scrub_pii` over every string VALUE in
    `meta`; (6) assign `seq` by incrementing the buffer's counter; (7) append to a bounded
    `collections.deque(maxlen=_MAX_QUEUE)`. When the deque is at capacity, count the drop and
    log at WARNING on the first drop and then every 500 — the feed losing rows must be visible,
    and a 24-angle run emitting a few thousand events is the expected case, not an anomaly.

    `emit_safe(run_id, *, stage, kind, build)` — the ONLY entry point pipeline modules use. One
    `try/except Exception` around BOTH the `build()` call and the `emit(...)` that follows it, so a
    `KeyError` / `TypeError` / `AttributeError` raised while composing the text or the meta dict is
    swallowed exactly like a failure inside `emit`. On a raising `build`, log at WARNING naming
    run / stage / kind and the exception type, then return `None`. Validate that `build()` returned
    a 2-tuple; anything else is logged and dropped rather than unpacked blindly. Document in the
    docstring WHY the thunk exists — arguments are evaluated before the callee is entered, so
    wrapping `emit`'s body is not the same control-flow guarantee as wrapping the call site — and
    that this is what makes D-06 true at the sites rather than only inside the emitter.

    The drain task loops: sleep `_FLUSH_S`, take up to `_BATCH` events under a lock, and write
    them with ONE `executemany`-shaped multi-row INSERT inside a single
    `sessionmaker()` + `session.begin()` + `set_tenant_context(session, tenant_id)` block —
    the same own-session pattern `set_stage` uses, so tenant binding stays in one place. Any
    exception is logged at WARNING and the batch is DISCARDED, not retried: retrying a failing
    write forever is how an observability path starts consuming the run it observes.

    `close_run(run_id)` — cancel the drain task, drain what remains synchronously (bounded by
    one final batch loop), pop the registry entry. Idempotent: a second call is a no-op, so the
    pipeline's `finally` and its `done` write can both call it.

    Env tunables, `os.environ.get(name, default)` exactly as `stage_feed.py` does:
    `NESTOR_RUN_EVENT_FLUSH_S` (1.0), `NESTOR_RUN_EVENT_BATCH` (200),
    `NESTOR_RUN_EVENT_QUEUE_MAX` (5000), `NESTOR_RUN_EVENT_TEXT_MAX` (400).

    Module docstring must state, in words: this module NEVER raises into a caller; a run that
    loses events is degraded, a run that dies because of an event write is a regression (D-06).

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.3-01 | Information disclosure | `run_events.emit` text/meta | mitigate | `scrub_pii` at enqueue, BEFORE the length clamp; meta values scrubbed too |
| T-15.3-02 | Information disclosure | `run_event` cross-tenant read | mitigate | ENABLE + FORCE RLS + `run_event_tenant_isolation` in migration 0015; reads go through `set_tenant_context` |
| T-15.3-03 | Denial of service | unbounded event volume on a 24-angle run | mitigate | bounded deque (`NESTOR_RUN_EVENT_QUEUE_MAX`), batched insert, drops counted and logged, never retried |

| T-15.3-05 | Tampering | `meta` growing arbitrary keys from a typo | mitigate | key whitelist + WARNING on drop, mirroring `StageFeed._ROW_FIELDS` |
