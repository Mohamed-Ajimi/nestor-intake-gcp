# Phase 15.3 Plan 01: Run-Event Substrate Summary

**An append-only, tenant-isolated, PII-scrubbed `run_event` row can now be written from anywhere in the pipeline by a synchronous call that is structurally incapable of failing the run — including when the text of the event is itself built from a malformed provider dict.**

## Accomplishments

- **The D-06 guarantee is structural, not a discipline.** `emit_safe(run_id, *, stage, kind, build)` takes a zero-argument thunk, and ONE `try/except Exception` wraps BOTH the `build()` call and the `emit(...)` that follows it. The failure this prevents — `f"...{result['facts']}"` raising `KeyError` at the call site inside the paid angle-dispatch loop, where no code inside `emit` can catch it — is driven through the real `emit_safe` by three separate exception types in the suite.
- **The one plausible wrong implementation is pinned by a negative control.** `test_hoisting_build_above_the_try_would_reintroduce_the_defect` builds the `built = build()`-above-the-try variant inline and asserts it raises `ZeroDivisionError` on the exact input the shipped one swallows. Without it the D-06 tests could have passed against an `emit_safe` that never had a defect to prevent.
- **Scrub-before-clamp is pinned by counterfactual, not by presence.** The order test asserts that clamp-then-scrub *does* leak the fragment `someone@ex` before asserting that the shipped order removes the address entirely. A test that only checked "the address is gone" would have passed on both orders.
- **The engine gate reconciles at 28 of 28.** `collecting: 28 of 28 expected files`, read from the log rather than inferred from the exit status.

## Decisions Made

- **The queue-full policy refuses the NEWEST row.** The plan asked for both `deque(maxlen=...)` and a counted drop, which are in tension: `maxlen` eviction discards the OLDEST silently and leaves nothing to count. Resolved by keeping `maxlen` as a hard ceiling *and* adding an explicit capacity check that refuses the new row and counts it. The early events are what explain how a run got where it is, and a feed that silently rotates its own history is the failure mode this table exists to end.
- **The `RunEvent` ORM model is not the write path.** The emitter uses a raw multi-row INSERT so the emit path stays cheap and never opens the ORM identity map inside a paid run. Both definitions are documented as needing to stay in step.

Notes the downstream plans need:

- **Call `emit_safe`, never `emit`.** `emit` stays public only because `emit_safe` delegates to it and the tests drive it directly. One grep (`grep -n "run_events.emit("` returning nothing outside this module and its test) is the check.
- **`build` must return a 2-tuple `(text, meta)`.** A list is rejected. Anything else is logged and dropped.
- **`meta` keys are whitelisted:** `sub, is_live, worked, actions, items, cost, audit_id, provider, model, angle, attempt, max, wait_s`. A key outside that set is dropped with a WARNING; extending the set is an edit to `_META_FIELDS` in this module, not a per-caller decision.
- **`open_run` / `close_run` must be wired by whichever plan owns the pipeline lifecycle.** Until then every `emit_safe` drops with one WARNING per run. `close_run` is idempotent, so the pipeline's `finally` and its `done` write may both call it.
