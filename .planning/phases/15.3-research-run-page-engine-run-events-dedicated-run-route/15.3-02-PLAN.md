<objective>
Make the persisted events readable: one paginated, seq-ordered, tenant-scoped endpoint, and one
additive cursor field on the metrics the intake poll driver already fetches every ~3 seconds.

Purpose: D-01 requires that closing and reopening the page shows TRUE progress. That is a
backfill read, not a stream — the stream only carries what happens while you are watching. The
`event_seq` cursor is what lets the page fetch only the delta instead of re-downloading a
thousand rows per tick.

Output: `GET /api/runs/{run_id}/events`, `RunMetrics.event_seq`, and their denial/pagination tests.
</objective>

<interfaces>
Produced by this plan; consumed by 15.3-06 (metrics mirror) and 15.3-07 (intake proxy).

    GET /api/runs/{run_id}/events?after_seq={int}&limit={int}

    200 -> {
      "run_id":        str,
      "events":        [ {"seq": int, "ts": str, "stage": str,
                          "kind": str, "text": str, "meta": dict | null} ],
      "next_after_seq": int,      # the highest seq in this page; the client's next cursor
      "has_more":       bool      # true when the page was cut by `limit`
    }
    404 -> unknown OR cross-tenant run (indistinguishable, by design)

    after_seq default 0, limit default 500, clamped to 1..1000.
    Ordering is `seq ASC`. There is NO descending mode and NO offset paging.

    RunMetrics gains ONE additive field:
      event_seq: int | None   # MAX(run_event.seq) for the run; None when no events
</interfaces>

    Add `get_run_events` handler for `@router.get("/{run_id}/events", response_model=RunEventPage)`.
    PLACE IT ABOVE the catch-all `@router.get("/{run_id}", ...)` — FastAPI resolves in declaration
    order and a later-declared sub-path is shadowed. `get_run_audit_body` is already above it;
    put this beside that one.

    Body, in order: resolve `Run` by id via `select(Run).where(Run.id == run_id)` +
    `scalar_one_or_none()` and raise `HTTPException(404, "run not found")` when None — the
    RLS-scoped session makes a cross-tenant run indistinguishable from a missing one, and that
    non-distinguishability is the security property. Then clamp `limit` to `max(1, min(limit,
    1000))` and coerce `after_seq` to `max(0, int(after_seq))`. Then one `text()` query:
    `SELECT seq, ts, stage, kind, text, meta FROM run_event WHERE run_id = :rid AND seq >
    :after ORDER BY seq ASC LIMIT :lim` with `lim = limit + 1`, so `has_more` is decided by
    whether the extra row came back rather than by a second COUNT query. Trim the extra row
    before building the response. `next_after_seq` is the last returned row's `seq`, or the
    incoming `after_seq` when the page is empty — never 0 on an empty page, which would rewind a
    live client to the beginning of the run.

    Declare `after_seq` and `limit` as typed query parameters with defaults (0 / 500) so FastAPI
    rejects a non-integer before the handler runs.

    Separately, in `get_run_metrics`, add ONE query
    `SELECT max(seq) FROM run_event WHERE run_id = :rid` and pass the result as `event_seq=`.
    Comment that this is an index-only backward scan on `idx_run_event_tenant_run_seq` and is
    why the intake poll driver can afford it at its ~3s cadence.

    Do NOT add any status gate to the events endpoint. A `failed`, `cancelled` or `parked` run is
    exactly the run whose events an operator most needs, and the CONTEXT records that today's
    failed/cancelled cards DROP the feed — this endpoint must not repeat that. Follow
    `get_run_verification`, which is deliberately gate-free, not `get_run_report`, which is gated.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP caller → tribunal runs API | A caller-supplied `run_id`, `after_seq` and `limit` cross into a DB query |
| tenant GUC → run_event rows | The RLS wall that must make another tenant's run invisible, not merely denied |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.3-10 | Information disclosure | `get_run_events` cross-tenant `run_id` | mitigate | `scalar_one_or_none()` under the tenant GUC -> `HTTPException(404, "run not found")`; no forbidden-status arm exists, pinned by a source gate |
| T-15.3-11 | Information disclosure | run existence leaked by response shape | mitigate | a missing run and a foreign run take the identical 404 path; no empty-200 arm |
| T-15.3-12 | Denial of service | unbounded page on a thousand-event run | mitigate | `limit` clamped 1..1000, `limit + 1` probe instead of COUNT, seq-ordered index scan |
| T-15.3-13 | Denial of service | `MAX(seq)` on a ~3s poll cadence | accept | index-only backward scan on `idx_run_event_tenant_run_seq`; the handler already runs three counts at that cadence |
| T-15.3-14 | Tampering | injected `after_seq` / `limit` | mitigate | typed query params + explicit `int()` coercion + clamp; parameterised `text()` binds, never string interpolation |
| T-15.3-15 | Tampering | npm/pip/cargo installs | accept | no new dependency |
