Consumed from plan 15.3-01, unchanged:

    from nestor_pulse_sdk.runs import run_events
    await run_events.open_run(run_id, tenant_id)
    run_events.emit_safe(run_id, stage=..., kind=...,
                         build=lambda: (text, meta))   # sync, never raises
    await run_events.close_run(run_id)

USE `emit_safe`, NEVER `emit`. This is not a style preference and it is the D-06 requirement at
the call site. Arguments are evaluated BEFORE the callee is entered, so
`emit(..., text=f"{result['facts']} facts")` raises `KeyError` in the paid angle-dispatch loop no
matter how defensive `emit`'s body is. `emit_safe` takes a zero-argument callable returning
`(text, meta)`, so every f-string, every subscript and every `.get()` chain runs inside the
emitter's try.

Do NOT hand-write a `try/except` per emit site instead. There are about thirty sites across five
modules; per-site discipline is checkable only by a reviewer, whereas
`grep -c "run_events.emit(" <file>` == 0 is checkable by a machine.

`kind` is one of: thinking, tool, search, plan, streams, dispatch, agent_run, agent_done,
agent_retry, agent_fail, summary, divider.

`meta` accepts only: sub, is_live, worked, actions, items, cost, audit_id, provider, model,
angle, attempt, max, wait_s.

THIS PLAN ADDS NO NEW KIND AND NO NEW META KEY. If a site seems to need one, it does not — use
`sub` for the secondary line and put the rest in `text`.
