<objective>
Put running software in the client project and prove it works with one real research run,
before anyone from the client has an account.

Purpose: D-23.4-06 exists because every earlier environment change in this repo shipped
unobserved. The rule for this plan is that nothing is recorded as working on the strength of
a green exit code: every claim is a read-back, a log line or something seen in a browser.

Output: both migration lines applied with their literal upgrade output BEFORE any service is
deployed, four running services, the second-pass URL wiring, a seeded superadmin, one completed
research run with a saved report, and a `client.tfvars` with no sentinels left.

Ordering is not a style choice here. `tribunal-worker` boots into a poll loop that claims before
it sleeps, so a worker deployed ahead of `tribunal-migrate` reads a table that does not exist,
and `/readyz` cannot see it — that endpoint is a bare `SELECT 1` through the pool
(`backend/app/main.py:296-309`) and returns 200 against an unmigrated database.

ahead of it cost more on top, all uncapped (`NESTOR_TRIBUNAL_UNCAPPED=1`, spend cap deferred
by standing operator ruling). The client project's Anthropic key must be funded before Task 3.
