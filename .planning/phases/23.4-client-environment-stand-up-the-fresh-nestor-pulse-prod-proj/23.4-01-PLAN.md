<objective>
Make `infra/` apply cleanly to a SECOND GCP project, then stand the client project's
infrastructure up with it.

Purpose: `infra/` is already multi-project-capable in its variables, but three things stop a
clean apply against `nestor-pulse-prod`: state has nowhere to live (the GCS backend is
commented out and no `.tfstate` exists), the image paths are hard-bound to `var.project` so
"promote the same digest" is not expressible, and two defaults are wrong for any new
environment (`tribunal_worker_stale_minutes = "90"`, a stopgap whose condition has passed —
D-23.4-07; and `nestor-api` `min_instance_count = 0`, which would silently disable the phase
23.3 reconciler — DEF-23.3-14). D-23.4-05 adds a fourth: the client must use ONE Anthropic
secret for nestor-api and both tribunal services, and as written that makes Terraform try to
create the same `secret_id` twice.

Output: a parametrised `infra/`, a committed `infra/env/client.tfvars` + backend-config, and
a client project whose Cloud SQL instance, service accounts, buckets, secret CONTAINERS,
Cloud Run services and jobs all exist. NO service image is deployed here and NO secret VALUE
is handled by the agent.
</objective>

**RULING 2 — image registry model.** `client.tfvars` currently sets
`image_registry_project = "project-cb01b861-cb4a-438d-b9a"`, i.e. the client project's Cloud

target. Alternative: set it to `""` and copy each image into the client project's own repo
before deploy, which costs a copy step per release and means the client runs a
byte-identical but separately-stored image.

image that any client revision references) carried into `infra/BOOTSTRAP.md` by plan 23.4-05.
