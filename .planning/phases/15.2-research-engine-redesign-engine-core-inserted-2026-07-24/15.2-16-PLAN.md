<decisions>
Decisions this plan makes inside Claude's Discretion (CONTEXT.md § *R1/R2/R3 parameters*,
§ *R7 mechanics*). Record each one in the SUMMARY. **DEC-3 is governed by 15.2-19** (the poll driver
and SSE live there) and is restated here verbatim because DEC-6's park branch and this plan's
resume verb depend on it; **DEC-5 is split** — the signature/sequence primitives are this plan's,
the `[park#<seq>]` mail marker is 15.2-19's.

**DEC-1 — Checkpoint granularity is per-stage, and deep research is per-ANGLE, not per-provider.**
15.2-RESEARCH § R3 proposes `ckpt_research_<provider>`. That is one row per provider, but
`run_angles` dispatches one paid deep-research job **per angle**, and a single provider serves
several angles (`_STAKES_PROVIDER`: high→gemini, med→openai, low→claude, plus the doubled
high-stakes copy). Per-provider granularity would silently discard angles 2..n of the same provider
on resume — i.e. re-charge them. So the research checkpoint is ONE `ckpt_research` row holding a
list keyed by angle index, guarded by a digest of the angle queries.

**DEC-2 — A resume never silently re-dispatches a paid job.** `NESTOR_TRIBUNAL_RESUME_REDISPATCH`
defaults to `"false"`: when a persisted job id is no longer retrievable (Gemini 404/410, OpenAI
`NotFoundError` past the ~10-minute retention window — RESEARCH A11), that angle returns a normal
error envelope with a named reason and the stream degrades (D-12/D-17: one or two streams lost ⇒
`completed_degraded`). Set the knob to `"true"` to fall through to a fresh dispatch. Rationale: the
operator's standing rule is "NO ESTIMATES — facts and correct calculations only"; quietly paying
twice for the same deep-research job is the money-side equivalent of a silent green.

**DEC-3 — `parked` IS terminal for the poll driver and for the SSE stream.** *(Owned by 15.2-19;
restated here because this plan's resume verb relies on it.)* 15.2-RESEARCH § R4 says "`parked` is
not terminal for the poll driver but IS terminal for the mail". That is wrong in this codebase:
`run_poll_driver` is a FastAPI `BackgroundTask` and a parked run waits on a human click that may be
hours away — a driver that keeps polling is a leaked task holding a Cloud Run instance, and the SSE
handler would burn to its 10-minute `MAX_STREAM_SECONDS` cap and put the browser into
`research.ts`'s reconnect loop. So `parked` joins all four terminal/close sets, and the intake-side
Resume endpoint schedules a **fresh** driver. Record this deviation explicitly.

**DEC-4 — The park signal travels on `RunMetrics.park`, an additive optional field.** The ONLY
channel from the engine to the intake driver is `GET /api/runs/{id}/metrics`, and `RunMetrics` has
no `error_message`. `get_run_metrics` projects `run.verification_summary["park"]` onto a new
optional `park: dict | None = None`. Additive Pydantic field, additive JSONB key on an existing DB
column — no audit payload, no migration, `verify_chain` untouched.

**DEC-5 — Mail idempotency is a monotonic `park.seq` carried by `ckpt_park`.** The pipeline hashes
`(stage, redacted reason)` into a signature; re-parking for the SAME signature keeps `seq`, a
different signature increments it. *(This plan owns `park_signature()` / `next_park_seq()` and the
`ckpt_park` write. 15.2-19 owns the consumer: `finalize_parked` stamps `error_message` as
`"[park#<seq>] <reason>"` and the driver skips the mail when the mirror row already carries that
exact marker prefix, so two drivers scheduled for the same park event send one mail.)*

**DEC-6 — The pipeline reports facts; `terminal_state()` decides.** The pipeline never returns the
string `"parked"`. It returns `terminal_inputs` constructed so that `terminal_state()` provably
yields `"parked"` (F6 sets `streams_lost == streams_total`; a hard wall sets `hard_wall=True`; a
gate stage that could not run sets `verify_ran=False`; a walled synthesis sets `synthesis_ran=False`).
The worker calls `terminal_state(**terminal_inputs)` and writes whatever it returns. If it ever
returns a non-park value on the park branch that is a genuine contract violation: log ERROR naming
it and write the computed value anyway. There is exactly ONE degradation/park rule in the codebase.
</decisions>
