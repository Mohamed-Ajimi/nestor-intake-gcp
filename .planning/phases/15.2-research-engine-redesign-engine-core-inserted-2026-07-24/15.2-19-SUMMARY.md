# Phase 15.2 Plan 19: Park Surfacing + the Click-Only Resume — Summary

The intake backend and operator UI half of D-17 park: a walled Tribunal run now mirrors as
`parked` with its reason in words, mails the triggering superadmin exactly once, closes both
server-side terminal sets and both client-side ones, and is resumed by a superadmin-only,
space-scoped, attempt-free `POST /intakes/{intake_id}/research/resume` that re-queues the
SAME engine run so nothing already paid for is re-charged.

## Vocabulary: three things that stayed three things

This was the plan's core risk and it held end to end:

| State | Trigger | What the operator gets |
|---|---|---|
| `completed_degraded` | 1-2 of 4 streams lost | The completion card + bundle + completion mail. A real ~$45 deliverable. |
| distiller fallback (D-14) | the distiller falls back | **Nothing special.** Normal operation, no status of its own, no mail, never near `terminal_state()`. |
| `parked` | ALL streams lost, or a hard wall (monthly cap / exhausted credits / 402) | The amber Resume card + the park mail + a free resume. |

`is_research_success("parked")` is `False` and `RESEARCH_SUCCESS` is byte-unchanged, so a
parked run gets no bundle, no report row and no chain verdict. `finalize_failed` is not on the
park path at all — its `{"failed","cancelled","parked"}` clamp now carries a comment saying it
exists only to protect the `on_error` route.

## Decisions

**DEC-3 — `parked` IS terminal for the poll driver and the SSE stream. Shipped as planned, and
it is a deliberate deviation from 15.2-RESEARCH § R4**, which says "`parked` is not terminal
for the poll driver but IS terminal for the mail". That is wrong for this codebase:
`run_poll_driver` is a FastAPI `BackgroundTask` and a parked run waits on a human click that
may be hours away, so a driver that kept polling would be a leaked task pinning a Cloud Run
instance, and the SSE handler would burn to its 10-minute `MAX_STREAM_SECONDS` cap and drop
the browser into its reconnect loop. All four sites 15.2-09 deliberately left open now
recognise `parked`; the Resume endpoint schedules a **fresh** driver. The formula recorded in
three docstrings: *terminal for the STREAM, never for the RUN*.

**DEC-5 consumer half — shipped as planned.** `finalize_parked` stamps
`error_message = "[park#<seq>] <reason>"` (clamped to 1000 chars) and the driver reads the
prior mirror row **before** finalizing; when that row is already `parked` and its
`error_message` starts with this exact marker, the mail is skipped and a WARNING naming the
marker is logged. Two drivers for the same park event send one mail; a genuinely new park
(different stage or reason ⇒ higher `seq`) does mail. If the prior-row read itself fails, the
code defaults to **not** notified and logs loudly — a duplicate mail is a nuisance, a dropped
one is the operator's only signal that a paid run stopped (the 16-05 failure class).

**DEC-1, DEC-2, DEC-4, DEC-6 shipped in 15.2-16 and the seam contract held from this plan's
point of view.** The 200/404/409 shape of `POST /api/runs/{run_id}/resume` and the additive
`RunMetrics.park` descriptor were consumed exactly as documented; nothing had to be
re-derived and no engine file was touched.

## New endpoint (for the 15.2-18 deploy runbook)

```
POST /intakes/{intake_id}/research/resume        (intake FastAPI, sync def)
  auth: superadmin only. _superadmin_gate is declared BEFORE get_tenant_repo so it
        resolves first, plus an in-body role re-check.
  202 -> {"research_run_id": "<uuid>", "status": "queued"}
  404 -> non-superadmin (incl. null-space), cross-tenant/missing intake, no run,
         run carrying no tribunal_run_id (WR-03). Body echoes no ids.
  409 -> the latest run's status is not exactly "parked"
  502 -> any other seam or transport failure
```

Seam-error mapping: engine **404 → 404** (existence-hidden), engine **409 → 409** (same
"Research is not paused for this intake" message), **everything else, plus `httpx.HTTPError`
transport failures → 502 "Research engine unavailable"**. Never an unhandled 500, and never a
driver scheduled after a failed seam call — the seam is called OUTSIDE any held DB session and
BEFORE the mirror patch.

The mirror patch (`status="queued"`, `error_message=None`, `completed_at=None`) and the
`research.resumed` audit row with `metadata={"from":"parked","to":"queued"}` commit in the SAME
short `tenant_session`, strictly before `background.add_task`. `run.attempt` is passed through
UNCHANGED and `_MAX_ATTEMPTS` is never consulted (F-02). The intake row's own status is not
touched — it is already `in_research`.

- **Found during:** Task 2
- **Issue:** The plan places `resume_research` immediately after `trigger_research`, but
  `_superadmin_gate` was defined ~200 lines later. A `Depends(...)` default is evaluated at
  `def` time, so the module would have raised `NameError` at import.
- **Fix:** Moved the `_superadmin_gate` definition to just after `_next_research_status`, with
  a comment recording why it lives there. Its body is byte-identical; no authorization changed.
- **Commit:** `9c70b91`

**2. [Rule 3 — Blocking] Toast locale keys placed in `admin.json`, not `intake.json`**
- **Found during:** Task 3

  `useTranslation("admin")`, so `intakeDetail.toast.*` resolves against `admin.json`. The
  plan's own claim that `intakeDetail.toast` sits in `intake.json` is stale — `researchStarted`
  / `researchStartFailed` live in `admin.json` today.
- **Fix:** 4 keys in `intake.json` (the component's namespace), 2 in `admin.json`. i18n-audit
  CHECK A and CHECK B both pass.
- **Commit:** `f73fd9f`

**3. [Rule 1 — Formatting regression] Two authored lines reshaped to hold the lint baseline**
