# Phase 15.2 Plan 14: Ask For The Fact List, Read It Back Summary

**The three third-party deep-research streams are now asked for a D8 machine-readable fact list at dispatch and read back D8-first, with a stream that ignores the instruction falling back to full prose distillation — recorded per provider in plain words — instead of contributing nothing.**

## Performance

- **Duration:** ~42 min across two executor sessions (the plan was interrupted after Task 2)
- **Started:** 2026-07-26 20:45 +02:00 (Task 1)
- **Completed:** 2026-07-26 21:27:15 +02:00 (Task 3 commit)
- **Tasks:** 3 of 3
- **Files modified:** 3 existing files + 1 new test file

## Accomplishments

### Task 1 — Ask for it (`dcc688d`)

`research_division.py` gained a module-scope allow-list, a kill switch, and a dispatch-site hook:

- `_D8_PROMPT_PROVIDERS = ("gemini", "claude", "openai")` — the three streams whose only
  lever is a prompt instruction, because structured-output mode is closed to a call that
  also asks for grounded citations. The own-researcher (`"own"`, registered by 15.2-13) is
  deliberately absent: 15.2-12 gives it a forced `emit_fact_list` client tool, which is tool
  use and therefore citation-compatible.
- `_D8_BLOCK_ENABLED` reads `NESTOR_TRIBUNAL_D8_FACT_LIST` (default `"true"`) at **import
  time**, matching `degraded_parallel._flag` so tests patch the resolved boolean.
- `_with_fact_list_block(query, provider, language) -> tuple[str, bool]` appends the block
  after a blank line, function-locally importing `build_fact_list_prompt_block`. It never
  raises: any failure returns the plain query and logs a WARNING, degrading to D-14 rather
  than aborting a paid angle.
- The call sits in `run_angles._one_angle` **after** `runner = _PROVIDER_RUNNERS[provider]`
  and **before** `async with sem:`. That ordering is load-bearing — it is what makes the
  coverage retry (`force_provider=alt`) attach the block for the provider it *actually*
  retried on.
- Every successful result tuple now carries `_d8_prompted: True|False` alongside `_angle`
  and `_stakes`.
- `divide()` and `_divide_from_winners()` now put the run's **report** language on every
  angle dict under the key `"language"`.

### Task 2 — Read it back (`9cc2e9f`)

`synthesis/steps.py` gained the orchestrator, two frozen dataclasses, and one additive
distiller change:

- `_build_distiller_prompt` and `claim_distiller` both gained keyword-only
  `full_extraction: bool = False`. The new rule text is built as a fragment that is the
  **empty string** in the default case, exactly the way `lang_rule` is — so the default
  prompt is byte-identical and neither D-15-protected test file needed editing.
- `collect_provider_facts` reads each report D8-first with 15.2-04's parser, always strips
  the block from the prose, sends only the reports that produced no list into **one**
  full-extraction distillation, normalises everything to one key set, and calls
  `_dedupe_claims` exactly once.
- Per-provider `ProviderFactsRecord` counters, a plain-words `fallback_notes` sentence, and
  a best-effort feed row per provider.

### Task 3 — Prove it with zero LLM calls (`7388366`)

`tests/test_factlist_fallback.py`: 37 tests, 1017 lines, no network, no database, no mocking

## Contract for 15.2-15 (consume verbatim)

### Signature

```python
async def collect_provider_facts(
    *,
    provider_reports: list,
    mission_brief: dict,
    audited: "AuditedLLMClient",
    run_id: uuid.UUID,
    tenant_id: uuid.UUID,
    feed: Any = None,
) -> ProviderFactsResult
```

### Dataclasses (both `@dataclass(frozen=True)`)

`ProviderFactsResult` — fields, in order:

| field | type | default |
|---|---|---|
| `claims` | `list[dict]` | `[]` |
| `reports` | `list[tuple[str, dict]]` | `[]` |
| `not_found` | `list[str]` | `[]` |
| `records` | `list[ProviderFactsRecord]` | `[]` |
| `fallback_notes` | `list[str]` | `[]` |

`ProviderFactsRecord` — fields, in order: `provider: str`, then
`reports_seen`, `reports_with_fact_list`, `reports_fell_back`, `facts_from_list`,
`claims_from_fallback`, `parse_errors`, `rejected_urls`, `dropped_over_cap` (all `int`,
default `0`), `prompted: bool = False`, `reason: str | None = None`.

`reason` carries 15.2-04's own `FactListResult.fallback_reason` **verbatim** (the first one
seen per provider). The count-bearing sentence an operator reads is in `fallback_notes`.

### Claim dict key set

Every claim carries the nine 15.2-04 keys **plus** `fact_source`, whichever path produced it:

```
text, facet, evidence, found_by, source_urls,
certainty, provider_quality, source_domain, quality_tier_hint,
fact_source
```

`fact_source` is `"fact_list"` or `"distiller_fallback"`.

On the **`distiller_fallback`** branch these four are hard-written to `None` in Python
(T-15.2-61 — a security control, not a default):
`certainty`, `provider_quality`, `source_domain`, `quality_tier_hint`.
`source_urls` is `[]` unless the claim already carried a list. The domain heuristic fills the
tier downstream, per D-13's provider-stated-wins / heuristic-fallback rule.

### Wiring instructions for `pipeline.py`

**The plan's line reference `pipeline.py:486-492` is stale.** In the tree as merged the
`claim_distiller` call is at **`pipeline.py:950-956`**, inside the `distill` stage between
the two `set_stage(..., "distill", ...)` calls.

1. Replace that `claim_distiller(...)` call with `collect_provider_facts(...)`, passing the
   same `mission_brief` / `audited` / `run_id` / `tenant_id`, plus the `distill` `StageFeed`
   as `feed=`.
2. Use `result.claims` where `claims` is used today (the `if not claims:` early-return at
   `:962` still applies unchanged).
3. **Rebind `provider_results = result.reports` immediately after the call.** That single
   rebind covers every downstream consumer without editing each site — the current uses are
   `_extract_sources_for_group` (`:1281`), `_extract_sources_for_claim` (`:1360`, `:2461`),
   the `provider_results=` argument at `:1454`, and `scrub_research` (`:1703-1704`). All of
   them then see prose with the machine-readable block already removed.
4. Carry `result.fallback_notes` and `result.not_found` into the verification report
   (`research_gap` rows / D-08's "What we could not establish" — 15.2-06 / 15.2-08).

**WARNING — do NOT feed `fallback_notes` into `terminal_state()`**, nor into `pipeline.run()`'s
`_note_degradation` accumulator, which is what feeds it. Per D-14 a fallback "degrades one
stream, not the run". D-12's degrading conditions are a non-zero bucket 3, a stream lost to a
tripped breaker, a workshop fallback, or a skipped stage — a D-14 fallback is none of those,
because the provider's research still reached the merge in full. Promoting it would drain
`completed_degraded` of meaning in exactly the way D-12 warns about for recovered retries.

### Resolved `fallback_notes` sentence templates

Built **only** from the provider name and integers (T-15.2-66), where `k` = reports that fell
back, `m` = reports seen, `c` = claims from the fallback.

Asked but did not comply (`prompted=True`):

> `{provider}` returned no usable fact list for `{k}` of `{m}` research report(s) — its prose was run through the full-extraction distiller instead (`{c}` claims), so those claims carry no provider-stated certainty or source quality and the domain heuristic fills the tier (D-14). The research still reached the merge; nothing was dropped.

Never asked (`prompted=False` — the kill switch, or the forced-tool stream):

> `{provider}` was not asked for a machine-readable fact list, so `{k}` of `{m}` research report(s) had none — its prose was run through the full-extraction distiller instead (`{c}` claims), so those claims carry no provider-stated certainty or source quality and the domain heuristic fills the tier (D-14). The research still reached the merge; nothing was dropped.

Both clear the >40-character plain-words bar for every input. The distinction exists because
an operator told "gemini did not comply" when gemini was never asked has been given a false
fault report.

### Per-angle language key

`divide()` did **not** already carry a per-angle report language from 15.2-13. This plan
**added** it, under the key **`"language"`**, on every angle dict `divide()` builds (the
primary angle, the doubled high-stakes copy, both broadcast-fallback angles) and in
`_divide_from_winners()`. It is sourced from `(mission_brief.get("language") or "").strip()`.

It is deliberately distinct from 15.2-13's `"langs"`, which is the **search** surface (which
languages an angle may search in). `"language"` is the **output** language the STATEMENT
cells must be written in. `run_angles` reads it purely as dispatcher metadata; it does not
change the query text and plays no part in the trim rule.

### Own-researcher hand-off — **TO BE CONFIRMED by 15.2-12 / 15.2-15**

`collect_provider_facts` assumes the forced-tool stream delivers its facts as
**`result["facts"]` — a non-empty `list` of `dict`s** on the result dict. When that is
present the facts are normalised and used verbatim, the report is counted as
`reports_with_fact_list`, and **the stream is never distilled** (re-distilling a stream that
already emitted structured facts is a pure double spend for a worse result). A malformed
value (e.g. a string) falls through to the prose path harmlessly.

This assumption is pinned by `test_pre_parsed_facts_are_used_verbatim_and_never_distilled`.
**If 15.2-12 lands that hand-off under a different key, that test is where it fails** — which
is the point of writing it now. Confirm on merge.

### D-15 restatement, for 15.2-18 (V-03)

V-03 removes the **wiring** that made `claim_distiller` the *primary* claim source — the
"distiller-as-shredder" path in `pipeline.py`, where every provider's prose was shredded into
claims regardless of whether the provider supplied a structured list. **V-03 does NOT remove
`claim_distiller` itself**, and it does not remove `tests/test_claim_distiller.py` or
`tests/test_distiller_coverage.py`, both of which must stay green through V-03.

`claim_distiller`'s `full_extraction` mode **is** D-14's per-provider fallback. Deleting the
function would silently delete the fallback with it and take every non-compliant stream's
research down. A D-15 paragraph now sits in `claim_distiller`'s own docstring so an executor
told to "remove the old engine path" hits it before deleting anything.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 — Bug] `_D8_BLOCK_MAX_CHARS` set to 2600, not the plan's 2000**
- **Found during:** Task 1
- **Issue:** The plan specified `_D8_BLOCK_MAX_CHARS = 2000`, written before `facts.py`
  existed. The real block measures 2159 characters (2399 with a language rule), so 2000
  would have tripped the over-size WARNING on **every angle of every run** — a permanently
  noisy log that says nothing.
- **Fix:** Set to 2600 from the measured worst case, with headroom for a longer language
  name and still under half the adapters' 5000-character audit-record ceiling. The rationale
  and both measurements are recorded in the constant's comment.
- **Files modified:** `pipeline/tribunal/research_division.py`
- **Commit:** `dcc688d`

**2. [Rule 1 — Bug] Byte-exact outbound-query assertions in `test_research_division_assignment.py`**
- **Found during:** Task 1 (three sites), then Task 3's gate run (a missed fourth site)
- **Issue:** Four assertions compared the outbound query byte-for-byte
  (`assert calls["gemini"] == ["q1"]`). Appending the D8 block to the dispatched query breaks
  all of them, but those assertions exist to pin **routing** — which stream received which
  angle — not prompt text.
- **Fix:** A `_briefs(calls, stream)` helper recovers the angle brief (the text before the
  first blank line; the queries in that file are single-line by construction) and the
  assertions compare briefs. Task 1 converted three sites; the fourth
  (`test_run_angles_defaults_provider_from_stakes_when_missing`, line 201) was **missed** and
  the plan's Task-1 verify block is a grep/AST gate that never runs the suite, so it shipped
  red. Task 3's engine gate caught it (1 failed / 515 passed) and it was fixed in the Task 3
  commit.
- **Files modified:** `tests/test_research_division_assignment.py`
- **Commits:** `dcc688d` (three sites), `7388366` (the fourth)

**3. [Rule 1 — Plan inaccuracy corrected] `found_by` is asserted at the flow level, not at the normaliser**
- **Found during:** Task 3
- **Issue:** The plan's test 16 asks to assert that `found_by` equals "the caller-supplied
  provider name only". Reading Task 2's actual `_normalise_fact_claim`, that is **not** what
  the helper does: it *preserves* a caller-supplied `found_by` list when one is present and
  only fills `[provider]` when it is missing or empty. Asserting the plan's wording against
  the helper in isolation would have been a false claim about the code.
- **Fix:** The real control is at the flow level — `_parse_distiller_response` sets `found_by`
  from the tuple name, and the distiller's line format has no `found_by` column, so a model
  cannot influence it. The test asserts `found_by == ["openai"]` through
  `collect_provider_facts` (the honest guarantee) and separately asserts the four
  hard-written `None` fields directly at `_normalise_fact_claim` (which the helper *does*
  guarantee unconditionally).
- **Files modified:** `tests/test_factlist_fallback.py`
- **Commit:** `7388366`

### Additive, beyond the plan

**4. [Rule 2 — Missing coverage] `test_not_found_union_is_capped_loudly`**
The plan's `test_collect_never_raises` case "400 NOT_FOUND lines" cannot actually exercise
`_NOT_FOUND_TOTAL_MAX`: 15.2-04's parser already caps a **single report** at 100 entries
(`_MAX_NOT_FOUND`), so one report can never reach the 300 union cap. Asserting the cap there
would have been vacuous. Added a separate test with four streams x 100 distinct entries = 400
distinct, which lands on exactly `_NOT_FOUND_TOTAL_MAX` (300) and proves the cap for real.
The hostile-input case still asserts `<= _NOT_FOUND_TOTAL_MAX`, which is honest.

**5. [Rule 2 — Missing coverage] `test_recorded_fixture_is_reached_through_the_in_package_copy`**
The plan asked for the fixture reader to be *reused* by import (single source of truth) but
its acceptance criteria also grep for a literal `loader._report_dir()` in the file. Rather
than satisfy the grep cosmetically, added a real Pitfall-8 guard that asserts the recorded
calls directory resolves through `loader._report_dir()` and that all three fixture bodies
slice to >20,000 characters — so a missing or mis-sliced fixture fails as "the fixture is not
there" rather than as a confusing failure inside a parametrised test.

**6. [Rule 2] `test_pre_parsed_facts_are_used_verbatim_and_never_distilled`**
Task 2 implemented the forced-tool hand-off (`result["facts"]`) as a documented but untested
assumption. Added a test that pins it, so 15.2-12's merge either confirms the contract or
fails loudly at a named test.
