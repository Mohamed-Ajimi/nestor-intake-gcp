# Phase 15.2 Plan 11: Question Workshop — Stage B (critique, tournament, scope guard) Summary

The workshop can now choose. `workshop_rank.py` screens the candidate population
KEEP/WEAK/KILL (**this is ENGINE-05**), ranks every survivor through a fixed four-round Swiss
tournament of batched pairwise judgements, sharpens the winners and tags their D7 search
languages, and then asserts D4 **in Python** — the winners' `parents` union must cover every
client-validated question, or the guard promotes a below-the-cut candidate or injects the
client's own text, ranks it first, and says so out loud.

### The winner dict, key by key

`text` (str) · `langs` (`list[str]`, **never empty**) · `parent` (str) · `rank` (int) ·
`parents` (`list[str]`) · `index` (int; `-1` on a verbatim injection) · `source`
(`"model"` / `"verbatim"`) · `scope_injected` (bool, present only when the guard added it) ·
`wins` (int) · `elo` (float, rounded to 2 dp) · `byes` (int) · `critique`
(`"KEEP"` / `"WEAK"`) · `flaw` (str).

**Plan 15.2-13 reads exactly four of these: `text`, `langs`, `parent`, `rank`.** The rest are
carried for the feed, this SUMMARY and the August post-mortem.

### `rank` is dense, 1-based, and LOAD-BEARING

`[w["rank"] for w in result["winners"]] == list(range(1, n + 1))`, always — on the happy path,
after a partial scope injection, and in the full fallback (three paths pinned by
`test_every_winner_carries_a_dense_rank`). Plan 15.2-13's `_stakes_for_rank` derives D6 stakes
and stream allocation from it.

**Scope-guard-injected and promoted winners are ranked FIRST, deliberately.** Appending an
injected client question at the bottom would give the client's own validated question the
*weakest* stakes and the fewest streams — scope-preserving on paper and quality-destroying in
practice.

### `workshop_fallback`, and the reason/note split

`workshop_fallback` is `True` when stage A fell back **or** every winner has
`source == "verbatim"`. That is D-12's *"the workshop fell back to client-validated questions
only"*, and nothing weaker maps to it.

The two sentence channels are separate **on purpose**:

- `degradation_reasons` — the real degradations only: unscreened critique batches, a failed
  critique call, unjudged matches, a round that produced no judgement, a failed evolve, the
  full fallback, plus everything stage A already reported.
- `workshop_notes` — the scope-guard promotions and injections. An injection means the output
  is **complete**: the client question *is* researched. Demoting the run for it would be
  exactly the alarm fatigue D-12 warns about.

## Deliberate divergences from `15.2-RESEARCH.md` (not drift)

1. **The evolve line is `INDEX | <text> | LANGS: de,en`**, not RESEARCH's
   `WINNER: … | LANGS: … | PARENT: …`. `PARENT` is neither requested nor believed: `parent`
   and `rank` are stamped in Python from the input winner at that index — the identical rule
   `_parse_distiller_response` applies to `provider`. Index addressing is simultaneously the
   prompt-injection control. A `PARENT:` segment that does arrive is read only far enough to
   log a DEBUG disagreement, then discarded (`test_model_supplied_parent_and_index_cannot_re_parent_a_winner`).
2. **An unjudged match defaults to the pair's LOWER ORIGINAL INDEX**, not presented side `0`.
   With A/B alternation the presented side is a function of `(round + match_index)`, so
   defaulting by side would make the default depend on the `_ALTERNATE_AB` knob and the winner
   order would change when that knob is flipped. `test_unjudged_match_defaults_to_the_lower_index`
   runs the whole tournament with alternation on and off and asserts identical output.

## Deviations from Plan

### Auto-fixed / clarified

**1. [Rule 1 — test defect] The critique's per-parent guard makes two of the plan's illustrative test setups unreachable**
- **Found during:** Task 1, on the first engine gate run (`3c777173`).
- **Issue:** the plan specifies BOTH a per-parent resurrection ("a KILL may not remove the last
  surviving candidate of a client question") AND test 31 ("three candidates from three
  different parents … candidate 2 is gone") AND test 36 ("every candidate KILL across three
  parents … an ERROR-level reason"). With the guard in place — which D4 requires and which the
  plan's own test 35 pins — a KILL of a parent's only candidate is always resurrected, so
  test 31's kill was unobservable and test 36's ERROR branch was unreachable.
- **Fix:** the guard is correct and was **not** weakened. Test 31 now kills a candidate that
  *shares* its parent with a survivor (parents `Q1, Q2, Q1`), which is the only arrangement in
  which a real KILL can be seen — itself the point. Test 36 now covers **both** branches
  explicitly: case A (three parents, everything killed ⇒ all three resurrected, per-parent
  guard) and case B (a malformed population carrying no parent label at all ⇒ the population
  guard, logging at ERROR).
- **Files:** `tests/test_workshop_critique.py`
- **Commit:** `11a8034`

**2. [Rule 3 — plumbing] Optional `stats` out-dicts on `critique_candidates`, `run_tournament` and `evolve_winners`**
- **Issue:** the plan fixes all three returns at a 2-tuple, but `run_workshop_stage_b` must
  report `feed.set_summary(actions=<total LLM calls>, cost_usd=…)` and
  `counts["matches_unjudged"]`. There was no way out.
- **Fix:** an OPTIONAL caller-owned `stats: dict | None = None` out-param — the same purely
  additive idiom `audited.*` uses for `audit_out` and plan 15.2-10 used for `stats`. Omit it
  and nothing changes.
- **Commits:** `c60bbbf`, `fc7a73e`, `6455aa6`

**3. [Rule 3 — plumbing] Optional `question_texts` on `enforce_scope_guard`**
- **Issue:** the plan passes `client_questions` as a list of LABELS and then requires a

- **Fix:** an optional `question_texts: dict[str, str] | None` label→text map, which
  `run_workshop_stage_b` fills from `stage_a["questions"]`. Without it the label is used as the
  text, so the signature stays backward-compatible.
- **Commit:** `6455aa6`

**4. `_pair_round` does NOT increment the bye counter.** The plan says "Record `byes += 1`"
