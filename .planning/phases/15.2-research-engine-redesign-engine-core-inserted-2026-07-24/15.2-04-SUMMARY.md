# Phase 15.2 Plan 04: D8 Structured Fact Lists Summary

Provider-emitted fact lists become the primary claim source: a fenced TAB-separated prompt
block, a parser that never raises and never treats model text as JSON, D-14 detection for
providers that ignore the instruction, and the Pitfall-10 fix that stops every Gemini source
grading as tier 3.

## What Was Built

Two new files, no existing file touched.

### `pipeline/tribunal/facts.py`

Public API (exact signatures):

```python
FACTS_START = "FACTS_START"
FACTS_END = "FACTS_END"
NOT_FOUND_START = "NOT_FOUND_START"
NOT_FOUND_END = "NOT_FOUND_END"
QUALITY_VALUES: tuple[str, ...] = ("official", "press", "other")   # DEFAULT_QUALITY = "other"
CERTAINTY_VALUES: tuple[str, ...] = ("certain", "single")          # DEFAULT_CERTAINTY = "single"
VERTEX_REDIRECT_HOST = "vertexaisearch.cloud.google.com"

def build_fact_list_prompt_block(*, language: str = "") -> str
def strip_fact_block(text: str | None) -> str
def build_label_index(text: str | None) -> dict[str, str]
def display_domain(url: str | None, *, label: str | None = None,
                   label_index: Mapping[str, str] | None = None) -> str
def parse_fact_list(text: str | None, *, provider: str, facet: str,
                    label_index: Mapping[str, str] | None = None) -> FactListResult

@dataclass(frozen=True)
class FactListResult: ...
```

Private helpers worth knowing about: `_quality_tier_hint(provider, domain)` (reuses
`derive_quality_tier`), `_clean_statement`, `_parse_url_cell`, `_clamp`, `_extract_region`.

### The fact-dict key set (exactly nine, in this order)

```
text, facet, evidence, found_by, source_urls, certainty, provider_quality,
source_domain, quality_tier_hint
```

The first five are the shape `persist_tribunal_claims` already consumes — `source_urls` is
already read at `extractor.py:498`, so **15.2-15 needs no persistence-loop change** for them.
`certainty` / `provider_quality` are the D-13 columns from migration 0013. `source_domain` and
`quality_tier_hint` are the Pitfall-10 pair.

### `FactListResult` — every field but the first two is a named loss

| Field | Meaning |
|---|---|
| `facts: list[dict]` | Claim dicts in report order. |
| `not_found: list[str]` | The provider's own "looked, could not establish" lines. Feeds D-08 (15.2-06) and the `research_gap` rows (15.2-15). |
| `had_block: bool` | A `FACTS_START` sentinel was present at all. Separates "ignored the instruction" from "complied but found nothing" — two different failures that must not look alike. |
| `parse_errors: int` | Lines ignored inside the block: no TAB, echoed header row, statement under 10 chars. Also counts a second, ignored fact block. |
| `rejected_urls: int` | SOURCE_URL cells dropped for a non-`http(s)` scheme or excess length. **The statement survives.** |
| `dropped_over_cap: int` | Facts discarded past `_MAX_FACTS`. |
| `needs_distiller_fallback: bool` | D-14. True when this provider yielded zero usable facts. |
| `fallback_reason: str \| None` | `None` when facts exist; otherwise a plain-English sentence naming the provider and the cause. |

### `fallback_reason` sentence templates (15.2-14 consumes these verbatim)

No block at all:

```
{provider} returned no FACTS_START/FACTS_END block — its report will be run through
the full-extraction distiller instead (D-14).
```

Block present but nothing parsable:

```
{provider} returned a FACTS_START/FACTS_END block but not one line in it parsed as a
fact ({parse_errors} line(s) ignored) — its report will be run through the
full-extraction distiller instead (D-14).
```

`provider` falls back to the literal `this provider` when the caller passes an empty string.
Both sentences exceed 40 characters in every case and are also emitted at `log.warning`.

### Env-tunable bounds (`NESTOR_TRIBUNAL_*` idiom)

| Env var | Default | Guards |
|---|---|---|
| `NESTOR_TRIBUNAL_FACTS_MAX_PER_PROVIDER` | `400` | facts accepted from one provider |
| `NESTOR_TRIBUNAL_FACT_MAX_CHARS` | `1200` | per-statement truncation (truncate, never drop) |
| `NESTOR_TRIBUNAL_NOT_FOUND_MAX` | `100` | NOT_FOUND entries |

Fixed bounds: `_MIN_STATEMENT_CHARS = 10`, `_MAX_URL_CHARS = 2048`,
`_MAX_NOT_FOUND_CHARS = 400`, `_MAX_LABEL_INDEX = 2000`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] `build_label_index` first-occurrence-wins left Pitfall 10 completely unfixed**

- **Found during:** Task 2, while validating the fixture assumptions before writing code.
- **Issue:** The plan specifies `build_label_index` as `{url: label}` with "first occurrence
  wins". Measured against the committed recorded output, that rule produces **zero** usable
  display domains on all three reports (tier-1/2 count 0/0/0). Every Gemini redirect URL is
  cited *twice*: first inline in the report body, where the markdown label is the
  self-referential string `vertexaisearch.cloud.google.com`, and again in the trailing numbered
  source list, where the label is the real domain. The inline occurrence always comes first, so
  first-occurrence-wins locks in the placeholder and `display_domain` correctly rejects it —
  falling back to the redirect host for 100% of URLs. The plan's own must-have ("no longer
  uniformly tier 3") and its acceptance criteria (`mit.edu` as a value; ≥3 tier-1/2 domains)
  were unsatisfiable as literally written.
- **Fix:** `build_label_index` now resolves the first **usable** label. A label that is itself
  the redirect host is treated as a placeholder and may be upgraded by a later real domain
  label; any other label is kept and never overwritten. Added `_is_placeholder_label`. The
  behaviour is documented in the function docstring with the measured before/after numbers so
  the reason cannot be lost.
- **Files modified:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/facts.py`
- **Commit:** `05a4945`

### Adjustments within plan latitude

- The plan cited recorded call 006 **line 95** for the self-referential-label edge case; in the
  committed fixture it is at lines 77/79/81/82/84 (many occurrences, not one). The test asserts
  the behaviour rather than a line number, so it is immune to this drift.
- The plan's `<interfaces>` block lists per-call `[cite: N]` marker counts (18 / 5 / 9). Measured
  *line* counts containing markers are 17 / 21 / 17. No test asserts a marker count — nothing in
  the acceptance criteria required it — so no claim rests on the discrepancy. Flagged here only

- `test_enum_clamping` was given 4 cases rather than the 2 named in the plan (added the
  empty-cell and mixed valid/invalid cases). `test_parser_never_raises` was given 9 hostile
  inputs against a required minimum of 7.

No architectural (Rule 4) decisions arose. No authentication gates. No package installs — the

## Threat Model Outcome

All four **high**-severity threats in the plan's register are mitigated with a named passing
test:

| Threat | Mitigation | Proving test |
|---|---|---|
| T-15.2-40 spoofed provenance | `provider` / `facet` are keyword args, never model-parsed | `test_provider_cannot_set_its_own_attribution` |
| T-15.2-41 tampered enums | clamp to `other` / `single` (G-11, fail toward more checking) | `test_enum_clamping` |
| T-15.2-42 DoS | `_MAX_FACTS`, `_MAX_STATEMENT_CHARS`, `_MAX_NOT_FOUND`, `_MAX_URL_CHARS`, `_MAX_LABEL_INDEX`, bounded regex quantifiers | `test_bounds_are_enforced`, `test_parser_never_raises` (5 MB line) |
| T-15.2-43 `javascript:`/`data:` URL as an operator-clickable link | `http`/`https` only; link dropped, fact kept | `test_non_http_url_is_rejected_but_the_fact_survives` |
| T-15.2-44 injection reaching skeptic prompts | statements hard-truncated at parse time | bounded by `_MAX_STATEMENT_CHARS` |
| T-15.2-45 JSON parsing of model text | `json` never imported; source-level gate | `test_no_json_parsing_of_model_text` |
| T-15.2-46 silent parse loss | named counters + >40-char `fallback_reason` | `test_recorded_reports_have_no_fact_block` |

`T-15.2-47` (SSRF) and `T-15.2-48` (audit chain) remain `accept` and are structurally

  per A3).

  downstream — `scrub_research` locates the passage to delete by matching that exact span, and the
  cite-marker regex eats preceding whitespace, so any cleaning silently breaks future scrubs.
