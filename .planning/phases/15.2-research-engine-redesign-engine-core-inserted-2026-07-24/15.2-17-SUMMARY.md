# Phase 15.2 Plan 17: Stubbed End-to-End Engine Proof Summary

One keyless, DB-less, network-less command now drives the redesigned pipeline from
`TribunalPipeline.run(...)` to a finished report — and it found that the engine
did not run at all.

## What this plan proved

`gcloud builds submit tribunal --config=tribunal/cloudbuild.test-engine.yaml`
runs five new tests that drive the real pipeline end to end with zero LLM calls,
zero database, zero network and zero API keys:

- **workshop → dispatch over four streams → per-provider fact lists → cross-provider
  merge → gates → grouped verification → report**, every stage exercised by
  production code, with only the MODEL and the third-party providers stubbed.
- **`merge` is observed strictly before `gate`** (D9/D11) — the reordering that
  makes a cross-provider contradiction reach ONE skeptic session instead of two.
  The contradictory pair is then proven to have arrived in exactly one session.
- **Provenance survives to persistence** (D-13): the fact two streams stated
  identically reaches `INSERT INTO claim` with `found_by == ["gemini","openai"]`,
  the single-source fact with one entry, and the cautious `certainty` wins the merge.
- **Subtractive verification sticks**: the refuted claim's passage is gone from the
  `synthesis_cache` bundle synthesis was written from, and the surviving claim's is not.
- **Both D-08 sections render with real content**, all three subgroups, in fixed
  order before `## Verification`.
- **Degradation is honest**: a run that loses the own-researcher stream and takes a
  D-14 distiller fallback on another finishes `completed_degraded` — not parked,
  not silently green — with the stream loss named in a sentence and the fallback
  deliberately NOT promoted into `degradation_reasons`.
- **D-12's carve-outs hold**: a recovered retry and a pending cost leave the run
  `completed`, and the retry is still visible as a retry row in the feed (R5).
- **Zero live calls, asserted rather than assumed**: the object's module, the absent
  real-client attributes, every route counter, `calls == sum(routes)`, and
  `get_engine.cache_info().misses == 0`.
- **D-04**: the recorded 1,162 claims reach the gates as merged provider facts and
  reproduce the recorded funnel exactly; both input shapes yield an identical funnel;
  the gate stage preserves the merge's provenance instead of stripping it.
- **The legal gate**: `verify_chain` green, the hashed payload frozen at 11 fields,
  and each of the nine names 15.2 introduced asserted absent BY NAME.

## What it deliberately does NOT prove (D-02 → V-01/V-02, August live run)

1. whether the tournament picks good questions;
2. whether real providers emit well-formed D8 fact lists;
3. whether the merge clusters real phrasings correctly (G-05 calibration);
4. whether the gates SELECT the right claims (G-01 calibration);
5. whether the own-researcher's findings are useful;
6. whether the writing model's report is good;
7. whether the skeptic's verdicts are correct.

Every one is a judgement about model output. A CI test that asserted any of them
would be judging its own script. This file asserts PLUMBING only, and says so in
its module docstring.

## Three production defects the e2e caught

They are the reason this plan touched production code at all. Each was invisible
to a per-component suite because each lives in a hand-off between two plans tested
in different files against different hand-made fixtures.

**1. `_run_staged` raised `UnboundLocalError` on its first statement — every run.**
`_outer_set_stage = set_stage` sat directly above `async def set_stage(...)`, which
makes the name a local for the whole method. `run()`'s park guard re-raises it (not
a HARD_WALL), so **every tribunal run since 15.2-16's split would have reported
`failed`** with no park and no partial work. Fixed by importing the module
attribute under a different name (commit `e01b7b2`).

**2. The workshop's brief-vs-world flags never rendered.**
`build_disputed_and_changed` read only `note`/`text`/`finding` off a conflict dict;
`workshop._parse_orientation` has only ever emitted
`{question, assumption, world_says, source_url}`. Every real D4 flag resolved to
the empty string and was dropped, so `### Where the brief did not match what the
research found` never appeared in any report. Fixed additively — the three legacy
keys keep priority (commit `9c15c6e`).

**3. The fourth stream's "could not establish" list was discarded.**
`collect_provider_facts`' forced-tool branch returned before `parse_fact_list` ran,
so the own-researcher's `not_found` lines never became `research_gap` rows and
never reached "What we could not establish". A stream that stated what it could not
establish read as a stream that found everything. Fixed by harvesting through the
SAME parser (one reader, its own bounds), discarding its facts so nothing is
double-counted (commit `9c15c6e`).

## Deviations from plan

### Auto-fixed issues

**1. [Rule 1 – Bug] `_run_staged` UnboundLocalError** — see above. Commit `e01b7b2`.

Each violates the letter of Task 1's acceptance criterion "`git diff --name-only`
lists exactly the test file". That criterion exists to stop a **test-only seam**
being added to production, and that purpose is fully honoured: the only injection
points used are the production `TribunalPipeline(audited=...)` constructor
parameter and `monkeypatch` over module attributes. No injectable
classifier/provider parameter was added, and `tribunal/cloudbuild.test-engine.yaml`
is byte-unchanged. Shipping a known `UnboundLocalError` that kills every run in
order to satisfy the letter of that criterion would have been the wrong trade.

### Plan expectations corrected against the merged tree

**A. `"serpapi_key_missing"` in `degradation_reasons`.** Task 2 required the literal
code in the operator-facing reason list. The merged tree deliberately publishes a
SENTENCE there — T-15.2-65 forbids a reason string naming the credential, its
variable or the endpoint, because `run.stage_detail` is polled by a superadmin's
browser. Asserting the code would have contradicted the fail-loud rule the same
task cites two bullets later. **Resolved by asserting both halves**: the machine
code on the availability probe (`serpapi.unavailable_reason() == REASON_KEY_MISSING`)
and the >40-character sentence on the operator surface.

**B. The D-14 fallback as a degradation reason.** Task 2 asked for it in
`degradation_reasons`. D-14 and the pipeline's own comments state the opposite:
a fallback degrades ONE STREAM, not the run, and `factlist_fallbacks` must never
reach `_note_degradation` or `terminal_state()`. **Resolved by asserting the
surface it really lands on** (`verification.factlist_fallbacks`, with a
provider-naming note >40 chars) **and asserting it is ABSENT from
`degradation_reasons`.**

**C. `own_research` in the expected stage set.** Task 1 required the observed stage
sequence to be a superset including `own_research`. Nothing writes that key —
see D17-1. Asserting it would have failed for a real reason the plan did not know
about. **Resolved by pinning the gap in a self-retiring test.**

**D. `return dict(RECORDED_FUNNEL_COUNTS)` grep.** Task 3's criterion expects that
literal; 15.2-08 deliberately changed it to `copy.deepcopy(...)` because the funnel
now carries a LIST value and a shallow copy would share it with the module
constant. The PROPERTY the criterion protects — both full-dict-equality callers
hold by construction — is unaffected and was verified green
(`test_funnel_reaches_verification_summary`, `test_recorded_stage_detail_enriched`).
Not changed.

**E. Gate 5's path.** The plan names `backend/cloudbuild.test.yaml`. No such file
exists; the backend gate is the repo-root `cloudbuild.test.yaml` (as D19-2 already
recorded). Ran the real one.

**F. `loader.py`'s invariant block.** Task 3 asked for it to be reconciled with
`checked_incidentally`. 15.2-08 had already done so (loader.py:117-123, the WR-10
one-claim-one-bucket form). Verified, not re-edited.

### Harness faithfulness note

The no-DB session **echoes `research_gap` rows back** on SELECT. This is not a
shortcut: 15.2-06 deliberately re-reads that table rather than taking a bundle

later, so a real database would return them. Answering `[]` would have made the
section render its empty placeholder and this file would have asserted that a
stated gap is correctly omitted.

D9-3, D15-1, D16-1 and D19-2 all named this plan as their home. **All four remain
open.** They are re-evidenced with measured counts in `deferred-items.md` § D17-2.

  because D19-1's `test_invite_carries_link` is still failing, and then requires
  deciding what a REQUIRED merge gate means — a structural call, not an
  executor's.

**One decision, not four:** the phase has no committed non-superuser DB gate with
room in it. That is the thing to put to the operator.

D9-2 is the exception: it is **resolved** (gate 6 exits 0, verified non-vacuous).
