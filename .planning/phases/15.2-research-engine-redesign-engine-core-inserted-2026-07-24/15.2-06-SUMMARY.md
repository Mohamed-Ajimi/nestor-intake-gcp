## Contracts for the plans that build on this

### Builder signatures

```python
def build_disputed_and_changed(
    *,
    group_reconciliations: Optional[list] = None,   # [{entity, attribute, disputed, relation, note, canonical}]
    superseded_notes: Optional[list] = None,        # ["[SUPERSEDED] <claim>: <note>", ...]
    brief_conflicts: Optional[list] = None,         # [str | {"note"|"text"|"finding": str}]
    language: str = "",                             # mission_brief["language"] — an English language NAME
) -> str

def build_could_not_establish(
    *,
    not_found_by_provider: Optional[dict] = None,   # {provider: [text, ...]}
    language: str = "",
) -> str
```

Both return a string starting with `## `, with no leading or trailing blank line.

### The three-state `not_found_by_provider` contract

| Value | Meaning | Rendered as |
|---|---|---|
| `None` | the gap list **could not be read** | `gaps_unreadable` — a named failure sentence containing the word `NOT` |
| `{}` | read fine, nothing to report | `gaps_empty` — "*(No provider reported a research gap.)*" |
| populated | the gaps | one block per provider, `sorted()` order; a provider with an empty list is **NAMED**, never omitted |

The first two are deliberately different strings. Rendering "no gaps" over a database error would put a false factual statement into a client-bound document (**T-15.2-33**).
