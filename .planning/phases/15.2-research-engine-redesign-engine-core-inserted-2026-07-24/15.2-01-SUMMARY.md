## FOR DOWNSTREAM PLANS — read this before writing code

### `research_gap` columns (plan 15.2-15)

```
id          UUID PK (ORM default uuid.uuid4)
tenant_id   UUID NOT NULL  FK org.id ON DELETE CASCADE
run_id      UUID NOT NULL  FK run.id ON DELETE CASCADE
provider    VARCHAR NOT NULL   -- 'gemini' | 'openai' | 'own' | ...
text        TEXT NOT NULL      -- the item that could not be established
created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
INDEX idx_research_gap_tenant_run (tenant_id, run_id)
```

ORM: `from nestor_pulse_sdk.db.models import ResearchGap`.

**The write path MUST run inside `db/rls.py::set_tenant_context`.** There is deliberately NO
`research_gap_worker_all` policy, so an INSERT attempted with an unset or empty `app.tenant_id`
is REJECTED by the policy's `WITH CHECK` — this is proven by
`test_research_gap_write_without_tenant_context_rejected`, not assumed. If `persist_tribunal_claims`
writes gaps outside a tenant context it will fail loudly at runtime.

### The nine-literal `ck_run_status` (plans 15.2-09 and 15.2-16)

```
'queued','running','completed','completed_degraded','parked','failed','cancelled','needs_input','needs_report_spec'
```

Byte-identical strings live in `alembic/versions/0013_fact_metadata_research_gap.py` (`_STATUS_NINE`)
and `db/models/run.py` (`ck_run_status` CheckConstraint). **`runs/schemas.py::RunStatus` was NOT
touched — it is plan 15.2-09's to sync.** Plan 15.2-16 can have the worker write `parked` and
`completed_degraded`: the DB CHECK accepts them as of 0013. The widening is a strict superset of
the previous seven, so no row could violate it and no backfill was needed.

Plan 15.2-16's Resume-endpoint cross-tenant denial tests can join this harness. **If you add a test

### The two planner corrections — do NOT "fix" these back

1. **The policy expression is `NULLIF(current_setting('app.tenant_id', true), '')::uuid`**, not the
   bare `current_setting('app.tenant_id')::uuid` that `15.2-RESEARCH.md` § *The D-13 Additive
   Migration* drafted and that 0002/0003/0011 still carry. The bare form raises
   `invalid input syntax for type uuid: ""` on a pooled connection whose GUC has reverted to the
   empty string, aborting the statement even though another OR'd policy branch is true — the
   recorded worker crash-loop that migrations 0009 and 0010 exist to fix. A regression here is a
   production outage, not a style question.
2. **No `research_gap_worker_all` policy and no explicit GRANT.** This matches the
   `verification_verdict` (0011) precedent. `worker_user` gets DML automatically via 0008's
   `ALTER DEFAULT PRIVILEGES FOR ROLE app_user IN SCHEMA tribunal`, because production runs
   `alembic upgrade head` under the app_user DSN. Both decisions are recorded in the migration's
   `Security posture for research_gap` docstring heading so they survive future edits.

## Deviations from Plan

**One, cosmetic and deliberate.** The plan's action text implied composing the policy DDL from a
module-level `_EXPR_EMPTY_OK` constant (0010's idiom), but the acceptance gate requires the NULLIF
literal to appear at least twice in the file — an f-string interpolation would have collapsed it to
a single occurrence and hidden the executable text from the grep. The `CREATE POLICY` statement
therefore writes the expression out literally in both `USING` and `WITH CHECK`, with a comment
recording why. No behavioural difference; the emitted SQL is identical.

Everything else executed as written. No Rule 1/2/3 auto-fixes were needed, no architectural
questions arose, and no package was installed (T-15.2-SC holds: the harnesses only
`pip install -r requirements.txt`).
