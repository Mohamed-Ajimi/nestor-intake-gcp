<the_trap>
## The `_ACCOUNTING_KEYS` trap — get this one right or every recorded run reports "no gate data"

`verification/report.py:117-128`:

`_ACCOUNTING_KEYS = ("checked", "should_have_been_checked", "gate_errors") + _NOT_CHECKABLE_KEYS`,
and `_accounting()` returns **`None`** when *any* key in that tuple is missing from the funnel.
That is deliberate and load-bearing: it is how the shaper detects a **pre-15.1 run** and reports
"no gate data" instead of a dict of zeros that would read as a clean bucket 3.

Adding `checked_incidentally` (or any of its four reason keys) to `_ACCOUNTING_KEYS` would make
**every funnel written before this plan** — including every run currently in the database — fail
the membership test and report `accounting: None`. The operator surface would go blank on runs that
have perfectly good gate data.

**Rule, non-negotiable:** read the new keys with `funnel.get("checked_incidentally_...", 0)`.
**Never extend `_ACCOUNTING_KEYS`.** A test in this plan asserts the tuple's exact membership so a
future edit cannot do it by accident.
</the_trap>

**A. `pipeline.py` — new pure counter `_count_incidental`, placed immediately BEFORE `_build_funnel`
(i.e. before line 237), module level.**

Signature: `def _count_incidental(claims: list[dict], verdicts_by_claim: dict[int, list[dict]]) -> dict[str, int]`.

Behaviour: iterate `claims`; select a claim when `(c.get("gate") or {}).get("strict") != "VERIFY"`
**and** `verdicts_by_claim.get(id(c))` is truthy — i.e. the gates did NOT select it, yet it came out
of the verify stage carrying at least one verdict. Attribute each selected claim to exactly one
reason key: `checked_incidentally_stable` when `strict == "SKIP_STABLE"`; otherwise read
`(c.get("gate") or {}).get("reason")` and map `"NOT_FALSIFIABLE"` →
`checked_incidentally_not_falsifiable`, `"NOT_LOAD_BEARING"` →
`checked_incidentally_not_load_bearing`, and **anything else** (including `"BOTH"`, `None`, and an
unrecognised string) → `checked_incidentally_both`. The catch-all direction is deliberate: `both` is
already the gate's own catch-all bucket (`gates.py:555-556` does the same), so an unattributable
incidental check is never dropped from the accounting.

Return a dict with exactly five int keys: the four reason keys plus `checked_incidentally`, which is
set to the **sum of the four** — computed once, in this function, so the total and the breakdown
cannot disagree. Never raise: a claim with no `gate` key is simply not selected (`.get` chains
handle it).

Docstring must state, in words: this is the WR-10 / D-10 Option 2 counter; it is computed from
CLAIM STATE at the end of the verify stage rather than tallied at the filing sites, for exactly the
reason `_observed_unchecked` (line 961-972) is — a tally only knows the causes it was taught to
name, while claim state knows what actually happened. Also state that `verdicts_by_claim` is seeded
with `[]` for every claim, so truthiness (not key presence) is the correct test.
