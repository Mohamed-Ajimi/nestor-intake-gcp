## Task 1 — the gate arrangement is closed

**The defect.** 15.2-20 seeded five gap-phase test filenames into `cloudbuild.test-engine.yaml` in
wave 1, four of them before their files existed. The `FILES=$(ls … 2>/dev/null || true)` idiom drops
a name whose file is absent — deliberate then, and exactly the "green because it ran nothing" trap
this repository has hit four times (D9-3, D15-1, D16-1, D19-2). It also drops a **mistyped** name,
forever, silently.

**The fix.** The 27 paths now live in a `WANTED` variable read twice: `ls` collects from it, and an
`EXPECTED_FILES=27` assertion reconciles against it. A mismatch prints which path is absent or
mistyped, says in words that the gate would have run less than it claims, prints the full expected
list, and exits 1. The empty-collection `exit 0` is gone.

Both halves are kept and the comment says why removing either one looks reasonable and is wrong:
`|| true` prevents a collection ERROR (an aborted script tells you nothing about the other 26
files); the assertion converts the SKIP it permits into a RED build.

**Proven BOTH ways, because an assertion that has never been seen to fail is the same false green
one level up:**

| Direction | Build | Result |
|---|---|---|
| GREEN at the right count | `6ed343db` | `collecting: 27 of 27 expected files` → **`713 passed, 13 skipped in 8.22s`** |
| RED on a wrong name | `c84a4201` | scratch copy with `test_stage_logging.py` → `test_stage_loggingX.py`; **BUILD FAILURE**, assertion fired, named the path, **pytest never ran** |

The RED build's message, verbatim:

```
############################################################
ENGINE GATE ASSERTION FAILED
collected 26 file(s); this config NAMES 27.

This is NOT a test failure and it is NOT a pass. It means the
gate would have run LESS than it claims. ...

ABSENT OR MISTYPED:
    nestor_pulse_sdk/tests/test_stage_loggingX.py
```

The scratch config (`tribunal/cloudbuild.SCRATCH-red-proof.yaml`) was deleted; `git status --short`
showed only the intended file afterwards. **Note what the old config would have done with that same
tree: collected 26 files, run them all, and exited SUCCESS.**

### 2. [Rule 2 — correctness] Step 15.2.j gained a reconciliation note, though the plan said not to rewrite it

- **Found during:** Task 2.
- **Issue:** the plan says "do not rewrite or duplicate what 20 wrote". But 15.2.j ends with
  `--min-instances=1`, and executing 15.2.j as written **during a gap-phase deploy** unpauses the

  full cost. Writing 15.2.k without touching 15.2.j would have left two procedures with

  the plan asked for, not a rewrite.
- **Files:** `infra/DEPLOY-RUNBOOK.md` · **Commit:** `6eb5a1f`

### 3. [Rule 1 — bug, self-inflicted] A `String.replace` metacharacter injected a duplicate of the document

- **Found during:** Task 3, while relocating two closure blocks under their original headings with a
  Node one-off.
- **Issue:** the D-F closure text quotes the stage-log whitelist regex, which ends `(key=value )*$`
  followed by a backtick. In a JavaScript `String.replace` **replacement**, `` $` `` means "insert
  everything before the match" — so the whole document prefix (35,642 characters) was spliced into
  the middle of the file. Headings appeared twice; the file doubled in length.
- **Fix:** repaired surgically with a slice-based script (no `replace`), restoring the two literal
  characters and removing exactly the injected region. Verified structurally
  (`grep -n "^## "` → one heading per defect) and by diff: **`354 insertions(+), 2 deletions(-)`**,
  the two deletions being the intended frontmatter `status` and `verdict` lines. No original content
  was lost.
- **Lesson worth keeping:** when scripting an edit to a document that quotes regexes or shell,
  slice — never `String.replace` with a computed replacement.
- **Files:** the findings document · **Commit:** `6afcb9a` (the repair is inside the same commit as
  the annotations; the broken state was never committed)
