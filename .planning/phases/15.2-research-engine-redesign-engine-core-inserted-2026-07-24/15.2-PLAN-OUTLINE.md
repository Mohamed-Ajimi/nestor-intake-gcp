## Deviations from RESEARCH's 17-plan / 6-wave decomposition

| # | Deviation | Why |
|---|-----------|-----|
| **1** | **The workshop is two plans (15.2-10 + 15.2-11), giving 18 plans.** | RESEARCH itself flags 15.2-10 as "the biggest plan; consider splitting steps 1–4 from 5–7", and PATTERNS already splits it into two source files (`workshop.py` agent loop / `workshop_rank.py` batch passes) with different analogs. Seven pipeline steps + four new test files is far past the 2–3 task / ~50% context bar. Split boundary = the file boundary. |
| **2** | **`tribunal/cloudbuild.test-engine.yaml` moves from the trailing test plan to Wave 1 (15.2-02).** | VALIDATION.md § Wave 0 Requirements and the phase's must-carry findings both place it in Wave 0: *"without this the phase has no runnable gate while the Anthropic account is capped."* Creating it last would leave waves 1–9 with no fast gate. It pre-lists every planned test file (the analog's `ls … \|\| true` tolerance makes missing files a skip, not a collection error), so **no later plan edits the config** — which also keeps it out of the shared-file conflict set. |
| **3** | **11 waves instead of 6.** | `pipeline/tribunal/pipeline.py` is touched by seven plans (05, 06, 07, 08, 13, 15, 16) and `synthesis/steps.py` by four (05, 06, 14, and 15's callers). GSD requires **zero `files_modified` overlap inside a wave** — same-wave plans execute in parallel worktrees and merge. Dependency *content* is unchanged from RESEARCH; the extra waves are pure file-ownership serialization. Precedent: 15.1 ran 16 plans across 9 waves. |
| **4** | **D-08's sections (15.2-06) moved from Wave 1 to a wave after 15.2-05.** | Both edit `synthesis/steps.py` and the `_write_final_report` region of `pipeline.py`. RESEARCH had them parallel in wave 1, which would collide. Merging them into one plan would breach the context budget, so they are serialized instead. |

**Not deviations:** every dependency edge in RESEARCH's table is preserved. No plan was dropped, no
deliverable merged away, and no feature was reduced to a "v1" or "static for now".

## Cross-Cutting Rules for Every Plan

Each per-plan agent must carry these into its PLAN.md (they are **not** repeated per task):

1. **All LLM egress through `audited.*`** — a direct `anthropic.Anthropic()` or raw `httpx` call to a
   model endpoint breaks the EU AI Act Art. 12 chain. SerpApi is not a model endpoint but its calls
   are still audited for C1 cost truth.
2. **Frozen audit payload: new fields ADD, never rename.** `verify_chain` green is a legal gate
   (deadline 2026-08-02); `test_hash_chain_replay.py` asserts additive fields are not chain members.
3. **No agent frameworks** — hand-written async loops (`group_skeptic.py` is the template).
4. **Untrusted-model-output parsing (ASVS V5)** — pre-fill, regex-extract the index, bounds-check,
   ignore garbled lines, clamp enums, **never `json.loads` raw model text**, never raise.
5. **Prompt-injection controls** — truncate embedded claim/snippet text and address by index; this is
   a security control, not formatting (`test_gate_replay.py:76-84`).
6. **Fail loud, in words** — never a silent green; every loss is named in the verification report and
   the feed.
7. **Tenant isolation** — every new table/endpoint gets FORCE RLS + a cross-tenant denial test **in
   the plan that creates it**; a cross-tenant `run_id` stays a 404, never a 403.
8. **No local Python/Docker** — author by construction; every command runs in Cloud Build.
9. **`security_enforcement` is ON** — every PLAN.md carries a `<threat_model>` block with a STRIDE
   register, a disposition per threat, and blocking on **high** severity. Threat IDs use the
   `T-15.2-NN` prefix. No package installs are planned (`httpx`, `alembic`, `sqlalchemy` are already
   pinned); if a plan proposes one, the Package Legitimacy Gate runs first and a
   `checkpoint:human-verify` precedes the install. **Reject `google-search-results`.**
10. **Env-tunable parameters** use the `NESTOR_TRIBUNAL_*` idiom so August can retune without a code
    change.
11. **Never plan work that already exists** — the dominant failure mode for 15.2 is building a second
    clusterer, a second retry policy, a second cite-stripper or a second feed model. Every plan opens
    by naming what it reuses.
