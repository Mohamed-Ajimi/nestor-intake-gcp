### `with_retry` signature and the `on_retry` callback (plan 15.2-03 binds this)

```python
await with_retry(
    fn,                       # zero-arg async callable
    attempts=RETRY_ATTEMPTS,  # TOTAL calls, not extra ones
    base_s=RETRY_BASE_S,
    on_retry=None,            # see below — may be sync OR async
    label="",                 # appears in every log line
    breaker=None,             # a CircuitBreaker; open => CircuitOpenError, fn never called
)
```

**`on_retry(attempt, max, wait_s, label)`** — `attempt` is **1-based**, `max` is the total attempt
count, `wait_s` is the wait actually chosen (jittered, or the provider's `retry-after` if it won).
It is called **before** sleeping and only on a retry, never on a hard wall. Write the already-legal
feed row (`runs/schemas.py:140-167`, `"retry"` is an existing status literal — zero frontend work):

```python
{"status": "retry", "retry": {"attempt": attempt, "max": max, "wait_s": wait_s}}
```

A callback that raises is logged at WARNING and swallowed — a feed write is best-effort and must
never break a run — but the retry itself is never swallowed. On exhaustion the **last exception is
re-raised**; `with_retry` never returns `None` to mean failure.

### `PauseContinuation.consume()` contract (plans 15.2-07, -10, -12 apply this)

```python
pause = PauseContinuation(max_pauses=MAX_PAUSE_CONTINUATIONS, label="group_skeptic")
...
if pause.consume(resp):
    msgs.append({"role": "assistant", "content": _content_to_serialisable(content)})
    continue          # and DO NOT count this as one of the tool-use turns
```

`consume` returns `True` **iff** `stop_reason == "pause_turn"` **and** budget remains (then spends
one). It returns `False` for any other stop_reason (spending nothing) and `False` once the budget
is gone, at which point the caller's existing failure path takes over. Serialisation stays at the
call site on purpose — `reliability.py` imports nothing from `group_skeptic`, so there is no cycle.
**Construct one per loop; never at module level.**

### `CircuitBreaker.force_open(reason)` — plan 15.2-12's seam

```python
if not os.environ.get("SERPAPI_API_KEY"):
    breakers.get("serpapi").force_open("SERPAPI_API_KEY not configured")
```

Opens the circuit with **no exception at all**, before the run starts. The stream is then never
attempted, the reason is named verbatim in `BreakerSet.reasons()` (which feeds D-12's
`degradation_reasons`), and the run finishes as a clean 3-stream `completed_degraded` rather than
failing mid-flight on a missing secret. Asserted end-to-end in
`test_reliability_breaker.py::test_force_open_reason_reaches_the_breaker_set_degradation_list`.

**`BreakerSet` is run-scoped by contract** — create one per run, never at module level, or one
run's provider failures would open another run's (and another tenant's) circuit.

### `terminal_state()` — D-17, pure

```python
terminal_state(streams_lost=…, streams_total=…, verify_ran=…, synthesis_ran=…,
               hard_wall=…, degradation_reasons=[…]) -> str
```

Returns one of `ENGINE_TERMINAL_STATES = ("completed", "completed_degraded", "parked")`.
`failed` / `cancelled` are outside its range (written by `runs/worker.py`). Two D-12 cases that
**do not** degrade a run, encoded in the docstring so a later caller does not add them: **recovered
retries** and **`cost_pending`**. The status *vocabulary* sites (`runs/schemas.py::RunStatus`,
`db/models/run.py::ck_run_status`) belong to plans 15.2-09 and 15.2-01 — this plan owns only the
decision.

### The 10 `NESTOR_TRIBUNAL_*` knobs (for plan 15.2-18's deploy runbook)

| Env var | Default | Controls |
|---|---|---|
| `NESTOR_TRIBUNAL_RETRY_ATTEMPTS` | `4` | total attempts (1 initial + 3 retries) |
| `NESTOR_TRIBUNAL_RETRY_BASE_S` | `2.0` | backoff base; attempt N waits base·2ⁿ |
| `NESTOR_TRIBUNAL_RETRY_JITTER` | `true` | full jitter on/off |
| `NESTOR_TRIBUNAL_RETRY_AFTER_MAX_S` | `300` | ceiling on a provider-supplied `retry-after` |
| `NESTOR_TRIBUNAL_MAX_PAUSE_CONTINUATIONS` | `3` | F8 pause_turn budget per loop |
| `NESTOR_TRIBUNAL_BREAKER_HARD_THRESHOLD` | `5` | consecutive identical hard failures before trip |
| `NESTOR_TRIBUNAL_BREAKER_OVERLOAD_THRESHOLD` | `10` | separate, higher threshold for 529/timeouts |
| `NESTOR_TRIBUNAL_BREAKER_OPEN_S` | `60` | first open window (doubles on each re-open) |
| `NESTOR_TRIBUNAL_BREAKER_OPEN_MAX_S` | `600` | cap on that escalation |
| `NESTOR_TRIBUNAL_BREAKER_SIGNATURE_CHARS` | `80` | how much of the message defines "identical" |

The five breaker numbers are **MEDIUM-confidence** community-consensus defaults, not measured
values. August's live run calibrates them — which is exactly why they are env-tunable.

**1. [Rule 2 — missing security control] `redact()` promoted to a module-level helper in Task 2**
- **Found during:** Task 2 (the plan scoped redaction to `error_signature`, a Task 3 artifact)
- **Issue:** `with_retry` logs failures at WARNING on every retry and on give-up. Those lines
  render the exception message, which for SerpApi carries the API key in a query string. Without
  redaction, T-15.2-02 would have been closed for the breaker but left open on the far more
  frequent retry path.
- **Fix:** `redact()` written in Task 2, applied to every `with_retry` log line; `error_signature`
  composes it in Task 3 exactly as specified.
- **Files:** `reliability.py`; asserted by 3 tests in `test_reliability_retry.py`
- **Commit:** `6e80b29`

**2. [Rule 2] `on_retry` accepts a sync callable as well as async**
- Plan specified `await on_retry(...)`. A `_maybe_await` shim was added so a synchronous callback
  (or a `lambda`) does not raise. Plan 15.2-03's `StageFeed` writer can be either. Asserted by
  `test_a_synchronous_on_retry_is_accepted`. Commit `6e80b29`.

**3. [cosmetic] Two comment lines in `cloudbuild.test-engine.yaml` say "Postgres", not "POSTGRES"**

  Reworded to lowercase so the assertion is literally clean with no loss of meaning. The
  substantive check — no DB or secret token on any **non-comment** line — passes either way and is
  what `test_engine_gate_provisions_no_database_and_consumes_no_secret` asserts.
- **Commit:** `52d667d`
