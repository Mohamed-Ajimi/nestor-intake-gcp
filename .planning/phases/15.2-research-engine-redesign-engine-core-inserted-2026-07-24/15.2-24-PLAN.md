<objective>
**D-F — the engine logs ONLY failures. D-L — the elapsed counter restarts on every page refresh.**
Two operability defects that between them cost an hour of misdiagnosis and produced a withdrawn
finding.

**D-F.** All **72** log lines from 08:09 to 08:53 of run `d6bb3aae` were either the workshop's own
output or angle-failure warnings. **Not one success marker. Not one stage transition.** So when the
run went quiet at 08:41 there was nothing to read, and diagnosis fell back to Cloud Run CPU metrics —
which produced the confident, wrong conclusion that the pipeline had stalled. It had not: it was
blocked on long-poll I/O the whole time and resumed on its own at 09:07 with
`OpenAI deep-research: RESUMING the existing response`. The withdrawn D-C section records the
misdiagnosis in full, and its closing lesson is the requirement for this plan:

> *on this engine, neither log silence nor idle CPU is evidence of a stall.*

A single INFO line per stage entry and exit would have made that obvious in seconds — the last line
would have named the stage the run was sitting inside, and "deep_research entered, 24 angles
dispatched" reads very differently from silence.

This is the same "green for the wrong reason" family the phase spent six waves eliminating, one layer
up: nothing raised, so nothing reported.

**D-L.** `ResearchRunProgress.tsx`'s `useElapsed(startedAt, active)` does
`const start = startedAt ? new Date(startedAt).getTime() : Date.now();`. `research.ts` declares
`started_at: string | null` and the component consumes it — **but the backend never sends it**. So the
field is always null, the clock counts from page load, and the same root cause makes the summary
card's `fmtDuration(run?.started_at, run?.completed_at)` render `—`.

This is a **producer-side fix only**, and it has three hops, of which only the first two are missing:

    tribunal run row (started_at, completed_at)     <- exists, written by the worker
      -> RunMetrics                                  <- MISSING: the schema has elapsed_seconds only
      -> research_runs mirror row                    <- MISSING: mirror_tick never patches them
      -> read_latest_research_run_dict               <- ALREADY EMITS BOTH (verified)
      -> ResearchRun.started_at / completed_at       <- ALREADY DECLARED AND CONSUMED

So no frontend file is touched by this plan. The contract already expects the fields; only the
producer is absent. `research_runs.started_at` and `.completed_at` are **already columns** on the
mirror table (`backend/app/db/models/research_runs.py`), so there is no intake-side migration either.

Purpose: make a long run readable while it runs, and make its clock true.
Output: stage entry/exit logging with counts at the one choke point that already exists, the two
timestamps added to `RunMetrics` and mirrored onto `research_runs`, and tests on both sides of the
seam.
</objective>
