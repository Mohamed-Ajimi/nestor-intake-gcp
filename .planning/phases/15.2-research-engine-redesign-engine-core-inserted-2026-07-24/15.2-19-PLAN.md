<decisions>
Decisions inherited from 15.2-16's discretion set. **DEC-3 is governed by THIS plan** (the poll
driver, the SSE close set and the frontend terminal sets live here); **DEC-5's consumer half is
THIS plan's** (the `[park#<seq>]` marker); DEC-1, DEC-2, DEC-4 and DEC-6 are 15.2-16's and are
restated in one line each so nothing looks lost. Record each one in the SUMMARY.

**DEC-1 (15.2-16)** — checkpoint granularity is per-stage, and deep research is per-ANGLE, not
per-provider: one `ckpt_research` row keyed by angle index, guarded by a digest of the angle queries.
Nothing in this plan depends on it beyond the promise that a resume re-charges nothing.

**DEC-2 (15.2-16)** — `NESTOR_TRIBUNAL_RESUME_REDISPATCH` defaults to `"false"`: a resume never
silently re-dispatches a paid job; an unretrievable job id degrades that one stream with a named
reason. Surfaces here only as the reason text the operator reads.

**DEC-3 — `parked` IS terminal for the poll driver and for the SSE stream.** *(Owned here.)*
15.2-RESEARCH § R4 says "`parked` is not terminal for the poll driver but IS terminal for the mail".
That is wrong in this codebase: `run_poll_driver` is a FastAPI `BackgroundTask` and a parked run waits
on a human click that may be hours away — a driver that keeps polling is a leaked task holding a
Cloud Run instance, and the SSE handler would burn to its 10-minute `MAX_STREAM_SECONDS` cap and put
the browser into `research.ts`'s reconnect loop. So `parked` joins all four terminal/close sets, and
the Resume endpoint schedules a **fresh** driver. Record this deviation explicitly. `parked` is
terminal for the STREAM, never for the RUN.

**DEC-4 (15.2-16)** — the park signal travels on `RunMetrics.park`, an additive optional field
projected from `run.verification_summary["park"]`. This plan is its only consumer: `metrics.get("park")`
in `write_fn`.

**DEC-5 — mail idempotency is a monotonic `park.seq`.** 15.2-16's pipeline hashes `(stage, redacted
reason)` into a signature; re-parking for the SAME signature keeps `seq`, a different signature
increments it. *(This plan owns the consumer:* `finalize_parked` stamps `error_message` as
`"[park#<seq>] <reason>"`, and the driver skips the mail when the mirror row already carries that
exact marker prefix. Two drivers scheduled for the same park event therefore send one mail, and a
genuinely new park does mail.*)*

**DEC-6 (15.2-16)** — the pipeline reports facts; `terminal_state()` decides. The engine never returns
the string `"parked"` from the pipeline; the worker computes and writes it. The consequence here is
that this plan trusts `metrics["status"]` verbatim and adds no second park rule of its own.
</decisions>
