# Phase 15.2 Plan 03: D15 Feed Writer, Stage Keys and Audit-ID Surface Summary

A single-owner `StageFeed` closes F9 (concurrent agents losing feed rows to
last-writer-wins), three missing stage keys are declared before any plan writes them
(WR-03), and an additive `audit_out` out-param finally lets a feed row carry the
`audit_id` of the LLM call behind it (F4) — with `verify_chain` provably untouched.

### 2. `runs/stage_feed.py` — the single-owner feed writer (F9)

`set_stage` merges with `||` (`stages.py:117-124`), and `||` **replaces** the whole
stage key. So every caller must hand it the *complete* item list built from its own
snapshot. That is safe today only because there is exactly one writer per stage
(`pipeline.py:453-465`). The 15.2 engine fans out N concurrent agents inside a single
stage — and with that pattern each agent's write replaces the others': last writer
wins, and rows the operator watched appear and then vanish.

The fix is **ownership, not a new writer**. One `StageFeed` instance per stage key
holds the list; every mutation goes through an `asyncio.Lock`; the debounced writer
**delegates** to `runs.stages.set_stage`. The module opens no session and issues no
SQL, so the tenant boundary stays in exactly one place.

**Public surface — this is the contract plans 10/11/12/13/15/16 code against:**

| Method | Purpose |
|---|---|
| `await declare(names, *, status="pending", task_prompts=None) -> list[int]` | Append the whole roster in ONE locked mutation; returns handles in input order. **The preferred entry point for a fan-out stage** — it fixes row order up front so the operator's view does not depend on task scheduling. |
| `await add(name, *, status, task_prompt, **fields) -> int` | Append one row, return its handle. |
| `await update(handle, **fields) -> None` | Merge fields into a row. Accepts `name`, `status`, `task_prompt`, `cost_usd`, `facts`, `audit_id`, `retry`. |
| `await mark_retry(handle, *, attempt, max, wait_s)` | R5. The callback surface plan **15.2-02's `with_retry(on_retry=…)`** binds to. |
| `await set_summary(*, duration_s, actions, items_read, cost_usd)` | The `StageSummary` rollup; `None` fields omitted. |
| `await flush()` | Cancel the pending debounce and write now. |
| `await close()` | Flush once, then go **inert**. |
| `async with StageFeed(...) as feed:` | `__aenter__`/`__aexit__`; exit closes, including on exception. |

`truncate_task_prompt(text, limit=None)` is exported alongside it — plans 10/11/12/13
should reuse it rather than each re-implementing a truncation at a slightly different
width.

**Tunable defaults (for the August retune — all `NESTOR_TRIBUNAL_*` env-overridable,
no code change or redeploy needed):**

| Constant | Env var | Default | Why |
|---|---|---|---|
| `_FEED_DEBOUNCE_S` | `NESTOR_TRIBUNAL_FEED_DEBOUNCE_S` | `0.75` | seconds of quiet before a dirty snapshot is written |
| `_FEED_PROMPT_MAX` | `NESTOR_TRIBUNAL_FEED_PROMPT_MAX` | `400` | chars of `task_prompt` per row (Pitfall 12) |
| `_FEED_MAX_ITEMS` | `NESTOR_TRIBUNAL_FEED_MAX_ITEMS` | `200` | rows per stage before overflow collapses |

(`_FEED_NAME_MAX = 120` bounds the display label; it is not env-tunable.)

**Fails loud, never silent** (cross-cutting rule 6): status clamped to the five legal
literals with a WARNING; overflow rendered *in the feed* as
`"+N more agent(s) not shown (feed row cap 200)"` rather than truncated away;
out-of-range handles logged rather than raised and never appended as phantom rows;
writer exceptions swallowed-and-logged per `set_stage`'s contract; and the feed goes
inert after `close()` so a late row cannot drag `run.current_stage` backwards onto a
finished stage.

### 3. `audit_out` — the F4 drill-down source

`anthropic_messages` and `gemini_generate` now accept an **optional, keyword-only**
`audit_out` dict, populated after `write_full_row` with `audit_id`, `cost_usd`
(string), `provider`, `model`, `duration_ms`.

**This is the single resolution of the outline's `audit_out` / `with_audit_id`
alternatives. Plans 10/11/12/16 must use this one API — do not add a second.** The
out-param form was chosen over a widened return type specifically so that **no
existing call site changes**: every current caller consumes the raw provider response
and would break on a tuple.

It is declared as an explicit parameter **ahead of `**kwargs`**, never fished out of
kwargs, because kwargs is forwarded verbatim to the provider SDK and an unknown key
there is an HTTP 400. A non-dict `audit_out` is a `log.debug`, not an exception —
telemetry must never abort a call that already succeeded and was already audited.

`openai_response`, `start_call` and `end_call` are untouched (plan 15.2-16 owns the
OpenAI surface).

### 4. [Deviation] Shared `_fill_audit_out` helper instead of two inline blocks

The plan's acceptance criterion says `audit_out` should appear "only inside
`anthropic_messages` and `gemini_generate`". I factored the five-line population block
into one private `AuditedLLMClient._fill_audit_out` static helper called from both,
rather than duplicating it. The intent of the criterion is fully preserved:
`audit_out` appears **nowhere** in `openai_response`, `start_call`, `end_call`,
`_build_payload_dict`, `write_full_row` or `upload_audit_body`. The benefit is that
the `isinstance(audit_out, dict)` guard and the `str(cost_usd)` rule live in exactly
one place, so plan 15.2-16 extending this to the OpenAI surface reuses the guard
instead of re-deriving it.

### 5. [Correctness, Rule 2] `update(handle, field=None)` means "leave alone", not "clear"

Not specified in the plan. These calls are made from inside per-agent code that often
passes an optional it does not have yet; letting a `None` through the merge would
silently downgrade an already-`done` row back to `pending`. `update` now filters
`None` values before merging. Row *creation* still omits `None` fields from the
emitted dict as specified.

### 6. [Honest reporting] The "fails if the Lock is removed" criterion, as literally written, is not achievable

Task 2's acceptance criteria say `test_concurrent_writers_do_not_lose_rows` must fail
if the `asyncio.Lock` is removed. **It would not**, and I am flagging that rather than
asserting something untrue. In single-threaded asyncio, the *mutation* path
(`self._items[handle] = …`) contains no `await`, so it cannot interleave and removing
the lock would not lose rows — the no-lost-rows property is delivered by single
**ownership**, not by the lock.

The lock's real, observable contribution is **write serialisation**: it is held across
the awaited write in `_write_locked`, so a slow full-snapshot write cannot be overtaken
by a newer one and re-lose rows. That property *is* pinned, by
`recorder.max_in_flight == 1` in the same test, and the recorder yields with
`await asyncio.sleep(0)` inside its critical section so an overlap would genuinely
interleave rather than being hidden by a synchronous fast path. Both properties are
stated in the test's docstring.
