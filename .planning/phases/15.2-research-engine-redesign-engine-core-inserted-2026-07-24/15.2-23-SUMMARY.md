# Phase 15.2 Plan 23: Outbound Personal-Identifier Scrub + Fact-List Placement Summary

Closes **D-I** (personal data dispatched to third-party research providers) with an egress
control at the single dispatch choke point, proven by the real query that caused the incident,
and ships the three offline-provable parts of **D-M** (Gemini ignored the fact-list instruction
on 8 of 8 reports).

## What was built

**D-I — the egress control.** `pipeline/tribunal/pii.py::scrub_pii(text) -> (text, count)` is a
pure, never-raising redactor for direct personal identifiers. It runs at the two places — and
only the two places — where text leaves this engine to an external processor:

1. `research_division.run_angles`, on `base_query`, immediately **before** the D8 block is
   attached. Every one of the four streams reaches the network through the one
   `runner(query=…)` call below that line, which is exactly why the control sits there rather
   than at the many places text enters the engine.
2. `own_researcher._clamp_search_input`, on the **model-authored** search query. The
   own-researcher writes its own searches from the angle it was given, so a scrubbed angle can
   still put an identifier back if the model recalls one from context. That function is already
   this stream's untrusted-model-input boundary, so the scrub belongs there and nowhere else in
   the file.

A removal is **reported, never silent**: the WARNING names the angle index, the stream and the
**count**, and never the value — formatting the removed identifier into a log line would write
it straight back into the log and the audit blob, which is the whole thing this control exists
to prevent (T-15.2-232).

**D-M — placement, and placeholder URLs.** `build_fact_list_prompt_block` gained a keyword-only
`provider` parameter that selects **placement, never content**. Gemini alone receives a
four-line `REQUIRED OUTPUT` lead-in ahead of the block; the full format rules still follow
verbatim at the tail. `_PLACEHOLDER_URLS` now rejects `N/A`, `none`, `-`, `unknown`, `tbd` and
their siblings **by name**, before the `http(s)` test, so the log says what actually happened.

## The honest limit of the D-M half

**Nothing here claims Gemini's compliance is fixed.** Whether a model obeys an instruction is a
live-LLM question, and no live run may be spent to answer it. What this ships is the cheapest
intervention that does not touch the format, plus the means to *measure* it next time. The
honour rate is already logged, per provider and in aggregate, by `pipeline/synthesis/steps.py`:

```
collect_provider_facts: <provider> returned no usable fact list for k of m research report(s)
... %d report(s) with a fact list
```

**Read those two lines after the next live run.** A second counter was deliberately not added —
`synthesis/steps.py` is the D-15 file and a nicer log line is not worth entering it.

**What must not be lost:** D-14's full-extraction distiller fallback caught all five
non-compliant Gemini reports live, first time, and is the reason run `d6bb3aae` produced claims
at all. `test_factlist_fallback.py` is green and untouched.

## The scrubber's boundary, stated plainly

This is in the module docstring too, because a scrubber that silently claims more than it does
is worse than one that says what it covers:

- **It covers** email addresses and dialling-shaped telephone numbers — the identifiers a
  machine can find without guessing.
- **It does not detect personal names.** A name detector loosed on research text about
  companies, brands and executives would either miss most names (giving false assurance) or
  delete half of every question — and a half-deleted question is a wasted paid deep-research
  call. Plan **15.2-21** is the other half of this: it removes the stakeholder lines that
  produce name-hunting questions in the first place. This plan is the defence that holds when
  that cause comes back.
- **It does not rewrite URLs.** An `@` inside a URL path is not an email address, and a
  corrupted source link breaks the evidence trail. URL-shaped tokens are skipped by name and
  four URL shapes are pinned by test.

The phone rule is where the real risk of over-reach lives, so it is a **dialling shape**, not a
digit run: it must start with `+` or `0`, carry 9–15 digits, and use at most two distinct
separator characters. Eleven strings this engine actually produces — year ranges (`2026-27`),
percentages, `EUR 1,2 miljard`, `EUR 3,50`, `8.000 tankstations`, and statutory opening hours
(`08.00-18.00`, which this engine literally researches) — are pinned as **untouched**
(T-15.2-233). The 8-digit exclusion exists specifically for that opening-hours case.

## Deviations from Plan

### 1. [Rule 3 — blocked by wave ownership] The operator feed clause was not written

- **Found during:** Task 2(a), third bullet.
- **Issue:** The plan says to "append one short clause to the row's display name", describing
  `_division_items` as a feed row "this loop already writes". It is not written in this loop —
  `_division_items` and `_angle_label` live in **`pipeline/tribunal/pipeline.py`**, they are
  built *before* `run_angles` is called, and that file belongs to plan **15.2-21**, which is
  editing it in this same wave. It is not in this plan's `files_modified`.
- **Resolution:** The count is recorded **additively** as `angle["pii_removed"]`, which costs
  the angle digest nothing and is ready to read. The `deep_research` feed rows are re-rendered
  from the live angle dicts on every `_on_angle_done` callback, so surfacing it is a one-line
  read inside `pipeline.py::_angle_label`:
  `+ (f" · {n} personal identifier(s) removed" if angle.get("pii_removed") else "")`.
- **Status:** **DEFERRED — one line, owner 15.2-21 or a later plan.** Until it lands, a
  redacted dispatch is visible in the WARNING log and in `angle["pii_removed"]`, but not in the
  operator's run feed. The plan's must-have "the operator sees that a dispatch was redacted" is
  therefore **partially met**: reported and recorded, not yet rendered.
- **Files:** none outside this plan's list were touched.

### 2. [Rule 1 — plan prose contradicted its own spec and an existing green test] Placeholder vs malformed URLs

- **Found during:** Task 3(b).
- **Issue:** The plan's action text says "Both paths still DROP the fact rather than keeping a
  sourceless claim." That contradicts (a) the plan's own Test 5, which drops the fact only for
  a **placeholder**, and (b) `test_non_http_url_is_rejected_but_the_fact_survives`, an existing
  green test whose whole point is that "losing the link must not lose the fact". Making both
  paths drop would have deleted real, sourced facts whose URL the model merely mistyped.
- **Fix:** Followed the plan's Test-5 spec and phase rule 3 (do not break what works):
  - **placeholder** (`N/A`, `-`, `unknown`, …) → the model says it had no source → **fact
    dropped**, counted in the new `FactListResult.placeholder_urls`;
  - **malformed** (`javascript:`, over-long, unparseable) → the model had a source and wrote it
    badly → **link dropped, fact survives** (unchanged since 15.2-04).
  The two paths are now pinned side by side in one test so a future edit cannot collapse them.
- **Commit:** `cf6dd4f`.

### 3. [Rule 2 — a lost fact must be a NAMED loss] `FactListResult.placeholder_urls` + a third fallback reason

- **Found during:** Task 3(b), implementing the drop.
- **Issue:** Dropping a fact with no counter would have been a silent loss, against the
  dataclass's own stated contract that "every field except `facts` and `not_found` is a NAMED
  LOSS". Worse, a block in which *every* line named a placeholder would have produced the
  fallback reason "…but not one line in it parsed as a fact (**0** line(s) ignored)", which
  reads as a parser failure and would mislead the operator about what the provider did.
- **Fix:** Added the `placeholder_urls` counter (keyword-only construction, single construction
  site, attribute-only consumption in `steps.py` — additive and safe) and a third
  `fallback_reason` branch that says plainly that every fact named a placeholder instead of a
  source. D-14 still fires in that case, so the prose is still distilled.
- **Commit:** `cf6dd4f`.

### 4. [Rule 3 — a budget's subject grew] `_D8_BLOCK_MAX_CHARS` 2600 → 3000

- **Found during:** Task 3(a).
- **Issue:** The gemini lead-in adds a fixed ~300 characters. A Dutch gemini angle would have
  exceeded 2600 and emitted a WARNING on **every angle of every run** — a designed, expected
  condition logged as an alarm, which is precisely the alarm fatigue D-12 rejects.
- **Fix:** Re-derived the constant, with the derivation written into the comment beside it, and
  stated explicitly that it was not raised to silence an assertion. `research_division.py` is
  in this plan's `files_modified`. The **behaviour** — an over-size block is logged and still
  sent whole, never trimmed — is pinned by `test_an_oversize_block_is_still_sent`, which drives
  the cap **down** to 10 rather than trusting the number; and
  `test_every_dispatched_block_fits_the_declared_budget` turns the derivation into a checked
  fact for all three prose-instructed streams.
- **Commit:** `cf6dd4f`.
