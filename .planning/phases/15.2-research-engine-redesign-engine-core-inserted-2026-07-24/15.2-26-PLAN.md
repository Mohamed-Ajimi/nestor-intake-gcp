<objective>
The gap phase's closing plan: make the gate honest, deploy the six fixes in the one order that is
safe, and perform the two operator actions the findings named.

**Three things converge here and none of them can be done earlier.**

1. **The gate count.** Plan 15.2-20 seeded five gap-phase test filenames into
   `cloudbuild.test-engine.yaml` in wave 1, four of them before their files existed. The config's
   `FILES=$$(ls … 2>/dev/null || true)` idiom silently drops a name whose file is absent — which is
   deliberate (a test that does not exist yet must be a skip, not a collection error) and is also
   exactly the "green because it ran nothing" trap this project has hit four times (deferred items
   D9-3, D15-1, D16-1, D19-2). Once every file exists, the arrangement must be closed: the gate
   asserts how many it collected.

2. **The deploy.** Six plans changed three services plus a migration. Migration 0014 must precede the
   worker image (the new `CLAIM_SQL` references columns that would not exist), the env revert must
   precede the unpause (or the run this phase exists to protect gets re-claimed), and the frontend
   must follow the backend (the Stop button calls a route that must already answer).

3. **The two operator actions the findings named**, both blocked on this plan's own deploy:
   - **Clear run `d6bb3aae-33e7-49fd-aa35-57dc529e05b3`** on intake
     `4a500d44-62b5-4f73-905f-792e31d0d9cc`. It is still `running` in the DB with a dead process, and
     `_RETRYABLE_RUN_STATUSES` excludes `running`, so that intake cannot be retried until the row
     resolves. This is D-D's acceptance demo: the first real use of the cancel button is the thing the
     absence of a cancel button caused.
   - **Revoke `roles/iam.serviceAccountTokenCreator` on `nestor-run@` from `tools@dotto.be`**
     (operator decision 2026-07-27, item 4). It was granted to attempt a manual seam cancel; it did
     not achieve one (the seam needs `X-Nestor-Tenant-Id`, which is reachable only by the intake
     backend), and it is a standing weakening of the Phase-14 lockdown. The decision explicitly says:
     revoke it when the UI cancel ships, **or** make it a deliberate documented capability. Do not
     leave it undecided.

**What this plan does NOT do.** It does not run V-01. The phase is still parked at plan 18 Tasks 4-6,
and a live validation run is a separate, operator-scheduled event against a fresh test intake. This
plan makes the engine safe to run; it does not run it.

Purpose: a fix that is not deployed is a fix that did not happen, and a gate that skips silently is
worse than no gate.
Output: an asserted gate count, one ordered deploy procedure, the six services and the migration live,
`d6bb3aae` resolved, the temporary env hacks gone, the IAM grant decided, and the findings document
marked up with what closed each defect.
</objective>
