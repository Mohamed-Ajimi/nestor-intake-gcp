# Phase 15.2 Plan 10: Question Workshop — Stage A (candidate funnel) Summary

The question workshop's candidate funnel now exists end to end: each client-validated
question gets a bounded web-orientation session, is deepened into `CANDIDATE: … | PARENT: …`
sub-questions whose parent is stamped by Python rather than parsed from the model, and the
population is collapsed onto distinct representatives **by calling the 15.1 clusterer, not by
building a second one**.

## The `run_workshop_stage_a` return contract (what 15.2-11 and 15.2-13 code against)

```python
result = await run_workshop_stage_a(
    brief=..., questions=None, brief_context=None,   # brief_context defaults to brief
    audited=..., run_id=..., tenant_id=...,
    feed=None, breaker=None, model=_WORKSHOP_MODEL,
)
```

| Key | Type | Contents |
|---|---|---|
| `questions` | `list[dict]` | `{label: str, text: str, source: str}` — the client-validated questions, verbatim, in brief order. Labels are **unique** (colliding labels get ` (2)`, ` (3)` …). `source` is `caller` / `detected` / `brief`. |
| `orientation` | `list[dict]` | Per question, in input order: `{label, findings: list[str], brief_conflicts: list[dict], citations: list[str], ok: bool, cost_usd: str, audit_id: str, calls: int}` plus `reason: str` when `ok is False`. |
| `brief_conflicts` | `list[dict]` | Flat, de-duplicated: `{question, assumption, world_says, source_url}`. **This is plan 15.2-06's "Disputed & changed" input.** `source_url` is `""` unless the model supplied an `http://`/`https://` URL. |
| `candidates` | `list[dict]` | The clustered representatives: `{index: int, text: str, parent: str, parents: list[str], source: "model"\|"verbatim", cluster_key: str, merged_from: list[int]}`. Ascending `index`. |
| `degradation_reasons` | `list[str]` | Ordered, de-duplicated plain-words sentences (each > 40 chars, counts as literal digits) for D-12 and the verification report. |
| `stage_a_fallback` | `bool` | `True` when **every** surviving candidate is `source == "verbatim"`. |
| `counts` | `dict[str,int]` | `questions`, `oriented`, `candidates_generated`, `candidates_after_cluster`, `brief_conflicts`. Integers only. |

**Never raises.** On an unexpected failure it returns the fallback shape — every client
question as its own verbatim candidate, `stage_a_fallback: True`, and a reason naming what
broke (D-17: a degraded deliverable beats no deliverable).

### For plan 15.2-11 specifically

1. **Union over `parents`, not `parent`.** A cluster can legitimately carry candidates from
   two different client questions; the representative keeps its own `parent` (the lowest-index
   member's) but `parents` is the ordered de-duplicated union of every member's parent. A D4
   superset assertion written against `parent` would report a false violation after a collapse.
   The correct assertion is:
   ```python
   union = set().union(*(w["parents"] for w in winners))
   assert union >= {q["label"] for q in result["questions"]}
   ```
2. **`stage_a_fallback` is the upstream half of `workshop_fallback: true`** — a D-12 degrading
   condition. Propagate it; do not recompute it from the winners.
3. **The degradation-reason vocabulary** lives in one place in `workshop.py`
   (`_reason_orientation_failed`, `_reason_orientation_uncapped`, `_reason_no_candidates`,
   `_reason_candidate_cap`, `_reason_cluster_collapse`, `_reason_stage_a_fallback`,
   `_reason_stage_a_crashed`). Add critique/tournament sentences to that block, not inline.
4. **The feed is NOT closed.** `run_workshop_stage_a` calls `set_summary` + `flush` and leaves
   the `workshop` stage open. Closing it would make 15.2-11's rows no-ops and drag
   `run.current_stage` backwards. Test 29 pins this.
5. **Import `tests/workshop_fakes.py`** (`ScriptedWorkshopAudited`, `FakeTextResponse`,
   `FakeToolUseResponse`, `search_result_block`, `text_block`) rather than re-writing fakes.
   `ScriptedWorkshopAudited` accepts a list script (FIFO) **or** a dict keyed by a
   discriminator substring matched against the rendered prompt. **Gotcha, learned the hard
   way here:** the candidate prompt embeds the brief context, so if the context contains the
   other questions' text a dict script mis-routes. Pass a narrow `brief_context` in
   multi-question tests.
6. **`test_workshop_critique.py` is pre-listed in `cloudbuild.test-engine.yaml`**, which no
   plan may edit. Append below the `SECTION 4 — the ENGINE-05 critique pass` banner at the
   end of the file; nothing above it needs restructuring.

### For plan 15.2-12

`EMIT_ORIENTATION_TOOL` + `force_emit_orientation()` landed in `tools.py` in **wave 2**, after
`force_emit_group_verdict`. Append `EMIT_FACT_LIST_TOOL` / `force_emit_fact_list()` **after**
them, and add the new names to the `Provides:` list (the CRITICAL INVARIANTS docstring now

## Deviations from Plan

### Auto-fixed / additive

**1. [Rule 2 — missing critical functionality] The global candidate cap is floored at the number of client questions**
- **Found during:** Task 2
- **Issue:** `_MAX_CANDIDATES` is env-tunable. If an operator set it below the number of client
  questions, round-robin trimming would still leave at least one client question with **zero**
  candidates — a D4 scope violation caused by a tuning knob.
- **Fix:** the effective cap is raised to `len(parents)` with a WARNING naming both numbers.
- **File:** `pipeline/tribunal/workshop.py` (`generate_candidates`)
- **Commit:** `b6f2be5`

**2. [Rule 2 — plumbing needed by the plan's own Task 3] Optional `stats` out-dict on `generate_candidates` and `cluster_candidates`**
- **Issue:** Task 3 requires `feed.set_summary(actions=<total LLM calls made>, cost_usd=…)`, but
  the plan fixes both functions' returns at a 2-tuple, so the call and cost counts had no way out.
- **Fix:** an OPTIONAL caller-owned `stats: dict | None = None` out-param, the same purely
  additive idiom `audited.anthropic_messages` uses for `audit_out`. Omit it and nothing changes.
- **Commit:** `b6f2be5`

**3. [Rule 3 — plan acceptance criterion] Docstring wording adjusted so `grep -c 'grouping\._cluster_block'` returns exactly 1**
- **Issue:** the plan requires that grep (over non-comment lines) to return **1**. Two module
  docstring sentences named the symbol, so the count was 3.
- **Fix:** those two sentences now name it as "the 15.1 clusterer in `grouping.py` (its
  `_cluster_block` entry point)" and "`grouping.py`'s own clusterer". The meaning is preserved
  and the assertion is exact.
- **Commit:** `b6f2be5`

**4. `_parse_orientation` takes an extra `citations` keyword.** The plan specifies
`_parse_orientation(block, *, label)` but also requires the returned dict to carry `citations`.
Signature is `(block, *, label, citations=None)`.

**5. Test-harness correction (not a code change).** Test 24 initially failed: the candidate
prompt embeds the brief context, and with the default context (= the whole brief) every
question's prompt contained every other question's text, so the substring-routed fake served
the wrong script entry. Fixed by passing a narrow `brief_context`. This is a property of the
**fake**, not of `workshop.py` — and it is documented above for plan 15.2-11, which will hit it.

### Not deviations, but worth stating

- `tribunal/cloudbuild.test-engine.yaml` was **not** edited (owned by 15.2-02, already
  pre-lists this file). `grouping.py`, `pipeline.py`, `group_skeptic.py` and
  `requirements.txt` are all untouched — `git diff --stat` on them is empty.
- `git diff --name-only master...HEAD` lists **exactly** the four paths in `files_modified`.
  (The plan writes `origin/master`; this worktree has no `origin` remote, so `master` was used.)
