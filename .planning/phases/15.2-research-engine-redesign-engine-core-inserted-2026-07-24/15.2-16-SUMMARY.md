# Phase 15.2 Plan 16: Engine-side park, checkpointing and provider-job resume — Summary

**A Tribunal run that loses every research stream or hits the Anthropic monthly cap now PARKS with its paid work recorded as `ckpt_*` rows, carries a redacted plain-English reason on `RunMetrics.park`, and can be re-queued by one tenant-scoped `POST /api/runs/{run_id}/resume` that re-uses the workshop and every completed research angle instead of buying them again.**

## Accomplishments

### Task 1 — the R3 store (`4325cad`)

`pipeline/tribunal/checkpoints.py`: `CheckpointStore` takes its `read`/`write` as
awaitables already bound to `(run_id, tenant_id)`, so the class contains **no
database code at all** — proven by grep (`CREATE TABLE|op.create_table|sessionmaker|AsyncSession`
returns nothing) and by 18 tests that back it with a plain dict.

- `CHECKPOINT_VERSION = 1` envelope; a payload from another version is DISCARDED on
  load with a WARNING naming the key (T-15.2-128) — this matters concretely, because
  a run may park before 2026-08-01 and resume after a redeploy.
- `angles_digest()` — the guard that makes index-keyed angle restore safe (T-15.2-123).
- `safe_job_id()` — bounded whitelist; the Gemini poll interpolates a provider id into
  a URL **path**, so a `/` or a `..` is path traversal (T-15.2-125). Returns `None`,
  never raises.
- `put()` refuses an oversized payload, writes nothing, returns `False` and names the
  byte count (T-15.2-131).
- `park_signature()` / `next_park_seq()` — DEC-5's mail-idempotency primitives.
- `resumed()` is False when the only stored key is `ckpt_park`: a park marker records
  why a run stopped, it is not resumable work.

### Task 2 — R7, reconnect instead of paying twice (`c09c8e0`)

Both deep-research raw methods gained `resume_job_id` and `on_job_started`
(keyword-only, defaulted, poll loops otherwise unchanged):

- Gemini: a resumed id SKIPS the dispatch POST entirely (**post count exactly 0**).
- OpenAI: a resumed id skips `responses.create` **and** the initial 30 s sleep, so an
  expired job is discovered now rather than half a minute from now.
- A 404/410 (Gemini) or `NotFoundError`/404 (OpenAI) on a **resumed** id returns a
  normal error envelope stating the job "is no longer retrievable … was NOT
  re-dispatched", degrading that one stream. It never crashes the run.
  `NESTOR_TRIBUNAL_RESUME_REDISPATCH=true` buys exactly one replacement job.
- `run_angles` gained `resume_results` / `resume_jobs` / `on_angle_result` /
  `on_job_started`. **A restored angle is never dispatched** — asserted as a call
  count, not a log line. `_RESUMABLE_PROVIDERS = ("gemini", "openai")`; Claude research
  is synchronous and the own-researcher is a local loop, so neither has a background
  job to reconnect to.
- Both `InsufficientProvidersError` raise sites are byte-unchanged (2 in
  `research_division.py`, 2 in `degraded_parallel.py`), and the local OpenAI
  create-retry helper is untouched (`git diff` touches no line containing its name).

### Task 3 — park end to end + the resume verb (`2ac0616`)

**`run()` was split into a thin guard plus `_run_staged`.** The R4 park needs ONE
try/except around the whole staged body, and a sibling method delivers that with the
body's indentation — and therefore the body itself — unchanged. Every local is passed
by name, so `degradation_reasons` is still the same one accumulator object and
`_note_degradation` is still its only writer.

- **F6:** `InsufficientProvidersError` is caught at the `run_angles` call site and
  turned into park facts with `streams_lost == streams_total`, which is what makes
  `terminal_state()` return `"parked"`. Defence-in-depth for any future raise site is
  an `isinstance` test inside the generic handler, so the file still contains exactly
  ONE `except InsufficientProvidersError` clause.
- **Hard wall:** one guard, `classify(exc) == HARD_WALL`. `RunCancelled` is listed
  FIRST and re-raised unconditionally — **a user cancel is never converted into a park.**
- **Verify-unable-to-run** is carried as a FACT (`verify_ran=False`) into
  `terminal_inputs`; it does not park inline. `terminal_state()` makes every call.
- **Worker:** the park branch computes `terminal_state(**terminal_inputs)` and writes
  the result. A non-park value logs the literal marker `park_state_inconsistent` and
  **the computed value is written anyway** — overriding it would create the second park
  rule this phase exists to remove. `park` is a sibling key on the persisted summary,
  write side only; `build_verification_summary()` and `RECORDED_FUNNEL_COUNTS` are
  untouched. `completed_at` is deliberately NOT stamped. All 5 terminal UPDATEs keep
  `WHERE id=:id AND status='running'`.
- **The success branch's pins are gone**: 15.2-09's `synthesis_ran=True, hard_wall=False`
  now read from `terminal_inputs` when present, falling back to exactly the old literals
  when absent (an ADK run, or a pre-15.2 `synthesis_cache` replayed after deploy).
- **`POST /api/runs/{run_id}/resume`** — `parked` → `queued`, `worker_id`/`error_message`
  cleared, the SAME run returned.

## Interfaces for 15.2-19 and 15.2-18

**Endpoint:** `POST /api/runs/{run_id}/resume` → `RunResponse` (the `cancel_run` shape:
`(run_id, session=Depends(get_db_session))`, **no `user` param**). `404` for an unknown
or cross-tenant id; `409` when the status is anything other than exactly `parked`.

**`RunMetrics.park`** (`park: dict | None = None`, `None` on every non-parked run):

```json
{"seq": 1, "stage": "deep_research", "reason": "<one sentence, <=400 chars>", "signature": "<12 hex chars>"}
```

`seq` is monotonic per park EVENT — re-parking for the same `(stage, redacted reason)`
keeps its number, which is how 15.2-19 sends one mail per event.

**`CHECKPOINT_KEYS`** (final): `("workshop", "angles", "research", "provider_jobs",
"merge", "gates", "verify", "park")`. `synthesis_cache` and `report_spec` are
deliberately NOT members — they own the pre-existing resume branch at the top of `run()`.

**New `NESTOR_TRIBUNAL_*` knobs, for 15.2-18's runbook:**

| Env var | Default | Effect |
|---|---|---|
| `NESTOR_TRIBUNAL_CHECKPOINTS` | `true` | Master switch. False = no checkpoint is read or written; the engine behaves exactly as before this plan. |
| `NESTOR_TRIBUNAL_CKPT_MAX_BYTES` | `16000000` | Refusal bound on one encoded checkpoint payload. A refusal costs a stage re-run, never a failed transaction. |
| `NESTOR_TRIBUNAL_RESUME_REDISPATCH` | `false` | True = a no-longer-retrievable job id falls through to a FRESH, separately billed dispatch instead of degrading the stream. |

## Deviations from Plan

### 1. [Rule 3 — blocking] Layer-B denial tests moved off testcontainers

- **Found during:** Task 3.
- **Issue:** The plan's acceptance criterion required
  `test_resume_cross_tenant_run_is_404` to EXECUTE in `cloudbuild.test.yaml`. That is
  **unsatisfiable, and would be worthless if it were satisfiable.** Commit `b479499`
  (landed the same day, before this plan ran) measured both facts and recorded them in
  that config's own header: (a) the testcontainers fixture does not start —
  `"host" network_mode is incompatible with port_bindings`; (b) testcontainers'
  Postgres runs as **SUPERUSER**, and RLS is bypassed unconditionally for a superuser,
  so the denial assertion would pass with a completely broken policy. That is exactly
  the bug 15.2-01 found, where four denial tests had never executed under a role RLS
  binds to.
- **Fix:** the three Layer-B tests were re-based onto the `DATABASE_URL` +
  `require_non_superuser` idiom of `test_rls_isolation.py`. They skip cleanly with a
  named reason when no DSN is set, skip LOUDLY on a superuser DSN, and execute
  faithfully under the non-superuser `app_user` harness.
- **Proof:** run in Cloud Build against a purpose-built clone of
  `cloudbuild.test-rls.yaml` (postgres:15, `app_user` NOSUPERUSER owner,
  `alembic upgrade head`, pytest under that DSN): **31 passed, 0 skipped**, build
  `373113c7-0e1f-4ec5-9111-5ce3820be248`, with `test_resume_cross_tenant_run_is_404
  PASSED` present by name and the anti-false-green block printing
  `RESUME PROOF GREEN: every test executed as non-superuser`.
- **Not committed:** the harness config. Editing `cloudbuild.test-rls.yaml` is
  forbidden (15.2-01 owns it; its block pins `6 passed`), and adding a fifth gate
  config is the phase owner's call. Recorded as **D16-1** in `deferred-items.md`.

### 2. [Judgement] `merge` / `gates` / `verify` ship WRITE-ONLY

- **Found during:** Task 3.
- **Issue:** restoring those three is an IDENTITY problem, not a data problem.
  `_group_selected` works because `apply_gates` mutates the very claim dicts the
  clusters hold *by identity*, and a JSON round-trip destroys identity. A correct
  restore must rebuild that coupling from claim indexes.
- **Decision:** the `merge` payload is already written in the index-referenced shape a
  restore needs, but no restore branch reads it. Nothing in the tree exercises such a
  branch end-to-end (`test_engine_e2e_stubbed.py` is not written yet, and no live run
  may be spent before 2026-08-01). Shipping an unexercised restore on a paid pipeline's
  hot path could corrupt a real claim set — a worse failure than re-running a cheap
  stage.
- **Consequence, stated plainly:** the must-have "a parked run re-uses every paid stage
  result" is **met for the workshop and for deep research** (the overwhelming majority
  of a run's cost) and **not yet met for gates/verify**. Recorded as **D16-2**.

### 3. [Implementation] The workshop checkpoint stores `workshop_result`, not `mission_brief`

The plan said "take `mission_brief` from the checkpoint". Everything between the two is
pure, deterministic Python (`build_mission_brief_from_winners` and the question
fallbacks), so re-deriving costs nothing and keeps ONE source of truth instead of two
that can drift across a redeploy. The paid stage is skipped either way.

### 4. [Implementation] `angles` is checkpointed but not restored

`divide()` is pure, deterministic and free, and re-running it preserves `_trims`, which
is where two of D-12's degradation reasons come from. The row exists for its DIGEST: a
resume compares it against the live angle list and logs loudly when the questions
changed.

### 5. [Rule 1 — bugs found by the gate, in my own tests]

Three test bugs the engine gate caught and that were fixed before commit. All three
were assertions that would have passed for the wrong reason or failed for a cosmetic
one — worth naming because each is the "green proves nothing" class:

1. `test_worker_park_branch_keeps_the_cancel_guard` counted `UPDATE run SET status=`
   across the module DOCSTRING as well as the SQL, making the guard assertion
   unsatisfiable (6 UPDATEs vs 5 guards). Now anchored on the leading quote.
2. The same test asserted `completed_at` absent from the park region — but the park
   branch's own comment *says* it deliberately does not stamp one. Comments are now
   stripped before the assertion, so it tests behaviour rather than wording.
3. `test_resume_handler_is_404_not_403_by_construction` failed because the handler's
   docstring quoted the forbidden status code. The docstring now spells "forbidden" in
   words, keeping both the documentation and its own gate.

Also caught pre-emptively: a `set_stage(run_id, tenant_id, _stage_key, detail={"items": …})`
call would have made `"items"` the first quoted token and broken the WR-03 source gates
in `test_stage_schema.py` and `test_research_division_assignment.py`. The detail dict is
now built into a local first.

### 6. [Rule 3 — blocking] `test_superseded_verdict.py` re-anchored after the method split

- **Found during:** the `cloudbuild.test-gates.yaml` regression run (build
  `0576fc54`), which went RED on
  `test_pipeline_wires_the_collector_into_contested_notes`.
- **Issue:** that CR-01 gate does `inspect.getsource(TribunalPipeline.run)` and asserts
  `_collect_superseded_notes(` appears in it. Splitting `run()` moved the staged body —
  and therefore that call — into `_run_staged()`. **The property itself never changed**:
  the collector still runs on every run. The test's source anchor was pointing at half
  the run path.
- **Fix:** the test now reads BOTH methods and concatenates them, so it keeps asserting
  the CONNECTION rather than the location. It was **not weakened** — every original
  assertion is intact, and a collector that is merely defined and never called still
  fails it.
- **Files modified:** `tribunal/nestor_pulse_sdk/tests/test_superseded_verdict.py`
  (one file outside this plan's declared `files_modified`, touched only because the
  refactor in this plan is what moved its target).
- **Commit:** `d6a7541`

**This is the finding I would flag hardest to the next executor:** any future test that
anchors on `inspect.getsource(TribunalPipeline.run)` must now read `_run_staged` too.
One such gate existed; it was found because the gates config was actually run rather
