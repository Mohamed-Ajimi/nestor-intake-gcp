## Decisions Made

**Why the stage-log state is module-level.** `_write_final_report` is a module-level function that writes the last two stages of every run (`synthesize`, `done`) and is *also* the interactive-resume path's entry point. A closure inside `_run_staged` cannot see it. The plan's action (d) said not to re-plumb those two call sites through the closure — "re-plumbing would change the call graph of a paid path for a log line, which is not a trade worth making" — and its action (c) required a closing summary line naming stages entered and total seconds, which needs shared state. A run-scoped registry satisfies both: no signature change, no new parameter, no changed call graph. It is bounded at 64 entries (oldest evicted), popped by `_stage_log_close`, and `run()` closes it in a `finally` so a park, a cancel, a failure, the zero-claim early return and the interactive `report_spec` pause all leave nothing behind.

**Why the workshop is an explicit span.** The `workshop` stage key is written by `StageFeed`, not by the shadowed `set_stage`, so no transition reaches the recorder for it — and the workshop is the longest silent stretch of a run (orientation, candidates, clustering, critique, a tournament, an evolve pass). Leaving it unlogged would have left the exact gap the plan closes. Pushing it through the transition recorder instead would have split the pipeline's two `intake` writes into two separate entries and re-introduced the entry-per-write noise the transition rule exists to prevent. So it gets an explicit `stage_enter`/`stage_exit` pair in the identical shape, nested inside `intake`'s open period — which is the honest picture, since the closure never left `intake`.

**Why `scrub_pii` is not called.** The plan's must-have is "no stage log line carries a credential, a personal identifier or an unbounded prompt body", and the phase forbids writing a second redactor. Neither is violated: no client-derived or provider-derived string reaches these lines at all. The control is structural — `_stage_log_line` renders every value through `int()` and every name through a key sanitiser, so a non-integer is **dropped whole, key and value**, not stringified. `test_a_non_integer_count_is_dropped_not_stringified` hands it a real research question and proves the question never appears. `reliability.redact` **is** imported and used, on the one thing here derived from an exception (the recorder's own failure path), per phase rule 8. The module comment names `pii.py::scrub_pii` as the function to use if a future edit ever formats a caller-supplied string into a stage line.

**Why `test_a_non_integer_count` is a whitelist, not a blacklist.** `test_no_stage_line_carries_content` requires every captured stage record to match `^tribunal_pipeline (stage_enter|stage_exit|run_stages_complete): (key=value )*$` where every value is `[a-z0-9_.]+`. A prompt body, a claim text, a research question or a URL cannot satisfy that pattern, so the assertion holds for content nobody thought to blacklist. The `http` / tab / `@` / length checks are kept alongside it as named, readable restatements.

**Why the engine's timestamps win at finalize.** `finalize_completed` already wrote `completed_at=func.now()`, so the mirror was never NULL there — the actual gap was `started_at`. Preferring `metrics["completed_at"]` when the engine sent it means both ends of the rendered duration come from **one clock**; `func.now()` remains the fallback, so an older engine build finalizes exactly as before.
