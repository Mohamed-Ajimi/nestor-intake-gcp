# Phase 15.2 Plan 05: Citation Anchors Summary

**The writing model now marks facts with an opaque `[[c:xxxxxxxx]]` token it cannot guess a number from, and Python rewrites each one into the `[n]` that `number_citations()` assigned — closing the D-05 loop that let last run ship 28 invented, unresolvable markers.**

## Accomplishments

### Task 1 — `citations/anchors.py` (commit `920e48a`)

A pure module: zero imports from `sqlalchemy`, `nestor_pulse_sdk.db`, `nestor_pulse_sdk.pipeline` or `httpx` (verified `grep -Ec` returns `0`). Everything provable is proved in the keyless, Postgres-less engine gate.

- `ANCHOR_RE` with a `pre` group that swallows leading whitespace, so a stripped anchor never leaves `word .` behind — pinned by three exact-string assertions.
- `collision_free_prefixes()` **excludes** any prefix claimed by two or more distinct claim ids rather than picking a winner. `build_ledger` and `anchor_number_map` both call it, so the ledger and the resolver can never disagree about which prefixes are usable.
- `apply_citation_anchors()` returns `(text, n_unresolved)` and **never raises** — `None`, `""`, non-strings, `[[c:zzzz]]`, `[[c:]]` and truncated tokens all degrade to `(text, 0)`.
- `count_model_numbers()` runs before the post-pass, when no number in the text can have come from Python, so every bare `[7]` found is model-invented. Counted, never stripped.
- 43 pure tests, including the non-collision trio and the prefix-collision safety rule.

### Task 2 — additive claim→`[n]` map + F10 (commit `23d6041`)

- `_assign_numbers()` extracted as a **pure** function; `number_citations()` is now a thin wrapper over it. Its signature, docstring contract and return value are byte-unchanged, and `git diff` shows no `-` line for either `def number_citations` or `derive_quality_tier`.
- `claim_to_n` maps **every** claim, because `setdefault` runs *before* the already-numbered early-out. A map built from `first_claim_id` alone would have left the majority of anchors unresolvable — the very count D-06 exists to drive down.
- The `ORDER BY c.position ASC NULLS LAST, c.id ASC, s.id ASC` determinism contract appears exactly once and is unchanged to the character.
- `_upsert_source(title=)` added on both INSERT paths. `title` is **not** part of `content_hash` — verified that the hash is still computed from `snapshot_capped` alone.

## The Pitfall-2 correction (the headline)

CONTEXT.md pointed D-05's anchor instruction at synthesis prompt **line 229**. That line lives in `final_synthesis_audited`, which `synthesize_report` calls **only** when `focus_areas == []` — the broadcast/control fallback. Every real run has focus areas and goes down the `_one_section` × N + `wrap_prompt` path, so patching line 229 would have produced green tests and **zero anchors in production**.

The rule landed in:

- `_one_section`'s prompt — with a facet-scoped `ledger_block`
- `wrap_prompt` — rule only, deliberately **no ledger**

`final_synthesis_audited` was **not** touched. That path legitimately produces zero anchors and the post-pass correctly reports zero unresolved for it.

**Proof:** `test_anchor_rule_reaches_both_prompt_sites` asserts `len(audited.prompts) == 3` and that every one contains `CITATION ANCHORS (non-negotiable):`. It carries a docstring naming why line 229 is the wrong site, so the trap cannot be silently reintroduced.

## Plan decisions recorded

**D-06 counts are siblings of the funnel, never members of it.** `verification_summary` is the *same dict object* as `verification_report["funnel"]`, and `RECORDED_FUNNEL_COUNTS` is compared by **full dict equality** in two tests (Pitfall 3). This plan writes nothing into the funnel dict — verified: `git diff` contains no `_build_funnel` line at all. `unresolved_anchors`, `orphan_cite_markers` and `model_invented_numbers` are added as siblings on both `verification_report` and the returned result dict, always present (0 on a run with no anchors). **15.2-08 owns** folding them onto `run.verification_summary` and owns the superadmin-facing wording.

**F10 state.** `_upsert_source(title=)` exists, defaults to `None`, and is **unused by production callers in this plan**. The one existing call site (the skeptic-evidence upsert) passes nothing — inventing a title from a URL would be a fabrication, and the graded renderer falls back to the display domain at render time instead, which is honest. **15.2-15 threads the real D8 provider-supplied titles through this parameter.**

### Auto-fixed issues

**1. [Rule 1 — Bug] Unconditional citation kwargs broke two pipeline tests**

- **Found during:** Task 3 close-out, via a deliberate extra regression run (build `01f23e7d`) of files that neither of this plan's two gates covers.
- **Issue:** Adding `anchor_ledger=` / `numbered_citations=` unconditionally to the `synthesize_report` call raised `TypeError` in `test_tribunal_pipeline.py::test_tribunal_pipeline_clear_brief_full_flow` and `::test_tribunal_pipeline_never_parks_for_clarification`. Both monkeypatch `synthesize_report` with a `fake_synthesis` double declaring explicit keyword-only params and **no `**kwargs`**.
- **Fix:** Build the citation kwargs conditionally, so the pre-15.2 call signature is preserved exactly on the no-citation path. Semantically identical — `synthesize_report` treats `None` and `[]` the same. Production still passes both kwargs, because `_load_citation_context` returns real rows there.
- **Why not fix the test doubles:** `test_tribunal_pipeline.py` is **not** in this plan's `files_modified`, and both the plan's acceptance criteria and the execution brief require staying inside it. The durable fix is recorded below as a deferred item.
- **Files modified:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/pipeline.py`
- **Commit:** `e88446a`

**2. [Rule 2 — Missing critical functionality] Anchor-stripped scan copy in the sources builder**

- **Found during:** Task 1 test design.
- **Issue:** `_MD_LINK_RE` requires `](` adjacency. `build_graded_sources_section` runs while anchors are still in the text (the post-pass runs later, in `pipeline.py`), so a model that dropped its anchor between a link's label and its URL — `[Aral][[c:9f2a41bd]](https://…)` — would make that URL match **nothing** and vanish from `## Sources` entirely. Silent data loss in the deliverable.
- **Fix:** Scan an anchor-stripped **copy**; the report text itself is never touched. Byte-equality with `_extract_sources_section` is preserved for anchor-free input (the input the acceptance criterion uses), and is now strictly better for anchored input.
- **Pinned by:** `test_c2_an_anchor_inside_a_link_hides_it_from_MD_LINK_RE` and `test_an_anchor_inside_a_link_does_not_lose_the_url`.
- **Commit:** `692771a`
