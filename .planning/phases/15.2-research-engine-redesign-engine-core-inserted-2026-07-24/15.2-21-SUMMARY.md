**The question workshop now deepens, ranks and dispatches ONLY the client's 11 decomposed research questions instead of the 32 lines it read off the whole context pack, and the tournament ranks materiality against the client's stated decision instead of against the project title `Deep research for moetest.`**

## Accomplishments

- **D-G closed.** `parse_brief` reads the brief's structure and classifies only digit-enumerated items under the question header as questions. On the recorded `d6bb3aae` brief shape the workshop input drops from 32 parents to exactly 11 — with `Output-omvang`, `NDA-status`, `Decision-maker` and the contact email provably absent from the question list.
- **The context pack is not dropped, it is reclassified.** It still reaches the engine in full, as `ParsedBrief.context`, which is what a context pack is named for. The workshop's orientation step still reads it; it can no longer deepen it.
- **D-H closed on both halves.** The intake backend now emits a `[DECISION]` block derived from the context pack's §3 line (then the intake's own decision answer, then the decomposition summary), and the engine prefers it over any model restatement. When nothing resolves, the run says so as a named degradation reason instead of silently ranking against a title.
- **The regression is demonstrated, not asserted.** `test_brief_input.py` runs the OLD detector over the SAME fixture string and pins that it still finds the offenders — so nobody can "fix" D-G later by widening the item regex without a test going red.
- **Both gates run green in Cloud Build**, on this machine's only real execution path (no local Python, no Docker).

## Decisions Made

- **Question text bounded at 400, not 120.** The plan said "bound each question to the same `_LABEL_MAX_CHARS` idiom `workshop.py` uses for labels". Taken literally that is 120 characters — but 120 is the bound on a question's LABEL (a dict key, and the join key the D4 superset assertion compares on), and `workshop.normalise_questions` already derives that 120-char label from whatever text it is handed. The intake's own headline question ("Which fuel retailers in Europe apply dynamic pricing today…") is longer than 120 characters, so bounding the TEXT there would have cut a real client question mid-clause before it was ever deepened — a quieter version of the defect this plan closes. `_QUESTION_MAX_CHARS = 400` is `workshop.py`'s own ceiling for a question pasted into a prompt, so nothing downstream ever sees more than it already bounded itself to. The constant carries this reasoning in full.
- **The missing-decision degradation demotes only STRUCTURED briefs.** See Deviations below.
- **Reason ordering.** The `_note_degradation` call for a missing decision is deferred until after the `workshop_fallback` branch, whose guard is `not degradation_reasons`. Emitting it earlier would have silently suppressed 15.2-11's own fallback wording.
- **Step 2 of the precedence is documented as dead.** `run_question_workshop` does not author a `deep_research_prompt`; it echoes one it is handed, and this call site has never handed it one. The log line "the workshop returned no research prompt" that fired on `d6bb3aae` was not bad luck — it is the only thing that can happen from this pipeline. Kept in the precedence because it is part of the workshop's published return shape, but the comment says plainly that nothing in this engine should be read as depending on it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Question text bounded at 400 rather than the plan's implied 120**
- **Found during:** Task 1 (`brief_input.py`)
- **Issue:** The plan's "bound each question to the same `_LABEL_MAX_CHARS` idiom" reads as a 120-character bound on question TEXT. Real client questions in this project are already longer than 120 characters, so applying it would have truncated the client's headline question before the workshop ever deepened it.
- **Fix:** `_QUESTION_MAX_CHARS = 400`, matching `workshop._QUESTION_MAX_CHARS` (the ceiling the workshop itself applies when pasting a question into a prompt), with a constant docstring explaining why 120 is wrong here and where the 120-char label still comes from.
- **Files modified:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/brief_input.py`
- **Verification:** `test_a_question_longer_than_the_bound_is_clamped_not_dropped` + `test_the_32_parent_brief_yields_exactly_its_eleven_client_questions` (which asserts the 11 questions round-trip byte-identically) — build `68b1a10c`.
- **Committed in:** `219a0b8`

**2. [Rule 1 - Bug] The missing-decision degradation demoted every stubbed and free-prose run**
- **Found during:** Task 2 (Stage 1 rewiring)
- **Issue:** As first written, the new `_note_degradation` fired on every run with no `[DECISION]` block. Because `run_question_workshop` never authors a research prompt (see Decisions), that is *every* run whose brief lacks the block — including free-prose and non-seam callers. Build `ef7c7c0d` failed exactly there: `test_clean_four_stream_run_completes_end_to_end` and `test_recovered_retry_and_cost_pending_do_not_degrade` both assert that a clean run names no degradation, "because a marker that is always on is a marker the operator learns to ignore" (D-12's alarm-fatigue rule).
- **Fix:** The fail-loud WARNING still fires on every decisionless run. The run-DEMOTING sentence was narrowed to `parsed.source == "structured"` — a brief that came through the intake seam with a question block, and which from Task 3 onward carries a `[DECISION]` block whenever a decision resolves at all. A free-prose brief has no decision block by construction. **The check that matters: run `d6bb3aae`'s brief WAS structured (`Onderzoeksvragen:` + 11 enumerated questions, no decision), so D-H would still have been reported on the run it was written for.** The reasoning, including that check, is in the code comment.
- **Files modified:** `tribunal/nestor_pulse_sdk/pipeline/tribunal/pipeline.py`
- **Verification:** build `8e6248ff` — 585 passed, identical to the pre-change baseline.
- **Committed in:** `d9ceb9d`
