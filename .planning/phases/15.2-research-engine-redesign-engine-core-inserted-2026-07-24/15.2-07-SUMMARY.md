## The four decisions, verbatim

**D-07-A (F7 — re-entry routes through the group skeptic).** `EMIT_VERDICT_TOOL`'s enum
is `["support","refute","insufficient"]` and `tools.py:99-103` forbids extending it.
D-11 resurrects re-entry, so that asymmetry now has production consequences: a
re-entered claim that is true-but-overtaken would come back `insufficient` (survives, no
caveat) instead of `superseded` (G-06/G-07 caveat reaches synthesis via
`contested_notes`). Re-entry therefore calls `run_group_skeptic` with a **single-member
group** — the cheapest correct move, per RESEARCH F7 and PATTERNS. Rejected: extending
the per-claim enum (explicitly forbidden in-source); leaving re-entry on `_one_skeptic`
(silently loses the fourth verdict on exactly the claims that got a second chance).

**D-07-B (the WR-01 cost trap).** `check_coverage` gains `selected_only: bool = True`,
intersecting the coverage surface with `(claim.get("gate") or {}).get("strict") ==
"VERIFY"` — RESEARCH's preferred option over an inline filter at the call site, because
it puts the rule in one auditable place and makes the module docstring honest (it still
claimed high-stakes claims are the coverage surface, which G-02 superseded). This
**extends D-11, it does not contradict it**: coverage still means "a claim the gates said
was worth checking and that got no verdict gets one last chance", and bucket 3 and the
coverage surface now count the same population by construction.

**D-07-C (the breaker gate is `state == "closed"`, not `allow()`).** `allow()` consumes
the single half-open probe and would authorise a whole **fan-out** of N sessions on the
strength of one probe token. Re-entry proceeds only from a fully closed circuit; `open`
and `half_open` both block, and the uncovered claims go to bucket 3 with a named reason.
This is the conservative reading of D-11 ("a tripped provider means no re-entry") and it
costs nothing in truth-telling, because the loss is counted and stated rather than
hidden. G-11's "fail toward MORE checking" does not apply: the alternative is not more
checking, it is more hard-400s (776 in 55 seconds on 2026-07-22).

**D-07-D (one thorough session, not three shallow ones).** Re-entry ran three
`_one_skeptic` calls per claim. It now runs **one** `run_group_skeptic` session at
`_GROUP_DEPTH["high"] == (6, 8, 5)` — six turns, eight searches, five fetches. This is
the engine's own stated economics ("stakes controls the DEPTH of that single session, NOT
the number of sessions"), it is what the grouped production path already does for every
checked claim, and `adjudicate`'s majority-independent rule already treats one
refute-with-independent-citation as authoritative. The pre-existing hard-coded three did
not even match `_PER_CLAIM_SKEPTICS`, which is 2.

## What changed

### Task 1 — `coverage_gate.py` (commit `ee43e02`)

`check_coverage(claims, adjudications, selected_only=True)`. The guard is one `continue`
before the existing `stakes` test, using the gate predicate copied character-for-character
from `pipeline._book_unchecked`, so there is no third spelling of the rule. Both docstrings
were rewritten: the pre-G-02 sentence "High-stakes claims (stakes='high') are the coverage
surface" is gone from the file, replaced by the arithmetic that forces the intersection
(706 DROP + 32 SKIP_STABLE = 738 claims with no verdict by design → ~2,100 extra Anthropic
sessions against a stage sized for ~150) and by the explicit statement that none of
`MAX_REENTRY`, D-11's breaker gate or the inert budget governor bounds that first wave.
`MAX_REENTRY` is still `1`.

`test_tribunal_adjudicate.py` (the 15.1 gates-gate regression surface) gained an optional
`gate` kwarg on `_make_claim`, set **only when provided** so the `adjudicate` tests above
it are byte-unaffected, plus two new tests — the cost-trap regression and the
`selected_only=False` legacy surface — living where the 15.1 gate will see them.

### Task 2 — `pipeline.py` (commit `142cf9d`)

- **WR-01 fixed.** `adjudications` is built by a nested `_adjudications_now()` closure
  returning `{id(c): True for c in claims if verdicts_by_claim.get(id(c))}`. The old
  `if id(c) in verdicts_by_claim` test was unconditionally true because the seed builds
  `{id(c): [] for c in claims}`, so `coverage["pass"]` was always True, `uncovered` always
  empty, the re-entry loop unreachable dead code, bucket-3 site (c) unable to fire and
  `reentry_count` permanently 0. The inverted comment above it was replaced with the truth,
  including the note that **the funnel stayed honest throughout** — WR-01 removed a
  *recovery* path, it did not lie.
- **The inverted comment site was grep-verified, not trusted.** It sits at the
  `adjudications` build (was `890-892`), NOT at `845-847`, which is bucket-3 site (b) — the
  budget-cap `_book_unchecked` in the grouped path. Both moved after plans 05/06; every
  edit was anchored on symbols.
- **Both `check_coverage` call sites pass `selected_only=True` explicitly**, with the trap
  commented in two sentences at the first one.
- **`_coverage_reentry_pass`** — new module-level async helper taking `book_unchecked` as a
  callable so it is drivable from a test with no pipeline run. Order: empty `uncovered` →
  zeros, dispatching nothing; breaker gate reads `getattr(breaker, "state", "closed")` and
  **never** calls `allow()`; on a non-closed circuit it builds a plain-words sentence from
  the claim count, the state and `snapshot()["reason"]` (guarded), books everything into
  bucket 3 and returns `sessions == 0`; otherwise one single-member-group session per claim
  through the shared `sem` and `asyncio.timeout(_SKEPTIC_TIMEOUT_S)`, gathered concurrently;
  harvest index 0, attach a **copied** meaningful reconciliation, extend `superseded_notes`
  via `_collect_superseded_notes`; then bucket-3 site (c) with the **unchanged recorded**
  cause string `"coverage-gate re-entry returned no verdict"`.
  Synthetic groups are deliberately NOT appended to `group_reconciliations` (a single-member
  group's `relation` defaults to `"single"` and its entity/attribute are display fallbacks,
  so filing it there would print noise under a made-up heading) — said so in a comment.
- **The two pre-seeding lines were deleted.** `verdicts_by_claim[id(claim)] = []` was a
  no-op by construction, and `adjudications[id(claim)] = True` declared the claim adjudicated
  *before* its session ran, so the second `check_coverage` could not see a failed re-entry.
- **Breaker bookkeeping.** `_one_skeptic` and `_one_group_pass` now call `_note_skeptic_ok()`
  / `_note_skeptic_failure(exc)` on the run-scoped `anthropic:skeptic` breaker. Both wrap the
  breaker call in `try/except` (Shared Pattern 6 — bookkeeping is best-effort and must never
  kill a batch); the *verification loss* is still counted separately by `_book_unchecked`,
  which is Pattern 5 and is NOT best-effort. Without this, D-11's gate was decorative: with
  no failure ever recorded the breaker could never trip.
- **`_recon_is_meaningful`** lifted to module level, pure, called from both `_flush_groups`
  and `_coverage_reentry_pass`. Behaviour-preserving extraction, pinned by a four-case test.
- **D-12's accumulator.** `breakers = BreakerSet()` and `degradation_reasons: list[str] = []`
  plus `_note_degradation` are declared in ONE block immediately after the
  `interactive_report` strip and **before** the resume-from-cache read.
  Declaration line **405**; `cached_spec = await _read_output(...)` line **453** — the
  declaration is earlier, as required. `grep -c` pins: one declaration, one `def
  _note_degradation`, two `_note_degradation(` occurrences (def + the blocked-re-entry call).
  Published on exactly two surfaces, both from that one list.
- **Full-dict-equality audit, as the plan required.** Grepped the test tree for a full-dict
  equality assertion on the bundle's `verification` dict and on the result dict: **there is
  none today.** `RECORDED_FUNNEL_COUNTS` is compared by full dict equality only against the
  FUNNEL (`fixtures/run_4cbb5311/loader.py:239-245`); `test_gate_replay.py:399` reads
  individual funnel keys; the key-set assertions in `test_verification_buckets.py:264`,
  `test_verdict_publication.py:259/309` and `test_research_bundle_endpoint.py:121` are on
  `report["unverified"]` and a route body, not on these two dicts. Adding the two keys is
  therefore safe, and the funnel itself was not written to
  (`grep -c 'funnel\["degradation_reasons"\]'` = 0).

### Task 3 — `group_skeptic.py` (commit `a094266`)

`for turn in range(1, max_turns + 1)` became `while turn < budget` with `turn += 1` first
and `is_final_turn = turn >= budget` driving the forcing rule, so the client tool is still
forced on the last turn actually available. A `pause_turn` now appends the paused assistant
message back unchanged (the same `_content_to_serialisable` call the `tool_use` branch
makes) and increments `budget` by 1, so a paused turn does not consume the tool-use turn
budget. `PauseContinuation` caps it at `MAX_PAUSE_CONTINUATIONS`, so `budget` can exceed
`max_turns` by at most 3 (T-15.2-73). Every other unexpected stop reason — and a pause whose
budget is spent — falls through to the **existing, unchanged** loud warning +
`_insufficient_group`. WR-10's member fill loop (`by_index.setdefault`, plan 08's edit site)
is untouched.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 2 — missing critical functionality] The zero-claim skeleton publishes the real accumulator, not a literal `[]`**

- **Found during:** Task 2 step 9.
- **Plan text:** add `"degradation_reasons": []` to the hand-built zero-claim early-return
  skeleton.
- **Issue:** stages that append reasons run **before** claim distillation — the question
  workshop's fallback (plan 15.2-11) and a lost own-researcher stream (plan 15.2-12) both
  happen upstream of it. A zero-claim run that had already lost two research streams would
  publish an empty list, and `runs/worker.py` would call the run `completed` instead of
  `completed_degraded`. That is a silent verification loss of exactly the kind this phase
  exists to close.
- **Fix:** `"degradation_reasons": list(degradation_reasons)` — the same one accumulator, a
  copy so a consumer cannot mutate it. Identical to `[]` today (nothing appends before
  distillation yet) and correct once 11/12 land.
- **Impact on the acceptance criteria:** none. The grep counting `"degradation_reasons"` at
  exactly 3 still holds; the key-name and shape contract 15.2-09 reads is unchanged.
- **Files modified:** `pipeline.py`.
- **Commit:** `142cf9d`.

**2. [Rule 3 — blocking issue] Two docstring lines reworded so grep-based acceptance criteria are not defeated by prose**

- **Found during:** Task 2 verification.
- **Issue:** the acceptance criteria `grep -c 'range(3)' pipeline.py == 0` and
  `grep -v '^\s*#' pipeline.py | grep -c '"degradation_reasons"' == 3` are literal token
  counts. My explanatory **docstrings** (not `#` comments, so `grep -v '^\s*#'` does not strip
  them) contained `range(3)` twice and the quoted key twice, taking the counts to 2 and 5
  respectively while the actual code was correct.
- **Fix:** reworded the prose without losing any meaning — "three per-claim skeptic calls"
  instead of the literal token, and "the TOP-LEVEL key on the dict `run()` returns" / "the
  same list on the synthesis bundle under `verification`" instead of the quoted subscripts.
  The latter wording is verbatim the plan's own `must_haves` truth.
- **Files modified:** `pipeline.py`.
- **Commit:** `142cf9d`.

No Rule 1 bugs found. No Rule 4 architectural decisions were needed. No package was installed;
`requirements.txt` is unchanged.
