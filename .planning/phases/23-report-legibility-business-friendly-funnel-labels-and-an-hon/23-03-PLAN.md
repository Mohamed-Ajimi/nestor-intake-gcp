## THE STREAM MUST STAY AT EXACTLY ONE

Today the intake detail page holds ONE research SSE connection, opened inside
`IntakeOpenRunLink` (`ResearchRunProgress.tsx:252-256`). That component's own docstring makes the
count a stated property: *"This mounts ONE SSE connection — the very same connection the removed
component already opened on that page. Strictly less network than before, never more."*

The banner needs the same run object. Calling `useActiveResearchRun` a second time — in the banner or
in the route alongside the untouched link — would open a **second** connection to the same endpoint
and quietly reverse that property. So this plan **lifts** the single call into the route and hands
the run down to both consumers. The link keeps its behaviour and loses only its private stream.

⛔ **`IntakeOpenRunLink` is the app's ONLY navigation into the run page.** Phase 22 planning nearly
deleted it by accident and `22-UAT.md`'s A5b exists solely to check it survived. Every task below that
touches it carries a blocking criterion that it still renders and still receives a run id.

## WHAT THIS PLAN MUST NOT DO

- **Do NOT modify `lib/intake-phase.ts`, `derivePhase`, or any `phaseShows*` helper.** The intake
  STATUS is not split; only the `in_research` phase's PRESENTATION is.
- **Do NOT revive or render the `ResearchRunProgress` COMPONENT** (DEF-22-01). Its body is ~350 lines
  of unreachable code that must stay compiled and unrendered. This plan changes exactly one exported
  function in that file — `IntakeOpenRunLink` — and its docstring.
- **Do NOT add, remove or re-style any button in the banner.** The `in_research` branch has no
  `actions` today and gains none: `FinalReportBlock` already renders on this phase
  (`phaseShowsFinalReport` includes `in_research`), so an "upload report" CTA in the banner would be a
  second copy of a control the page already has.
- **Do NOT delete `ResearchRunProgress.tsx`**, and do not remove the dead `export { triggerResearch }`
  or the unrendered component body. Both are DEF-22-01's, not this phase's.
- **Do NOT touch `research.currentStage`** — see Task 3, which records why it is out of scope.
