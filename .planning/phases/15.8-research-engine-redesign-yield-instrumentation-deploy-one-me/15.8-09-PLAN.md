<design_decisions>
Settled HERE so no executor has to discover them. A downstream reader re-opening one of these
is re-litigating decided work.

**1. WHERE the INSERT happens: after the deterministic dedupe, not inside `run_angles`.**
15.8-05's `record_assignment` takes `fact_list_parsed`, `claims_kept` and
`resolvable_sources` — and **none of the three exists inside `run_angles`.** The three live
adapters return a `{status, report}` envelope; only the `own` researcher returns `facts`, and
`own` is not in `_D6_STREAMS`. The fact list is parsed later, in `collect_provider_facts`.
So "research-resolve" for this table means **the distill boundary**: the line after
`claims = _dedupe_claims(claims)`, which is the first point at which the research half is
complete and the last point before the pipeline spends another cent. Everything upstream of
that line that this plan needs — cost, duration, the retry flag, the assignment identity —
travels there on the enriched result.

**2. `claims_kept` and `claims_surviving_verification` share ONE denominator basis.**
Both are counted over POST-`_dedupe_claims` claim objects: the numerator from `survivors`,
the denominator from `claims`. Counting the kept half from `facts_result.claims` (pre-dedupe)
and the survivor half from `survivors` (post-dedupe) would make the ratio quietly wrong in
the one run that gets measured.

**3. How a claim is attributed to an assignment.** `provider` must appear in the claim's
`found_by`, and then: if the assignment has a `group_id`, the claim's `corroboration_key`
must equal it; if it has none (the focus-area fallback path), the claim's
`corroboration_key` must be `None` AND its `facet` must equal the assignment's
`client_question`. **Matching on `facet` alone would be wrong for the cross-cutting group** —
its `client_question` is NULL by ruling while its claims file under `labels[0]` via the
orphan rule, so a facet match would attribute the whole `d1` group to Q1.

**Two imprecisions this creates, both stated rather than hidden.** (a) `_dedupe_claims` is
FIRST-WINS on `corroboration_key` and MERGES `found_by`, so a statement found in two groups is
counted against the first group only, and summing `claims_kept` across assignments does not
equal `len(claims)`. (b) A claim found by two providers counts for BOTH, because it did come
out of both assignments — a SUM over providers therefore exceeds the claim count by design.
Both belong in the column docstring at the seam and in the SUMMARY, because 15.8-15 reads
these numbers once and cannot re-run to check them.

**4. `fact_list_parsed` is DERIVED from `fact_source`, and the derivation is exact except in
one case.** A report whose D8 block parsed produces `fact_source="fact_list"` claims; a report
that fell back produces `fact_source="distiller_fallback"` claims. So: `True` when any of the
assignment's claims came from the fact list, `False` when it has claims and none did,
**`None` when it has no claims at all** — because "this assignment produced nothing" is not
evidence about whether its fact list parsed, and a `False` there would be a fabricated
measurement. The per-report parse outcome itself is only aggregated per-provider inside
`steps.py`, which this plan does not own; record that in the comment so the next reader does
not think it was overlooked.

**5. `retry_used` means the COVERAGE RETRY, and nothing else.** `run_angles` re-dispatches an
uncovered focus area ONCE on a different enabled stream via `force_provider`. That is the only
retry in this file. The D8 fact-list retry inside `collect_provider_facts` is a different
thing in a module this plan does not own — say so at the stamp site so the two are not
conflated by a reader of the column.

**6. `duration_s` is measured around the RUNNER AWAIT ONLY**, inside the semaphore — not
around the whole coroutine. Time spent queued behind `_ANGLE_CONCURRENCY` is not time the
provider spent working, and this column exists to compare providers. Use
`time.monotonic()`, never `time.time()`: a wall-clock step during a forty-minute deep-research
call would produce a negative or absurd duration, and `duration_s` is `NUMERIC(10, 3)`.

**7. A restored angle carries the ORIGINAL attempt's cost and duration**, because `_enriched`
is checkpointed and returned as the same object. That is the honest record: the run paid that
cost once, at that duration. **It also means a RESUMED run re-INSERTs a row for every restored
angle**, producing two rows on one natural key. This is the same class as the doubled
high-stakes fallback copy that 15.8-05 already logged, and it lands in the same place: the
completer reports the affected row count and WARNS when it is not exactly 1. **Do not try to
make the INSERT idempotent** — that would need a UNIQUE constraint (ruled out: a uniqueness
violation inside a paid run) or an edit to the emitter (forbidden: single owner). Log a
WARNING naming the restored assignment at the stamp site so a grep can find them, and record
the reader-side rule in the SUMMARY: **dedupe on the natural key before any SUM.**

**8. `research_division.py` does NOT import `runs.yield_records`.** The classifier returns
plain strings and stays a pure dispatch-shape concern; coupling the angle builder to a
database module would be a real dependency for a naming convenience. The vocabulary is pinned
instead by a TEST that imports `yield_records.PARENT_KINDS` and asserts the classifier's three
outputs are a SUBSET of it — subset and not an exact set, so the assertion cannot break if the
emitter ever gains a fourth kind, which is the "exact-set allowlist over a file a sibling plan
edits" trap that cost phase 15.5 a cross-plan regression.

**9. The pipeline calls ONLY the `_safe` wrappers.** `record_assignment(` and
`complete_assignment(` must not appear in `pipeline.py` at all. A caller's arguments are
evaluated before the callee is entered, so the plain form would let a `KeyError` escape at the
call site where no defensive code inside the emitter can catch it. Belt AND braces here: the
row builders are separately documented pure and never-raising, AND the seam loop has its own
`try/except Exception` backstop, AND the call goes through `_safe`. This is telemetry inside a
~$45 single-shot run; three layers is proportionate.

**10. No `run_events` line is emitted by this plan.** `RUN_EVENT_KINDS` is a CLOSED
twelve-value tuple and an out-of-vocabulary `kind` is dropped SILENTLY at `emit`. The whole
point of D-W5-1 was to stop routing this measurement through that feed.
</design_decisions>
