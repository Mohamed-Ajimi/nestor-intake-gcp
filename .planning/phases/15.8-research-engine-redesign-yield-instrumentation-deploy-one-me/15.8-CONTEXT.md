### D-W5-1 — The yield data gets its OWN tables, and a third alembic migration (operator, 2026-08-04)

**RULED: new tables + alembic `0018`.** Rejected: reusing `run_events` (no migration), and extending

Two tables:

```
assignment_yield
  run_id, provider, group_id, client_question, stakes,
```

**Why not `run_events`:** its `meta` passes a `_META_FIELDS` **allowlist**, so unknown yield keys are

drop the cap and keep the money"* is a query over many runs, not one.

**Why not `audit_log`:** it is the hash-chained EU AI Act Art. 12 record whose `verify_chain` is
re-gated on every deploy against a legal deadline. Altering the row shape of the chained table to
carry telemetry trades a legal guarantee for convenience.

**The cost is real and must be planned, not discovered:** this makes **THREE unpaid migrations** in
one deploy — `0015 -> 0016`, `0016 -> 0017`, `0017 -> 0018`. **None of 0016 or 0017 has ever touched
a database.** Each is proven by its literal `Running upgrade X -> Y` line and **never** by exit code
0. The backend gate has never printed that line; this repo has been burned by exactly that.

**⚠ AMENDED 2026-08-04 — THE ONE-LINE FIX IS A `NameError`. THE FIX IS TWO CHANGES.**

### D-W5-14 — The autouse resolver kill-switch does NOT make the `actions` tests vacuous — but it sharpens the ruling (orchestrator, 2026-08-04)

15.8-11 found `tests/conftest.py`'s **autouse** `_no_live_redirect_resolution` fixture, which sets
`NESTOR_REDIRECT_RESOLVE_ENABLED=0` for every test that does not opt out, and asked whether any test
asserting `admission_resolver_calls` therefore runs against a structurally-zero value. **Good question.
Answered NO, in source.**

`workshop_admission.py:638-641`:
```
resolver_calls = 0
if batch_urls:
    resolver_calls = 1
    try:
        resolved = await resolve_redirects(batch_urls) or {}
```
**`resolver_calls = 1` is set BEFORE the call and regardless of the kill switch.** `resolve_redirects`
returns early when disabled, but the counter is already 1. So the counter is not zeroed by the fixture,
and `test_discovery_bracket.py:1246` (`assert stats["admission_resolver_calls"] == 1`) is a real
assertion, not a vacuous one. **No test needs changing for this.**

**⚠ But it makes D-W5-9 sharper, and the operator should rule with this in hand.** The counter does not
mean *"a network call happened"* and it certainly does not mean *"we paid for something"* — it means
**"the resolver was invoked"**, an invocation that issues **zero HTTP requests** whenever the kill
switch is off. Production defaults the switch ON, so it usually does resolve; but the counter's
semantics are invocation, not work and not spend.

That strengthens the case for **removing it from the `actions` sum**: it is not merely non-LLM work, it
is work that **may be a complete no-op** — while `actions` is the number a reader uses to judge what the
run did. Fold this into 15.8-06's decision record.
