### D-W5-1 — The yield data gets its OWN tables, and a third alembic migration (operator, 2026-08-04)

**RULED: new tables + alembic `0018`.** Rejected: reusing `run_events` (no migration), and extending
`audit_log`.

Two tables:

```
assignment_yield
  run_id, provider, group_id, client_question, stakes,
  fact_list_parsed, retry_used, claims_kept,
  claims_surviving_verification, resolvable_sources,
  cost_usd, duration_s

workshop_round_yield
  run_id, round_no, candidates_in, new_candidates,
  keep_count, weak_count, kill_count,
  new_entrants_top_n, barred_drops, round_cost_usd
```

**Why not `run_events`:** its `meta` passes a `_META_FIELDS` **allowlist**, so unknown yield keys are
dropped *silently* — the exact inert-instrumentation class this project has now been burned by three
times (V-01 stage logging, D-W4-11 workshop notes, and the out-of-vocabulary `kind` trap). Its text
is also scrubbed and clamped to 400 chars, and it is a per-run feed rather than a cross-run table.
**Cross-run is the entire point:** *"if round 7+ never produces a new entrant across several runs,
drop the cap and keep the money"* is a query over many runs, not one.

**Why not `audit_log`:** it is the hash-chained EU AI Act Art. 12 record whose `verify_chain` is
re-gated on every deploy against a legal deadline. Altering the row shape of the chained table to
carry telemetry trades a legal guarantee for convenience.

**The cost is real and must be planned, not discovered:** this makes **THREE unpaid migrations** in
one deploy — `0015 -> 0016`, `0016 -> 0017`, `0017 -> 0018`. **None of 0016 or 0017 has ever touched
a database.** Each is proven by its literal `Running upgrade X -> Y` line and **never** by exit code
0. The backend gate has never printed that line; this repo has been burned by exactly that.

### D-W5-6 — The drop-cause seam: giving `DROP_CLUSTERED_ONTO_LIVE` a writer CONTAMINATES `barred_drops` unless three readers change with it (found by 15.8-04's planner, 2026-08-04; verified in source)

`workshop_register.record_drop` appends **both** causes to ONE list, `register["drops"]`.
`workshop_rank.py` reads that list by **BARE LENGTH** in three places, and all three are named for the
**barred** cause only:

- `workshop_rank.py:4527` — `drops_before = len(register.get("drops") or [])`
- `workshop_rank.py:4540` — the delta, feeding `round_metrics(dropped_as_reproposal=…)`
- `workshop_rank.py:5007` — `"dropped_as_reproposal": len(register.get("drops") or [])`

Today only the barred cause can ever be written, so a bare length is **accidentally correct**. The
moment 15.8-04 lands a production live-drop writer, `dropped_as_reproposal` starts counting ordinary
near-copy merges — so **the "loop is SPINNING" metric silently absorbs the OPPOSITE failure it was
built to distinguish.** That is precisely the separation D-W4-1 exists to make, and `record_drop`'s own
docstring spells out both directions.

**Why it is not cosmetic:** 15.8-10 persists `round_metrics` into `workshop_round_yield.barred_drops`,
and 15.8-15 reads that table as **the one measurement**. An inflated `barred_drops` in the only
measuring run is not recoverable.

**RULED:**
- **15.8-04** adds `workshop_register.count_drops(register, *, cause=None, round_no=None)` and states
  the hazard in `record_drop`'s docstring. Both are in files it owns.
- **15.8-10 swaps all three reads** to the cause-filtered counter. **NOT 15.8-03** — `count_drops` is a
  symbol 15.8-04 creates, and 15.8-03 runs in a parallel worktree in the same wave, so it cannot see
  it. A plan calling a function a sibling is creating in an isolated tree is the exact shape that
  produced 15.5's cross-plan regression (three green verifications, plan-checker passed, all executors
  reported success; only executing the merged tree found it).
- **`15.8-10 depends_on` therefore includes `15.8-04`**, so the dependency is explicit and assertable
  rather than resting on "wave 1 merged, so it must be there."
- **Swap all three or none.** `:4527` and `:4540` are a matched pair — fixing one leaves a delta
  between two different denominators, which is worse than leaving both wrong.

### D-W5-11 — `round_metrics` does not emit two of `workshop_round_yield`'s columns AT ALL — 15.8-10 must EXTEND it, not map it (2026-08-04)

**`new_entrants_top_n` is the single most important counter in D-R8.** ENGINE-REDESIGN-SPEC § 6:

**RULED: the columns stand exactly as D-W5-1 specified. 15.8-10 EXTENDS `round_metrics`** to carry
