## Accomplishments

### Task 1 — `round_metrics` carries the four missing counters (D-W5-17)

`round_metrics` emitted ten keys. Four of `workshop_round_yield`'s columns — `keep_count`,
`weak_count`, `kill_count`, `new_entrants_top_n` — **had no source at all**. It now emits
**fourteen**, in D-W5-1's column order.

**None of the four has a default**, matching the ten existing parameters. That is a correctness
requirement, not a style choice: `round_metrics` has exactly ONE production caller, so a default
of `0` would turn "the wiring was forgotten" into a confident zero in the only measuring run.

**No import was added** — `workshop_loop.py` remains stdlib-only (its grep for a
`nestor_pulse_sdk` import still returns **0**), and every new value goes through the existing
`_count_of`.

The docstring gained **THE TWO DENOMINATORS**: `winners`/`weak_winners` are WINNER-scoped;
`keep_count`/`weak_count`/`kill_count` are CRITIQUE-scoped and sum exactly to `candidates_in`.
The triple is critique-scoped in **all three** members because **a KILL has no winner-scoped
meaning** — a killed candidate is removed before ranking, so there is no such thing as a killed
winner.

At the loop site the triple is computed **before the two bar loops**, which rebind the name
`killed`, and after `critique_candidates` has reconciled `killed_out`.
`new_entrants_top_n` is read **straight off `verdict`** — `exit_verdict` is its one authority.

### Task 2 — three cause-filtered drop reads, and one row per round

**D-W5-6 — all three swapped, no partial.** `record_drop` appends both causes to ONE list, and
15.8-04 landed the production `DROP_CLUSTERED_ONTO_LIVE` writer, so from that moment a bare
`len(register["drops"])` made `dropped_as_reproposal` — the *"the loop is SPINNING"* metric —
silently absorb ordinary near-copy merges, **the opposite failure D-W4-1 built the log to
distinguish**. Sites 1 and 2 now use the **byte-identical** call expression, verified
structurally by comparing their `ast` source segments rather than by eye.

The `round_no=` filter was **rejected** for the delta: it would silently return zero if a drop
were ever stamped with an unexpected round. `barred` (bars CREATED) is untouched and stays a
bare length — a different quantity.

`_persist_round_yield` maps the nine columns and is awaited **once per round**, immediately
after `round_records.append` and before the `hold_reason` log, so a run that dies in round 7
keeps rounds 1-6 and the table can never disagree with `loop_rounds`.

## Deviations from Plan

**1. [Rule 1 — bug] The plan's `pytest.raises` instruction was SELF-INVALIDATING for `test_workshop_loop.py`.**
- **Found during:** Task 1, before writing the required-parameter test.
- **Issue:** Task 1(c) says to add "a test that each of the four is REQUIRED (`pytest.raises(TypeError)` per parameter)". That file **imports no pytest**, and **its module docstring forbids it in terms**: *"So: no `import pytest`, no fixtures, no parametrise, no `pytest.raises`."* The docstring states the reason and it is load-bearing: it is what lets those functions "be driven by a twenty-line loader on the one stdlib-only interpreter this machine has".
- **Verified before deciding:** the module **does** import on the bundled interpreter today. Adding `import pytest` would have broken that for the **whole module** — destroying my only local proof mechanism, on a machine with no pytest, in order to satisfy a stylistic instruction.
- **Fix:** a bare `try/except TypeError` loop asserting the same thing, plus a **positive control** that the complete call succeeds so the loop cannot pass vacuously. The three surviving `pytest` mentions in that file are all **prose inside docstrings** — no import, no live call — and the module still imports locally.
- **Per the brief:** where a plan criterion contradicts the file's own documented invariant, the invariant wins, and it is said here rather than silently complied with.

**2. [Rule 2 — missing critical functionality] `_persist_round_yield` wraps its own `await`.**
- **Found during:** Task 2, running the never-raises driver.
- **Issue:** The plan had the helper delegate entirely to `record_round_safe`'s internal try/except. A driver replacing the emitter with a raiser showed the `RuntimeError` **escaping `_persist_round_yield` uncaught** — and the plan's own `<behavior>` block requires *"a writer that RAISES leaves `_persist_round_yield` returning normally"*, as does mutation row 9.
- **Fix:** one `try/except Exception` with a `log.warning`, no retry.
- **Why it matters:** `runs/yield_records.py` is a file **this plan may not edit** (15.8-05 owns it). Depending solely on a sibling module's internal discipline to protect a ~$45 run is the wrong dependency — one refactor there, invisible from here, and an exception reaches `run_workshop_stage_b`'s outer handler, which **returns `_fallback_winners`** rather than merely logging.

**3. [Rule 1 — bug] My own test used `ast.get_docstring()` to strip a docstring, which silently does NOTHING.**
- **Found during:** Task 2 verification, running the source assertions.
- **Issue:** `test_the_winner_scoped_keys_are_never_read_inside_the_helper` did `body.replace(ast.get_docstring(fn), "")`. `get_docstring` returns the **cleaned, dedented** text, which does not appear verbatim in the source, so the replace matched nothing and the assertion ran over the docstring — which names all three forbidden keys **on purpose**. **It would have failed in Cloud Build**, on prose, while the code was correct.
- **Fix:** strip the docstring **by its own `ast` source segment** (skip the leading `Expr`/`Constant`/`str` statement). Recorded in the test's own comment so it is not reintroduced.
- **Why it is recorded:** this is the harness-lies-before-the-code-does class, caught only because the check was actually run rather than assumed.

**4. [process] Task 3's `2-remove` edit was written, reverted, and re-applied to keep commits atomic.**
- Both Task 2's and Task 3's changes live in `workshop_rank.py`. The Task 3 hunk was temporarily reverted so the Task 2 commit contained only Task 2's work, then re-applied. No functional consequence; noted so the commit sequence reads honestly.
