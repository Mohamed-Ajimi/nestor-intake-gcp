## THE TWO PATHS. This distinction is the whole point of the cost half.

`compute()` branches BEFORE `_rate` is ever called:

- **Key ABSENT** -> the `if key not in prices` branch -> logs `Unknown LLM model cost` at WARNING ->
  returns `None`. The caller writes NULL `cost_usd`. This is the HONEST state.
- **Key PRESENT with null values** -> `_rate` runs -> `entry.get(field) is None` -> logs
  `missing rate ... treating as 0` -> returns `Decimal("0")` for EVERY field -> `compute` returns a
  confident `Decimal('0')`.

    missing key                      -> None

## A CORRECTION THE EXECUTOR MUST CARRY (do not repeat the looser framing)

The shorthand "a null rate clears `cost_pending`" is not accurate for THIS model, and the accurate
version matters to 15.8-15.

`run.cost_pending` is set by `AuditedLLMClient.end_call` only via `dr_cost_pending`, and that flag is
set ONLY on the `handle.provider == "google"` branch (a deep-research call with no `usageMetadata`),
plus separately by `serpapi_search` when the SerpApi unit price is unknown. The `openai` branch never
sets it. So for `gpt-5.6-sol` today:

- the five calls write `cost_usd = NULL` on their `audit_log` rows;
- `run.cost_pending` is NOT set by them;
- the run total is `COALESCE((SELECT SUM(cost_usd) FROM audit_log WHERE run_id = :id), 0)`
  (four sites in `runs/worker.py`), and SQL `SUM` SKIPS NULLs.

Therefore the total is SILENTLY a floor: nothing flags it, and the only way to see it is to count
`audit_log` rows where `cost_usd IS NULL`. Adding the key with nulls would turn those five NULL rows
into five confident `$0.00` rows and make the total look COMPLETE while still being a floor — which
is strictly worse than today, because today the NULLs are at least countable. Record this in
`15.8-PRECONDITIONS.md`; 15.8-15 needs it to read V-01's `$53.48` correctly.

## The redaction path

`tribunal/nestor_pulse_sdk/audit/gcs_blob.py`:

- `_DEFAULT_REDACT_KEYS` is a `frozenset` of eight lowercase KEY NAMES: `authorization`, `x-api-key`,
  `anthropic-api-key`, `openai-api-key`, `google-api-key`, `x-goog-api-key`, `api_key`, `apikey`.
- `_redact_dict(d, redact_keys)` recurses dicts and lists and replaces a value with the literal
  `"[REDACTED]"` **when its KEY NAME matches**. It never inspects a value.
- `upload_audit_body(...)` does exactly two things with the bodies:
  `safe_request = _redact_dict(deepcopy(request_dict), redact_set)` and
  `safe_response = deepcopy(response_dict)`.

**Two live gaps, both observed, both in scope for this plan:**

1. **Key-name-only.** A credential inside a URL VALUE is not touched. Observed on this machine:
   `_redact_dict({"url": "https://serpapi.com/search.json?q=x&api_key=LIVESECRET"}, _DEFAULT_REDACT_KEYS)`
   returns the dict UNCHANGED, secret intact.
2. **The response half is not redacted AT ALL.** `safe_response` is a bare `deepcopy`. This is not
   theoretical: `AuditedLLMClient.write_failure` builds
   `error_dict = {"error": str(error), "type": type(error).__name__}` and passes it as
   `response_dict` with `request_dict={}`. Any provider exception whose `str()` renders a request URL
   lands verbatim in a 7-year-retained object.

`pipeline/tribunal/serpapi.py` is already careful and is NOT the defect: `SerpApiError` carries a
status code and a `_safe_excerpt`-scrubbed body and no URL, `_safe_url()` returns the path only, and
`AuditedLLMClient.serpapi_search` builds its `request_dict` from a WHITELIST containing `url_path`
and no key under any spelling. Its own docstring says the `gcs_blob` redactor is "belt-and-braces
here, not the control." **This plan's job is to make the belt-and-braces actually hold**, because
`search()` does NOT wrap the `httpx` `.get()` in a try/except — a transport-layer exception
propagates RAW out of `search()` into `serpapi_search`'s `except Exception as exc:` and then into
`write_failure`.

Existing coverage to extend, not duplicate:
- `tests/test_own_researcher.py` already asserts `gcs_blob._redact_dict({"params": {"api_key": ...}})`
  redacts by key name. That is the covered half.
- `tests/test_audit_body_endpoint.py` asserts the stored body is already redacted on read-back.
- `tests/test_cost_serpapi.py` is the cost/SerpApi/credential-hygiene test module and is ALREADY in
  the engine gate's file list. Its docstring already claims a SerpApi audit row "carr[ies] no
  credential", which makes it the correct home for the url-query assertions.
