# Phase 15.8 Plan 04: workshop_register / cluster_candidates gap closure Summary

**Both halves of D-W4-1's drop signal are now recordable in production, the barred list suppresses what the model is actually about to re-propose, and a raised clusterer no longer erases the run's spend signal.**

## Performance

- **Duration:** ~78 min

- **Files modified:** 3 (exactly the plan's `files_modified`)

## Accomplishments

### Task 1 — `barred_block` renders the NEWEST bars, and a zero cap renders none

`barred_block` sliced from the FRONT of the list, so once a run passed
`_BARRED_MAX_ENTRIES = 24` every generate and evolve prompt carried the OLDEST 24 bars and hid
the NEWEST. The bars a model has just earned are exactly the ones it is about to re-propose, so
the block was least useful precisely when it began to matter — and a 10-round loop over a
~36-candidate population reaches 24 bars.

The slice now takes the last `limit` entries **with an explicit zero branch**. A bare
`entries[-limit:]` would have been wrong in the one case that matters: at `limit == 0` it returns
the entire list, turning the prompt bound into no bound at all (T-15.8-04-02), and `limit`
reaches 0 legitimately through `cap_entries=0` and through the `max(0, limit)` clamp.

Both places that asserted the old order were corrected — `barred_block`'s docstring paragraph and
the `_BARRED_MAX_ENTRIES` widths comment — so the code and its comments do not disagree. The
widths paragraph names the `entries[-0:]` trap explicitly so the next reader does not "simplify"
the guard away.

### Task 2 — a production `DROP_CLUSTERED_ONTO_LIVE` writer, and `count_drops`

`DROP_CLUSTERED_ONTO_LIVE` had **no production writer**: only `test_workshop_critique.py` wrote
it, so `drop_summary`'s third branch was dead code. D-W4-1 requires the drop log to separate two
OPPOSITE measured failures — the loop SPINNING, and an over-eager dedup strangling discovery
invisibly — and only the first was recordable.

`cluster_candidates` now records one drop per merged member in the representative-building branch,
with `clustered_onto` = the surviving representative. Guarded by `register is not None` because
`run_workshop_stage_a` calls this function with no register at all and `_slots` warns on every
non-dict — without the guard, every ordinary stage-A merge would emit a warning about a register
nobody passed. Wrapped in `try/except`: instrumentation may never fail a paid round.

`workshop_register.count_drops(register, *, cause=None, round_no=None)` was added, standard library
only, never raising.

### Task 3 — D-W5-7, a raised clusterer stops zeroing the run's accumulated calls

The EXCEPTION path did `stats["calls"] = 0` — an ASSIGN — while the SUCCESS path in the same
function accumulated. The loop creates ONE `cluster_stats` per run and calls this function once per
round, so a single raised clusterer discarded every earlier round's count. **Two changes, because
the one-line fix is a `NameError`:** `calls = 0` was hoisted above the `try:` (the chunking block
that runs first inside it reads `grouping._CLUSTER_MAX_BLOCK` / `_CLUSTER_BATCH` and can raise
before `calls` would otherwise be bound), and only then does the handler accumulate.

## ⚠ FOR 15.8-10 — THE D-W5-6 DROP-CAUSE HAZARD, RESTATED

**This plan has just made three reads in `workshop_rank.py` wrong, and it is not allowed to fix
them.** `workshop_register.record_drop` appends **both** causes to ONE list, `register["drops"]`.
That is the module's deliberate design and this plan did not change it. But `workshop_rank.py`
reads that list by **BARE LENGTH** in three places, and all three are named for the **barred** cause
alone (confirmed present in the tree this plan was cut from — re-locate by symbol, the line numbers
are an aid only):

| Site | Read |
|------|------|
| `workshop_rank.py:4527` | `drops_before = len(register.get("drops") or [])` |
| `workshop_rank.py:4540` | `dropped_this_round = len(register.get("drops") or []) - drops_before`, feeding `round_metrics(dropped_as_reproposal=…)` at `:4573` |
| `workshop_rank.py:5007` | `"dropped_as_reproposal": len(register.get("drops") or [])` in the stage-B `counts` block |

A bare length was **accidentally** correct only for as long as `DROP_CLUSTERED_ONTO_LIVE` had no
production writer. **It now has one, and live merges are the COMMON case**, so
`dropped_as_reproposal` will silently start counting ordinary near-copy merges — the "loop is
SPINNING" metric absorbing the exact opposite failure it exists to distinguish.

**Why it is not cosmetic:** 15.8-10 persists `round_metrics` into
`workshop_round_yield.barred_drops`, and 15.8-15 reads that table as **THE ONE MEASUREMENT**. An
inflated `barred_drops` in the only measuring run is not recoverable.

**The replacement is shipped and ready:**
`workshop_register.count_drops(register, cause=workshop_register.DROP_CLUSTERED_ONTO_BARRED)`,
which also takes `round_no=`. It exists as of commit `8ec2446` and `15.8-10 depends_on` includes
`15.8-04`, so the symbol is provably present rather than assumed.

**SWAP ALL THREE OR NONE.** `:4527` and `:4540` are a **matched pair** — fixing one leaves a delta
between two different denominators, which is worse than leaving both wrong. `:5007` is the stage-B
`counts` block and is named for the same cause, so it goes with them.

The hazard is also stated in `record_drop`'s docstring, which is in the module `workshop_rank`
already imports, so a reader who never sees this SUMMARY still meets it.

### Row 9 correction — a mutation that did not mutate

**The first attempt at row 9 stayed GREEN, and that was a defect in the mutation, not evidence about
the source.** It placed `calls = 0` as the *first* statement inside the `try:` — i.e. BEFORE the
chunking block — so `calls` was always bound and no test could fail. The original defect had
`calls = 0` inside the `try` but **AFTER** the chunking block, beside the semaphore. Re-applied at
the true original position, row 9 went red immediately with an `UnboundLocalError`. Recorded because
a mutation table row that silently fails to mutate reads exactly like a source that is correctly
guarded.
