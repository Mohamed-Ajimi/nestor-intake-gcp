## Deviations from Plan

### 1. `[Rule 3 — blocking] 15.8-PRECONDITIONS.md does not exist; the must_have naming it was not satisfiable as written

**Found during:** Task 1, at `read_first`.

**Issue:** The plan's `read_first` and its `must_haves.truths` require the sentinel table to name
*"one concrete sentinel per plan 15.8-01 .. 15.8-10, **derived from that plan's merged SUMMARY**"*.
**`15.8-08-SUMMARY.md` does not exist on this tree** — plan 15.8-08 is `autonomous: false` and has not
executed. Its artifact `15.8-PRECONDITIONS.md` is likewise absent, so the two blocking pre-conditions
it records could not be read either, and the plan's `key_links` entry pointing `15.8-UAT.md` at that
file could not be checked against its real content.

**Fix:** 15.8-08's sentinel row was derived from its **PLAN's `files_modified`** (`15.8-08-PLAN.md:11`)
instead of its SUMMARY, and names the same artifact. This is correct at the time the runbook is
*executed* — every plan will have merged by then — and it is the one row of the ten whose target was
not confirmed on disk. The two pre-conditions were sourced from `15.8-CONTEXT.md` § Specifics rather
than from the (absent) record, and the NULL-cost query shape from the plan's own `<interfaces>` block.

**Files modified:** `infra/DEPLOY-RUNBOOK.md` (step 15.8.a).

**Commit:** `113c0eb`

**This is the seventh-of-eleven pattern this phase warned about** — a criterion that cannot be met as
literally written because it depends on a sibling that has not run. It is recorded rather than
silently complied with.

### 2. `[Rule 3 — blocking] The stale-base trap fired again — HEAD was at `a3a0c96`

**Found during:** the pre-flight branch check, before any file was read.

**Issue:** `git merge-base HEAD 0e74a95…` returned **`a3a0c96`**, i.e. the expected base was not an
ancestor at all — the worktree was cut from the same stale ref this repo has now hit on **every**
worktree this phase.

**Fix:** `git reset --hard 0e74a95589485d31ccdd6df1b675963b5243e5b7`, confirmed by `rev-parse`. All
three phase artifacts (`0018_yield_instrumentation.py`, `runs/yield_records.py`, `15.4-11-PLAN.md`)
asserted present afterwards.

**Note for the tally:** `rev-list --count BASE..HEAD == 0` would have read **GREEN** here. Only the
merge-base comparison caught it. That reasoning is now written into runbook step 15.8.a so the
operator inherits it.

### 3. `[Rule 1 — bug] `n/a — feature did not exist` written with an ASCII hyphen, deliberately

**Found during:** Task 2, while writing to the plan's own verification block.

**Issue:** The plan's automated verify runs `grep -qi "n/a . feature did not exist"`. The `.` matches
**one character**. An em dash is **three bytes** in UTF-8, so under a `C`/`POSIX` locale — which is
what a Cloud Build step gets by default — the pattern **fails against the em-dash form**, and the
check would go red on a correct file.

**Fix:** the cell literal is `n/a - feature did not exist` (ASCII hyphen), which matches the pattern
byte-for-byte in any locale. Prose around it still uses the em dash.

**Files modified:** `15.8-UAT.md`.

**Commit:** `40a3628`

## Corrections carried into the written procedure (D-W5-16, D-W5-18, D-W5-19)

These contradict earlier standing assumptions and are now stated in the runbook, not just in CONTEXT:

- **The deploy surface is TWO services, not four.** `tribunal-worker` + `tribunal-api` rebuild;
  `tribunal-migrate` repins and executes; **`nestor-api` and `nestor-frontend` are CONFIRM-ONLY** and
  `nestor-migrate` is not executed (INTAKE head stays **0013**, and the runbook makes the operator
  **read it back to confirm it did not move**). All four stay in the record. The runbook gives the
  command that **re-derives** the empty diff at deploy time and says plainly that a non-empty result
  puts those images back into the build list at the shared `$SHA`.
- **`NESTOR_WORKER_STALE_MINUTES` is 60, not 525600** — the operator is made to **read the live value
  back** rather than assert it. Paired with `cancel_research`'s rule that **only resolving the ROW
  stops a run** (pausing is not cancelling; cancellation is cooperative at 10.0s).
- **The absence of every `NESTOR_TRIBUNAL_WORKSHOP_*` on the live worker is written as a POSITIVE
  read-back finding**, because the Wave-4 validated config **is** the code defaults — if one is set,
  15.8-15 measures a configuration nobody validated.
- **Corroboration is measured at the ANGLE level.** At claim level it fails **by design** (the
  distiller-fallback path builds units as `(provider_name, chunk_text)`, so the angle is gone before
  distillation). A naive zero-NULLs check would report a design decision as a regression.
- **Three locales, not four**, and the `own` stream is **removed by design** — denominator 3 of 3.
- **The yield tables have NO read surface** (D-W5-18) is carried into step 15.8.i and into the Wave 5
  section of the UAT table, both saying that without 15.8-15's Q-PRE-4 grant every Wave 5 row is
  unfillable **after** the money is spent.
- **The unpaired-zero warning** is generalised into step 15.8.a: a sentinel asserting an absence must
  be paired with a presence over the same file.
