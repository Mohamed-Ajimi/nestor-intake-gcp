## FOR 15.8-09 AND 15.8-10 — THE PUBLIC SIGNATURES

```python
# runs/yield_records.py

PARENT_KINDS = ("client_question", "discovery_rider", "cross_cutting")
PARENT_KIND_UNKNOWN = "unknown"      # NOT a member of PARENT_KINDS
PROVIDER_UNKNOWN    = "unknown"      # NOT a member of any provider vocabulary
MAX_QUESTION_CHARS  = int(os.environ.get("NESTOR_YIELD_QUESTION_MAX", "600"))
MAX_LABEL_CHARS     = 64

async def record_assignment(run_id, tenant_id, *, provider, group_id, client_question,
                            parent_kind, stakes, fact_list_parsed, retry_used,
                            claims_kept, resolvable_sources, cost_usd, duration_s) -> None

async def complete_assignment(run_id, tenant_id, *, provider, group_id, client_question,
                              claims_surviving_verification) -> None

async def record_round(run_id, tenant_id, *, round_no, candidates_in, new_candidates,
                       keep_count, weak_count, kill_count, new_entrants_top_n,
                       barred_drops, round_cost_usd) -> None

async def record_assignment_safe(run_id, tenant_id, *, build) -> None
async def complete_assignment_safe(run_id, tenant_id, *, build) -> None
async def record_round_safe(run_id, tenant_id, *, build) -> None
```

`build` is a **zero-argument callable returning a dict** of the keyword fields. A pipeline module
calls the `_safe` trio and nothing else: a caller's arguments are evaluated *before* the callee is
entered, so only moving the construction inside the wrapper's `try` protects the paid loop from a
`KeyError` raised while building them.

`record_assignment` has **no `claims_surviving_verification` parameter** — it is not known yet.

### ⚠ PASS RAW VALUES ON BOTH PATHS. DO NOT PRE-NORMALISE ANYTHING.

The module owns the natural key `(run_id, provider, group_id, client_question)` and therefore owns
its symmetry. Three of the four members are normalised — `provider` clamps to a sentinel, `group_id`
turns `''` into NULL, `client_question` is scrubbed then clamped — and **both halves reach those
rules only through `_natural_key`**.

A caller that helpfully cleaned a value before calling would reintroduce the mismatch. The failure is
silent: the UPDATE matches nothing, and this module's own warning reads 0 affected rows as *"the
INSERT half never landed"* — a specific, confident and **wrong** diagnosis of a different failure, in
the one measuring run.

### `unknown` MEANS AN ENGINE BUG, NOT A LOST ROW

`parent_kind` and `provider` **clamp** to `'unknown'` and the row is still written with every measured
column intact. Seeing `unknown` in the table means the engine authored a bad discriminator — never
that a row went missing. There is deliberately no CHECK constraint: it would turn the same event into
a failed transaction mid-run. A dropped row would also **silently understate spend**, because
`SUM(cost_usd)` skips NULL rows across four `COALESCE` sites in `runs/worker.py`.

### FOR 15.8-10 SPECIFICALLY — three bindings that would look plausible and be wrong

- **`workshop_round_yield.barred_drops` means the BARRED cause and nothing else** (D-W5-6). Swap all
  three bare-length reads in `workshop_rank.py` (:4527, :4540, :5007) to the cause-filtered
  `count_drops` *before* persisting into this column.
- **`keep_count` is the KEEP critique-verdict count, NOT the winner-set size.** `round_metrics`'
  `winners` is `len(entries)`; KEEP is a verdict (`_KEEP`/`_WEAK`/`_KILL`).
- **`kill_count` and `new_entrants_top_n` have NO producer in `round_metrics` today.**
  `new_entrants` is computed inside `exit_verdict` and returned in *that* dict. `round_metrics` must
  be **extended**, not mapped.

- **Found during:** Task 2. My allowlist expected `("execute", None)`.
- **Fix:** added `_sql_statements()` and asserted the six statements **verbatim** instead of counting

**3. [Rule 1 — Bug] the `CHECK (` denylist entry fired on the REQUIRED `WITH CHECK (`**
- **Found during:** Task 2. A guard that is red on correct code invites a tired reviewer to delete it.
- **Fix:** replaced with a lookbehind guard plus a **two-way** negative control proving it
  distinguishes a policy's `WITH CHECK` from a real CHECK constraint, including one hiding in the
  same statement.
- **Commit:** `0bfddfd`

**4. [Rule 1 — Bug] two wrong test EXPECTATIONS in `test_yield_records.py`**
- **Found during:** Task 3.

- (b) the scrub-before-clamp cap was tight enough to clip the `<redacted>` marker itself, which would
  have stopped the test distinguishing "scrubbed" from "clamped away". Cap and prefix adjusted; the
  load-bearing assertion (`"someone@" not in stored`) and the inline counterfactual are unchanged.
- **Commit:** `8964c3b`

**5. [Rule 3 — Blocking] two harness bugs found before the code was blamed**

  synthetic name. Confirmed a false positive by running the checker over known-good
  `runs/run_events.py` and `runs/stages.py`, which report it identically; allowlisted.
- **Both are scratchpad tooling, not repo files.** Recorded because *the harness lies before the code
