### Three ways this entry breaks the file's own OpenAI pattern

Recorded so a future reader does not "correct" any of them:

1. **`cache_creation_5m: 6.25` is the first non-zero cache-write rate for any `openai/*`
   model in the file** — every other OpenAI entry is `0.0`. GPT-5.6 changed OpenAI's
   caching economics (cache writes at 1.25× uncached input). **The field NAME is
   imported**: it carries Anthropic's 5-minute-TTL naming, while OpenAI documents a
   **30-MINUTE** minimum TTL for this model. The number is right; the label is a schema
   artefact shared with the Anthropic block and does not describe OpenAI's TTL.
2. **`cache_read: 0.50` is a 90% discount**, where `gpt-4o` is 50% off and `o3` /

3. `completion: 30.00` is 6× prompt, a wider spread than `gpt-4o`'s 4×.

### ⚠ A KNOWN, DELIBERATE IMPRECISION — the 272K long-context meter

**Operator ruled 2026-08-04: record it, do NOT fix it.**

`gpt-5.6-sol` has a long-context meter. Above **272,000 INPUT tokens the ENTIRE request
re-bills** at **2× input and 1.5× output** (prompt $10.00, completion $45.00, cache_read
$1.00).

`_rate()` returns one flat number per field and has no notion of a tier, so the rates
above are **exactly correct below 272K and UNDER-REPORT by 2×/1.5× above it**.

Making `compute()` / `_rate()` tier-aware **was considered and declined** — too risky a
change to the audit cost path one plan before deploy, in code feeding a 7-year-retention
record.

**OBLIGATION HANDED TO 15.8-15:** measure the **actual `prompt_tokens`** on the five
openai deep-research calls against the 272K boundary and report **whether it bound**. If
it did, the figure is corrected with real measured data — **not guessed now**.

### The reading discipline for 15.8-15 — how to read a run total correctly

State it once, and never present a floor as a total.

- `compute()` returns **`None`** for a **missing key**, and **`Decimal("0")`** for a key
  **present with null rates**. These are different things. `Decimal("0")` is **falsy**, so
  a truthiness check cannot tell them apart.
- Measured in-session 2026-08-04 (bundled interpreter, real import):

  ```
  missing key openai/gpt-5.6-sol   -> None
  known key   openai/gpt-4o, 1M in -> Decimal('2.50000000')
  entry with all four rates null   -> Decimal('0')
  ```

- **The openai branch of `end_call` NEVER sets `run.cost_pending`.** `dr_cost_pending` is
  set at exactly one site — `audited_llm_client.py:1223`, inside the
  `handle.provider == "google"` branch. So `cost_pending` is **not** the protection here.
- `SUM(cost_usd)` **skips NULLs** (four sites in `runs/worker.py`: 316, 338, 416, 569,
  all `COALESCE(..., 0)`).

**THE RUN TOTAL IS A FLOOR FOR THREE MECHANICALLY DISTINCT REASONS:**

1. **`gpt-5.6-sol` rows that wrote NULL `cost_usd`** before this ruling — silently skipped
   by `SUM`. (Fixed going forward by this entry; V-01's recorded **$53.48 is itself a
   floor** and must be compared as one.)
2. **WR-02** — a failed or timed-out angle emits **no `assignment_yield` row at all**, so
   `SUM` misses it **with no column to explain the gap**.
3. **The 272K long-context meter** above — flat rates under-report by 2×/1.5× above the
   boundary.

**The query that makes reason 1 visible — use it literally:**

```sql
SELECT count(*) FROM audit_log WHERE run_id = :id AND cost_usd IS NULL;
```

## Pre-condition 2 — the audit-blob credential scan ⛔ NOT SETTLED — BLOCKING

**This pre-condition is OPEN. `15.8-14` must not proceed past it.**

Writing it early to unblock a deploy would defeat the entire gate.

### What plan 15.8-08 DID change (the code half) — commit `5c04421`

Both defects below were **confirmed live in source** before the fix:

1. **`_redact_dict` matches KEY NAMES ONLY** and never inspects a value, so a credential
   inside a URL query parameter — `https://serpapi.com/search.json?q=x&api_key=LIVE` —
   passed through untouched. **SerpApi authenticates by query parameter.**
2. **`safe_response` was a bare `deepcopy`** — the response half of every audit blob had
   **no redaction of any kind** — while `AuditedLLMClient.write_failure` writes
   `{"error": str(error), "type": ...}` onto that half, and `serpapi.search` does **not**
   wrap its `httpx` `.get()`, so a transport exception rendering the full request URL
   landed verbatim in a 7-year-retained object.

**Fixed by** adding `_scrub_urls_in_value` (value-level, non-raising, walks
`str`/`bytes`/`dict`/`list`) and wiring **both** the key-name redactor and the URL scrubber
into **both** halves of `upload_audit_body`. Proven by mutation: reverting either half, a
greedy value terminator, and loose parameter-name matching each turn the tests red.

**⚠ THE CODE FIX ONLY PROTECTS BLOBS WRITTEN FROM NOW ON.** It cannot reach objects
already in the bucket. That is what the operator scan is for, and why this pre-condition
is evidence, not code.
