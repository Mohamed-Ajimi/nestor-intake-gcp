<objective>
Close defect 2 from the 2026-08-31 intake test. Two independent bugs with one shared blast radius.

**2a — the client cannot tick.** `routes/intake.$id.tsx:106` sets `editable: intake.status === "draft"`.
The validation phase is entered at status `reviewed` (`:110-113`), so `editable` is ALWAYS false there,
and `IntakeForm.tsx:491` passes `disabled={!editable}` into `FieldRenderer`, which hands it to
`<input type="checkbox" disabled>`. The checkboxes render and are inert.

**2b — the operator's curation is ignored.** `AIReviewPanel.tsx:352` writes `show_to_client: q.include`.
Nothing in the repository reads it — one occurrence, the write. The client would therefore be shown
every proposal, including the ones the operator deliberately excluded.

They must ship together: fixing 2a alone makes 2b worse, because it turns an inert list of
all-proposals into a LIVE list of all-proposals, letting the client add questions the operator rejected.
</objective>

<critical_trap>
`ProposalListControl`'s toggle is:

```ts
const toggle = (i: number) => {
  const next = items.map((it, idx) => (idx === i ? { ...it, approved: !it.approved } : it));
  onChange(next);        // ← writes the WHOLE array back
};
```

It maps over `items` and passes the entire result to `onChange`. If `items` is filtered down to the
client-visible subset, the first tick **persists only that subset** and the operator-excluded
proposals are permanently deleted from the answer. The filter must therefore be **display-only**:
keep the full array as the write surface, render a projection of it, and map the clicked display
index back to its index in the full array.
</critical_trap>
