# 260909-g8b — Make the new trace design the whole run page, for every phase, from the first event

**Operator ruling 2026-09-09:** "make the new design the whole run page." The grouped light-mode
trace shipped in `7188b7e` (live as `nestor-frontend-00040-tgk`) renders ONLY for the
`deep_research` phase, and only after the first trace-tagged event arrives. Opening a run shows
the old feed; the new design appears mid-run, for one section. That is not what was asked for.

## Where the boundary is today — measured, do not re-derive

* `frontend/src/components/research/RunFeed.tsx` renders one `FeedGroup` per phase
  (`divider` row = phase title, `summary` row = "Worked for … · N actions · $cost · items",
  `body` = the rest). At ~line 257: `const grouped = executions.length > 0;` and at ~314
  `grouped ? <ResearchTrace …>{body.map(renderEvent)}</ResearchTrace> : shown.map(renderEvent)`.
* `executions` comes from `projectResearchTrace(events)` in `lib/research/groupedTrace.ts`,
  which at line 98 does `if (event.stage !== "deep_research") continue;`. So the switch flips
  ONLY for deep research, ONLY once trace meta exists.
* `ResearchTrace.tsx` = the new design: a `<section class="my-4 min-w-0 border border-ink/20
  bg-paper text-ink [color-scheme:only_light]">` shell with a serif `<h3>` title + `text-xs`
  scope line in a bordered header, execution bands on `bg-paperLight`, a progress bar
  (`bg-agenic-green`), one `<details>` per question group with `TaskBadge`/`StateIcon`, and a
  collapsible "original events" `<details>` footer that renders `children` (the raw rows).
  Props: `executions, active, activeExecutionId, executionIds, eventCount, unmatched, children`.
* `RunStatusCard.tsx:90` container: `mb-5 border border-ink/30 border-l-4 bg-paperLight px-6 py-5`
  with an accent left border. `EmptyFeed` in `routes/admin.pulse.runs.$runId.index.tsx:419`
  renders plain text for queued/empty runs.

## Target

Every phase of every run — adaptive intake, question workshop, research division, deep research,
distillation, merge, gates, skeptic, adjudication, conflict detection, synthesis, done — renders in
the new shell, unconditionally, from the very first event. The deep-research task grouping becomes
an ENHANCEMENT inside its phase's shell, not the trigger for the design. A freshly opened run with
zero events already shows the new design.

## Task 1 — split the shell from the deep-research body

`ResearchTrace.tsx` →
* `TraceSection` (the shell): the `<section>` + header (title, subline) + a body slot + the
  existing "original events" `<details>` footer + the `unmatched` notice. Props:
  `title: string`, `subline?: React.ReactNode`, `active: boolean`, `eventCount: number`,
  `unmatched?: boolean`, `raw?: React.ReactNode` (what goes in the original-events footer),
  `children` (the body).
* `ResearchTraceBody`: the executions → question groups → task badges → progress bar, exactly the
  logic that exists today. Props: `executions, active, activeExecutionId, executionIds`.
* Keep a thin `ResearchTrace` export composed of the two so `ResearchTrace.test.ts` keeps
  compiling; update those tests rather than deleting them.

## Task 2 — `FeedGroup` always renders the shell

In `RunFeed.tsx`:
* Delete the `grouped ?` switch and the `shown.map(renderEvent)` fallback branch.
* Every `FeedGroup` renders `<TraceSection title={dividerText} subline={summaryLine} …>`.
  - `title` = the divider row's text (the phase label the engine emitted; `NON_SCHEMA_STAGE_LABELS`
    already localises `done` → "Run complete"). Do NOT also render the divider as a `FeedRow`.
  - `subline` = the summary row's content when present ("Worked for … · actions · cost · items",
    reuse the existing summary parsing and `t()` keys); while the phase is live and no summary
    exists, the existing live indicator/blink. Do NOT also render the summary as a `FeedRow`.
* Body: if `executions.length > 0` → `<ResearchTraceBody …>` with the raw rows passed as `raw`;
  else → the rows via `renderEvent` directly in the body slot, with the D-09 "show more" rule
  preserved verbatim (`isComplete && hasHiddenRows(body.length)` — ask whether rows are hidden,
  never whether the phase is over).
* `isRowLive`, `settledSeqs`, `cursorSeq`, `canDrill`/`onDrill`/`renderAfterRow` (audit drill-down)
  keep working in BOTH bodies. `activeExecutionId` logic unchanged.
* `EmptyFeed` (queued / no events / terminal-with-no-history) renders INSIDE a `TraceSection` with
  the run's current stage label as title, so an empty or just-started run is already the new design.
