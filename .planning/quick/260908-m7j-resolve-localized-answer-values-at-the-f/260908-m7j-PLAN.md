been through the AI review — the refined text the client is asked to approve is unreadable.

call-site changes.

<interfaces>
The one contract this work depends on — `frontend/src/lib/i18n/localizeSchema.ts:38`:

```typescript
export function pick(value: unknown, lang: string): string | undefined;
```

Behaviour that makes it the correct discriminator (from its own docstring — load-bearing):
- `undefined` / `null` -> `undefined`
- a plain `string` -> returned unchanged (passthrough)
- non-object (number, boolean) -> `undefined`
- an object: `obj[lang.slice(0,2)] ?? obj.nl`, then a last-resort scan of ONLY `["nl","fr","en"]`
- **`undefined` means "not a localized value"** — deliberately restricted to the three locale keys so
  a stakeholder row `{name, role, email}` does NOT resolve to a name and look like a success.

`FieldDisplay` already relies on that contract. Do NOT modify `pick()` and do NOT widen its
locale-key restriction.

The answer-row shape being read — `frontend/src/lib/api/answers.ts:14`:

```typescript

```
